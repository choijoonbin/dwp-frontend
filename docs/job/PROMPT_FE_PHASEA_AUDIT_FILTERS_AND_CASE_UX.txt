[SynapseX][Phase A] 감사추적로그 필터/케이스 상세 Action·감사스트림 UX 정리 (Frontend Prompt)

목표
- Phase A 범위에서 “동작은 됐는데 의미를 확인할 수 없음/빈 화면처럼 보임” 문제를 제거한다.
- 감사추적로그(Audit) 필터는 하드코딩 제거 + 트렌드에 맞는 ‘기본 필터 4~5개 + Advanced 접힘’ 구조로 정리한다.
- 케이스 상세의 우측 버튼/탭(액션, 감사 스트림)이 Phase A 수준에서 사용자에게 명확한 의미를 갖도록 문구/동작을 정리한다.
- Phase B(조치 생성/추천/실행)는 아직 미구현이므로, 관련 영역은 ‘정상적인 Empty 상태’를 명확히 보여준다.

전제(현황)
- Audit 화면의 필터 옵션(카테고리/이벤트유형/결과/행위자 유형 등)이 프론트 하드코딩으로 구성되어 있음.
- 케이스 상세의 ‘액션 승인/거절/정보 요청’은 “상태만 변경 + audit만 남김” 수준으로 동작하여 사용자가 ‘아무 일도 안 일어남’으로 인지함.
- ‘조치 실행 센터’는 /api/synapse/actions?caseId=... 호출 결과가 0건(Phase B 미구현이면 정상)인데, 사용자에게 정상 상태임이 드러나지 않음.
- ‘감사 스트림’ 탭은 사실상 감사추적로그로 이동 링크만 제공하여 탭의 존재 이유가 약함.

작업 범위(Frontend)
1) 감사추적로그 필터 UI/UX 재설계 + 코드 API 바인딩
2) 케이스 상세: 상태 변경(해결/무시/정보요청) 동작 후 사용자 피드백(Toast/링크) 강화
3) 조치 실행 센터: Empty 상태 문구/가이드 추가 + Phase B 대기임을 명확화
4) 케이스 상세 ‘감사 스트림’ 탭: 최소 유지안(링크 탭) 또는 추천안(타임라인 탭) 중 1안 적용
   - 최종 선택은 아래 “선택지” 기준으로 구현하되, 기본은 안1(최소 변경)로 진행 가능.

================================================================================
1) 감사추적로그 필터: 하드코딩 제거 + UI 정리
================================================================================

1-1. 코드 API 사용 방식(필수)
- 기존 useCodes(groupKey) 또는 공통 codes fetch 훅을 재사용하여 아래 groupKey들을 조회한다.
  - AUDIT_CATEGORY
  - AUDIT_EVENT_TYPE
  - AUDIT_OUTCOME
  - AUDIT_ACTOR_TYPE
  - (선택) AUDIT_SEVERITY, RESOURCE_TYPE
- 응답 스키마는 기존 /api/admin/codes?groupKey=... 형태를 따른다고 가정
  - code / label(name) / sortOrder / isActive / tenantId 등

1-2. 필터 구조(트렌드 기준)
- “기본 필터(상단 고정)” 4~5개 + 검색어 1개
  - 기간(period): 기본 ‘최근 1시간’ 또는 ‘오늘’
  - 카테고리(category): 기본 ‘케이스’ 또는 ‘전체’
  - 이벤트유형(eventType): 기본 ‘전체’
  - 결과(outcome): 기본 ‘전체’
  - 행위자유형(actorType): 기본 ‘전체’
  - 검색어(q): caseId, actor, resourceId 등 빠른 검색
- Advanced(접힘 패널 또는 Drawer):
  - 심각도(severity), 리소스타입(resourceType), 채널(channel), IP, User-Agent 등
  - 현재 화면에 ‘지저분함’을 만드는 옵션은 Advanced로 이동
- 초기화 버튼: “필터 초기화”는 기본필터만 초기화 + Advanced는 별도 초기화 또는 함께 초기화(둘 중 1개로 통일)

1-3. UI 컴포넌트 가이드
- 기본필터는 한 줄(또는 두 줄)로 정렬되게 하고, 줄바꿈 최소화
- Select는 “상위 5~7개 고정 + 나머지 스크롤/검색” 규칙 적용
  - 옵션이 20개 이상이면 반드시 검색을 제공(ComboBox/Searchable Select)
- Shadcn UI 또는 프로젝트 표준 컴포넌트를 사용
- 필터칩(현재 적용된 필터 요약)은 상단 또는 검색창 아래에 “chips” 형태로 노출(선택)

1-4. DoD(완료 기준)
- 하드코딩된 옵션 배열/enum이 제거되고, 코드 API 값으로 렌더링됨
- QA가 2~3 클릭으로 “케이스ID(예: 85114) 관련 audit 이벤트”를 조회할 수 있음
- 필터 영역이 한 화면에서 과도하게 커지지 않음(‘지저분함’ 해소)
- Empty 상태/로딩 상태가 명확함

================================================================================
2) 케이스 상세: 상태 변경 후 사용자 피드백(Phase A)
================================================================================

2-1. 상태 변경 동작(현 상태 유지)
- ‘액션 승인’ → RESOLVED(해결됨)
- ‘거절’ → DISMISSED(무시됨)
- ‘정보 요청’ → TRIAGED 또는 OPEN/IN_PROGRESS로 되돌리는 정책 중 현재 백엔드 정책에 맞춤
  - 단, 버튼 라벨은 “액션 승인/거절”처럼 오해 유발 -> Phase A에서는 상태 변경임을 명확히:
    - “해결 처리”, “무시 처리”, “추가정보 요청(상태 표시)” 등으로 개선

2-2. 상태 변경 직후 UX(필수)
- 성공 시 Toast
  - 예: “상태가 ‘해결됨’으로 변경되었습니다. (감사로그에서 확인)”
- Toast 내 또는 화면 내에 링크 제공:
  - “감사로그에서 확인” 클릭 시 /synapse/audit?caseId=85114(가능하면 query로 filter 적용)
  - query 키는 백엔드/프론트 기존 규칙에 맞춤. 없다면 검색어(q)에 caseId를 프리필로 전달.

2-3. DoD
- 사용자는 상태 변경 후 “무슨 일이 일어났는지” 즉시 인지 가능
- 상태 변경 후 Audit 화면에서 해당 이벤트가 보이는 경로가 제공됨

================================================================================
3) 조치 실행 센터(Phase A: Empty 정상화)
================================================================================

3-1. Empty State(필수)
- /api/synapse/actions?caseId=... 가 0건일 때 문구를 다음 취지로 명확히:
  - “아직 생성된 조치가 없습니다. (Phase B에서 조치 추천/생성 연동 예정)”
- ‘액션 생성’ 버튼이 존재한다면:
  - Phase B 미완료 시 비활성 + Tooltip(“Phase B에서 활성화 예정”) 또는 노출 자체를 숨김(정책 1개 선택)
- 페이지 상단 KPI(승인대기/오늘승인/오늘실행)가 0일 때도 “정상”으로 보이게 설명

3-2. DoD
- 사용자가 ‘버그’로 오해하지 않도록 Empty 상태가 설명됨

================================================================================
4) 케이스 상세 ‘감사 스트림’ 탭 재정의(택1)
================================================================================

선택지 안1(최소 변경, 권장 for Phase A)
- 탭 이름: “감사 로그”
- 탭 내용: “감사 로그 보기(케이스 필터)” CTA 버튼 1개 + 간단한 설명
- 클릭 시 감사추적로그로 이동 + caseId 필터 적용

선택지 안2(추천, 가능하면)
- 탭 내에 케이스 단위 타임라인(최근 N건=20) 표시(읽기 전용)
- 하단에 “전체 감사 로그 보기” 링크 제공
- 필요 API: /api/synapse/audit-events?caseId=... (백엔드가 제공하면 연동)

DoD
- 탭에 들어갔을 때 “이 탭을 왜 보는지”가 즉시 이해됨(단순 링크 탭이라도 OK)
