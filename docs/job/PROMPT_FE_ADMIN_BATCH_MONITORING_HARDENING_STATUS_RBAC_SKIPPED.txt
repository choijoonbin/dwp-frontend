[FRONTEND PROMPT] Admin Batch Monitoring 보완(P0) — Scheduler Status 표시 + RBAC(403) UX + SKIPPED 운영 UX
(대상: DWP Frontend / Admin Batch Monitoring 화면, Aura 제외)

## 결론/결정안(3줄)
- “정지/재시작 토글” UI는 넣지 않는다(운영 리스크).
- 대신 **Scheduler Status(조회 전용)** 를 상단에 표시하고, **RBAC(403)** 및 **SKIPPED(락 미획득)** UX를 표준화한다.
- Manual Run 이후 runs 목록/상세가 즉시 갱신되도록 invalidate/refetch를 고정한다.

---

## 0) 전제(백엔드 변경 반영)
백엔드가 아래를 제공/보강했다고 가정한다.
- GET `/api/synapse/admin/detect/scheduler/status`
  - enabled, schedule_type, interval_minutes|cron_expression, last_success_at, last_fail_at, running, running_run_id, (optional) next_planned_at
- Admin APIs는 RBAC 강화로 403이 정상 발생할 수 있음
- Manual Run(POST) 응답이 SKIPPED일 때 `skipReason`, `runningRunId`(또는 동등 정보)가 포함될 수 있음

---

## 1) 구현 범위(In/Out)
### In
A) **Scheduler Status 패널(상단)**
- 위치: Batch Monitoring 상단(테이블 위)
- 표시(최소):
  - Auto Enabled: ON/OFF
  - Interval/Cron
  - Running 여부 + runningRunId
  - Last Success / Last Fail
  - (있으면) Next Planned
- Polling: 30~60초 간격 또는 화면 포커스 시 refetch

B) **RBAC(권한) UX**
- 메뉴/페이지 진입:
  - 권한 없으면 메뉴 숨김(가능하면) + 접근 시 403 페이지/배너
- API 403 응답 시:
  - “권한이 없습니다(ADMIN_OPERATIONS 필요)” 안내
  - 불필요한 재시도 루프 금지

C) **SKIPPED 운영 UX**
- Manual Run 실행 결과가 SKIPPED면:
  - toast: “다른 인스턴스에서 배치 실행 중(락 미획득)”
  - detail에 runningRunId/skipReason 표시(있을 때)
  - History 목록은 그대로 유지(실행 생성이 없을 수도 있음)

D) **Invalidate/Refetch 고정**
- Run Now 성공/실패/스킵 모두:
  - runs 목록 query invalidate
  - 선택된 runId가 있으면 detail refetch

### Out
- enable/disable 토글
- cron/interval 수정 UI
- 룰 편집 UI

---

## 2) 화면 상세(권장 UI)
### 2.1 Scheduler Status Card
- 컴포넌트 예: `<SchedulerStatusCard />`
- 상태 배지:
  - enabled=true: “AUTO”
  - running=true: “RUNNING”
  - lastFailAt 최근이면 “DEGRADED”(선택)
- 링크:
  - “View last run” → 마지막 runId detail open(있으면)

### 2.2 Run History Table
- 기존 구현 유지
- status 컬럼에 SKIPPED 포함
- RUNNING 강조(배지/스피너)

### 2.3 Manual Run 영역
- Confirm modal 필수
- 실행 결과에 따라 toast 분기:
  - COMPLETED: success
  - FAILED: error + “View Audit”
  - SKIPPED: warning + runningRunId 표시

---

## 3) TanStack Query 설계
- status
  - queryKey: ['detectSchedulerStatus']
  - refetchInterval: 60000 (권장)
- runs
  - queryKey: ['detectRuns', filters, page, size, sort]
- run detail
  - queryKey: ['detectRunDetail', runId]

Mutation: runNow
- onSuccess/onSettled:
  - invalidateQueries(['detectRuns'])
  - if selectedRunId: refetch(['detectRunDetail', selectedRunId])
  - refetch(['detectSchedulerStatus'])

---

## 4) Definition of Done
- 페이지 상단에 Scheduler Status가 표시된다(enabled/interval/running/last success/fail)
- 권한 없는 사용자:
  - 메뉴가 숨겨지거나, 접근 시 403 안내가 뜬다
- Manual Run 결과가 SKIPPED일 때:
  - warning toast + runningRunId/skipReason이 보인다
- 실행 후 목록/상세가 즉시 갱신된다
- 다크모드에서 배지/텍스트 가독성 유지

---

## 5) 테스트 시나리오
1) ADMIN 권한 사용자:
- 페이지 진입 → status 카드 값 확인
- Run Now 클릭 → 실행 후 목록 갱신 확인

2) 권한 없는 사용자:
- 직접 URL 접근 → 403 안내 확인

3) SKIPPED 재현:
- Run Now를 브라우저 2개 탭에서 거의 동시에 실행
- 한쪽은 SKIPPED → warning toast + runningRunId 표시 확인
