[FRONTEND PROMPT] Admin 배치 모니터링(최소) 메뉴 구현 — Run History/Detail/Manual Run
(대상: DWP Frontend / SynapseX, Aura 제외)

## 0) 전제(백엔드 준비)
- detect_run 조회/상세/수동 실행 API가 존재하거나, 이번 작업에서 BE가 제공한다.
- 수동 실행 결과는 COMPLETED/FAILED/SKIPPED 중 하나일 수 있다(특히 advisory lock 미획득 시 SKIPPED). fileciteturn11file1

---

## 1) 목적
운영자가 “배치가 정상 동작하는지 / 재실행 / (옵션) backfill”을 확인할 수 있는
최소 관제 화면을 Admin에 추가한다.

---

## 2) 라우트/메뉴
- Admin > Batch Monitoring (또는 Admin > Operations > Batch)
- 라우트 예: `/admin/batch` (프로젝트 라우팅 규칙에 맞춰 결정)

---

## 3) 화면 구성(정석 최소)
### A) Run History (테이블)
- 필수 컬럼:
  - started_at, status, window_from~to, duration_ms, created_count, updated_count, suppressed_count, run_id
- 기능:
  - 기간 필터(from/to)
  - status 필터(RUNNING/SUCCESS/FAILED/SKIPPED)
  - 페이징/정렬(기본 started_at desc)
- Row click → Run Detail drawer

### B) Run Detail (Drawer)
- counts_json 표시(있으면 rule breakdown)
- “View Audit” 링크(runId 또는 caseId 기반)
- (가능하면) “Affected Cases” 링크(runId로 케이스 리스트 필터)

### C) Manual Controls (권한 제한)
- Run Now 버튼(Confirm modal 필수)
- Backfill(선택): windowMinutes 또는 from/to 입력
- 실행 후:
  - toast(성공/실패/SKIPPED)
  - runs query invalidate → 목록 자동 갱신

---

## 4) 데이터 패칭/상태
- TanStack Query
  - queryKey: ['detectRuns', filters, page, size, sort]
  - queryKey: ['detectRunDetail', runId]
- Mutation:
  - runNowMutation → onSuccess: invalidate(['detectRuns'])
- 상태:
  - filters(from,to,status)
  - pagination(page,size)
  - selectedRunId

---

## 5) UX/에러 처리
- RUNNING: spinner/badge
- SKIPPED: warning badge + 이유(“다른 인스턴스가 실행 중(락 미획득)”) 간단 문구
- FAILED: error badge + “View Audit” 유도
- Empty: “실행 이력이 없습니다”

---

## 6) Definition of Done
- Run History 조회/필터/페이징이 정상
- Run Detail drawer가 정상
- Manual Run 실행 후 목록 갱신
- 권한 없으면 메뉴 자체가 숨겨지거나(추천) 접근 시 403 처리
- 다크모드에서 배지/텍스트 가독성 유지
