1) 구현 범위(In/Out)
IN(P0)
- CasesPage: status select UX 개선(검색형 combobox + pinned + maxHeight)
- Cases list: 카드/테이블에 표시되는 값은 API 응답 기반으로만 렌더링(하드코딩 제거)
- QueryKey/filters: q,status,severity,date range, sort, paging → 실제 API query로 전달

IN(P1)
- CaseDetailPage: Summary(좌측), 3-panel 구조 유지
- Tabs:
  - AI 분석: /cases/{id}/analysis
  - 에이전트 스트림: aura SSE hook 연결(있다면) + fallback(메타 표시)
  - 신뢰도: /confidence
  - 유사케이스: /similar
  - RAG: /rag/evidence
- 모든 탭에 Skeleton/Empty/Error 표준 적용

IN(P2)
- 시뮬레이션 모드: 버튼/토글 UX + /simulation 호출 + 결과 렌더
- “관련 미결재 항목”: 링크 클릭 시 open-items 화면으로 이동하면서 “관련 필터”를 전달(caseId 또는 bukrs/belnr/gjahr) fileciteturn28file0
- “데이터 계보보기”: lineage 페이지로 이동 + 관련 키 전달

OUT
- 자동 번역/AI 분석 고도화(모델/RAG 품질)는 별도 phase

2) 프론트 작업(라우트/컴포넌트/상태/쿼리키/필터바/스켈레톤/에러처리)

- /synapse/cases
- /synapse/cases/:id
- /synapse/open-items (관련 필터 수신)
- /synapse/lineage (관련 필터 수신)

2-2) Query Keys
- ['synapse','cases','list', tenantId, filters]

  (A) API 응답 또는 (B) sys_codes(code->label) 매핑 결과만 사용
- 임시 mock은 feature flag로 분리하고 default off

2-4) UI/UX 표준
- status select: searchable combobox + pinned 5~7 + scroll
- 긴 옵션은 virtualization 고려
- Empty state는 “데이터 없음” + “필터 초기화” CTA
- Error state: 표준 에러 포맷 표시 + 재시도 버튼

3) 스모크 플로우(클릭 경로 → API → 기대 audit_event_log)

- 케이스 클릭 → detail API 호출
