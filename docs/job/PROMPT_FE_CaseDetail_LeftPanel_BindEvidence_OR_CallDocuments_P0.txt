# PROMPT_FE_CaseDetail_LeftPanel_BindEvidence_OR_CallDocuments_P0.txt
목적: Case Detail(케이스 상세) 화면에서 좌측 “FI 문서” 카드가 N/A로 보이는 문제를 **근본적으로 해결**한다.
현황: `GET /api/synapse/cases/{caseId}` 응답에는 `data.evidence.documentOrOpenItem`에 문서 핵심값이 존재하나,
프론트는 `/api/synapse/documents`를 호출하지도 않고(호출 0건), 좌측 카드도 N/A로 렌더링됨.

---

## 0) 작업 원칙(반드시 준수)
- FE는 audit_event_log를 직접 쓰지 않는다.
- Tenant 헤더(X-Tenant-ID) 등 기존 axiosInstance 규칙 유지.
- “추가 API/스키마 가정 금지”: **현재 존재하는 `/api/synapse/cases/{id}` 응답만으로 우선 해결**(P0).
- 후속(P1)로 “문서 상세 API 호출”은 선택지로만 제시.

---

## 1) 재현(현재 상태 확인)
1) 케이스 목록에서 Case 85114(또는 임의 케이스) 진입
2) DevTools > Network 확인
   - 호출됨: `GET /api/synapse/cases/{id}` (200)
   - 호출 안됨: `/api/synapse/documents*` (0건)
3) UI 확인
   - 좌측 FI 문서 카드: 문서번호/일자/금액/거래처가 N/A, 0 USD로 표시됨

---

## 2) 원인 가설(둘 중 하나)
A. (가장 유력) **좌측 FI 문서 카드가 `caseDetail.keys.*` 또는 별도 state만 참조**하고,
   실제 데이터가 들어있는 `caseDetail.evidence.documentOrOpenItem`를 바인딩하지 않음.
B. 문서 카드가 원래 `/api/synapse/documents`를 호출하도록 설계되어 있었으나
   - 호출 트리거(useEffect/QueryKey) 누락
   - docKey 파라미터 생성 누락
   - 또는 feature flag/조건 분기에서 빠짐

---

## 3) P0 해결책(권장): “/cases/{id}만으로 좌측 FI 카드 채우기”
### 3-1. 바인딩 소스 확정
`caseDetail.data.evidence.documentOrOpenItem`를 단일 소스로 사용한다.

- 문서 식별:
  - docKey = evidence.documentOrOpenItem.docKey (예: "1000-1900000005-2024")
  - headerSummary.bukrs/belnr/gjahr/budat/xblnr
- 금액/통화:
  - evidence.documentOrOpenItem.amount, currency
- 거래처:
  - items[0].lifnr (vendor) 또는 items[0].kunnr (customer) 우선순위로 표시
- 라인 항목:
  - items 배열 길이 표시(현재 “라인 항목(0)” → items.length)

### 3-2. UI 매핑 규칙(필수)
- “N/A” 표시는 **해당 값이 실제로 null/empty일 때만**.
- 값이 있으면 반드시 렌더링.
  - 문서번호: headerSummary.belnr
  - 일자: headerSummary.budat
  - 금액: amount + currency (KRW)
  - 거래처: lifnr 또는 kunnr

### 3-3. 코드 변경 포인트(찾아서 수정)
- Case Detail 좌측 패널 컴포넌트(예: `CaseEvidencePanel`, `CaseLeftPanel`, `FiDocumentCard` 등)
- 현재 props/state가 무엇을 받고 있는지 확인 후 아래 중 하나로 통일:
  - `const doc = caseDetail?.evidence?.documentOrOpenItem`
  - `const header = doc?.headerSummary`
  - `const items = doc?.items ?? []`

### 3-4. Empty/Reason 유지(중앙 탭)
이번 작업은 좌측 FI 카드만. 기존 중앙(analysis/stream/confidence/similar/rag) empty fallback 정책은 건드리지 않는다.

---

## 4) 선택지(P1): “/api/synapse/documents 호출로 상세 확장”
P0 완료 후 필요 시만 진행.
- 트리거: 케이스 응답에서 docKey 확보 후, documents API 호출
- QueryKey 예시: `['documents', docKey]`
- 호출 조건: docKey 존재 && (사용자가 “문서 관계” 카드 클릭 시)
- DoD: 좌측 카드 기본은 /cases 응답으로, 클릭 시 documents 상세로 확장

---

## 5) 완료 조건(Definition of Done)
- 케이스 상세 진입 시 `/api/synapse/cases/{id}` 응답에 값이 있을 경우,
  좌측 FI 문서 카드가 아래를 **즉시 표시**해야 함:
  1) 문서번호(belnr)
  2) 일자(budat)
  3) 금액(amount + currency)
  4) 거래처(lifnr/kunnr)
  5) 라인 항목 수(items.length)
- Network에 `/api/synapse/documents` 호출이 없어도 좌측이 N/A가 아니어야 함(P0).
- 다크모드 대비/색상 깨짐 없음.
