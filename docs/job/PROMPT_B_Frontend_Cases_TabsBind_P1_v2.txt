[B) Front Prompt (React/Next)] Case Detail 탭 4종 실데이터 바인딩(P1) — BE Proxy 기준 (재생성본)

파일 경로 / 생성 파일명:
- docs/prompts/PHASE_Cases_Frontend_TabsBind_P1.md (산출 문서)
- (코드) apps/remotes/synapsex/src/pages/** 또는 case-detail/* (프로젝트 구조에 맞게)
- (가능하면) libs/shared-utils 또는 libs/design-system에 탭 공통 Empty/Error 컴포넌트 재사용

전제(가정)
- BE가 다음 endpoint를 제공한다(없으면 먼저 “PROMPT_A_Backend_Cases_TabsProxy_P1_v2.txt” 수행 필요):
  - GET /api/synapse/cases/{caseId}/analysis
  - GET /api/synapse/cases/{caseId}/confidence
  - GET /api/synapse/cases/{caseId}/similar
  - GET /api/synapse/cases/{caseId}/rag/evidence
- FE는 Axios 인스턴스로 X-Tenant-ID, Authorization을 자동 포함한다(프로젝트 표준)

목표
- Case Detail 화면의 탭 4종(analysis/confidence/similar/rag evidence)을 **하드코딩 없이 실데이터 API로 바인딩**한다.
- 각 탭은 “로딩 스켈레톤 / empty state / 에러(재시도)”까지 표준을 갖춘다.
- queryKey를 탭 단위로 분리하여 캐싱하고, 탭 이동 시 불필요한 중복 호출을 줄인다.

0) 결론/결정안(1~3줄)
- 탭 데이터는 BE Proxy 단일 경로(/api/synapse/**)로만 호출한다(라우팅/보안 안정성).
- 탭별 QueryKey/DTO를 분리하고, 탭 클릭 시에만 fetch(enable 조건)한다.
- SSE Stream은 이번 P1에서 제외하고(경로/프록시 확정 후), 우선 4개 탭을 완성한다.

1) 구현 범위(In/Out)
IN(P1)
- Case Detail 탭 4종 실데이터 바인딩
  1) AI 분석(Analysis)
  2) 신뢰도(Confidence)
  3) 유사케이스(Similar)
  4) RAG Evidence
- 각 탭 공통: Skeleton / Empty / Error+Retry
- i18n: empty/error/button 텍스트는 t() 키로 처리

OUT(P1)
- SSE Stream 탭 “실시간” 바인딩(별도 P1.5)
- 시뮬레이션(write 없는 what-if) (별도 P2)

2) 작업 지시(구체)
2-1) API Client 함수 추가(권장 경로)
- (예) apps/remotes/synapsex/src/api/cases.ts
  - getCaseAnalysis(caseId)
  - getCaseConfidence(caseId)
  - getCaseSimilar(caseId)
  - getCaseRagEvidence(caseId)

2-2) TanStack Query hooks 추가
- (예) apps/remotes/synapsex/src/queries/cases.ts
  - useCaseAnalysis(caseId, { enabled })
  - useCaseConfidence(caseId, { enabled })
  - useCaseSimilar(caseId, { enabled })
  - useCaseRagEvidence(caseId, { enabled })

QueryKey 규칙
- ['synapse','cases','analysis', tenantId, caseId]
- ['synapse','cases','confidence', tenantId, caseId]
- ['synapse','cases','similar', tenantId, caseId]
- ['synapse','cases','ragEvidence', tenantId, caseId]

2-3) 탭 컴포넌트 바인딩
- CaseDetailPage 내 Tabs:
  - 탭 선택 상태(activeTab)에 따라 해당 hook의 enabled를 true로
  - 탭 전환 시 이전 탭 데이터는 캐시 유지
- 각 탭 컴포넌트는 아래 상태를 반드시 처리:
  - isLoading → Skeleton
  - isError → ErrorPanel(메시지 + Retry)
  - data empty → EmptyState(“데이터 없음” + 안내)
  - data 존재 → 렌더

2-4) UI 표준 컴포넌트(있으면 재사용)
- <SkeletonCard/Panel />
- <EmptyState title/description action />
- <ErrorState title/description onRetry />

2-5) i18n 키(예시)
common.json:
- "cases.tabs.analysis.empty.title"
- "cases.tabs.analysis.error.title"
- "common.retry"
- "common.noData"

3) 완료 기준(Definition of Done)
- 케이스 상세 화면에서 탭 클릭 시 Network에 아래 호출이 보임:
  - /api/synapse/cases/{id}/analysis
  - /api/synapse/cases/{id}/confidence
  - /api/synapse/cases/{id}/similar
  - /api/synapse/cases/{id}/rag/evidence
- 탭별로 Loading/Empty/Error/Success 상태가 모두 UX 표준에 맞게 표시됨
- 하드코딩된 더미/문구/숫자 없이 API 응답 기반으로 표시됨
- 다크모드에서 텍스트/배지 대비 문제 없음
- lint/tsc 통과

4) 검증 방법(테스트 시나리오)
- seed 1건 이상 준비
- Case Detail 진입
- 탭 4개를 각각 1회 클릭
- 각 탭에서:
  - 데이터가 있으면 렌더 확인(스크린샷)
  - 데이터가 없으면 EmptyState 확인(스크린샷)
  - 의도적으로 401/500을 내고 ErrorState + Retry 확인(선택)
- 결과물로 다음을 첨부:
  - 탭별 스크린샷 4장
  - Network 캡처 1장(4개 요청이 찍힌 화면)
