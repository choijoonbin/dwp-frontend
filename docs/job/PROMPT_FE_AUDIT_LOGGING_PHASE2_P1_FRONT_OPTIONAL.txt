[FRONTEND PROMPT] Audit Logging 2차 적용(P1) — “UI 텔레메트리(선택)” + Audit 조회용 UX 보완
(주의: 2차는 1차(백엔드 audit 완성) 완료 후 진행)

============================================================
0) 결론/원칙
============================================================
- FE는 감사 로그(audit_event_log)를 ‘직접’ 쓰지 않는다.
- FE가 할 일은 2가지 중 선택:
  A) “감사 로그가 남는지” 확인을 위한 QA/디버그 도구(개발자용) 보강
  B) UI 상호작용 분석을 위한 Telemetry(ui_event_log 등) 별도 수집(운영 필요 시)

============================================================
1) 2차 범위 옵션
============================================================
옵션 A(권장, 가볍고 실용)
- 각 주요 화면에 “최근 활동 확인” 링크 제공:
  - Audit 화면으로 이동(/synapse/audit?filter=...) 또는
  - 케이스 상세에서 audit 탭으로 바로 연결
- 개발모드에서만 노출 가능한 “Audit Debug Panel”:
  - 마지막 API 호출과 event_type 기대값을 표시(로컬 상태)

옵션 B(필요 시)
- 별도 endpoint(/api/ui-events)로 UI 이벤트 전송
- 테이블 분리(ui_event_log), 샘플링/버퍼링 필요
- 이번 프로젝트 1차 목표(감사/규정)에는 불필요할 수 있음

============================================================
2) 2차 DoD(옵션 A 기준)
============================================================
- QA가 케이스/문서/오픈아이템/조치 화면에서 “이 동작이 audit에 남았는지”를 2~3클릭 내 확인 가능
- FE 변경은 최소이며, 감사 로그의 진실성은 BE가 유지
