## 1) P0: 수동 검증 체크리스트(필수, 결과 캡처 포함)
### P0-1 Admin 단독 실행 i18n 검증(F-1)
- 실행: `yarn dev:admin` (Host 없이 Admin만)
- 확인(ko↔en 토글 후):
  - ConfirmDialog(삭제/확인) 문구가 언어별로 바뀜
  - ErrorBoundary/Empty state 문구가 언어별로 바뀜
  - 네트워크: API 요청에 Accept-Language 헤더 포함
- 산출물:
  - 스크린샷 2장(ko/en)
  - 네트워크 캡처(헤더 포함)

### P0-2 Host 전파 검증(F-2) — 8개 라우트
- Host에서 ko→en 전환 후 아래 라우트로 이동하면서 “즉시 반영” 확인
  1) /synapse/command-center
  2) /synapse/cases
  3) /synapse/documents
  4) /synapse/open-items
  5) /synapse/actions
  6) /synapse/audit
  7) /admin/menus
  8) /ai-workspace
- 산출물: 각 화면별 1장 스크린샷(언어 전환 직후)

### P0-3 EN 레이아웃 회귀(F-3)
- EN 상태에서 다음 UI 깨짐 여부 점검:
  - Topbar 버튼(언어 버튼 포함), Sidebar 메뉴 truncate, Table column overflow, Chip/Badge, Confirm/Delete 버튼
- 산출물: 깨짐 있는 화면 스크린샷 + 해당 컴포넌트명/경로

### P0-4 CI/빌드 환경(F-4)
- CI에서 `self-signed certificate in certificate chain` 재현 여부만 확인
- 재현 시: Node/yarn가 참조하는 CA/프록시 설정 가이드 문서화(코드 변경 X)

## 2) P0: “케이스 라벨 코드 소스 API” 확정(Backend B-1 해결의 전제)
### P0-5 /synapse/cases 화면에서 코드 조회 API를 확정하고 기록
- DevTools Network에서 아래를 확인:
  - 호출 URL (예: /api/admin/codes?groupKey=CASE_TYPE 또는 synapsex 전용 endpoint)
  - Response payload에 label/name_ko/name_en 유무
  - Request headers: Accept-Language가 ko/en에 따라 바뀌는지
- 산출물:
  - Network HAR 또는 캡처(요청 URL+응답 JSON 일부)

## 3) P1: Mail Remote 단독 실행 i18n 보완(F-2 ⚠️)
### P1-1 Mail Remote 엔트리에 I18nProvider 추가(최소)
- Mail Remote가 Host에서 로드될 때는 Host i18n을 공유하지만,
  단독 실행(dev)에서는 i18n이 없을 수 있으므로 아래 중 1개 택일:

A) Remote entry(main.tsx)에서 ThemeProvider 아래에 I18nProvider 래핑
- Admin/SynapseX와 동일 패턴 적용
- InitI18nAxios도 포함(헤더 주입)

B) shared-i18n의 safeInit를 Remote 엔트리에서 1회 호출
- Provider 없이도 useTranslation이 동작하는지 확인 필요

권장: A)
