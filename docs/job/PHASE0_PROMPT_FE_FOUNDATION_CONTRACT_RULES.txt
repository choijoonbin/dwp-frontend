[PHASE 0 / Front Prompt] 표준 프로세스 기반 FE 계약/구조 정비 — 헤더/에러/페이지 규칙 + 메뉴/라우트 고정
(목표: Phase A/E2E와 Phase B/탐지배치를 얹기 전에, FE가 ‘표준 계약’을 깨지 않게 기초를 정리)

## 0) 원칙
- 기능 추가 최소: Phase 0에서는 ‘화면 확장’이 아니라 **계약/공통 규칙 정리**가 목적.
- 표준 헤더: 모든 REST/SSE에서 `X-Tenant-ID`, `Authorization`, `X-User-ID`, `X-Trace-ID` 전송.
- Error UI 표준: 에러를 mock/fallback으로 숨기지 않는다.
- 메뉴/라우트 키는 확정된 것만 사용(/synapse, /cases, /audit, /admin 등).

## 2) 구현 범위(In/Out)
### In
- axiosInstance/interceptor에서 표준 헤더 강제(누락 시 에러 로그)
- SSE 훅에서도 동일 헤더 전송(X-User-ID 포함)
- 공통 ErrorState/EmptyState/Skeleton 컴포넌트 톤 정리(이미 있으면 재사용)
- 페이지네이션/정렬 파라미터 표준(있다면) 문서화

### Out
- 신규 메뉴/대시보드 확장
- 케이스 생성 UI
- Agentic UI 고도화(Phase A)

---

## 3) 작업 순서
1) 표준 헤더 전수 점검(REST + SSE)
2) 공통 에러/빈상태 처리 규칙 문서화 + 컴포넌트 정비
3) route-map 문서 작성(실제 소스 기반)

---

## 4) Definition of Done
- “헤더 누락” 케이스가 0
- contract-rules / route-map 문서가 실제 코드 경로 포함
