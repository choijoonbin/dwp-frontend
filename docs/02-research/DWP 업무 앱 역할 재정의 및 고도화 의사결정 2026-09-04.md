후속 요청에 따른 기능 선행 개발 결과와 최신 검증 범위는 [업무 앱 고도화 구현 기록](../05-features/DWP-R1-WRK-001-unified-work-execution/implementation-report.md)을 참고한다. 본 문서의 구현 현황은 고도화 이전 감사 시점의 기록이다.

검토 대상은 현재 작업 디렉터리의 업무 홈과 통합업무함, 인접 앱, 실제 API·데이터 모델이다. 구현 감사, 제품·UX/정보구조, 글로벌 제품 비교의 세 전문 에이전트와 통합 아키텍처 검토를 병렬 수행했다.

## 1. 권고하는 결정

**업무 앱을 ‘여러 앱에 흩어진 내 조치를 실제 처리와 결과 확인까지 연결하는 통합업무함’으로 유지한다. 현재 업무 홈의 중복 요약은 개인 홈(Flow)에 흡수하고, 통합업무함을 업무 앱의 기본 진입으로 삼는다.**

이 권고의 우선순위는 원본 업무 연결과 완료의 신뢰성을 확보하는 것이다. 디자인 변경이나 메뉴 두 개의 유지 자체를 목표로 삼지 않는다. 개인 홈의 업무 발견 경로와 원본 처리 여정을 먼저 검증한 뒤 메뉴 제거·기본 진입 변경을 적용한다.

사용자에게 제시할 업무 앱의 약속은 다음과 같다.

> 여러 앱에 흩어진 내가 처리할 일을 한곳에서 확인하고, 필요한 근거를 보고 처리하며, 실제 결과까지 확인합니다.

| 판단 대상                            | 권고                                   | 이유                                                                                                   |
| ------------------------------------ | -------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 업무 앱 자체                         | 유지·역할 재정의                       | 날짜나 앱에 관계없이 지속되는 ‘내 처리 책임’을 모을 공간이 필요하다.                                   |
| 현재 업무 홈                         | 요약을 Flow에 흡수한 뒤 독립 메뉴 제거 | 같은 큐의 건수와 상위 항목을 다시 보여주는 중간 화면이다.                                              |
| 통합업무함                           | 핵심 화면으로 고도화                   | 여러 원천의 업무를 찾고 유형에 맞게 처리하는 고유 역할을 맡는다.                                       |
| ‘오늘 할 일’ 신규 메뉴               | 초기에는 도입하지 않음                 | 오늘 마감 필터와 개인이 오늘 하기로 선택한 계획은 다른 기능이다. 계획 수요와 모델이 확인되면 확장한다. |
| 캘린더·결재·알림에 업무 앱 전체 통합 | 비추천                                 | 각각 시간, 결재 결정, 변경 통지를 소유하며 횡단 업무 전체를 대표하지 못한다.                           |
| 범용 프로젝트 관리로 확대            | 현재 범위에서 제외                     | 간트·프로젝트·자원계획의 전면 구축은 기존 PRD와 다른 제품 투자다.                                      |

## 5. 글로벌 비교: 어떤 제품과 비교하는 것이 맞는가

‘글로벌 Top 3’에는 시장·매출·고객 규모·평가 기관 등 순위 기준이 필요하다. 이번 분석은 순위 주장을 하지 않고 **DWP의 직원 업무 통합 목적에 가까운 대표 비교군 3개**를 선정한다.

- Microsoft 365 Planner/To Do: 개인 업무와 협업 업무를 모아 실행하는 경험.
- ServiceNow Employee Center/Employee Slate: 직원의 할당 업무·승인·요청을 통합하는 경험.
- SAP Task Center: 서로 다른 업무 원천의 할당 작업과 처리 명령을 연결하는 경험.

Asana·monday.com은 개인 업무 관리의 깊이를 확인하는 보조 비교군으로 사용한다. 이들의 전체 프로젝트 관리 기능 수를 DWP 업무 앱의 충족률로 환산하지 않는다.

## 8. 권고 정보구조와 사용자 경험

### 8.1 메뉴와 경로

- 앱 표시명은 ‘업무’를 유지하고 중심 화면 제목을 ‘통합업무함’으로 일치시킨다.
- `/work`의 기본 진입을 통합업무함으로 바꾸는 것이 목표다.
- 기존 `/work/home`은 북마크·링크 호환을 위해 리디렉션으로 유지한다. 검색·선택 매개변수를 보존한다.
- Work Home 요약은 Flow의 기존 업무 제공자를 재사용한다. 동일 KPI 묶음을 새 위젯으로 추가하지 않는다.
- DWAI·ON은 선택 업무의 분석·초안·설명에 집중하며, 업무 홈과 별개의 복제 원장을 만들지 않는다.

### 8.2 단일 업무함의 기본 구성

주 사용자: 여러 원천에서 할당 업무를 받는 직원·승인자. 핵심 질문: ‘지금 내 조치가 필요한 것은 무엇이고, 바로 다음에 무엇을 해야 하는가?’ 주 행동: 선택 항목의 유형별 처리 또는 정확한 원본 상세 열기. 화면 유형: 목록과 상세.

| 영역         | 내용                                                                  |
| ------------ | --------------------------------------------------------------------- |
| 기본 보기    | 내 조치 필요. 미처리 모든 항목을 무조건 긴 목록으로 보여주지 않음     |
| 보조 보기    | 진행 중, 다른 사람 응답 대기, 완료, 내가 추적 중                      |
| 빠른 필터    | 지연, 오늘 마감, 원천, 업무 유형. 저장 보기와 URL 복귀 제공           |
| 행 정보      | 할 일, 원천, 필요한 행동, 기한/지연, 대기 대상, 최신성                |
| 상세         | 왜 내 업무인지, 필요한 근거, 원본의 현재 상태, 허용된 행동, 결과 이력 |
| 주 버튼 예   | 승인 검토, 보완 제출, 권한 검토, 원본에서 처리                        |
| 보조 버튼 예 | 원문 보기, 수행 시간 잡기, 추적하기. 권한과 지원 범위에 따라 노출     |

‘내 조치 필요’와 ‘다른 사람 응답 대기’는 현재 WAITING만으로 충분히 구분할 수 없으므로 데이터 계약을 먼저 추가한다. 단순 라벨 교체로 구현 완료라고 판단하지 않는다.

‘오늘 마감’ 저장 보기는 조건에 맞는 업무의 집합이다. 개인 계획 기능을 추가한다면 사용자는 날짜 없는 업무도 오늘 계획에 넣고, 순서를 정하고, 계획에서 빼도 원본 업무를 유지할 수 있어야 한다. 이 기능을 제공하기 전에는 My Day/오늘 계획이라는 이름을 사용하지 않는다.

### 9.3 명령과 완료의 경계

1. 결재·보완·검토는 원천 서비스가 상태와 업무 규칙을 소유한다.
2. 업무함은 원천의 현재 권한·버전을 확인하고 허용 명령만 제공한다.
3. 처리 요청 접수만으로 완료 표시하지 않는다. 비동기 처리는 반영 중으로 보여준다.
4. 통합 상세를 지원하지 않는 원천은 정확한 원본 화면으로 연결하며 지원 범위를 설명한다.
5. 재시도에는 동일 명령 식별자를 사용하고 중복 실행을 막는다. 서로 다른 원천의 일괄 처리에는 항목별 결과를 표시한다.
6. 일반 ‘완료’는 DWP가 직접 소유하는 할 일에만 허용한다. 그런 할 일 기능을 추가할 경우 생성·수정·완료·재개·원문 연결의 최소 생명주기를 함께 책임진다.
7. 캘린더 예약 종료, 알림 읽음, AI 초안 생성은 원본 업무 완료의 증거가 아니다.

이 원칙은 원천별 로직을 업무 앱에 복제하는 것을 막는다. 접근 권한 검토의 projection·전용 명령·감사 패턴을 공통 기반으로 추출하되 기존 Auth 도메인을 범용 업무 엔진으로 확대하지 않는다.

## 10. DWP 안에서 사용자가 하게 될 일

다음은 고도화 목표 여정이다. 현재 모두 제공된다는 뜻은 아니다.

### 여정 A: 부서장의 승인과 권한 검토

개인 홈에서 ‘오늘 내 판단이 필요한 업무’를 확인한다 → 업무함에서 구매 승인과 접근 권한 검토를 함께 본다 → 구매는 결재 근거·전용 결정으로, 권한 검토는 유지/회수 절차로 처리한다 → 원본 결과가 같은 큐에 반영된다.

사용자 가치: 어떤 앱에 승인할 일이 있는지 기억하고 순회할 필요가 줄어든다. 승인 결정 완료와 실제 권한/업무 반영 완료가 다를 경우 그 차이를 확인할 수 있다.

### 여정 B: 직원의 자료 보완과 작업 시간 확보

업무함에서 내 서비스 요청에 자료 보완이 필요함을 확인한다 → 필요한 근거와 양식을 연다 → 시간이 필요하면 캘린더에 30분 수행 시간을 잡는다 → 원본 요청에 자료를 제출한다 → 내 보완 의무는 해소되고 담당자 응답 대기로 이동한다.

사용자 가치: 언제 일할지 정하는 것과 무엇을 제출해야 끝나는지를 연결한다. 캘린더 예약을 옮겨도 요청의 실제 마감과 완료 상태는 유지된다.

### 여정 C: 대화에서 받은 후속조치

메신저 요청을 사용자가 ‘업무로 추적’한다 → 담당·기한·원문 링크를 확정한다 → 업무함에서 실행하고 DWAI·ON에 근거 요약·초안을 요청한다 → 결과를 해당 원문/업무에 제출하고 완료 근거를 연결한다.

사용자 가치: 대화 속 약속을 잃지 않으며, 모든 메시지가 할 일로 쌓이는 부담도 줄인다. 원문 접근 권한이 사라지면 보존 가능한 최소 업무 정보만 남기고 원문 노출을 차단해야 한다.

## 12. 차별성과 성과를 어떻게 판단할 것인가

‘통합업무함’과 ‘AI 우선순위’ 자체는 글로벌 시장의 독점적 차별점이 아니다. DWP 내에서의 차별성은 명확하게 정할 수 있지만, 경쟁 우위는 다음 결과로 검증해야 한다.

| 확보할 가치              | 증명할 결과                                                         |
| ------------------------ | ------------------------------------------------------------------- |
| 앱을 몰라도 내 일을 발견 | 연결된 원천의 실제 미처리 의무를 빠짐없이 발견하고 원천별 순회 감소 |
| 유형에 맞는 처리         | 승인·보완·검토를 정확한 도메인 규칙으로 수행                        |
| 믿을 수 있는 완료        | DWP의 완료 표시와 원본 결과의 일치, 반영 지연·실패의 설명           |
| 시간과 실행의 연결       | 수행 시간 예약 후에도 원본 업무 책임·기한 유지                      |
| 맥락 있는 AI 지원        | 같은 업무의 원문·근거·상태에 기반한 초안과 설명이 처리 시간을 줄임  |

권고 성과 지표는 다음과 같다. 수치는 이번 조사에서 측정하지 않았으며 충족률·시간절감률을 임의로 제시하지 않는다.

- **원본 확인된 유효 처리 수**: 큐의 단순 완료 클릭 수와 분리한다. 원본 실행이 필요한 업무는 확인된 결과만 집계한다.
- **첫 유효 행동까지 걸린 시간**: 첫 업무 진입부터 권한 있는 처리 시작까지의 중앙값과 상위 지연 구간.
- **원천별 발견 누락·중복·지연**: 권한 있는 원천 기준 목록과 대조한다.
- **업무당 화면 전환 수와 재입력 횟수**: 기존 원본 앱 동선과 같은 시나리오로 비교한다.
- **기한 초과·대기 병목**: 업무함 도입 전후를 비교하되 업무 난이도·조직별 차이를 고려한다.
- **잘못된 완료·권한 없는 노출**: 출시 수용 사례에서는 0건을 요구한다.

앱 방문률만으로 성공을 판단하지 않는다. Flow나 원본 deep link에서 바로 업무를 끝내면 독립 앱 방문 횟수가 적어도 사용자의 성과는 좋아질 수 있다.

| 사용자들이 실제로 여러 원천을 넘나들지 않을 수 있다         | 직원·승인자·서비스 요청자 시나리오로 기존/제안 동선을 비교한다. 단일 원천만 유효하면 독립 앱 노출을 축소한다. |

## 13. 이번 검토의 산출물과 다음 구현의 시작점

이번 검토에서 도출한 것은 업무 앱의 역할, 인접 앱 책임, 비교군과 기능 격차, 유지·통합·제거 대안, 목표 정보구조, 원천 처리 계약, 단계별 백로그와 수용 기준이다. 실행 코드는 변경하지 않았다.

고도화의 첫 구현은 **일반 완료의 의미 교정과 Review 연결 검증 → 원천별 업무·명령 계약 → 최소 실제 연동 → 중복 홈 정리** 순서가 적절하다. 이 순서가 갖춰져야 사용자는 업무 앱을 ‘상태를 표시하는 화면’에서 ‘내 일을 끝내는 공간’으로 이해할 수 있다.
