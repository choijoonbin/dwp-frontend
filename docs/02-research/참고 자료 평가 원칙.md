# 참고 자료 평가 원칙

## 목적

사용자가 제공하는 Screenshot, Website와 글로벌 제품은 좋은 기능과 문제 해결 원리를
찾기 위한 Evidence다. 동일한 외형이나 기능 목록을 무조건 복제하지 않는다.

## 평가 Record

각 참고 자료는 다음 항목으로 기록한다.

| 항목         | 내용                                             |
| ------------ | ------------------------------------------------ |
| Source       | 제품·URL·Screenshot·관찰일·Version               |
| User problem | 어떤 사용자 문제를 해결하는가                    |
| Interaction  | Trigger, 상태 변화, 완료·실패·복구 Flow          |
| Strength     | 정보 탐색, 처리시간, 신뢰, 접근성 측면의 장점    |
| Trade-off    | 복잡도, Vendor 종속, 개인정보, 운영비와 학습비용 |
| DWP fit      | Horizontal Core, Industry Pack 또는 Non-goal     |
| Decision     | Adopt, Adapt, Experiment, Reject                 |
| Validation   | Prototype, 사용자 Test와 성공 Metric             |
| Rights       | License, Asset·Source 복사 여부와 검토 상태      |

## 채택 기준

- 서로 다른 산업에서도 반복되는 문제를 해결한다.
- Legacy와 System of Record를 다시 만들지 않고 연결할 수 있다.
- 권한, Privacy, Audit와 오류 회복을 설명할 수 있다.
- AI 기능은 출처, 이유, 승인과 실행 결과를 확인할 수 있다.
- Mobile과 Desktop에서 서로 다른 핵심 업무를 지원한다.
- DWP Design Token과 Component로 독립 구현할 수 있다.

## 금지

- Screenshot을 Pixel 단위 복제
- 출처 불명 Asset·Icon·Font·Source 반입
- 제품 이름만 바꾼 Information Architecture
- Demo Data와 Sample Tenant를 Production 기본값으로 사용
- 사용성 검증 없이 Feature 수만 맞추는 구현
