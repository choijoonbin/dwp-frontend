# ADR-002: PER physical identity and schema boundary

Status: `DECIDED_FOR_G3`

## Decision

PER remains an extraction-ready bounded context inside `dwp-people-server`, isolated in the
`hris_performance` PostgreSQL schema. Every `prf_*` table has a database-local
`BIGINT GENERATED BY DEFAULT AS IDENTITY` primary key named `internal_id`. The existing
semantic UUID (`cycle_id`, `review_id`, and so on) is the aggregate's public identifier and
has a tenant-composite unique key. HTTP, event, audit, cache and cross-context contracts use
only the semantic UUID; `internal_id` never leaves the repository adapter.

This naming is the sole exception to the generic column spelling `public_id`: retaining the
aggregate-specific UUID name keeps OpenAPI/event/DDL vocabulary unambiguous. It is not an
exception to the DWP identity rule: internal identity is BIGINT and external identity is UUID.

## Persistence and join rule

New JPA entities use `internal_id` as their persistence identity. Repository commands first
resolve `(tenant_id, semantic_uuid)` under RLS, then use the resolved internal key within the
transaction. The G3 migration may add internal-key companion columns to high-volume local
relations after the generated schema and query plan are reviewed; it must retain the
tenant-composite UUID FK as a database safety constraint. No other service may reference
either key through a physical FK.

## Migration and search path

- Integration Control allocates the Flyway version in `dwp-people-server`; a module agent
  must not invent one.
- Migration SQL schema-qualifies all production objects. `SET search_path` in this blueprint
  is only a parse/review convenience and must not be relied upon by application SQL.
- The datasource role receives explicit privileges on `hris_performance`; no `public`
  schema fallback or cross-context write is allowed.
- `dwp.tenant_id`, `SET LOCAL ROLE`, `ENABLE/FORCE ROW LEVEL SECURITY`, and pool reset are
  verified with the same Testcontainers tenant-negative harness as other DWP services.

## Capacity evidence before merge

The PER slice must attach `EXPLAIN (ANALYZE, BUFFERS)` evidence for participant, review,
answer, result and inbox/outbox hot paths at the NFR reference volume. Acceptance requires no
sequential tenant-wide scan, bounded p95, correct composite index selection, and measured
index/storage growth. Partitioning remains off until a later measured-volume ADR provides a
default partition, lifecycle automation and boundary tests.

## Required contract tests

1. Public UUID lookup cannot cross a tenant even when another tenant uses the same UUID.
2. Missing/blank/reset `dwp.tenant_id` fails closed for API and worker roles.
3. A pooled connection cannot observe the prior transaction's tenant or role.
4. API/event payload schemas reject `internal_id`.
5. Migration validation fails on an unqualified production table, a missing FORCE RLS table,
   or a tenant-owned FK without the tenant dimension.
