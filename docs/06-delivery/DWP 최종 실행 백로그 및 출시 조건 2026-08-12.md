# DWP 최종 실행 백로그 및 출시 조건

- 문서 상태: Execution Backlog SSOT v1.8
- 기준일: 2026-08-20
- 기준선 시작 커밋: Frontend `73eb826`, Backend `810298d`, Agent `f823a04`
- 검증 대상: 이 문서와 함께 반영되는 `dwp-dev` 최신 커밋
- 적용 범위: 관리 대상 제품 메뉴, 공통 Shell, Backend 8개 데이터 소유 서비스, Gateway, Agent Runtime
- 목적: Wave 1~3 이후 남은 작업을 하나의 실행 목록으로 통합하고 중복·완료 항목을 제거한다.
- 상세 근거: `../02-research/DWP 메뉴별 UI UX 감사 2026-08-11.md`
- 구현 흐름: `../02-research/DWP Experience Modernization Roadmap 2026-08-12.md`
- 제품 역량 묶음: `../01-product/최종 잔여작업 실행목록.md`

이 문서는 DWP 잔여작업의 **최종 실행 기준**이다. 기존 감사·로드맵의 최초 문제 목록은
발견 당시의 기준선으로 보존하되, 작업 상태와 실행 순서는 이 문서를 우선한다.

**현재 판정:** `R0-01`~~`R0-04`와 `R1-01`~~`R1-23`의 저장소 내부 구현 가능 기준선은
완료됐다. `R1-21` Enterprise Approval Decision Hub, `R1-22` Enterprise Calendar,
`R1-23` Adaptive Workday Home은 실제 API·Database·권한·감사·대표 UI를 갖춘
`implemented-baseline`이다. 남은 출시 필수 항목은 저장소만으로 만들 수 없는 실제 환경·규모·사용자 증거인
`R2` 5건, 운영 Topology·보안 인프라를 요구하는 `R3` 5건과 책임자 승인 `A` 5건이다.
외부 결정 `D-01`~~`D-18`은 승인 전 기능을 fail-closed 또는 비활성 상태로 유지한다.
`P3` 후보 6건은 잔여 결함이 아니며 독립 PRD 승인 전 착수하지 않는다.
보안 정책 감사에서 `R3-02-KMS`를 승인된 후속 TODO로 등록했다. 공통 키 Provider와 로컬
개발 어댑터는 내부 구현 대기이며, 실제 KMS/HSM 연결과 운영 증거는 `R3-02` 외부 Gate다.

## 1. 판정 기준

| 상태        | 의미                                                              |
| ----------- | ----------------------------------------------------------------- |
| `완료`      | 실제 API·권한·감사·대표 Journey와 자동 검증이 존재한다.           |
| `내부 진행` | 외부 계약 없이 현재 저장소에서 구현·검증할 수 있다.               |
| `출시 검증` | 기능은 있으나 실제 규모·환경·사용자 증거가 부족하다.              |
| `결정 대기` | 고객·보안·인프라·외부 Provider 결정 전 구현하면 거짓 동작이 된다. |
| `확장 대기` | 현재 안전한 범위는 완료됐고 승인된 정책 이후 범위를 넓힌다.       |

`A` 등급이나 경쟁사 우위는 실제 고객 사용성·성능·접근성 비교 증거가 생기기 전에는
부여하지 않는다.

### 1.1 P0~P3 우선순위 계약

| 우선순위 | 판정 기준                                                                        |
| -------- | -------------------------------------------------------------------------------- |
| `P0`     | 출시 재현성, 권한·Tenant 격리, 데이터 보호, 복구·접근성 증거를 막는 항목         |
| `P1`     | 핵심 Journey를 끝까지 연결하고 공통 UX·운영 계약을 완결하는 항목                 |
| `P2`     | 이미 안전하게 동작하는 범위의 일관성·표시·편의를 높이는 항목                     |
| `P3`     | P0~P2 Gate 통과 후 독립 PRD·아키텍처·Pilot 증거로 착수할 차별화·산업별 신규 범위 |

`R0`부터 `R3`까지는 작업 성격을 나누는 실행 Lane이고, `P0`부터 `P3`까지는
각 항목의 우선순위다.
`D-*`는 내부 작업과 병행해 결정하되, Gate가 닫혀 있는 기능을 완료로 표시하거나
실제 데이터처럼 합성하지 않는다.

### 2.1 문서 현행화 판정

- 프로젝트 Roadmap, Experience Modernization Roadmap, 메뉴별 감사, 대표 Feature 수용
  테스트와 Delivery Index는 위 구현·검증 기준으로 현행화했다.
- 실행 상태는 이 문서만 단일 원장으로 사용한다. 제품 폴더의 `최종 잔여작업 실행목록.md`는
  장기 역량과 의존성을 설명하는 Portfolio Companion이다.
- Catalog, Navigation·App Access, Localization, Account, 공유·반출을 독립 Feature
  Package로 분리해 기획·화면·디자인·데이터·API·Agent·수용 테스트를 코드와 연결했다.
- `release-evidence/release-readiness.json`이 `R2`·`R3`·`D`·`A`의 상태와 증거 경로를
  기계 검증하며, 외부 증거가 없는 항목을 완료로 바꾸지 못하게 한다.

- `R0`와 출시 대상에 해당하는 `R1` 항목이 완료 상태다.
