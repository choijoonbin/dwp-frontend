## 2) 작업 항목(P0/P1)
### P0-1. 메뉴명 다국어 적용(서버 기반 우선)
현재 Sidebar는 서버 name(또는 menuName)을 사용하며 FE 매핑은 미구현 상태.
- BE에서 menus/tree가 menuName을 언어별로 내려주는 것이 이미 ✅라고 보고됨.
- FE에서 Sidebar가 “menuName” 필드를 실제로 사용하고 있는지 확인 후 아래 보완:
  - menu node의 표시값을 **항상 menuName**으로 사용(없으면 기존 name fallback)
  - Remote 라우트 타이틀도 menuName 기반으로 표시(가능하면)

### P0-2. 코드 라벨(케이스 타입/상태/심각도) 다국어 표시(코드관리 API 연동)
- Backend 결과에 따르면 sys_codes는 name_ko/name_en을 갖고 있고 API가 lang별로 name/label을 반환함.
- FE에서 아래 공통 훅/캐시를 추가:
  - useCodes(groupKey): TanStack Query로 가져와 Map(code->label) 생성
  - CaseList/CaseDetail/Badge 컴포넌트에서 code를 label로 렌더링
  - 누락 시 fallback=code

권장 그룹Key:
- CASE_TYPE, CASE_STATUS, SEVERITY (실제 BE groupKey에 맞춤)

### P0-3. 에러/토스트/Confirm 문구 t() 전수 치환
- 공통 에러 페이지(403/404/500), ConfirmDialog, Toast 메시지를 i18n 키로 치환
- 백엔드 메시지 문자열을 그대로 번역하지 말고, errorCode 기반으로 FE에서 번역

### P0-4. 날짜/숫자/통화 최소 포맷 적용(Intl)
- 공통 유틸: formatNumber, formatCurrency, formatDate
- lang에 따라 Intl locale: ko-KR / en-US (또는 en)
- Case amount, KPI, 테이블 숫자 컬럼 적용

### P0-5. Remote 단독 실행 fallback(개발 편의)
문제: Remote를 Host 없이 단독 실행하면 shared-i18n 인스턴스를 못 받는 케이스 발생 가능
- 전략: shared-i18n이 “이미 init 되었으면 재-init 금지”, “init 안 되었으면 최소 init” 하도록 설계
- Remote entry에서 I18nProvider를 감싸는 것이 아니라, shared-i18n 내부에서 안전 init되게 처리
- 단독 실행 모드에서는 locales를 remote 번들에서 로드 가능해야 함

### P1-1. 네임스페이스 로딩 실패 fallback 검증/보강
- 현재 fallbackLng:'ko' 설정은 있으나, 네임스페이스 로딩 실패 시 실제 동작이 불확실
- resourcesToBackend dynamic import 예외 처리 추가:
  - import 실패 → 빈 리소스 등록 + console warn + fallbackLng 적용 확인

### P1-2. 레이아웃 회귀 테스트(EN 길이 증가)
- 상단바 버튼/Sidebar 폭/테이블 컬럼/칩이 깨지는 화면 목록화
- 최소 대응: truncate/tooltip/버튼 min-width/반응형
