# 04 데이터 설계

## Schema

| Table                           | 책임                          | 핵심 제약                                       |
| ------------------------------- | ----------------------------- | ----------------------------------------------- |
| `com_organization_units`        | Tenant 조직 계층              | Tenant Key Unique, Same-tenant Parent FK        |
| `com_users.primary_org_unit_id` | 사용자 기본 조직 0..1         | `(tenant_id, org_unit_id)` 복합 FK              |
| `com_groups`                    | 조직과 분리된 Directory Group | Tenant Key Unique, Source·Status Check          |
| `com_group_members`             | Group의 직접 User Membership  | Tenant Group·User 복합 FK, Membership Unique    |
| `sys_identity_audit_events`     | Directory 변경 원장           | Tenant·Actor·Action·Target·Snapshot·Correlation |

Organization과 Group은 `revision`과 JPA `version`을 분리한다. Revision은 Domain 변경
순서이고 Version은 동시 수정 충돌 검출 값이다. `source_type`은 `LOCAL|SCIM`, `status`는
`ACTIVE|INACTIVE`만 허용한다.

## Transaction

- 조직 계층 변경은 Tenant 조직 집합을 ID 순으로 잠근 뒤 Cycle을 검사한다.
- Membership 교체는 관련 User를 잠그고 Diff만 적용한다.
- 조직 이동은 이전 조직과 새 조직 Revision을 모두 증가시키고 별도 이동 Audit를 남긴다.
- 변경 User의 `access_revision` 증가와 Active Session 폐기는 Membership·Audit와 같은
  Transaction에서 처리한다.
- Active Child 또는 Member가 남은 조직, Member가 남은 Group의 비활성화는 `409`다.

Hard Delete API는 제공하지 않는다. SCIM-owned 레코드는 Local Mutation에서 `409`로
Fail-closed한다.
