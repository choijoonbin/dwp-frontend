# DWP-R1-SVC-001 Employee Services

## 목표

구성원이 부서를 알지 못해도 필요한 지원을 검색·신청하고, 담당 조직과 SLA 및 처리 이력을 끝까지 추적할 수 있는 공통 서비스 센터를 제공한다. 테넌트 관리자는 서비스 정의를 통제하고 서비스 처리자는 허용된 상태 전이와 근거를 사용해 요청을 운영한다.

## 사용자 Journey

1. 개인 홈의 `서비스 센터` 앱을 연다.
2. 검색, 카테고리 또는 추천 서비스에서 필요한 항목을 찾는다.
3. 서버가 제공한 버전형 스키마로 신청 양식을 작성한다.
4. 불완전한 요청은 임시 저장하고, 제출 시 필수값·유형·선택값을 검증한다.
5. `진행 중인 요청`에서 담당 조직, SLA 목표, 상태와 처리 타임라인을 확인한다.
6. 서비스 처리자는 관리 센터 운영 큐에서 요청을 분류·배정·처리하고 근거를 기록한다.
7. 카탈로그 관리자는 다국어 정의, 양식, SLA, 데이터 등급과 수명주기를 버전으로 관리한다.

## 화면 계약

### 서비스 찾기

- 실제 제품 맥락 이미지 위에 검색과 가치 문구를 배치하며 기능을 카드 안에 가두지 않는다.
- 추천 서비스와 전체 서비스는 중복 노출이 허용되지만 같은 정의를 사용한다.
- 카드에는 서비스 이름, 설명, 예상 처리 시간, 데이터 등급과 명확한 시작 명령을 표시한다.
- 카테고리 필터는 수평 스크롤이 가능하며 모바일에서 화면을 넘지 않는다.

### 동적 요청 양식

- `TEXT`, `TEXTAREA`, `SELECT`, `DATE`, `NUMBER`, `CHECKBOX`를 지원한다.
- 저장과 제출을 분리한다. 임시 저장은 요약만 필수이며 제출은 전체 필수 항목을 검증한다.
- 데이터 등급과 전달 대상 조직을 제출 전에 안내한다.
- 제출은 UUID 멱등성 키를 사용해 이중 클릭·재시도의 중복 요청을 막는다.

### 내 요청

- 활성 요청과 임시 저장을 분리한다.
- 행 높이와 컬럼 정렬을 고정하고 요청 번호, 서비스, 요약, 상태, 담당 조직, 변경 시각을 제공한다.
- 상세에는 제출 정보와 최신순 append-only 타임라인, SLA와 담당 정보를 함께 표시한다.
- 사용자 취소는 허용된 초기 상태에서만 제공한다.

### 관리 센터

- `서비스 운영` 그룹 아래 `서비스 카탈로그`, `요청 운영`을 분리한다.
- 카탈로그는 한·영 원문을 함께 편집하고, 동적 필드를 구조화된 UI로 관리한다.
- 운영 큐는 활성·대기·SLA 임박·초과 KPI와 검색·상태 필터를 제공한다.
- 상세 패널에서 제출값, 처리 이력, 허용 다음 상태, 담당자와 처리 근거를 한 맥락에서 관리한다.

## API 계약

| Method         | Path                                                       | 권한                              | 책임                                               |
| -------------- | ---------------------------------------------------------- | --------------------------------- | -------------------------------------------------- |
| `GET`          | `/api/platform/v1/services/catalog`                        | `APP.EMPLOYEE_SERVICES:VIEW`      | 지역화된 활성 서비스 카탈로그                      |
| `GET`          | `/api/platform/v1/services/requests`                       | 동일                              | 내 요청 목록                                       |
| `GET`          | `/api/platform/v1/services/requests/{id}`                  | 동일 + 소유자                     | 내 요청 상세와 타임라인                            |
| `POST`         | `/api/platform/v1/services/requests`                       | 동일                              | 멱등 요청 생성·임시 저장                           |
| `PUT`          | `/api/platform/v1/services/requests/{id}/draft`            | 동일 + 소유자                     | 임시 저장 수정 또는 편집 내용과 제출의 원자적 처리 |

| `GET/POST/PUT` | `/api/platform/v1/admin/services/catalog`                  | `ADMIN.SERVICE_CATALOG`           | 카탈로그 조회·생성·수정                            |
| `GET`          | `/api/platform/v1/admin/services/requests`                 | `ADMIN.SERVICE_OPERATIONS:VIEW`   | 운영 큐·상세                                       |
| `POST`         | `/api/platform/v1/admin/services/requests/{id}/transition` | `ADMIN.SERVICE_OPERATIONS:MANAGE` | 허용 상태 전이·배정·근거                           |

## 수용 기준

- 테넌트와 서비스 앱 권한이 없는 사용자는 목록·직접 URL·API 모두 접근할 수 없다.
- 카탈로그 관리자와 서비스 처리자 권한은 서로 교차되지 않는다.
- 임시 저장은 불완전한 필드를 허용하고 제출은 서버에서 필수값과 타입을 검증한다.
- 등록되지 않은 SELECT 값과 스키마 외 필드는 거부한다.
- 과거 요청은 이후 카탈로그 변경에도 한·영 서비스명과 제출 당시 양식을 보존한다.
- 사용자 간 요청 상세 조회와 교차 테넌트 조회가 차단된다.
- 운영 큐와 운영 상세 API는 `DRAFT`를 반환하지 않으며 직접 ID 접근도 거부한다.
- 허용되지 않은 상태 건너뛰기와 stale version 변경은 충돌로 거부한다.
- 요청 타임라인의 UPDATE·DELETE는 DB에서도 거부되고 요청 삭제는 복합 FK로 제한된다.
- 한국어와 영어에서 누락 키가 없고, 390px 모바일과 1440px 데스크톱에서 겹침과 가로 오버플로가 없다.
