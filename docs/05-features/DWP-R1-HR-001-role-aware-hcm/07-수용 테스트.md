# 07. 수용 테스트

## 기능

- [x] 구성원이 HR Home, 인사정보, 근태, 휴가, 복리후생, 급여, 성장 메뉴를 본다.
- [x] 실제 보고 관계가 없는 구성원은 팀 메뉴를 보지 못하고 직접 URL도 복귀한다.
- [x] 실제 Manager는 팀 Queue를 보고 자신의 직속 구성원만 결정한다.
- [x] 도메인 관리자는 허용된 운영 메뉴만 보며 다른 도메인 API는 403이다.
- [x] HR Admin은 다섯 HR 도메인의 운영 API를 사용할 수 있다.
- [x] 근태 Entry 저장·제출·Manager 승인과 Audit Outbox 기록이 연결된다.
- [x] 휴가 기간·분·잔액·중복을 검증하고 승인 전이는 Version을 검사한다.
- [x] 본인은 제출 휴가만 사유와 Version으로 철회하고 Pending Balance와 감사 근거를 갱신한다.
- [x] Manager는 현재 직속 관계의 승인 Queue와 향후 60일 팀 부재를 함께 확인한다.
- [x] 근태 예외의 코드·심각도·발생일·설명·해결 상태와 수정 경로가 표시된다.
- [x] HR 도움 허브가 공통 Service Catalog·Request·Timeline을 재사용하고 중복 Case를 만들지 않는다.
- [x] 급여 금액은 DWP DB에 저장하지 않고 보안 문서 Reference만 노출한다.

## 보안·데이터

- [x] 외부가 보낸 Identity Header를 Gateway가 제거하고 검증된 Identity만 전달한다.
- [x] 인증된 `person_public_id`가 없거나 활성 Worker와 연결되지 않으면 HR Self-service를 거부한다.
- [x] Tenant 복합 FK가 교차 Tenant 참조를 차단한다.
- [x] 제출·승인 휴가의 중복 구간을 DB Exclusion Constraint가 차단한다.
- [x] 중복 경합이 500이 아닌 업무 충돌로 변환된다.
- [x] 변경 명령이 Actor·Target·Correlation ID와 함께 Audit Outbox에 기록된다.

## UI·품질

- [x] HCM 정적 번역 Key의 한국어·영어 누락이 없다.
- [x] HCM·Calendar·Approvals Shell이 서로 다른 Product Experience Profile을 사용한다.
- [x] 1280px 개인·관리자 경로에 Runtime Error와 가로 Overflow가 없다.
- [x] 390px HR Home에 가로 Overflow와 인사말 비정상 단어 분리가 없다.
- [x] 일반 구성원 메뉴 은닉과 직접 URL Guard를 브라우저에서 검증했다.
- [x] Frontend Typecheck, Lint, Unit Test, Production Build, Bundle Budget를 통과했다.
- [x] People·Auth·Gateway Backend Test를 통과했다.

## 고객 출시 전 미완료 Gate

- [ ] 고객 HRIS Payload·Field Mapping·Delta/Full·Reconciliation 책임 승인
- [ ] 국가별 근로·휴가·급여 정책과 노무·법무 승인
- [ ] 실제 Payroll·Benefits·LMS·Document Store Connector와 KMS 승인
- [ ] 최대 Tenant·Worker·Queue 규모의 성능 시험과 장애 복구 훈련
- [ ] Screen Reader와 고객 보조기술 사용자 수용 시험
- [ ] 민감 필드 보존·삭제·반출·SIEM 정책 승인

Local Baseline 통과는 위 고객 출시 Gate를 대체하지 않는다.
