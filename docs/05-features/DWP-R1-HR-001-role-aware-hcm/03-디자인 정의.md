# 03. 디자인 정의

## 경험 원칙

1. HR은 오래 머무르는 분석 도구보다 빠르게 판단하고 행동하는 개인 업무 공간이다.
2. 배경·Surface·강조색의 명도 차이를 사용하고 한 Hue로 화면 전체를 덮지 않는다.
3. 카드는 실제 반복 객체, Widget, 명령 Surface에만 사용하고 Section 전체를 카드로 감싸지 않는다.
4. Micro Visualization은 기간·기준·Drill-down이 있을 때만 사용한다.
5. 움직임은 상태 변화와 순서 변경을 설명하는 데만 사용하며 Reduced Motion을 준수한다.

## Visual Language

| 요소    | 규칙                                                                    |
| ------- | ----------------------------------------------------------------------- |
| 배경    | Light Neutral 기반, 장식 Gradient·Orb 금지                              |
| Surface | 흰색 또는 Theme Surface, Radius 최대 8px                                |
| 강조    | 브랜드 Blue, Success Green, Attention Amber, Critical Red를 의미별 사용 |
| Icon    | Lucide 선형 Icon, 동일 Stroke와 안정된 40/48px Container                |
| 숫자    | 단위·기준일·출처를 함께 제공하고 의미 없는 큰 KPI 금지                  |
| Chart   | Sparkline·Progress·Donut은 읽을 수 있는 Text 대체값과 상세 이동 제공    |

## DWP HCM Product Experience Profile

- DWP HCM Concept은 `people-flow`, 기본 밀도는 `comfortable`이다.
- Canvas는 Cool Neutral, 핵심 선택·진행은 Teal, 사람 관련 주의 신호는 제한된 Coral을 쓴다.
- Calendar의 시간축 Blue·Cyan, Approvals의 근거·위험 Ink·Amber와 구분하되 공통 Form,
  Button, 상태색, Focus Ring, Radius는 바꾸지 않는다.
- 앱별 차별화는 장식 Hero나 Palette 교체가 아니라 정보 구조, 기본 밀도, 대표 신호와
  상호작용 우선순위에서 만들어야 한다.

## 상호작용

- 근태 입력과 휴가 신청은 Form Dialog로 현재 문맥에서 완료한다.
- 제출·승인·반려는 결과 상태와 갱신된 Version을 즉시 반영한다.
- 위험 명령은 명확한 동사, 영향 대상, 사유 입력, 확인 단계를 제공한다.
- Widget 편집은 Drag 또는 Keyboard 이동, 저장 상태, 복원 기능을 제공한다.
- 표의 행 전체를 모호한 Click Target으로 만들지 않고 명령은 전용 Button/Menu로 분리한다.

## 금지 패턴

- 데이터가 없는 상태를 그럴듯한 급여·휴가·성과 숫자로 채우기
- 직함 문자열만으로 Manager 또는 HR 관리자 판정
- HR Admin에게 모든 Tenant·Provider 기능 자동 노출
- 중요 명령을 색상 Badge나 설명 없는 Icon 하나에 숨기기
- 모바일에서 Desktop 표를 축소해 가로 스크롤로만 제공
