# Stitch Work 01–12 design-reference

기준일: 2026-09-04. 원본 프로젝트: https://stitch.withgoogle.com/projects/13391261371843159731

이 폴더는 Stitch 프로젝트에서 확인한 Work 01–12의 실제 화면 소스와 캡처를 보존한다. 제품 코드는 포함하지 않는다. 각 code.html은 Stitch ZIP 또는 Stitch Preview의 about:srcdoc에서 확보한 원본이며, 각 screen.png의 출처는 manifest.json에 구분했다.

## 결론

- Work 화면 노드 18개를 모두 식별했고 code.html 18개와 screen.png 18개를 저장했다.
- 01–03 desktop/mobile 중 5개와 12 M1/M2의 screen.png는 Stitch ZIP 원본이다. 03 mobile–11의 11개 캡처는 동일한 Stitch code.html을 Chrome에서 다시 렌더링했다.
- 디자인 결과는 레이아웃 참고 자료로 사용할 수 있지만 디자인 프롬프트의 수용 게이트를 통과하지 못했다. 화면을 그대로 제품 계약으로 해석하거나 구현 완료 증거로 사용하면 안 된다.
- 데스크톱 프레임 이름은 모두 1440px을 주장하지만 ReactFlow 래퍼는 모두 폭 1280px이다.
- 12 M2는 이름과 화면 본문에서 320px을 주장하지만 실제 래퍼·HTML·원본 PNG는 390px이다.
- dark, 강제 고대비, 200% 확대, 실제 320px, 정확한 1440×900 및 1280×800 제출물이 없다.
- 06–11의 개별 모바일 화면은 없다. 12의 M1/M2 두 긴 합성 화면이 일부 모바일 여정을 대신할 뿐이다.

## 디자인 수용에 부족한 제출물

1. 1440×900, 1280×800, 390×844, 320×568을 각각 실제 viewport로 만든 프레임.
2. 주요 정상 화면의 dark 변형과 중요 예외의 강제 고대비 변형.
3. 1280px 200% 확대에서 재배치와 주 행동 접근을 검증한 프레임.
4. 화면별 로딩·실제 빈 상태·검색 없음·부분 실패·stale·권한 회수·충돌·실행 중·성공·실패 프레임.
5. 06–11 각각의 모바일 여정. 12의 합성 설명 화면은 개별 화면의 실제 반응형 검증을 대신하지 못한다.
6. 대화상자 focus trap/복원, 목록 선택·필터·스크롤 유지, 가상 키보드, 한글 IME 조합 중 Enter, Reduced Motion을 확인할 prototype 또는 명세.
7. 컴포넌트 anatomy/variants/spacing/텍스트 처리와 필드·행동의 전제/효과/취소/실패/복귀 표.

## 참고용으로만 사용할 요소

- 생성 화면의 이름, 금액, 시간, 조직, 티켓 번호, 시스템 버전은 디자인 fixture다.
- 사이드바의 통합업무함·내 조치 대기·오늘 계획·진행 중·응답 대기·완료된 업무와 모바일 5탭은 정보 구조 제안일 뿐 확정 메뉴가 아니다. 상세·계획·결과 패널을 영구 메뉴로 추가하지 않는다.
- “실시간 동기화”, “동기화 완료”, “AVAILABLE”, “ITSM-BRIDGE-LIVE”, 엔진 버전, “법적 효력 보장”, “감사 로그 동기화/기록”, “API 검증 완료”, “92% 완료 확률”, “초안 자동 반영”은 UI 문구만으로 운영 사실이 되지 않는다.
- 원천 업무에 일반 완료를 붙이거나 원본 열기·AI 답변·Calendar 예약을 업무 완료로 해석하지 않는다.
- 시안은 주로 #2563EB, Geist, Material Symbols를 사용한다. 제품 계약의 #285C9E, 한글 시스템 글꼴, Lucide 및 기존 DWP 토큰과 합치해야 한다.
- 04·05 desktop code.html은 1280px Chrome 재렌더에서 각각 1440px·1480px의 실제 가로 폭을 만들었다. 해당 시각 구조를 반응형 구현의 근거로 복제하면 안 된다.

## 파일 사용법

- contact-sheet.png: 18개 screen.png의 파생 축소 미리보기. 픽셀 대조에는 개별 원본을 사용한다.
- manifest.json: node ID, 래퍼 치수, 코드·캡처 출처, PNG 픽셀 크기와 불일치.
- implementation-comparison.md: 현재 구현 기반과 Stitch 시안의 기능 경계.
- checksums.sha256: 확보한 code.html, screen.png, DESIGN.md의 무결성 확인.
- Stitch ZIP 원본 PNG는 Stitch가 최대 높이에 맞춰 다시 샘플링할 수 있으므로 PNG 픽셀 크기와 캔버스 래퍼 크기를 같은 viewport로 간주하지 않는다.
