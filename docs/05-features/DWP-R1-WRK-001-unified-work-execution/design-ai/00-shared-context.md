## 제품 역할과 사용자 약속

DWP는 회사별 조직·사용자·권한을 기반으로 업무, 전자결재, 캘린더, 서비스, 메일, 메신저, 알림과 AI를 연결하는 디지털 워크플레이스입니다. 이번 대상은 그 안의 업무 앱입니다.

> 여러 앱에 흩어진 내가 처리할 일을 한곳에서 확인하고, 필요한 근거를 보고 처리하며, 실제 결과까지 확인합니다.

주 사용자는 일반 구성원입니다. 결재자·권한 검토자도 관리자 화면 대신 자신에게 배정된 의무를 처리합니다. 전체 조직의 업무 현황, 직원 감시, 프로젝트 자원 배분은 대상이 아닙니다.

업무 앱의 차별성은 많은 메뉴가 아니라 **횡단하는 내 책임, 올바른 다음 행동, 원본과 일치하는 결과**입니다. 첫 화면에서 무엇이 남았는지, 왜 지금 확인해야 하는지, 내가 무엇을 할 수 있는지 읽혀야 합니다.

## 확정한 정보 구조

- 기본 진입은 통합업무함 `/work/queue`입니다. `/work`와 구 `/work/home`은 호환 진입 처리 대상입니다.
- 기존 ‘업무 홈’의 KPI와 상위 목록을 별도 홈 화면으로 재설계하지 않습니다. 발견용 요약은 전체 홈인 Flow가 담당합니다.
- ‘내 조치’, ‘진행’, ‘응답 대기’, ‘완료’, ‘오늘 계획’은 같은 업무함의 보기·필터·개인 계획 상태입니다. 화면 예시의 탭·뷰 전환을 모두 영구 좌측 메뉴로 추가하지 않습니다.
- 오늘 계획은 사용자가 오늘 하기로 선택한 업무의 집합입니다. 오늘 마감과 다르며, 계획 추가·제거로 기한이나 원본 상태를 바꾸지 않습니다.
- 상세, 개인 할 일 폼, 일정 연결, 원천 상태, AI 지원은 목록 맥락에서 열리는 상세·대화상자·패널입니다. 개별 영구 메뉴를 만들지 않습니다.
- 공통 DWP 헤더, 앱 전환, 전역 검색·알림·사용자 메뉴를 유지합니다. 본문에 같은 기능을 다시 만들지 않습니다.

## 반드시 구분할 데이터 의미

1. 원본 업무 상태: 담당 앱이 확정한 진행·대기·결정·완료입니다.
2. 시간 신호: 기한 초과·오늘 마감·임박·기한 없음입니다. 진행 상태와 동시에 존재할 수 있습니다.
3. 개인 계획: 특정 날짜에 하기로 선택함·개인 순서입니다. 업무 마감이 아닙니다.
4. 일정 예약: Calendar에 실제 생성한 시간 슬롯입니다. 시간이 지났다고 업무가 완료되지는 않습니다.
5. 원천 반영: 요청 전송·반영 확인 중·성공·실패·확인 불가입니다. ‘처리 요청됨’과 ‘완료됨’을 다르게 표시합니다.
6. 알림/AI 상태: 알림 읽음, AI 응답 완료, 제안 검토는 업무 완료를 뜻하지 않습니다.

원천 업무에는 해당 유형과 사용자 권한에 맞는 행동만 표시합니다. 전자결재를 범용 ‘완료’ 체크박스로 처리하지 않습니다. 직접 처리 계약이 없으면 ‘원본에서 검토’처럼 실제 이동임을 설명합니다. 개인이 DWP에서 만든 할 일에만 DWP의 시작·완료·편집 의미를 적용합니다.

## 원천 확인 상태와 개인 북마크

- `AVAILABLE`: 서버가 현재 접근을 확인했습니다. 개별 변경 행동은 별도 허용 계약을 따릅니다.
- `REFERENCE_ONLY`: 승인/서비스/Review 등의 원천 식별자를 개인 북마크로 저장했습니다. 원본 API에서 권한·최신 내용을 확인하기 전이므로 사용자에게는 ‘원본 확인 필요’처럼 표현합니다. 연결 성공·동기화 완료·원본 최신 상태로 표시하지 않습니다.
- `UNAVAILABLE`: 현재 원천 확인/사용이 불가능합니다. 정상 0건이나 업무 완료가 아닙니다.

북마크의 사용자 작성 메모와 권한 기반 원천 preview를 구분하고 원천 접근 회수 시 민감 preview를 폐기합니다. 실제 capture 버튼의 화면 연결과 원천 조회 지원 여부는 구현 확인표를 따릅니다.

## 상태와 접근성 계약

- 정상 0건, 검색 0건, 아직 연결된 원천 없음, 전체 로딩, 전체 실패, 일부 원천 실패, 오래된 정보, 접근 불가, 권한 회수, 버전 충돌, 변경 성공·실패를 각각 다룹니다.
- 0·없음과 조회 실패를 구분합니다. 일부 원천이 실패한 때 ‘모든 업무 완료’라고 말하지 않습니다.
- 실제 조회 시각과 원천 성공 시각을 구분합니다. 실시간 이벤트가 없는 화면에 맥박 애니메이션과 ‘실시간’ 라벨을 붙이지 않습니다.
- 정상 빈 상태에는 업무의 유입 범위를 짧게 설명하고, 권한이 있으면 ‘개인 할 일 추가’ 또는 지원 원천 안내를 제공합니다.
- 1440×900, 1280×800, 390×844, 320×568 및 1280px의 200% 확대를 제공합니다. 모바일을 데스크톱 축소판으로 만들지 않습니다.
- 키보드 순서, 항상 보이는 focus, Enter/Space 행동, Escape/뒤로 복귀, dialog focus trap·복원, 스크린리더 제목·상태 공지를 명세합니다. 한글 IME 입력 중 Enter를 제출로 처리하지 않습니다.
- 라이트·다크·강제 고대비, 긴 한영 제목·부서·값, Reduced Motion을 포함합니다. 텍스트 대비 4.5:1, 큰 텍스트/핵심 경계·조작 상태 3:1을 기준으로 검토합니다. 색만으로 상태를 구분하지 않습니다.
- 가로 페이지 넘침, 겹침, 잘린 주 행동, 모바일 키보드에 가려진 입력/오류, 과도한 중첩 세로 스크롤은 실패입니다.

## 구현 범위를 정직하게 다루는 법

초기 감사에서는 목록·검색·저장 보기·일반 상태 변경·권한 검토 상세가 코드로 확인됐고, 현재 요청에서 네이티브 할 일·개인 계획·원천 처리 계약의 선행 개발이 진행 중입니다. 현재 파일을 읽지 못하는 디자인 AI는 ‘개발 중’ 목표를 ‘운영 제공’으로 바꾸면 안 됩니다.

각 화면의 프레임 주석에 `기존 기반`, `선행 개발 목표`, `조건부/후속` 구분을 붙이고 구현 확인표와 대조해 주세요. 사용자가 누를 수 있는 실제 제품 문구에 내부 API 키·권한 정책 ID·마이그레이션명·개발 티켓을 넣지 않습니다. 디자인은 기능 계약을 확장하는 승인이 아닙니다.

## 원하는 산출물

1. 식별 가능한 화면 ID, 기준 크기·테마·상태가 포함된 전체 프레임.
2. 정상 대표 화면과 중요한 상태 변형. 작은 성공 토스트만으로 실패·부분 성공 명세를 대신하지 않음.
3. 클릭/키보드/모바일의 사용자 흐름 및 원천 앱으로 이동했다 돌아오는 흐름.
4. 반복 컴포넌트의 anatomy, variants, 상태, 최소/최대 폭, 긴 텍스트, 밀도·반응형 규칙, 토큰 대응.
5. 필드·행동 명세: 데이터 의미, null 표현, 수정 주체, 행동 전제, 결과, 실패·취소·복귀.
6. 해당 화면 프롬프트의 통과/실패 체크리스트에 대한 자체 검수와 미해결 질문. 미지원 계약을 임의 기능으로 채우지 않음.
