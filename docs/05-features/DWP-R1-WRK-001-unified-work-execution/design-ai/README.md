# 업무 앱 디자인 AI 인계 패키지

기준일: 2026-09-04. 범위: 통합업무함 중심 제품 방향의 화면별 디자인 의뢰.

**현재 업무 홈을 다시 꾸미는 의뢰가 아닙니다.** 여러 원천의 내 조치를 발견·판단·처리·결과 확인까지 이어 주는 통합업무함을 설계합니다. 전체 Flow 홈에는 짧은 업무 요약을 남기고, 오늘 계획·상세·입력 폼·연결 대화상자를 불필요한 상시 메뉴로 추가하지 않습니다.

이 패키지는 복사해 전달할 수 있는 프롬프트이며 최종 디자인 파일·개발된 새 화면이 아닙니다. 기존 구현, 이번 선행 개발, 아직 조건부인 기능은 [구현 확인표](implementation-coverage.md)에서 구분합니다. 디자인 문서 준비와 제품 기능의 개발/운영 완료를 같은 의미로 사용하지 않습니다.

[공통 후속 CLOSED / FROZEN](../../DWP-R1-CORE-006-product-surface-separation/11-2026-09-04-closeout.md)의 전체 단위·production build PASS는 디자인 인계와 별도 검증입니다. 기존 U09 배정 연결의 코드 도달성은 확인됐지만, 외부 출시 증적 37건 BLOCKED와 Meeting 원천 승격 NO-GO는 유지됩니다. 새 Work 화면은 아래 프롬프트로 디자인을 받은 뒤 구현합니다.

## 전달 방법

1. 첫 디자인 세션에는 [00 공통 맥락](00-shared-context.md)과 [01 통합업무함](01-unified-queue.md)을 순서대로 붙여 넣습니다. 가능하면 현재 DWP 셸 캡처를 함께 전달합니다.
2. 그다음 원하는 화면의 프롬프트 **전체**를 복사합니다. 각각에 필요한 공통 제약이 포함되어 있어 별도 AI 세션에서도 단독 사용 가능합니다.
3. [구현 확인표](implementation-coverage.md)의 해당 화면 행을 함께 전달합니다. 확인되지 않은 조건부 직접 처리·캡처·Calendar 생성·AI 컨텍스트 지원을 디자이너가 임의로 활성 기능으로 바꾸지 않게 합니다.
4. 첫 정상 프레임으로 구성 방향을 맞춘 뒤 같은 문서에 적힌 실패·빈 상태·모바일·확대·키보드 변형까지 받습니다. 보기 좋은 대표 한 장만으로 종료하지 않습니다.
5. 받은 디자인은 아래 ‘반환할 결과물’ 형식으로 이 작업에 전달하면 코드와 API 계약에 맞춰 화면 개발에 사용할 수 있습니다. 현재 요청에는 이미지 디자인이나 화면 코드 생성이 포함되어 있지 않습니다.

## 반환할 디자인 결과물

- 전체 프레임: `WRK-Q01-1440-light-populated`와 같이 화면ID·크기·테마·상태가 드러나는 이름. 이미지/PDF와 편집 가능한 원본 또는 접근 가능한 디자인 링크를 함께 받으면 좋습니다.
- 상태 목록: 정상·빈 상태·로딩·검색 0건·부분 실패·지연·권한 회수·충돌·실행 결과 중 화면별 해당 상태. 정확한 문구와 표시 조건 포함.
- 반응형: 1440×900, 1280×800, 390×844, 320×568, 1280px 200% 확대. 모바일 가상 키보드, 라이트/다크/강제 고대비, Reduced Motion 주석.
- 연결 흐름: 큐→유형 상세→원본 처리/폼→결과→동일 큐 복귀, 개인 할 일→오늘 계획→Calendar, 선택 업무→DWAI·ON. 클릭뿐 아니라 focus·뒤로·스크롤 유지 포함.
- 컴포넌트 명세: 행·선택 상태·상태 라벨·기한·계획 토글·원천 안내·결과 행·폼·도움말·오류·dialog·모바일 내비게이션의 anatomy와 변형.
- 필드/행동 표: 필수/선택/없음, 데이터 의미, 편집 주체, 행동 전제, 생성/변경 대상, 실패·취소·재시도·복귀.
- 미해결 항목: 시각적 판단과 기능 계약 미확정을 구분. 지원되지 않는 기능은 화면에서 억지 성공으로 채우지 않음.

## 디자인 수용 게이트

다음 중 하나라도 실패하면 해당 화면을 구현 준비 완료로 표시하지 않습니다.

1. 원천 업무에 일반 완료 버튼을 붙이거나 원본 열기를 완료로 표현한다.
2. 오늘 계획·기한·Calendar 예약의 의미를 합친다.
3. REFERENCE_ONLY를 원천 접근/연결 성공처럼 표현한다.
4. 권한 회수 뒤 이전 민감 내용·숫자를 남긴다.
5. 실패·미조회·부분 누락을 정상 0건으로 표현한다.
6. 320px·200% 확대에서 주 행동/오류가 가려지거나 page 가로 넘침이 있다.
7. 키보드/모바일에서 핵심 여정을 완료하고 기존 맥락으로 복귀할 수 없다.
8. 현재 업무 홈을 다시 추가하거나 대화상자를 불필요한 영구 메뉴로 바꾼다.
9. 구현 확인 없이 외부 제품 연동·직접 원천 처리·AI 실행 성공을 제공 중인 기능으로 표시한다.
10. 대표 한 화면만 있고 상태·컴포넌트·필드/행동·접근성 명세가 없다.

## 참고 근거와 변경 경계

- [전문가 분석 보고서](../../../02-research/DWP%20업무%20앱%20역할%20재정의%20및%20고도화%20의사결정%202026-09-04.md): 초기 기능 감사와 앱 경계·최적안.
- 보고서의 ‘오늘 계획 후순위’는 최초 분석 시점의 판단입니다. 이번 후속 요청에서는 원본 기한과 독립된 개인 계획의 선행 기능 개발·디자인 계약까지 포함합니다. 별도 영구 메뉴 도입을 뜻하지 않습니다.
- 제품 경험·디자인 토큰은 00 문서의 저장소 근거를 따릅니다. 기존 공통 셸·등록 토큰을 기능별 새 테마로 갈아엎지 않습니다.
- 이 폴더는 디자인 인계 문서만 소유합니다. 제품 코드·API·마이그레이션의 실제 변경 결과와 테스트 증거는 구현 담당의 문서/최종 보고를 근거로 대조합니다.
