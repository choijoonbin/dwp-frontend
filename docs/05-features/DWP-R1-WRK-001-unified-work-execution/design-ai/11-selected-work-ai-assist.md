# 11. 선택 업무의 DWAI·ON 지원 — 근거·초안·다음 행동

화면 ID: `WRK-A01` · 기준일: 2026-09-04 · 상태: 디자인 목표, 구현 확인표 대조 필요

## 독립 전달용 공통 계약

이 문서 전체를 디자인 AI에 전달해 주세요. 다른 번호의 문서를 보지 않아도 아래 계약을 지켜 디자인할 수 있습니다. 00-shared-context.md가 함께 제공되면 상세 토큰·용어 정의를 추가 적용합니다.

DWP는 조직·권한 기반 디지털 워크플레이스입니다. 업무 앱은 여러 앱의 **내 처리 책임과 실제 결과**를 연결합니다. 기본 진입은 통합업무함이며 기존 ‘업무 홈’을 새로 디자인하지 않습니다. 보기·상세·대화상자를 별도 영구 메뉴로 늘리지 않습니다. Flow는 발견·앱 실행, Calendar는 시간 예약, 전자결재/서비스는 원본 처리, 알림은 읽음·전달, 메일/메신저는 대화, DWAI·ON은 분석·초안·검토형 실행을 소유합니다.

원본 상태, 기한의 긴급도, 개인이 선택한 오늘 계획, Calendar 예약, 원천 반영 결과를 구분합니다. 알림 정리·원본 열기·AI 응답·시간 경과를 업무 완료로 표시하지 않습니다. 원천 항목에는 해당 원천이 허용한 행동만, 네이티브 개인 할 일에는 DWP의 시작·완료·편집을 제공합니다. 권한/지원 계약이 확인되지 않으면 직접 처리 대신 허용된 원본 이동이나 해당 기능 없는 상태를 설계합니다.

원천 접근 상태는 서버가 현재 접근을 확인한 AVAILABLE, 개인 북마크에 참조만 저장된 REFERENCE_ONLY, 확인/사용 불가인 UNAVAILABLE을 구분합니다. REFERENCE_ONLY는 ‘원본 확인 필요’이며 원본 API에서 권한·최신 내용을 확인하기 전입니다. 연결/동기화 성공으로 표현하지 않습니다. AVAILABLE도 개별 변경 명령의 권한을 자동 허용하지 않습니다.

현재 요청은 **디자인 의뢰**입니다. 전체 화면·상태 변형·상호작용·컴포넌트/필드 명세를 만들어 주세요. 코드를 생성하거나 새 앱을 개발·배포하지 마세요. 아래 수치·사람·제목은 모두 기준 시각 2026-09-04 09:30 Asia/Seoul의 **가상 디자인 fixture**입니다. 운영 데이터·실제 연동·완료된 API라고 설명하지 마세요. ‘기존 기반 / 선행 개발 목표 / 조건부 후속’ 구분은 디자인 인계 주석에 남기고 내부 기술명은 사용자 화면에서 숨깁니다.

기존 DWP 셸과 업무 execution-flow/standard 밀도를 사용합니다. 라이트 모드 참고: accent #285C9E, secondary #0C847C, canvas #F5F7FA, selection #E5EDF7. 모서리 4/6/8px, 간격 4/8/12/16/24/32px, 한글 시스템 글꼴, Lucide 아이콘. 의미 토큰으로 다크·고대비에 대응합니다. 유동 셸 안의 안정적인 목록·상세 관계를 쓰고 큰 Hero·무관한 이미지·KPI 카드 나열·장식 차트·글로우·경쟁사 외관 복제를 피합니다.

## 사용자 과업

- 주 사용자: 선택한 업무의 맥락을 이해하거나 답변/문서 초안을 준비할 구성원.
- 질문: “이 업무에서 무엇을 확인하고 어떤 내용을 준비하면 되는가?”
- 주 행동: 선택 업무를 대상으로 질문·요약·초안 요청 후 근거를 검토.
- Archetype: 연결된 AI 작업 패널 또는 기존 DWAI·ON으로 handoff. 별도 AI 앱/제안함을 만들지 않습니다.
- 위치: 업무 상세의 ‘DWAI·ON에 도움받기’. 기존 전역 AI 진입과 일관된 동작.

## 맥락 계약

현재 선택 업무의 제목·원천·허용된 참조·현재 상태·기준 시각을 작게 보여줍니다. 사용자가 무엇을 AI에 전달하는지 이해할 수 있어야 합니다. 큐 전체·모든 메일·권한 밖 원문을 자동 전송하는 시안을 만들지 않습니다. 자유 텍스트 질문이나 민감 본문을 URL query에 넣는 방식은 금지합니다.

선택 업무 컨텍스트 전달 API가 확인되지 않으면 기본은 ‘이 업무로 질문 준비’ 또는 기존 DWAI·ON으로 이동하는 조건부 연결입니다. 원문이 AI에게 이미 전달된 것처럼 첨부 완료 배지를 붙이지 않습니다. 구현된 계약이 있으면 검증된 참조/일회성 launch 방식으로 연결하며 UI에는 내부 ID를 노출하지 않습니다.

2026-09-04 선행 코드 대조에서 선택 업무 한 건을 새로 확인한 뒤 검토된 제목·원천 참조·상태·기한·기준 시각을 질문 launch로 전달하는 headless helper가 확인됐습니다. **새 업무 AI 입력/미리보기 화면은 아직 미제작**입니다. 질문은 공백 제거 후 2~2,000자이며 전체 전달 맥락 길이 제한에 걸리면 질문을 줄이라는 오류를 표시합니다. 기준 시각이 5분을 넘거나 선택 업무·버전이 달라졌으면 현재 내용을 다시 검토하게 합니다. 내부 key·version·launch ID를 사용자가 입력하도록 만들지 않습니다. 목록 맥락 전달을 원문 전체 열람이나 원본 행동 실행으로 표현하지 않습니다.

## 행동 경계

AI 답변 완료와 원본 업무 완료를 분리합니다. 요약 결과가 나왔다고 큐 상태나 계획·기한을 바꾸지 않습니다. ‘초안 적용’은 허용된 원본 폼에 사용자 검토용 내용을 전달하는 계약이 있을 때만 사용합니다. 계약이 없으면 복사 또는 원본 열기로 표현합니다. 실제 실행 제안이 있는 경우 검토 화면에서 대상·변경·근거·현재 권한을 확인하고 원본 결과를 기다립니다. 무조건 자동 실행·무조건 별도 추가 승인 정책을 발명하지 않습니다.

선택을 바꾸면 이전 답변의 대상과 현재 상세가 섞이지 않아야 합니다. 처리 중 다른 업무 선택/패널 닫기 시 요청의 계속/중지 여부, 대화 저장 여부, 재개 경로는 기존 DWAI·ON 계약에 맞춥니다.

## 필수 상태

- 질문 전/처리 중/근거 있는 답변/부분 근거/출처 없음/기능 미사용 권한.
- 모델 사용 불가·제한된 대체 응답: 생성형 분석 완성으로 포장하지 않음.
- 원천 권한 회수·기한/상태 변경: 오래된 결과의 기준 시점을 명시하고 필요한 민감 내용 폐기.
- 요청 실패·재시도·이미 저장된 대화 재개, 질문 내용 유지 정책.
- 원본 실행 연결 불가: 분석·초안은 유지하되 실행된 것처럼 표시하지 않음.
- 모바일 전체 화면 AI→원업무 상세 복귀, 키보드·스크린리더 답변/근거 순서.

## 통과/실패

- AI가 읽을 대상·근거·답변의 적용 범위가 명확하면 통과.
- 질문 제출만으로 승인·보완 제출·업무 완료가 실행되면 실패.
- 실제 근거 없이 ‘정확도 98%’·위험 점수·연결된 모든 시스템 분석 완료를 표시하면 실패.
- 민감 질문이 URL에 보이거나 선택 업무가 바뀌어도 이전 내용을 새 업무 답변처럼 보여주면 실패.
- 기존 DWAI·ON의 대화/제안/실행 이력을 복제하는 새로운 메뉴가 생기면 실패.
