# 10. Flow 홈의 업무 요약 — 발견에서 실행으로

화면 ID: `WRK-H01` · 기준일: 2026-09-04 · 상태: 디자인 목표, 구현 확인표 대조 필요

## 독립 전달용 공통 계약

이 문서 전체를 디자인 AI에 전달해 주세요. 다른 번호의 문서를 보지 않아도 아래 계약을 지켜 디자인할 수 있습니다. 00-shared-context.md가 함께 제공되면 상세 토큰·용어 정의를 추가 적용합니다.

DWP는 조직·권한 기반 디지털 워크플레이스입니다. 업무 앱은 여러 앱의 **내 처리 책임과 실제 결과**를 연결합니다. 기본 진입은 통합업무함이며 기존 ‘업무 홈’을 새로 디자인하지 않습니다. 보기·상세·대화상자를 별도 영구 메뉴로 늘리지 않습니다. Flow는 발견·앱 실행, Calendar는 시간 예약, 전자결재/서비스는 원본 처리, 알림은 읽음·전달, 메일/메신저는 대화, DWAI·ON은 분석·초안·검토형 실행을 소유합니다.

원본 상태, 기한의 긴급도, 개인이 선택한 오늘 계획, Calendar 예약, 원천 반영 결과를 구분합니다. 알림 정리·원본 열기·AI 응답·시간 경과를 업무 완료로 표시하지 않습니다. 원천 항목에는 해당 원천이 허용한 행동만, 네이티브 개인 할 일에는 DWP의 시작·완료·편집을 제공합니다. 권한/지원 계약이 확인되지 않으면 직접 처리 대신 허용된 원본 이동이나 해당 기능 없는 상태를 설계합니다.

원천 접근 상태는 서버가 현재 접근을 확인한 AVAILABLE, 개인 북마크에 참조만 저장된 REFERENCE_ONLY, 확인/사용 불가인 UNAVAILABLE을 구분합니다. REFERENCE_ONLY는 ‘원본 확인 필요’이며 원본 API에서 권한·최신 내용을 확인하기 전입니다. 연결/동기화 성공으로 표현하지 않습니다. AVAILABLE도 개별 변경 명령의 권한을 자동 허용하지 않습니다.

현재 요청은 **디자인 의뢰**입니다. 전체 화면·상태 변형·상호작용·컴포넌트/필드 명세를 만들어 주세요. 코드를 생성하거나 새 앱을 개발·배포하지 마세요. 아래 수치·사람·제목은 모두 기준 시각 2026-09-04 09:30 Asia/Seoul의 **가상 디자인 fixture**입니다. 운영 데이터·실제 연동·완료된 API라고 설명하지 마세요. ‘기존 기반 / 선행 개발 목표 / 조건부 후속’ 구분은 디자인 인계 주석에 남기고 내부 기술명은 사용자 화면에서 숨깁니다.

기존 DWP 셸과 업무 execution-flow/standard 밀도를 사용합니다. 라이트 모드 참고: accent #285C9E, secondary #0C847C, canvas #F5F7FA, selection #E5EDF7. 모서리 4/6/8px, 간격 4/8/12/16/24/32px, 한글 시스템 글꼴, Lucide 아이콘. 의미 토큰으로 다크·고대비에 대응합니다. 유동 셸 안의 안정적인 목록·상세 관계를 쓰고 큰 Hero·무관한 이미지·KPI 카드 나열·장식 차트·글로우·경쟁사 외관 복제를 피합니다.

## 사용자 과업

- 주 사용자: 전체 DWP 홈에서 업무를 시작하는 구성원.
- 질문: “지금 확인할 업무가 있는가, 어디로 들어가면 되는가?”
- 주 행동: 우선 업무 열기 또는 통합업무함으로 이동.
- Archetype: 기존 개인 command center 안의 짧은 업무 contribution.
- 위치: 전체 Flow 홈의 기존 구성 요소. 독립 업무 홈이나 전체 Flow 재설계가 아닙니다.

## 범위와 시각 위계

공통 Flow의 앱 실행·조직 소식·일정·개인화 구조를 유지합니다. 업무 요약은 작업을 발견하는 짧은 영역입니다. 깊은 필터·일괄 선택·양식·긴 결재선을 홈에 펼치지 않습니다. 기존 작업 요약을 또 하나 추가하는 대신 동일 업무 contribution을 개선합니다.

작은 제목 ‘내가 처리할 업무’, 신뢰할 수 있는 짧은 범위·기한 신호, 최대 3~5개의 우선 항목 또는 실제 등록된 widget 콘텐츠 예산, ‘통합업무함 열기’를 제공합니다. 한 항목은 제목/원천/다음 행동/기한 정도로 읽히고 클릭 대상이 명확해야 합니다. 남은 총건수는 조회 범위와 완료 제외 정의가 맞는 경우만 표시합니다.

현재 Flow에는 work-queue contribution과 직접 앱 contribution의 중복 제거 구조가 있습니다. 동일 승인 요청이 두 데이터 경로에 있다고 두 번 보여주지 않습니다. 같은 문서의 서로 다른 담당 Task는 잘못 합치지 않도록 원천 참조·행동/담당 차이를 개발 인계에 명시합니다.

## Fixture와 흐름

APR-031 ‘고객 지원 장비 구매 승인 · 오늘 11:00’, IG-014 ‘재무 시스템 접근권한 검토 · 오늘 17:00’, NAT-001 ‘안내 초안 정리 · 오늘 계획 · 기한 없음’을 사용합니다. 예시 개수는 디자인용입니다. 제목을 일반 ‘업무 3건’ 카드로만 표현하지 않고 사용자가 다음 행동을 예상할 수 있게 합니다.

항목 클릭 → 같은 업무가 선택된 통합업무함/권한 검증된 원본 상세 → 처리 → Flow 재방문 시 최신 상태. 진입점의 식별자 계약은 유형마다 올바른 참조를 써야 합니다. 특히 Review의 표시용 ID를 실제 원천 참조 대신 쓰는 흐름을 피합니다. 이동했다는 사실만으로 홈에서 완료 처리하지 않습니다.

## 필수 상태

- 소수 업무/초과 항목/기한 없음과 오늘 계획의 구별.
- 완료 제외 집계와 예외 요약. 의미 없는 활성·전체·진행 네 KPI 반복 금지.
- 정상 0건: 범위가 확인됐을 때 “현재 내 조치가 없습니다”; 허용된 개인 할 일 추가 또는 큐 링크.
- 업무 앱 권한 없음: 제목·숫자·존재 여부를 노출하지 않고 기존 홈의 공간 재배치.
- 한 원천 지연: 다른 정상 업무 유지, 마지막 확인과 누락 경고; 완전한 완료 선언 금지.
- 오래된 홈 데이터/다른 날짜의 기한: 정확한 기준일/시간, ‘오늘’ 잘못 표기 금지.
- 좁은 widget/모바일/200% 확대: 행동과 기한을 유지한 행 축약; 제목을 전부 생략하지 않음.

## 구현 범위와 통과/실패

기존 Flow contribution은 구현 토대가 있습니다. 최신 링크/원천 상태/개인 계획 반영은 선행 개발 확인 대상입니다. Flow의 개인화·크기·필수 영역·권한 정책을 우회하는 고정 구성으로 만들지 않습니다.

- 홈에서 업무함으로 한 번에 연결되고 구 Work Home을 중간에 끼우지 않으면 통과.
- 같은 원본 조치를 중복 표시하거나 서로 다른 결정 Task를 한 건으로 합치면 실패.
- 전체 Flow 배경/앱 Dock/편집기를 새 디자인 대상으로 확장하면 실패.
- 일부 조회 실패를 ‘처리할 업무 없음’으로 표시하거나 유효한 근거 없이 실시간·AI 우선순위라고 쓰면 실패.
- 모바일에서도 다음 행동이 읽히고 전체 목록으로 들어갈 수 있으면 통과.

## 필수 제출과 공통 통과 기준

- 프레임 이름은 `화면ID-크기-테마-상태`로 명명합니다. 1440×900, 1280×800, 390×844, 320×568, 1280px 200% 확대를 모두 제출합니다. 주요 정상 화면은 라이트/다크, 중요 예외는 강제 고대비 변형을 포함합니다.
- 데스크톱을 축소하지 말고 모바일 목록→상세→행동→복귀를 재배치합니다. 320px에서 페이지 가로 넘침·중첩 패널·가려진 주요 행동이 없어야 합니다. 터치 대상은 최소 44px 조작 영역을 확보합니다.
- 키보드 Tab 순서, 가시적 focus, Enter/Space, Escape/뒤로, 대화상자 focus trap/복원, 상태 공지의 문구·시점을 명세합니다. 드래그는 버튼 대안을 제공하고 한글 IME 중 Enter 제출을 막는 동작을 표시합니다.
- 본문 대비 4.5:1, 큰 글자와 핵심 경계/조작 상태 3:1, 상태의 텍스트/아이콘 병기, 긴 한영 제목과 없는 값의 표현을 확인합니다. Reduced Motion에서 위치 이동·지속 애니메이션 없이 같은 의미를 전달합니다.
- 전체 로딩/오류, 정상 0건, 검색 0건, 부분 실패, stale, 권한 없음/회수, 버전 충돌, 실행 중/성공/실패 중 이 화면에 해당하는 상태를 별도 프레임 또는 명세로 제출합니다. 실패를 0이나 성공으로 바꾸면 실패입니다.
- 반복 컴포넌트 anatomy/variants/spacing/최소폭/최대폭/텍스트 처리/모바일 변화/상태/토큰 대응, 필드 의미·편집 주체·null, 행동 전제·효과·취소·실패·복귀를 표로 제출합니다.
- 그림뿐 아니라 사용자의 행동 전후를 연결한 prototype 또는 번호가 있는 흐름도를 제공합니다. 다른 앱으로 이동했다가 돌아왔을 때 필터·선택·스크롤·작성 상태 중 무엇을 유지하는지 명시합니다.
- 아래 화면별 기준과 공통 기준을 모두 통과해야 디자인 완료입니다. 단순히 메뉴가 있거나 API 이름이 보이거나 성공 화면 한 장이 있다는 이유로 통과시키지 않습니다. 기능 지원 여부가 미확정이면 구현 확인표에 남기고 성공한 것처럼 꾸미지 않습니다.

관련 구현·범위 확인은 `implementation-coverage.md`와 저장소의 최신 코드/검증 결과를 사용합니다. 이 프롬프트만으로 운영 제공을 보증하지 않습니다.
