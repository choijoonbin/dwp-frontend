DWP는 조직·권한 기반 디지털 워크플레이스입니다. 업무 앱은 여러 앱의 **내 처리 책임과 실제 결과**를 연결합니다. 기본 진입은 통합업무함이며 기존 ‘업무 홈’을 새로 디자인하지 않습니다. 보기·상세·대화상자를 별도 영구 메뉴로 늘리지 않습니다. Flow는 발견·앱 실행, Calendar는 시간 예약, 전자결재/서비스는 원본 처리, 알림은 읽음·전달, 메일/메신저는 대화, DWAI·ON은 분석·초안·검토형 실행을 소유합니다.

원본 상태, 기한의 긴급도, 개인이 선택한 오늘 계획, Calendar 예약, 원천 반영 결과를 구분합니다. 알림 정리·원본 열기·AI 응답·시간 경과를 업무 완료로 표시하지 않습니다. 원천 항목에는 해당 원천이 허용한 행동만, 네이티브 개인 할 일에는 DWP의 시작·완료·편집을 제공합니다. 권한/지원 계약이 확인되지 않으면 직접 처리 대신 허용된 원본 이동이나 해당 기능 없는 상태를 설계합니다.

원천 접근 상태는 서버가 현재 접근을 확인한 AVAILABLE, 개인 북마크에 참조만 저장된 REFERENCE_ONLY, 확인/사용 불가인 UNAVAILABLE을 구분합니다. REFERENCE_ONLY는 ‘원본 확인 필요’이며 원본 API에서 권한·최신 내용을 확인하기 전입니다. 연결/동기화 성공으로 표현하지 않습니다. AVAILABLE도 개별 변경 명령의 권한을 자동 허용하지 않습니다.

현재 요청은 **디자인 의뢰**입니다. 전체 화면·상태 변형·상호작용·컴포넌트/필드 명세를 만들어 주세요. 코드를 생성하거나 새 앱을 개발·배포하지 마세요. 아래 수치·사람·제목은 모두 기준 시각 2026-09-04 09:30 Asia/Seoul의 **가상 디자인 fixture**입니다. 운영 데이터·실제 연동·완료된 API라고 설명하지 마세요. ‘기존 기반 / 선행 개발 목표 / 조건부 후속’ 구분은 디자인 인계 주석에 남기고 내부 기술명은 사용자 화면에서 숨깁니다.

기존 DWP 셸과 업무 execution-flow/standard 밀도를 사용합니다. 라이트 모드 참고: accent #285C9E, secondary #0C847C, canvas #F5F7FA, selection #E5EDF7. 모서리 4/6/8px, 간격 4/8/12/16/24/32px, 한글 시스템 글꼴, Lucide 아이콘. 의미 토큰으로 다크·고대비에 대응합니다. 유동 셸 안의 안정적인 목록·상세 관계를 쓰고 큰 Hero·무관한 이미지·KPI 카드 나열·장식 차트·글로우·경쟁사 외관 복제를 피합니다.

## 사용자 과업

- 주 사용자: 선택한 업무를 처리할 시간을 확보하려는 구성원.
- 질문: “이 업무를 언제 수행할지 캘린더에 어떻게 이어서 잡을까?”
- 주 행동: 선택 업무 맥락을 가지고 Calendar의 일정 작성/집중시간 예약으로 이동.
- Archetype: 작은 focus form/연결 미리보기 + 원본 Calendar workflow.
- 위치: 업무 상세/계획의 ‘수행 시간 잡기’. 별도 메뉴나 업무 앱 안의 새 캘린더를 만들지 않습니다.

## 소유권과 기본 변형

업무는 제목·원본 참조·기한·내 계획을 소유하고 Calendar는 실제 시작/종료·시간대·충돌·일정 권한을 소유합니다. 두 객체가 연결되더라도 업무 완료와 일정 종료는 독립입니다.

기본 변형 A는 **작성 화면 handoff**입니다. 업무 제목과 안전한 내부 참조, 선택한 시간 후보가 있으면 이를 보여주고 ‘캘린더에서 이어서 작성’을 제공합니다. 이동 직후 ‘예약 완료’라고 표시하지 않습니다. 기존 Calendar의 필수 입력·가용성·일정 저장 결과를 따릅니다.

변형 B는 **실제 예약 결과를 돌려받는 연결**입니다. 일정 생성과 업무 참조 연결의 API가 확인된 때만 ‘시간 예약’을 직접 실행하는 변형으로 디자인합니다. 성공하면 일정 ID·시간·링크 등 실제 확인된 응답으로 예약됨을 표시합니다. 캘린더 생성 성공/업무 링크 실패를 하나의 완전 성공으로 숨기지 않습니다.

2026-09-04 선행 코드 대조에서 B의 headless 생성·참조 저장·조회·해제가 확인됐습니다. **전용 예약 화면은 아직 미제작**입니다. 이번에 확인된 직접 생성 범위는 생성 가능한 **개인 Calendar의 비공개·반복 없음·참석자 없는 집중시간**입니다. 공유/팀 캘린더 예약·회의 초대·반복 일정으로 임의 확대하지 않습니다. 제목은 최대 300자이고 유효한 시작/종료·시간대를 받습니다. 업무 기한·계획·완료는 바뀌지 않습니다.

반드시 구분할 복구 프레임: Calendar 생성 결과 미확인, 일정은 생성됐으나 업무 링크 저장 미완료, 일정과 링크 확인, 링크만 해제. 결과 미확인 때 같은 요청으로 확인하고, 일정 확인 뒤 링크 저장만 실패했다면 기존 일정을 유지한 채 링크만 재확인합니다. 링크 해제는 Calendar 일정 취소가 아닙니다. 저장된 링크만으로 일정 접근·제목·시간을 확인한 것으로 표현하지 않으며 Calendar 원본 조회가 필요합니다. 조회 범위에서 일정이 없다는 이유만으로 삭제됨이라고 단정하지 않습니다.

## 필수 상태와 왕복

- 정상 A: 미리보기→Calendar 작성→사용자 저장/취소→업무함 복귀.
- 정상 B: 허용 계약 있음→생성 중→예약됨+일정 열기. B는 조건부 프레임으로 표시.
- Calendar VIEW만 있고 생성 권한 없음, 앱 이용 권한 없음, 캘린더 선택 불가: 가능한 원본 이동 또는 단순 안내, 비활성 사유를 정확하게.
- 겹치는 시간·시간대 변경·종료가 시작보다 빠름·작업 기한 이후 예약: 실제 정책에 따른 오류/주의, 임의 차단 정책은 만들지 않음.
- 사용자 취소: 업무 상태·기한·계획은 바뀌지 않음.
- 응답 불확실/이미 생성된 일정: 중복 생성 대신 결과 확인 경로.
- 생성 성공·링크 실패: 실제 예약 존재와 연결 미완료를 구분하고 허용된 복구 경로.
- 원본 업무 접근 회수: 민감 내용을 폐기하고 작성 흐름의 지속 가능 여부를 Calendar 권한 계약에 맞게 설명.

## 모바일과 인계

320px에서 날짜/시각/시간대를 세로로 배치할 수 있어야 합니다. Calendar 전체 주간 그리드를 작은 dialog 안에 넣지 않습니다. 이동 전 작성값·복귀 위치·취소 시 남는 것과 생성된 후 남는 것을 흐름도로 제공합니다. Calendar 디자인 자체를 이번 화면에서 다시 정의하지 않습니다.

## 통과/실패

- 실제 Calendar 저장 성공 전 ‘예약 완료’가 보이면 실패.
- 일정 시간이 지나면 할 일이 완료되거나 계획 추가가 자동 일정 생성이 되면 실패.
- 업무 기한·개인 계획 날짜·예약 시간을 별도로 읽을 수 있으면 통과.
- 가용성 조회 없이 ‘충돌 없음’ 또는 ‘최적 시간’을 표시하면 실패.
- 권한·시간대·개인정보 공개 의미가 Calendar 원본 계약을 유지하면 통과.
