# 업무 앱: 통합업무함 고도화

기준일: 2026-09-04

업무 앱의 역할은 **여러 앱에서 발생한 내 처리 책임을 한곳에서 발견하고, 각 원본이 허용하는 행동과 확인된 결과까지 안전하게 이어 주는 것**이다. 개인 할 일과 오늘 계획은 업무 앱이 소유한다. 결재·서비스·권한 검토는 각 원본 앱이 상태와 최종 행동을 소유하고, Calendar는 실행 시간을 소유하며, DWAI·ON은 분석과 초안 대화를 소유한다.

고도화된 기본 진입점은 `/work/queue`다. `/work`, `/work/home`과 폐기된 업무 하위 경로는 지원하는 query를 보존해 이 경로로 이동한다. 중복된 업무 홈 메뉴와 화면은 제거했으며, 오늘 계획·상세·작성·Calendar·AI 흐름은 통합업무함의 보기·패널·대화상자로 구성했다.

## 사용자가 할 수 있는 일

- Workspace·결재·서비스·개인 할 일 등 여러 원천의 내 책임을 원천 상태와 함께 조회하고, 검색·필터·정렬·선택 상세로 판단한다.
- 원천 일부가 제한·지연·실패해도 조회된 부분과 누락 범위를 구분해 확인한다. 권한이 회수되면 이전 원천 내용을 제거한다.
- 개인 할 일을 생성·편집하고 시작·대기·완료·재개·보관하며, 연결된 원천 참조를 명시적으로 해제하고 전체 timeline을 확인한다.
- 날짜별 오늘 계획에 업무를 추가·제거·정렬한다. 저장된 불투명 참조와 접근할 수 없는 선택도 현재 계획 receipt에 따라 안전하게 보존한다.
- 개인 집중시간을 Calendar에 만들고 업무 관계를 연결한다. 일정 생성 뒤 링크 저장이 실패하거나 응답이 불확실한 경우 receipt를 보존해 남은 단계만 복구한다. 연결만 해제해도 Calendar 일정은 취소되지 않는다.
- 허용된 원천 행동 또는 원본 앱 handoff, Access Review·Service handoff, 선택 업무의 DWAI·ON 질문 전달을 수행한다.
- 일괄 실행 전 대상과 행동을 검토하고, 원자적 요청이 전체 확인되면 항목별 confirmed receipt를 표시한다. 응답을 확인할 수 없으면 어느 항목도 임의 성공·실패로 확정하지 않는다.

## 책임 경계

| 표면       | 사용자가 하는 일                                                | 상태를 소유하는 곳             |
| ---------- | --------------------------------------------------------------- | ------------------------------ |
| Flow 홈    | 중요한 업무를 짧게 발견하고 통합업무함으로 진입                 | Flow는 요약과 이동             |
| 통합업무함 | 내 조치·진행 대기·완료를 구분하고 허용된 행동 또는 handoff 수행 | 투영은 Work, 원본 상태는 각 앱 |
| 개인 할 일 | 직접 작성·편집·시작·대기·완료·재개·보관                         | 업무 앱                        |
| 오늘 계획  | 날짜별로 할 일을 선택·정렬·제거                                 | 업무 앱의 사용자 개인 계획     |
| Calendar   | 집중시간 생성·변경·취소 및 일정 상세 확인                       | Calendar 앱                    |
| DWAI·ON    | 선택 업무의 확인 사항·분석·초안 작성                            | 기존 AI 대화·제안 체계         |
| 알림·활동  | 전달·읽음 또는 검증된 사건 확인                                 | 각 원본 기록 체계              |

원본 열기, 알림 읽음, 계획 추가, 일정 생성, 관계 연결, AI 답변 완료를 업무 완료로 취급하지 않는다. `AVAILABLE`도 모든 수정 권한을 뜻하지 않는다. 결재·서비스의 범용 직접 처리는 제공하지 않으며 현재 원본 계약이 검증한 행동만 노출한다.

## 디자인 적용과 확인 범위

Stitch 프로젝트의 01–12 결과에서 18개 프레임과 HTML을 확보해 목록–상세 구조, 정보 밀도, 모바일 여정, 대화상자 구성을 참고했다. 제품에는 DWP 토큰·Lucide·기존 셸과 실제 API 계약을 적용했다. 시안의 고정 6개 하위 메뉴, 임의 지표, 실시간·법적 효력·감사 동기화·AI 자동 반영 같은 검증되지 않은 문구는 채택하지 않았다.

Stitch 제출물은 공식 completeness gate를 충족하지 않는다. 데스크톱 래퍼는 제목의 1440px과 달리 모두 1280px이며, M2도 제목의 320px과 달리 실제 390px이다. 06–11 개별 모바일, dark, 강제 고대비, 200% 확대 제출물도 없다. 부족한 상태와 viewport는 제품 코드와 자동 검증으로 보완했으며, 실제 보조기기·운영 원천 검증을 디자인 이미지가 대신하지 않는다.

Meeting 원천의 내부 resolve/read만 연결돼 있다. CREATE는 `AUTHORITY_UNVERIFIED`, REASSIGN은 `TARGET_ELIGIBILITY_UNVERIFIED`로 fail-closed이며 현재 **NO-GO**다. 외부 운영 배포 증적, Mail·Messaging의 캡처 진입, 범용 직접 승인·서비스 완료는 이번 완료 범위가 아니다.
