# Meeting 출처 Work 배정 — 검증 매트릭스

상태: 2026-09-04 구현 수용 기준과 담당 작업의 검증 보고입니다. Work 배정 backend 42개(실제 PostgreSQL 15개 포함, 실패/오류/skip 0), shared API의 기존 snapshot 단위 11개가 통과했습니다. 이후 U09의 기존 배정 코드 소비·도달성도 확인했습니다. 아래 공격 매트릭스 전체와 실제 Meeting 연결이 모두 검증됐다는 뜻은 아닙니다. 각 계층의 제공 범위는 마지막 증거 표를 따르며 이전 개인 업무 집계를 합산하지 않습니다.

모든 데이터는 별도 테스트 tenant·합성 사용자·가상 meeting/report/candidate로 구성합니다. Meeting adapter가 stub이면 source 권한 통합을 실제 확인한 것으로 기록하지 않습니다. 구현 파일의 snapshot·명령·환경·결과 파일을 증거와 함께 기록합니다.

## 상태·권한 불변식

- PENDING/DECLINED를 IN_PROGRESS/COMPLETED처럼 집계하지 않습니다. 수락과 수행은 별도 축입니다.
- 수락은 현재 담당자의 의사이며 creator가 대신하지 않습니다. 새 담당자에게 과거 acceptedAt/완료 결과를 승계하지 않습니다.
- cancel/reassign creator-only, 조회는 현재 creator/assignee + VIEW, 변경은 VIEW+UPDATE와 현재 action 권한을 요구합니다.
- 완료/취소 terminal의 허용 전이, 동일 상태 새 명령, 사유 필수 여부는 service guard를 직접 검증합니다. 미지원 보관/재개/편집을 테스트 fixture에 숨겨 넣지 않습니다.
- source UNAVAILABLE과 NOT_REQUESTED는 모두 reference/link/version 비노출입니다. NOT_REQUESTED는 목록의 정상 미조회 상태이며 원천 거부/장애와 구분합니다. 두 상태 모두 Work 정본 상태·보존과 독립이고, 목록 canReassign은 false입니다.
- source version, Work version, assignmentRevision, command appliedVersion은 목적이 다르며 하나의 숫자로 대체하지 않습니다.
