# 회의 출처 업무 배정 — 구현 결과와 연결 인계

기준일: 2026-09-04의 Work 소유 backend·DB·공개 API·공유 클라이언트 기록을 보존하고, 2026-09-09 현재 배정 업무의 Work 화면 구현 상태로 갱신했다. 목록·상세, 수락 상태와 수행 상태의 두 축, 현재 역할·capability에 따른 활성 명령, receipt 복구·409 재검토·권한 회수, 반응형·접근성 검증을 제품 코드에 연결했다. 현재 구현과 최종 실행 결과는 [완료 보고](../2026-09-09-stitch-completion-remediation.md)와 [검증 증거](../implementation-evidence/2026-09-08-stitch-completion/validation.json)를 기준으로 판단한다.

실제 Meeting 원천 승격과 재배정은 별도 경계다. Meeting authority, People 대상자 적격성, 안전한 대상·정책 선택 계약이 제공되기 전까지 CREATE/by-source/REASSIGN은 **NO-GO**이며, 이 상태를 Work 화면 구현 누락으로 해석하지 않는다.

## 사용자 행동과 소유권

회의에서 사람이 확정한 제목·설명·담당자·기한으로 독립 Work 업무를 만든다. 담당자는 조건을 보고 수락 또는 거절하며, 수락 후 시작·대기·완료한다. 요청자는 허용된 취소·재배정을 할 수 있다. 재배정하면 새 담당자의 수락이 다시 필요하고 이전 담당자의 조회·명령 권한은 사라진다.

이 객체는 개인 할 일과 구분한다. Meeting은 후보·원문·인용·후보 확정을 소유하며, Work는 확정된 업무 조건·수락·배정·진행을 소유한다. Meeting 원천 접근이 사라져도 독립 Work 조건과 수행은 현재 Work 권한에 따라 유지한다. 원천 참조·버전·링크는 모두 숨기며 새 생성·재배정은 현재 원천 검증에 실패하면 실행하지 않는다.

공통 서비스 인터페이스 등록과 현재 Meeting 권한 포트는 서로 다른 게이트다. 정적 검사 통과만으로 실제 source 전환을 활성화하지 않는다. 로컬 Platform DB/API는 실행했지만 Meeting source 설정·비밀키·grant는 활성화하지 않았다. 다른 작업의 변경과 섞인 부분 commit을 만들지 않았다.

공통 마감은 해당 공유 작업 트리의 **CLOSED / FROZEN**이며 immutable release attestation이 아니다. 2026-09-09 Work 화면은 별도 완료 증거로 검증됐지만 CREATE/by-source·REASSIGN은 Meeting authority·People 대상자 적격성·안전한 대상 선택 계약과 수신부 연결 전 **NO-GO**다. 공통 후속은 `build:products` 16종이나 backend 전체 check를 재실행한 증거도 아니다.

구체적인 보안·회귀 수용 기준은 [검증 매트릭스](verification-matrix.md), 서비스 간 인증 bytes와 공개 테스트 키는 [원천 프로토콜](source-protocol-v1.md) 및 [golden fixture](evidence/source-golden-v1.json)를 따른다.

## 파일 소유 범위

- Backend: `dwp-platform-server/src/main/java/com/dwp/services/platform/workhub/assignment/`의 DTO·controller·service·repository·source port·protocol·signer·HTTP adapter·body subscriber 9개와 같은 패키지의 테스트 5개, `V226__create_work_assignments.sql`, 테스트 golden fixture.
- Frontend의 2026-09-04 SDK 범위: `libs/shared-utils/src/api/work-assignment-contracts.ts`, `work-assignment-api.ts`, `work-assignment-api.test.ts`. 2026-09-09 Work 화면 범위와 증거는 [완료 보고](../2026-09-09-stitch-completion-remediation.md)에 별도로 기록한다.
- 문서: 이 `meeting-assignment/` 디렉터리. 기존 `design-ai/00~12`는 그대로 유지하고 배정 업무 추가 요구와 현재 구현 결과를 연결한다.
- 현재 작업 디렉터리에는 다른 작업의 변경도 있다. 전체 git diff를 이번 업무 배정 변경으로 해석하거나 일괄 commit하지 않는다.
