# 업무 앱 자체 고도화 최종 마감

기준 시각: 2026-09-07 18:58 KST. 사용자 제공 [Stitch 프로젝트](https://stitch.withgoogle.com/projects/13391261371843159731)의 18개 화면과 앞선 구현 대조를 기준으로, 다른 앱의 운영 권한·실데이터·소유 계약이 없어 진행할 수 없는 부분을 제외한 **Work 소유 개발 범위를 `CLOSED_FROZEN`으로 마감**했다.

업무 앱의 주 사용자는 여러 원천 앱에 처리 책임이 흩어진 임직원이다. 이 앱이 답해야 할 운영 질문은 “지금 무엇을 어떤 순서로 처리하고, 실제 처리는 어디에서 해야 하는가?”다. 주 행동은 업무 선택, 근거 확인, Work 소유 명령 실행 또는 원천 앱 인계이며 화면 유형은 목록–상세형 실행 허브와 오늘 계획 워크플로다.

## 이번에 추가로 찾아 닫은 결함

1. **사용자·테넌트·권한 전환 격리:** actor ID만 같아도 role, group, resource role, permission이 달라지면 별도 실행 소유자로 취급한다. 이전 owner의 요청·캐시·복구 행·일괄 처리·저장 후속 동작이 새 화면에 반영되지 않는다. 메뉴 전환과 URL 기반 modal 전환도 Work 화면 수명을 분리한다.
2. **오류 복구의 권한 경계:** 5xx와 transport 장애에서만 같은 owner의 마지막 확인 행을 유지한다. 401/403/404/409/422 뒤에는 이전 업무가 다시 나타나지 않는다.
3. **개인 업무 저장 안전성:** 동기 이중 제출을 막고, 늦은 생성·편집·409 재조회·오늘 계획 저장이 owner 전환 또는 unmount 뒤 URL, dialog, cache, 계획을 바꾸지 못하게 했다.
4. **동시 편집 충돌:** 서버 최신 버전을 기존 초안에 조용히 붙이던 덮어쓰기 경로를 제거했다. 최신 제목·설명·우선순위·기한·원천·체크리스트를 먼저 확인한 뒤 최신 내용 사용 또는 내 초안 유지를 명시적으로 선택해야 저장할 수 있다. 재충돌하면 다시 검토한다.
5. **선택 상태와 URL 정합:** 업무 메뉴, 검색, 원천, 긴급도 범위가 달라지면 일괄 선택을 비운다. 메뉴 이동 시 `select`를 제거하며 잘못된 `sort`·`density` 값은 안전한 기본값으로 처리한다. URL의 `compose`·`panel`을 뒤로 가기로 제거하면 열린 화면도 함께 닫힌다.
6. **오늘 계획 키보드 흐름:** 키보드로 후보를 추가하거나 제거한 뒤 사라진 버튼 대신 결과 업무 또는 복구 가능한 후보 버튼으로 포커스를 옮긴다. 후보가 필터로 숨겨지면 영역 제목을 사용한다.
7. **고정 탐색과 포커스:** 200% 확대 및 낮은 입력 뷰포트에서 포커스된 상태 버튼이 헤더나 하단 메뉴 뒤에 숨으면 Work 본문 안에서만 보이는 위치로 이동한다. dialog 등 portal에는 적용하지 않는다.
8. **모바일 확대 배치:** 390px WebKit 글자 200%에서 개인 업무 제목과 편집·삭제 버튼, 하단 DWAI·ON과 더보기 라벨이 겹치던 배치를 수정했다. 각 메뉴 라벨은 자기 터치 영역 안에서 줄바꿈한다.
9. **검증 자산 정합:** 실제 탭 확대에 쓰는 Chrome service worker의 `chrome` 런타임 전역을 증거 파일 안에 국소 선언해 저장소 ESLint를 막지 않게 했다. 공통 lint 규칙은 완화하지 않았다.

상세 재현과 보완 근거는 [데이터·오류 복구 감사](implementation-evidence/2026-09-07-resume/work-recovery/review.md), [편집 충돌 감사](implementation-evidence/2026-09-07-owned-scope-audit/edit-conflict-audit.md), [모바일·접근성 감사](implementation-evidence/2026-09-07-resume/mobile-accessibility-final/README.md)에 있다.

## 외부 조건과 소유 작업 요청

Work 코드를 더 작성해서 해결할 수 없는 조건은 해당 소유 작업에 요청했다. 요청 시 Work에 원천 앱 명령을 복제하거나 임의 권한을 넓히지 않도록 완료 기준도 함께 전달했다.

| 소유 작업                      | 필요한 조건과 완료 기준                                                                                                                                    | 요청 상태                                                                                                                               |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **앱 관리자 UX 고도화 제안**   | Services v6의 독립 Provider 승인·Platform 활성화·changeRef·checksum/CAS, 실제 tenant 제출 증거. Gateway OpenAPI 재동기화 후 동일 checkout 공통 gate 재실행 | 전달 완료. 최신 schema drift 체크섬과 재동기화 요청까지 추가 전달                                                                       |
| **고도화 전자결재 양식 관리**  | 실제 scope·관계·행위 권한으로 Work deep link → 결재 처리 → Work 갱신, 권한 없음·자기 결재·409·복귀 검증                                                    | 해당 작업의 장기 실행 turn 때문에 직접 follow-up API가 두 번 거절됨. 중앙 통합 작업에 동일 요청을 전달해 종료 직후 인계하도록 요청 완료 |
| **캘린더 메뉴 고도화 및 개발** | 실제 개인 캘린더에서 일정 1개+Work link 1개, 시간대·부분 실패·멱등 재시도·연결 해제 검증                                                                   | 전달 완료                                                                                                                               |
| **홈화면 위젯 고도화**         | 실제 개인 업무·오늘 계획 contribution 갱신, owner/tenant 격리, 중복 제거·부분 실패 검증                                                                    | 전달 완료                                                                                                                               |
| **DWAI·ON 고도화 로드맵 제시** | 선택 업무 전용 exact-owner 조회 계약, expected version, 취소·권한 회수·stream correlation·이어보기 검증                                                    | 전달 완료. 소유 작업이 전체 목록 검색 결함을 확인했으며 공유 typed 계약을 먼저 동결한 뒤 최소 Work adapter 시그니처를 회신하기로 함     |

Services v6은 여전히 `DRAFT/BLOCKED_EXTERNAL`이다. DWAI의 선택 업무 전용 서버 계약도 소유 작업에서 확인된 새 선행 조건이다. 이 두 항목과 운영 계정 검증은 Work 자체 완료 상태와 구분한다. 외부 계약이 동결되면 추정 구현을 하지 않고 확정된 타입으로 최소 adapter만 연결해야 한다.
