# 접근 권한 검토 모바일 마감

대상 사용자는 접근 검토를 배정받은 검토자다. 현재 업무 범위에서 이 권한을 유지할 수 있는지 판단하고, 근거를 기록한 후 유지 또는 회수 결정을 제출한다. 화면 유형은 검토 근거가 연결된 집중 입력 양식이다.

## 변경 범위

- `apps/dwp/src/features/work/access-review-work-item.tsx`: 대상 구성원과 검토 권한을 요약하고, 모바일에서는 캠페인·권한 근거를 접을 수 있게 했다. 데스크톱에서는 모든 기존 근거가 펼쳐진다.
- 특권 권한 주의 문구는 근거를 접어도 표시한다. 모바일의 유지·회수는 같은 행에 배치하며, 사유 입력과 제출 전 확인을 바로 이어 배치했다.
- 근거 토글 및 화면 높이 변경은 입력 사유를 지우지 않는다. 기존 객체 배정 검사, 결정 권한 검사, 최신 버전 재확인, 409 충돌 시 사유 보존, 원천 권한 반영과 검토 결정의 구분은 그대로 유지했다.
- 두 번역 키는 `mobile-review-i18n.json`으로 전달했고 ko/en Work 사전에 병합되었다.

## 검증

`e2e/work-access-review-responsive.spec.ts`에서 Chromium 및 mobile 프로젝트 총 10개 사례가 통과했다. 이후 요약 영역의 열 비율을 1:2로 조정하여 확대된 긴 권한명의 줄바꿈을 보정했고, 영향을 받는 모바일 사례 3개를 다시 통과했다.

- 390px·320px에서 유지/회수 동일 행, 접힌 근거 키보드 조작, 사유 보존, 가로 넘침 없음.
- 화면 높이를 440px로 줄인 입력 상황에서 사유 입력과 제출 전 확인 버튼, 하단 탐색의 겹침 없음. 실제 OS 가상 키보드 기기 테스트 대신 화면 높이 변화로 재현했다.
- 1440px·1280px의 영어·다크 모드·고대비에서 기존 증거 노출.
- 390px에서 글자 크기를 200%로 확대한 상태의 사유 입력 및 제출 미리보기. 브라우저 자체 200% 확대와 구분한다.

결과는 `mobile-review-test.log`, 최종 배치 재검증은 `mobile-review-final-layout.log`, 최종 캡처는 `mobile-review-final-layout/`에 보관했다. 데스크톱 캡처 및 두 프로젝트 결과는 `mobile-review-results/`에 있다.

## 원본 대조 상태

최신 원본은 Stitch 프로젝트 13391261371843159731의 M1 node `bd6232c66d2e43f783e92b8603a291b3`이며, 이 작업은 조정 에이전트가 직접 확인한 최신 원본 구조를 반영했다. 담당 에이전트의 별도 원본 탭은 미리보기 기기 프레임 이후 Chrome 연결이 끊겨 이미지 직접 대조를 완료하지 못했다. 원본 픽셀 수준의 최종 대조는 조정 에이전트의 정상 연결에서 마감해야 한다. 18개 전체 화면 또는 실운영 테넌트 활성화 완료의 증거로 이 제한된 검증을 사용하지 않는다.

담당 코드 및 전용 테스트는 추가 편집을 중지한 상태다. 공유 상세 패널, 소유 앱 라우트, 전체 Work 회귀와 Workspace 빌드 마감은 조정 에이전트가 통합한다.
