## 이번 감사에서 수정한 부분

- 개인 할 일 삭제를 큰 붉은 주 행동에서 내용 헤더의 명확한 보조 행동으로 옮겼다. 권한 조건과 삭제 확인·버전 검증은 유지했다.
- 실제 이력은 계속 노출하고, 이력이 없는 경우는 키보드로 열 수 있는 접힘 영역으로 줄였다.
- 개인 상태 선택에서 기존 Work 명령 처리기를 재사용할 수 있도록 연결했다. 진행·대기·완료 등의 중복 명령 경로를 피하고 응답 유실 시 재시도 식별자를 유지한다.
- 상세 화면의 체크리스트 진행률은 서버가 확인한 완료 수/전체 수로 표시한다. 저장 전 체크박스 초안과 확정 진행률을 구분하며, 저장 실패로 완료율이 올라가지 않는다. 작성·편집 양식의 진행률은 작성 중인 초안을 그대로 나타낸다.
- 200% 확대 검증이 제거된 중복 ‘시작’ 버튼 대신 실제 4개 상태 선택의 ‘진행 중’을 검사하도록 갱신했다.
- 공유 개발 서버의 지연된 초기 제품·언어 청크 로딩에 한해 최초 화면 준비를 20초까지 기다린다. 후속 행동과 결과 검증의 시간 제한은 그대로 유지했다.

## 원본 대조의 범위와 차이

05 모바일, 06·07·08·09·11 데스크톱은 보관된 원본 PNG를 직접 확인했다. 원본 09 PNG는 내용 상단이 잘린 상태이므로 해당 이미지로 전체 영역의 픽셀 일치를 주장하지 않는다. 원본 07의 예상 소요 시간·성공 확률 같은 예시 숫자는 실제 계약에 없는 데이터여서 복제하지 않았다. 11의 외부 서비스 입력 양식과 자동 초안 적용은 원천 앱 소유 경계를 따른다.

원본 M2의 현재 노드는 `83bce81c3d3748229ba72f9fa38852bf`이며, 보관된 이전 노드는 `6953f797f9ef4baeb2967a1aef0a777d`이다. 전체 검증 담당자가 최신 Stitch의 접근성 트리와 실제 원본 이미지에서 빈 큐/추가/계획/수행 시간의 4단계, 500자 제목, 오늘 계획 선택, Calendar 연결, 저장·취소를 직접 확인했다. 최신 원본은 빈 큐와 빠른 생성 폼을 한 프레임에 배치한 여정 예시다. 제품에서는 실제 결과가 비어 있을 때 빈 큐를 표시하고, 추가 행동으로 확장 입력 양식을 연다. 이전 M2는 제목상 320px, 실제 390px이다. 이 개인 감사의 보관 PNG는 이전 버전이므로 최신 M2의 픽셀 일치 증거로 간주하지 않는다. 최신 M2의 시각 확인 내용은 전체 원본 감사 자료와 함께 확인해야 한다.

## 증거 파일

- `personal-plan-unit.log`: 관련 6개 파일, 42개 단위 검증 통과.
- `personal-plan-e2e-interrupted-load.log`: 개발 서버 동시 부하로 초기 화면 준비가 지연되어 중단한 이전 실행. 최종 통과 증거가 아니다.
- `personal-plan-e2e-final.log`: Chromium·모바일 최종 42개 검증 통과, 3.1분. 재시도 없이 완료했다.
- `personal-plan-final/`: 최종 실행의 1440/1280/390/320px, 200%, 어두운 테마·고대비, 키보드 여정 캡처.
- `personal-plan-manifest.json`: 최종 캡처의 경로·픽셀 크기·SHA-256과 검증 결과.
- `checklist-confirmed-unit.log`: 확정 진행률과 실패 보존을 추가 검증한 관련 2개 파일, 22개 단위 검증 통과.
- `checklist-confirmed-e2e.log`: 확정 진행률 변경 후 관련 14개 PC·모바일 검증 통과, 재시도 없이 48.1초.
- `checklist-progress-captures/`: 최종 05 상세·06 편집 캡처. 진행률이 고정 내비게이션에 가리지 않는 가운데 스크롤 위치를 별도로 캡처했다. 1440/1280/390/320px, PC·모바일 8개 검증 통과.

실제 모바일 키보드 캡처는 뷰포트 높이를 줄여 재배치를 검증한 것이다. 실제 단말 운영체제의 가상 키보드를 캡처했다는 의미는 아니다.
