# 04 데이터 설계

## `adm_registry_entries`

논리 Key의 각 Revision을 한 Row로 저장한다.

| Column                                    | 계약                                           |
| ----------------------------------------- | ---------------------------------------------- |
| `tenant_id`, `registry_type`, `entry_key` | Tenant 안의 논리 식별자                        |
| `revision`                                | 1부터 증가하는 Definition Revision             |
| `owner_ref`                               | 사용자 ID가 아닌 안정적인 Team·Owner Reference |
| `risk_tier`                               | `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`            |
| `artifact_version`                        | 실제 배포 Artifact의 Version Label             |
| `lifecycle_state`                         | `DRAFT`, `ACTIVE`, `RETIRED`                   |
| `version`                                 | Optimistic Lock                                |

Unique 제약은 `(tenant_id, registry_type, entry_key, revision)`이며 PostgreSQL Partial
Unique Index로 논리 Key당 Draft와 Active를 각각 최대 1개로 제한한다.

실행 가능한 상세 Definition은 이 Table에 JSON으로 추가하지 않는다. Connector,
Agent, Tool과 Policy 전용 Table은 각 Feature의 Version·승인 계약에 따라 분리한다.
