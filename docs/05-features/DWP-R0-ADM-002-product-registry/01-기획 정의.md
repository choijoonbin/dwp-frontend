# 01 기획 정의

## 문제와 사용자

앱, 연동과 Agent가 늘어나면 무엇이 어느 Tenant에 배포됐고 누가 책임지며 어떤 위험을
갖는지 추적하기 어렵다. 실행 Definition보다 먼저 제품 Inventory와 Lifecycle의 공통
통제가 필요하다.

- Persona: Tenant Admin, Integration Owner, Agent Owner, Security Reviewer
- JTBD: “배포 대상을 활성화하기 전에 소유자, 위험과 Version을 확인하고 이력을 남긴다.”
- End state: 하나의 Active Revision만 Runtime Catalog에 노출된다.

## 범위와 KPI

| 범위               | 수용 목표                                           |
| ------------------ | --------------------------------------------------- |
| Registry Inventory | 모든 Active 객체의 Type·Key·Owner·Risk·Version 100% |
| Version 전환       | Key별 Active Revision 최대 1개                      |
| Audit              | 생성·편집·활성·대체·폐기 100%                       |
| Tenant 격리        | Cross-tenant 노출 0건                               |

## Non-goal

Registry는 임의 JSON 설정 저장소가 아니다. 유형별 실행 계약과 Secret은 전용 Schema,
Vault와 승인 Workflow가 준비된 뒤 연결한다.
