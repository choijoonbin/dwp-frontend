# DWP-R1-CORE-002 데이터 설계

## 1. `adm_home_experiences`

| Column                                  | 목적                                 |
| --------------------------------------- | ------------------------------------ |
| `tenant_id`                             | Tenant 단일 Aggregate PK             |
| `headline`, `subheadline`               | Home Presentation 문구               |
| `localized_content`                     | Locale별 제목·설명 JSONB             |
| `default_locale`                        | Runtime Fallback과 게시 검증 기준    |
| `background_position`                   | `LEFT`, `CENTER`, `RIGHT`            |
| `overlay_opacity`                       | 0~70 가독성 Overlay                  |
| `background_asset_key`                  | Storage 내부 Tenant Scope Key        |
| `background_original_name`              | 정제된 원본 파일명                   |
| `background_content_type`               | 검증된 `image/png` 또는 `image/jpeg` |
| `background_size_bytes`                 | 실제 Binary 크기                     |
| `background_sha256`                     | 무결성·ETag Hash                     |
| `background_width`, `background_height` | Decode된 Pixel 크기                  |
| `version`                               | 낙관적 잠금                          |
| `created_*`, `updated_*`                | 감사용 Actor와 시각                  |

Asset Key가 없으면 모든 Asset Metadata도 `NULL`이어야 하며, Key가 있으면 Metadata가
완전해야 한다. Overlay, Position과 Metadata 완전성은 DB Check Constraint로 보호한다.

## 2. `adm_tenant_branding`

Tenant별 `organization_name`, `accent_color`, Logo Asset Key·원본명·MIME·크기·SHA-256·너비·높이와
낙관적 `version`, 생성·수정 Actor를 저장한다. Logo Key와 Metadata는 모두 `NULL`이거나
모두 완전해야 한다.

## 3. `usr_home_preferences`

| Column                   | 목적                                            |
| ------------------------ | ----------------------------------------------- |
| `home_preference_id`     | 내부 PK                                         |
| `tenant_id`, `user_id`   | 사용자별 유일 범위                              |
| `schema_version`         | Layout 계약 마이그레이션 기준                   |
| `layout_payload`         | 등록된 App Folder·순서와 Widget 표시·순서 JSONB |
| `version`                | 동시 편집 충돌 방지                             |
| `created_*`, `updated_*` | 감사 Actor와 시각                               |

서버는 Payload 크기, App·Folder·Group 식별자 구조, 등록 Widget 목록과 숨김 가능 정책을
검증한다. Frontend는 조회 시 현재 App Registry와 Entitlement로 다시 조정한다. 업무 본문,
메일, Prompt와 외부 자격정보는 저장하지 않는다. 조회 응답의 `customized`가 저장 행의
존재 여부를 명시하며, 최초 저장 행도 낙관적 잠금 `version=0`일 수 있으므로 Version 값으로
기본 상태 여부를 추론하지 않는다.

## 4. `adm_announcements`

Tenant, 제목·본문, `INFO|SUCCESS|WARNING|CRITICAL`, `DRAFT|PUBLISHED|ARCHIVED`,
`ALL|ROLE` 대상, 게시 시작·종료, 고정 여부, 안전한 Action과 게시 Actor·시각·Version을
저장한다. 종료는 시작보다 늦어야 하고 Action Label과 URL은 함께 존재해야 한다.

## 5. Revision과 참여 증적

- `adm_experience_revisions`: Tenant, `BRANDING|HOME`, 원본 Version, 변경 유형, 전체 Snapshot,
  Correlation, Actor와 시각을 저장한다. Baseline은 Aggregate당 한 건이며 게시·Asset 교체·
  Reset·Rollback은 append-only Revision으로 남긴다.
- `sys_announcement_engagements`: `(tenant_id, announcement_id, user_id)`별 최초·최근 View,
  View 횟수, 최초·최근 Action과 Action 횟수를 저장한다. 관리자 응답에는 개인 행이 아니라
  Announcement별 집계만 노출한다.

## 6. 파일 저장

- Local: `${user.home}/.dwp/platform-assets/{tenantId}/home/backgrounds/{uuid}.{ext}`
- Local Logo: `${user.home}/.dwp/platform-assets/{tenantId}/branding/logos/{uuid}.{ext}`
- 임시 파일에 쓴 뒤 Atomic Move한다.
- Path Normalize, Tenant Prefix와 Traversal 검증을 통과해야 Load·Delete할 수 있다.
- Transaction Rollback 시 새 임시·신규 파일을 삭제한다.
- 게시된 이전 파일은 불변 Revision이 Rollback에서 참조할 수 있으므로 교체 즉시 삭제하지 않는다.
- 미참조 Asset 삭제는 `D-14`의 보존기간·Legal Hold·감사 정책이 확정된 Lifecycle Job만 수행한다.

## 7. 운영 전환

`TenantMediaStorage` 구현만 S3 Adapter로 교체한다. DB Schema와 API는 유지하고 Object Key,
Encryption, Versioning, Lifecycle, Malware Scan과 CDN Purge를 운영 설정으로 추가한다.
