# 홈 앱 거버넌스 및 공통 내비게이션 정책

## 1. 결정

Home의 `업무 시작`, `소통과 협업`, `구성원과 서비스`, `시스템과 통제`는 Frontend에 고정된
개인 Folder가 아니다. Tenant 관리자가 조직의 정보 구조로 게시하는 **관리형 Home 영역**이다.
기본 네 영역은 초기값이며 관리자는 `관리 센터 > 사용자 경험 > 홈 앱 구성`에서 최대 8개까지
동적으로 추가·이름 변경·정렬할 수 있다.

사용자에게는 별도 개인 설정 Admin을 만들지 않는다. Home의 단일 `홈 화면 편집` 동작에서
App 순서, 영역 간 이동, Folder 생성, 숨김·복원과 기본값 초기화를 수행한다. 이 분리는 관리형
Dashboard와 개인 재배치를 구분하는 Microsoft Viva Connections, 관리형 App Library 위에
사용자 Home 구성을 두는 Apple의 모델과 일치한다.

## 2. 책임 경계

| 계층        | 소유자              | 관리 대상                                              | 저장 위치                                      |
| ----------- | ------------------- | ------------------------------------------------------ | ---------------------------------------------- |
| App 공급    | Provider·App 관리자 | App Registry, Lifecycle, Tenant Entitlement            | `adm_workspace_apps`, 권한 계약                |
| Tenant 기본 | Tenant 관리자       | 영역, 다국어 명칭·설명, 순서, 활성 상태, App 기본 배치 | `adm_home_experiences.launchpad_configuration` |
| 접근 통제   | Tenant 관리자·IAM   | 사용자·Group별 App 조회·실행 권한                      | RBAC·Entitlement                               |
| 개인 구성   | 로그인 사용자       | 순서, 영역 간 이동, Folder, 숨김·복원                  | `usr_home_preferences.layout_payload`          |

개인 설정은 권한을 만들지 않는다. 권한이 없는 App은 Home과 Route에서 모두 제거된다. Tenant
영역을 변경하면 저장된 개인 Layout을 현재 정책으로 조정하고, 사라진 영역과 App을 정리하며,
새 App은 관리형 기본 위치에 추가한다.

## 3. 게시 프로세스

1. Provider가 App Registry와 Tenant Entitlement를 게시한다.
2. Tenant 관리자가 Home 영역의 한국어·영문 명칭과 기본 App 배치를 편집한다.
3. API가 Group·Locale·Resource 무결성과 비활성 Group의 잔여 App을 검증한다.
4. 낙관적 잠금으로 게시하고 Revision과 Audit Event를 남긴다.
5. 사용자가 Home을 열면 `Tenant 기본 → Entitlement 필터 → 개인 Layout 조정` 순서로 계산한다.
6. 사용자의 편집은 자신의 Home에만 저장되며 언제든 Tenant 기본값으로 초기화할 수 있다.

## 4. 공통 Sidebar 정책

- Home(`/`)에는 Sidebar가 없다.
- 모든 Business·People·Collaboration·Control Center App은 같은 Desktop Sidebar 계약을 사용한다.
- 기본은 Expanded, 사용자가 접으면 Compact Icon Rail이 되며 본문은 남은 폭을 즉시 사용한다.
- 상태는 `tenantId:userId` 범위로 저장되어 다른 App으로 이동해도 유지된다.
- Compact Rail에서도 모든 허용 메뉴에 Icon, Tooltip, 선택 상태와 Badge를 제공한다.
- `lg` 미만에서는 축소 Rail을 사용하지 않고 Modal Drawer로 열어 본문 폭을 보존한다.
- Tenant가 Appearance Policy로 Rail 또는 Top Navigation을 강제하면 사용자 Toggle보다 우선한다.
- Toggle은 `aria-controls`, `aria-expanded`, 다국어 Label과 40px Hit Target을 제공한다.

## 5. 근거와 모범사례

- [Microsoft Viva Connections Dashboard](https://learn.microsoft.com/en-us/viva/connections/create-dashboard): 관리자가 Card와 Audience를 게시하고 사용자는 자신의 Dashboard 순서·표시만 조정한다.
- [Viva Connections Audience Targeting](https://learn.microsoft.com/en-us/viva/connections/use-audience-targeting-in-viva-connections): 역할·Group을 기반으로 관리형 콘텐츠를 선별한다.
- [Apple Home Screen 구성](https://support.apple.com/en-us/108307): Long press, Drag, App 겹침 Folder 생성의 익숙한 개인 편집 모델을 제공한다.
- [Apple App Library](https://support.apple.com/en-us/108324): 시스템 분류와 개인 Home 노출을 분리하고 Home에서 제거해도 App 자체는 유지한다.
- [Carbon UI Shell Left Panel](https://carbondesignsystem.com/components/UI-shell-left-panel/usage/): 제품 전반에 일관된 Shell과 축소 가능한 Left Navigation을 적용한다.

## 6. 확장 원칙

향후 Audience별 Tenant 기본 배치가 필요하면 `placements`에 별도 Targeting Rule ID를 추가하고
기존 사용자 Layout Schema는 유지한다. Device별 기본값, 추천 영역, AI 배치 제안도 관리형 정책의
새 Schema Version으로 확장하며, AI가 직접 게시하지 않고 변경안·영향 범위·승인·감사 절차를 거친다.
