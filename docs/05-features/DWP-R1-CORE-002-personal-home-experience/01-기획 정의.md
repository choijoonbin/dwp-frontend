# DWP-R1-CORE-002 기획 정의

## 1. 문제

로그인 직후부터 업무 Sidebar를 노출하면 개인이 사용할 수 있는 전체 앱과 오늘의 정보를
조망하기 전에 특정 Navigation 구조를 강요한다. Tenant별 브랜드 이미지를 Source에 직접
교체하는 방식은 고객별 Delivery와 운영 감사를 지원하지 못한다.

## 2. 목표

- 로그인 후 첫 화면을 Sidebar 없는 개인 Home으로 제공한다.
- 권한이 부여된 앱만 목적별로 보여주고 실행 시 업무 Shell로 전환한다.
- Product Mark로 언제든 Home에 복귀한다.
- 사용자 이름·직책·Avatar와 알림을 분리된 Header 계층으로 제공한다.
- Tenant 관리자가 Home 문구, 배경, 위치와 Overlay를 관리한다.
- Tenant 회사 로고와 DWP Product Mark를 공동 브랜드 Lockup으로 제공한다.
- 사용자가 허용된 Widget의 표시·순서를 편집하고 서버에 저장한다.
- 관리자가 공지를 작성·게시·예약·대상화하고 Home에 필수 노출한다.

## 3. 포함 범위

- Desktop·Mobile Personal Home Shell
- Entitlement 기반 App Group, Reorder, Folder와 비 Drag 대체 조작
- Daily Brief, Focus, Schedule, Activity Reference 영역
- 공지, 사용자 Home Editor와 서버 저장 Personalization
- Tenant Organization Name·Logo와 Header Co-branding
- Admin Home Presentation 조회·수정·이미지 업로드·기본값 복원
- Admin Branding과 Announcement 작성·게시·보관
- Local Asset Storage, Metadata, Version, Audit와 향후 S3 Port

## 4. 제외 범위

- 자유 크기 Widget Builder, 임의 외부 Script와 사용자가 만든 HTML
- Tenant별 임의 Font·Navigation·전체 Theme 편집기
- 운영 S3, CDN, Malware Scanner
- 실제 Mail·Calendar·Workflow Connector 데이터

## 5. 핵심 정책

- Entitlement가 없는 App은 DOM과 Route 모두에서 노출하지 않는다.
- Tenant 설정은 모든 사용자에게 적용되고 개인 순서·Folder는 그 아래 우선순위다.
- 공지처럼 관리자가 고정한 Widget은 사용자가 숨길 수 없다.
- 사용자 설정은 등록된 App·Widget ID와 Versioned Layout Schema만 저장한다.
- 회사 로고는 DWP를 대체하지 않고 `Tenant logo | DWP mark + Digital Workplace` 순서로
  공동 표시한다.
- 이미지가 없거나 조회에 실패해도 Built-in Background와 Home 기능은 유지한다.
- Admin 설정 변경은 낙관적 Version과 Audit Event를 남긴다.
