# 07. 수용 테스트

## 1. 완료 정의

다음 항목을 모두 통과하기 전에는 `Enterprise Messenger 완성`으로 표시하지 않는다. 화면이
보이거나 Seed Message가 전송되는 것만으로 완료 처리하지 않는다.

## 2. 기능 수용 기준

### 1:1과 그룹 대화

- 같은 두 사용자가 어느 화면에서 시작해도 하나의 1:1 DM을 재사용한다.
- 동시 생성 Request가 와도 Unique Fingerprint와 Idempotency로 중복 대화가 생기지 않는다.
- 비활성·다른 Tenant·검색 불가 사용자는 대화 대상으로 추가되지 않는다.
- 그룹 구성원 추가·제거와 History Policy가 API와 검색에 동일하게 적용된다.

### Space 대화

- Space Membership Event가 `MIRRORED` 채널에 반영된다.
- `SCOPED_SUBSET`에 Space 비구성원을 넣을 수 없다.
- Space 탈퇴 후 전송, History, 검색, 파일, WebSocket 구독이 모두 차단된다.
- Event 중복, 지연, 순서 역전 후에도 Inbox와 Reconciliation으로 정합성이 회복된다.
- Space 삭제·Archive 정책이 연결 대화의 상태로 전파된다.

### Message와 Thread

- 성공 응답한 메시지는 재시작·Kafka 장애 후에도 History에 남는다.
- 동일 Idempotency Key 재시도는 같은 Message를 반환한다.
- 다른 Payload로 같은 Key를 쓰면 `409`를 반환한다.
- 편집 Window, 삭제 정책, Moderator 조치, Retention 삭제가 구분된 상태로 표시된다.
- Thread, Reaction, Mention, Quote가 Message 삭제와 권한 변경을 안전하게 처리한다.
- 긴 한글·영문, Code, Link, Mention, Emoji, IME 전송을 검증한다.
- 멘션 대상 ID와 Snapshot이 메시지에 구조화되어 저장되고 동명인·표시명 변경에서도 알림 대상이 바뀌지 않는다.
- `@모두`·`@everyone`은 Owner·Moderator만 사용하며, 일반 구성원의 조작된 API 요청도 거부한다.
- 전송 완료 응답 전에 다음 메시지를 입력해도 새 초안을 초기화하지 않는다.

### 읽음과 실시간

- 읽음 Cursor는 뒤로 이동하지 않는다.
- Reconnect 시 마지막 Sequence 이후 Event만 복구하고 중복을 표시하지 않는다.
- Offline 전송은 Pending→Committed 또는 Failed로 명확히 전환된다.
- 느린 Client가 Gateway 메모리를 무한 증가시키지 않는다.
- Presence·Typing 유실이 Durable Message에 영향을 주지 않는다.
- 같은 사용자의 다중 Tab·기기에서 Cursor와 Draft가 충돌 없이 합쳐진다.

### 검색

- 현재 Membership과 `history_start_sequence` 밖의 결과를 반환하지 않는다.
- Space 탈퇴와 Message 삭제 후 Stale OpenSearch Hit도 최종 ACL 재검증에서 제거된다.
- Search Index 장애 중 메시지 송수신은 정상 동작한다.
- 복구 후 Tombstone과 누락 문서를 Reconciliation한다.

### 파일

- 검사 전 파일은 누구도 다운로드할 수 없다.
- 확장자 위장, 잘못된 MIME, Malware, Archive Bomb, 정책 초과 파일을 차단한다.
- 차단된 파일이 Preview·검색·Notification에 노출되지 않는다.
- File Retention과 Legal Hold가 Message 수명주기와 일치한다.
- 업로드 Token 경합에서 승자 Object가 패자 요청에 의해 덮어쓰기·삭제되지 않는다.
- `Content-Length` 누락, 배포 절대 한도 초과, 선언 크기 불일치 요청은 저장 전에 차단한다.
- Scanner·Object Storage 실패 후 남은 격리 Object는 즉시 삭제하거나 만료 Job이 재처리한다.
- 전송 전 제거·대화 이동·페이지 이탈로 버린 파일은 작성자 Scope에서 폐기된다.
- 다운로드 Grant는 1회 소비, 만료, 다른 사용자·대화 재사용을 모두 거부한다.
- 다운로드 직전에 Size와 SHA-256 무결성을 다시 검증한다.

## 3. 권한과 보안 수용 기준

- `WORKSPACE_MEMBER`는 `APP.MESSAGING` 없이는 Route와 API를 사용할 수 없다.
- Messaging Admin은 대화 본문, Draft, 검색 Query, 파일명을 조회할 수 없다.
- Compliance Officer는 승인 Case, Scope, 기간, 사유 없이는 본문을 검색할 수 없다.
- Tenant Admin에게 Messaging Admin·Compliance 권한이 자동으로 나타나지 않는다.
- Provider Support는 Tenant 본문과 Compliance Export를 조회할 수 없다.
- Forward, Quote, Action Capsule은 원문과 대상 객체 권한을 다시 확인한다.
- IDOR, Tenant Header 변조, Conversation ID 추측, WebSocket 재구독을 차단한다.
- WebSocket Ticket 재사용, 만료, 잘못된 Origin, 다른 Device 사용을 차단한다.
- Link Preview SSRF, DNS Rebinding, Unsafe Redirect, IDN Spoofing을 테스트한다.
- Log와 Trace에 Message Body, Draft, Attachment Name, Search Query 원문이 남지 않는다.

## 4. 관리자 수용 기준

- 운영 Dashboard는 Payload 없는 SLO·Lag·오류·저장량만 표시한다.
- Retention 변경은 적용 전 Dry Run과 예상 영향을 제공한다.
- 보존 기간 단축과 Hold 해제는 정책상 Dual Approval을 수행한다.
- App/Bot은 승인 Scope 밖 Message를 읽거나 쓸 수 없다.
- DLQ 재처리는 Event ID, Schema, Correlation, 결과를 감사한다.
- 관리자 화면에서 연결되지 않은 Search, DLP, WORM, AI를 정상으로 표시하지 않는다.

## 5. UI/UX 수용 기준

- Desktop 1440·1920, Laptop 1280, Tablet 1024·768, Mobile 390·360을 검증한다.
- Context Pane이 좁은 화면에서 본문을 비정상적으로 밀거나 Composer를 가리지 않는다.
- 긴 이름, 긴 Space명, 99+ Badge, 다국어, 200% Zoom에서 겹침이 없다.
- Message Stream Scroll Anchor가 과거 Loading, Image Load, 편집·삭제 후 유지된다.
- Keyboard만으로 새 대화, 검색, 전송, Reply, Reaction, Thread, 닫기를 수행한다.
- 이모티콘·업무 표현 피커는 검색·분류·최근 사용·키보드 탐색을 제공하고 한·영 툴팁이 현재 언어와 일치한다.
- 멘션 추천은 이름, 직책, 조직, Presence를 표시하고 Arrow·Enter·Escape로 조작할 수 있다.
- 회의 대기 상태는 불필요한 빈 공간 없이 표시되고, 장치 점검·실제 회의실·종료 이력으로 단계적으로 확장된다.
- Screen Reader가 새 메시지를 폭주해 읽지 않고 요약 신호를 제공한다.
- Reduced Motion에서 이동 Animation 없이 모든 기능을 사용할 수 있다.
- Focus Ring, Contrast, Touch Target이 WCAG 2.2 AA를 충족한다.
- Light·Dark 또는 Tenant Theme가 도입돼도 상태 의미가 유지된다.

## 6. 성능과 신뢰성 수용 기준

### 목표 Latency

- Message Commit: p95 250ms 이하, p99 500ms 이하
- Online Fanout: Commit 후 p95 500ms 이하, p99 1.5초 이하
- 첫 History Page: p95 200ms 이하
- Search: p95 800ms 이하
- Search Index Lag: p95 5초 이하

### Wave 0 기준 부하 Profile

이는 용량 약속이 아니라 첫 Architecture Gate다.

- 동시 WebSocket 20,000
- 15분 Burst 1,000 Message/sec
- 1억 건 Synthetic Message History
- Hot Conversation 200 Message/sec
- 사용자당 2,000 접근 가능 Conversation의 검색 ACL
- Gateway Pod 강제 종료와 Kafka·Redis·OpenSearch 부분 장애

목표 고객 규모가 이 Profile을 넘으면 수치를 먼저 상향하고 아키텍처를 재검증한다.

### 장애 테스트

- PostgreSQL Failover 중 성공·실패 경계와 중복 없음
- Kafka 중단 시 Commit 유지, 복구 후 Outbox Catch-up
- Redis 중단 시 Presence·Typing 저하, REST History 정상
- OpenSearch 중단 시 검색만 Degraded
- Gateway Rolling Deploy 중 Connection Drain과 Resume
- Object Scanner 지연 시 Quarantine 유지

## 7. 보존과 Compliance 수용 기준

- Tenant·유형·분류별 Retention 우선순위를 검증한다.
- Hold 대상 Message와 Revision은 사용자 삭제·Retention Job으로 제거되지 않는다.
- Hold 종료 후 기존 정책에 따라 삭제 시점을 재계산한다.
- Export Manifest Hash, Object Version, Watermark, 행위자, 사유를 검증한다.
- 사용자 화면 삭제와 Compliance 보존의 차이를 감사 가능하게 유지한다.
- Partition Drop 전에 Hold·미만료 Row가 없음을 검증한다.

## 8. AI 확장 수용 기준

AI가 활성화되는 단계에서만 적용한다.

- Summary가 접근 가능한 Message ID를 문장 단위로 인용한다.
- 다른 Tenant·대화·History 범위의 문맥을 가져오지 않는다.
- Message 안 Prompt Injection이 Tool·권한을 바꾸지 못한다.
- 자동 발송, 자동 휴가, 자동 일정, 자동 초대를 거부한다.
- 근거 삭제·권한 해지 시 파생 Insight가 무효화된다.
- AI 장애가 Message 전송, History, 검색의 기본 기능을 막지 않는다.

## 10. Seed와 실제 데이터

- Frontend Source에 Message Mock 배열을 두지 않는다.
- SKAX 개발 Tenant의 활성 구성원, Space, Calendar Event를 참조해 Backend Seed를 만든다.
- Seed는 실제 개인정보 문장 대신 명확히 Synthetic한 업무 대화를 생성한다.
- 사용자·Space·권한·보존 정책과 Message Membership이 서로 일치해야 한다.
- Seed 전용 계정과 Production Migration을 분리하고 Production Profile에서는 Seed를 실행하지 않는다.
