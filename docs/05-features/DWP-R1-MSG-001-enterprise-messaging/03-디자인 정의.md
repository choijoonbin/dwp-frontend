# 03. 디자인 정의

## 1. 디자인 방향

`조용하지만 빠르고, 밀도는 높지만 복잡하지 않은 업무 대화`를 목표로 한다. Slack의 색과
구조를 모사하지 않고 DWP Design Token, MUI Theme, 공통 Button·Form·Dialog·State 계약을
사용한다.

### 시각 원칙

- 화면 전체를 Card로 나누지 않고 Panel 경계와 여백으로 구조를 만든다.
- Card는 App Capsule, 파일, 반복 항목처럼 실제로 프레임이 필요한 객체에만 사용한다.
- Border Radius는 8px 이하를 기본으로 한다.
- Header·Sidebar·본문을 단일 Hue로 칠하지 않는다.
- 대화 본문은 중립 Surface, Action과 Focus만 DWP Accent를 사용한다.
- Unread, Mention, Restricted, Failed는 의미별 색을 사용하고 색 외 Label을 함께 둔다.
- Hero Type과 큰 KPI를 사용하지 않는다.

## 2. 현재 기술과 추가 후보

현재 Frontend는 React 19.2, MUI 7.3, TanStack Query 5, Zustand 5, React Router 7,
Lucide, `dnd-kit`을 사용한다. 이 기반을 교체하지 않는다.

| 영역                   | 선택                        | 이유                                         |
| ---------------------- | --------------------------- | -------------------------------------------- |
| Server State           | TanStack Query              | History·Home·Search Cache와 재검증           |
| Ephemeral UI           | Zustand 또는 지역 State     | 열린 Panel, Draft UI, Command Palette        |
| Icons                  | Lucide                      | 기존 시스템 일관성, Tooltip 계약             |
| Section DnD            | 기존 `dnd-kit`              | Keyboard Sensor와 기존 의존성 재사용         |
| Composer               | Lexical                     | Messaging용 확장성, 접근성, 성능, React 연동 |
| Message Virtualization | `react-virtuoso` Core Spike | 가변 높이, 양방향 Loading, MIT Core          |
| Realtime               | Native WebSocket Adapter    | 낮은 의존성, Protocol 직접 통제              |

상용 `@virtuoso.dev/message-list`는 Chat 전용 Scroll 기능이 우수하지만 Commercial License다.
R1 Spike에서 MIT Core로 10만 개 혼합 높이 메시지, 역방향 Pagination, Image Resize, 삭제·삽입,
Scroll Anchor를 통과하지 못한 경우에만 구매를 검토한다. UI는 `MessageViewport` Adapter 뒤에
두어 구현체를 바꿀 수 있게 한다.

## 4. 메시지 콘텐츠 계약

Lexical Editor State를 그대로 서버 원장으로 저장하지 않는다. Composer는 전송 전에 DWP의
Versioned Content Schema로 변환한다.

```json
{
  "version": 1,
  "blocks": [
    {
      "type": "paragraph",
      "children": [
        { "type": "text", "text": "검토 부탁드립니다. " },
        { "type": "mention", "personPublicId": "...", "label": "김민서" }
      ]
    }
  ]
}
```

- 허용 Block과 Mark만 서버가 검증한다.
- HTML, Inline Script, 임의 Style, 외부 Embed를 저장하지 않는다.
- Mention Label은 표시 Snapshot이고 권한·알림 대상은 안정 ID로 판정한다.
- Link는 원문 URL과 안전 판정 Metadata를 분리한다.
- App Capsule은 자유 JSON이 아니라 App Manifest에 등록된 Versioned Schema를 사용한다.

## 5. 키보드 경험

| 입력         | 동작                                     |
| ------------ | ---------------------------------------- |
| `Cmd/Ctrl+K` | 검색·명령 팔레트                         |
| `Cmd/Ctrl+N` | 새 대화                                  |
| `Alt+↑/↓`    | 이전·다음 대화                           |
| `R`          | 선택 메시지 Reply, 입력 중에는 문자 입력 |
| `E`          | 내 메시지 편집                           |
| `S`          | 나중에 저장                              |
| `Esc`        | Menu→Thread→Overlay 순서로 닫기          |
| `Enter`      | Row 열기 또는 설정에 따른 전송           |

Shortcut는 Focus Context를 확인하고 입력 중 전역 명령을 가로채지 않는다. 모든 IconButton에
Tooltip과 접근 가능한 이름을 제공한다.

## 6. 상호작용과 Motion

- Panel: `160~200ms`, opacity + 8px 이하 이동
- Reaction: `120~160ms`, Scale은 최대 1.06
- 새 메시지: 위치가 정해진 뒤 짧은 Fade, 기존 행을 밀어내는 과장된 Animation 금지
- Pending→Sent: 상태 Icon의 색·형태만 전환
- Typing: 3점 무한 Animation 대신 이름과 정적인 `입력 중`을 우선하고 Motion을 절제
- Drag: 선택 항목만 1~2px Elevation, 주변 Layout은 고정
- `prefers-reduced-motion`에서는 이동·흔들림 없이 상태를 즉시 전환

## 7. 접근성

- WCAG 2.2 AA Color Contrast와 200% Zoom을 충족한다.
- 메시지 Stream을 하나의 무한 `aria-live`로 두지 않는다. 새 메시지 수를 한 번 요약하고 사용자가
  `최신으로 이동`할 때 읽게 한다.
- Virtualized Row가 DOM에서 사라져도 현재 Focus가 유실되지 않게 Roving Focus를 관리한다.
- 날짜, 발신자, 수정, Thread, Reaction을 Screen Reader가 순서 있게 읽는다.
- Presence와 Delivery State를 색 외 텍스트로 제공한다.
- IME 조합 중 Enter로 전송하지 않는다.
- 한글·영문·긴 이메일·URL·CJK 줄바꿈과 RTL/Bidi 안전 표시를 검증한다.

## 8. 성능 설계

- 초기 Bundle에서 Admin, Compliance, Rich Format Plugin을 Lazy Load한다.
- Message Row는 안정 Key와 Memoized Selector를 사용한다.
- History는 Cursor 기반으로 앞쪽을 Load하고 Scroll Anchor를 보존한다.
- Image 크기를 Metadata로 먼저 예약해 Load 후 Layout Shift를 막는다.
- Presence Update는 화면에 보이는 사용자만 구독하고 Batch한다.
- Read Cursor는 Scroll 중 매 Event를 보내지 않고 의미 있는 경계로 Throttle한다.
- 검색 입력은 Deferred Query와 취소 가능한 Request를 사용한다.
- WebSocket Event는 Normalized Cache에 적용하고 모든 Query를 무효화하지 않는다.

## 9. 금지할 UI 패턴

- 모든 메시지를 큰 좌우 말풍선으로 표시
- Hover에서만 가능한 필수 Action
- 읽지 않음 숫자만 큰 KPI로 강조
- Context Pane을 열 때 항상 본문 폭을 강제로 축소
- Toolbar를 아이콘으로 빽빽하게 채우고 Tooltip을 생략
- 관리자 화면에 사용자 메시지 Preview 표시
- 연결되지 않은 AI·Provider 기능을 활성 상태로 표시
- 카드 안의 카드, 과한 Glassmorphism, 배경 Gradient Orb
