# 02. 화면 설계서

## 1. 화면 구조 원칙

메신저는 실제 업무 화면으로 시작한다. 마케팅 Hero나 큰 장식형 Dashboard를 만들지 않는다.
Global Header 아래에서 Messenger Navigator, Conversation, Context의 세 영역을 사용한다.
기존 Product Sidebar와 별도 Conversation Sidebar를 중복해 네 겹 Navigation을 만들지 않는다.

```text
┌──────────────────────────── Global Header ────────────────────────────┐
│  Messenger Navigator  │        Conversation / Home       │ Context   │
│  264px                 │        min 520px, flexible       │ 380px     │
│  Home / Activity       │        header                    │ thread    │
│  DM / Space sections   │        virtual message stream    │ details   │
│  recent conversations  │        composer                  │ files     │
└───────────────────────────────────────────────────────────────────────┘
```

- Navigator: `248~288px`, 사용자가 조절 가능하되 범위를 고정한다.
- Context Pane: `360~420px`, 필요할 때만 열고 1280px 이하에서는 Overlay로 표시한다.
- Conversation: 최소 `520px`; 텍스트 열은 읽기 폭을 제한하되 메시지 영역 전체를 Card로 감싸지 않는다.
- Panel Resize는 키보드 조작과 Reset을 제공한다.

## 2. 메신저 홈

`/messages/home`은 모든 대화를 나열하지 않고 지금 처리할 흐름을 제공한다.

### 상단

- 제목 `메신저`
- 연결 상태와 마지막 동기화는 오류·복구 중일 때만 노출
- `새 대화`, `검색`, `Cmd/Ctrl+K`
- 큰 KPI Card나 장식용 그래프는 사용하지 않음

### 주의 필요

한 행 기반 Queue로 표시한다.

- 직접 멘션
- 내 답변을 기다리는 Thread
- 내 담당 Action Capsule
- 오늘 마감인 결정·업무
- Restricted/External 안전 신호

각 항목은 `왜 우선인지`를 1개의 짧은 Label로 설명한다. AI가 없더라도 명시적 Event로 완전하게
동작해야 한다.

### 이어서 보기

- 최근 활성 DM과 채널
- 작성 중인 Draft
- 예약 발송
- Snooze가 끝난 Later
- 회의 시작 전·후 이어지는 대화

### 내 Space 대화

Space 이름, 목적, 접근 출처, 읽지 않음, 최근 결정만 표시한다. App Home 안에 Space Card를
중첩하지 않고 Section Row로 구성한다.

## 3. Navigator

### 고정 영역

- 홈
- 활동
- Thread
- 나중에
- 파일

### 대화 영역

- 다이렉트 메시지
- Space 대화
- 사용자 정의 섹션

섹션은 접기·펼치기와 `dnd-kit` 기반 재정렬을 지원한다. Drag Handle은 Hover와 Keyboard Focus
때 나타나며, Drag 중에도 Unread Badge 크기가 Layout을 밀지 않게 고정 폭을 사용한다.

대화 Row에는 Avatar/Icon, 이름, 짧은 Preview, 시각, Unread/Mention, Mute를 표시한다.
Presence는 색만으로 전달하지 않고 접근 가능한 상태 이름을 제공한다.

## 4. 대화 화면

### Conversation Header

- 대화명, 유형, Space/Meeting 연결 출처
- 구성원 수 또는 1:1 상대의 직책·상태
- Search, Meeting, Pin, Details IconButton
- Restricted, External, Retention 정책은 위험이 있을 때만 명확한 Badge로 표시

### Message Stream

채널과 업무 대화는 모바일 메신저식 좌우 말풍선보다 좌측 정렬 Grouped Message Row를 사용한다.
긴 코드, 표, 업무 카드, Thread가 많은 엔터프라이즈 대화에서 가로 공간과 스캔 효율이 더 좋다.

- 같은 발신자의 연속 메시지는 Avatar와 이름을 묶는다.
- 날짜, 새 메시지, 이력 시작점 Marker를 Sticky하게 제공한다.
- Hover Toolbar는 Reaction, Reply, Save, More를 제공한다.
- Keyboard Focus에서도 같은 Action을 사용할 수 있다.
- 수정·삭제·정책 삭제는 각각 상태 문구가 다른 Tombstone을 사용한다.
- 실패한 내 메시지는 Stream 안에서 재전송·편집을 제공한다.
- Thread Reply Count, 최근 참여자, 미확인 표시를 한 줄로 제공한다.

### Context Pane

하나의 Panel이 다음 Mode를 전환한다.

- Thread
- 대화 정보와 구성원
- Pins와 Decisions
- Files와 Links
- 연결된 Space·Meeting·업무 객체

Desktop 넓은 화면에서는 본문 옆에 열리고, 좁은 Desktop과 Tablet에서는 본문 위 Overlay,
Mobile에서는 전체 화면 Sheet로 연다. 열릴 때 본문을 항상 380px 밀어 Layout Shift를 만들지 않는다.

## 5. Composer

- 기본 상태는 낮은 높이의 단정한 입력 면이며 내용에 따라 정해진 최대 높이까지 확장한다.
- Lexical 기반 Mention, Link, List, Quote, Code, Emoji를 제공한다.
- 첨부, 서식, Emoji, Schedule, Quick Action은 익숙한 IconButton과 Tooltip을 사용한다.
- `Enter` 전송, `Shift+Enter` 줄바꿈은 개인 설정 가능하고 현재 설정을 Composer 도움말에서 확인한다.
- `@`는 People·Group, `/`는 승인된 Command, `+`는 파일·업무 객체를 연다.
- 전송 전 DLP 차단은 입력을 잃지 않고 이유, 수정, 관리자 문의 경로를 제공한다.
- 파일은 Upload, Scan, Ready, Blocked 상태를 Composer 안에서 표시한다.
- 예약 발송은 사용자의 Timezone과 절대 시각을 함께 확인한다.

## 6. 새 대화와 People 검색

`새 대화`는 중앙 Modal이 아니라 Navigator 위 Command Surface로 열어 맥락을 유지한다.

- 이름, 회사 이메일, 조직, 직책 검색
- 최근 연락, 같은 Space, 같은 조직을 보조 그룹으로 제공
- 동명이인은 이메일, 조직, 직책을 함께 표시
- 비활성, 휴직, 외부 사용자는 상태와 정책을 표시
- 선택한 사람이 많아지면 Token Wrap과 가상 목록을 사용
- 1:1은 기존 대화를 재사용하고 그룹은 제목을 나중에 설정할 수 있음

## 7. Space 연결 화면

Space 상세의 `대화` Tab은 새 UI를 복제하지 않고 `/messages/spaces/:spaceKey/:conversationKey`로
Deep Link한다. 메신저 Header에는 Space Breadcrumb와 `Space 열기`가 있다.

Membership 설명 예시:

```text
프로젝트 Atlas Space 구성원 자격으로 참여 중 · 2026-08-10부터 이력 열람
```

부분 채널 생성 시 대상은 현재 Space 구성원으로 제한한다. Space를 나간 사용자는 즉시 입력이
잠기고 `접근 권한이 변경되었습니다` 상태로 전환한다.

## 8. Meeting Continuity

Calendar Event 상세에 `대화`를 제공하고 다음 수명주기를 유지한다.

- 회의 전: Agenda, 자료, 질문
- 회의 중: Link, Note, 결정, Action
- 회의 후: Follow-up, Recording Reference, 미완료 Action

회의 참석자와 채팅 구성원이 항상 같다고 가정하지 않는다. Organizer 정책과 참석자 변경 Event를
통해 Membership을 투영하고, 외부 참석자는 R1에서 자동 포함하지 않는다.

## 9. 관리자 화면

### 운영 개요

- 성공률, Commit/Fanout Latency, 연결 수, Kafka/Search Lag, DLP Queue
- Tenant 총 메시지·저장량은 집계만 제공
- 사용자별 대화명·Preview·본문을 표시하지 않음

### 정책

- 대화 생성, 편집·삭제 Window, Read Receipt, Presence, `@all`, 파일, Link Preview
- 변경 전 영향 범위와 기존 설정 Diff
- 고위험 변경은 사유와 승인 정책 적용

### 보존 및 Hold

- 정책 Version, 적용 Scope, 예상 삭제량, Dry Run
- Retention 단축은 경고와 Dual Control
- Compliance Case는 별도 Role과 Watermarked Export

### Integrations

- App/Bot Manifest, Publisher, Scope, 설치 대상, Secret Reference, 상태
- 과도한 Scope와 미사용 App 경고
- Webhook Payload Sample에 실제 본문을 노출하지 않음

### 운영 진단

- Outbox/Inbox, DLQ, Projection Lag, Search Tombstone, Membership Drift
- Correlation ID 기반 재처리
- 운영 Log에서 본문·첨부명·개인 Draft를 제외

## 10. 반응형

| 폭          | 동작                                                               |
| ----------- | ------------------------------------------------------------------ |
| 1440px 이상 | Navigator + Conversation + 선택적 Context                          |
| 1024~1439px | Navigator 축소 가능, Context Overlay                               |
| 768~1023px  | Navigator와 Conversation 2단, Thread Sheet                         |
| 767px 이하  | 목록→대화 Push Navigation, Composer Safe Area, Context Full Screen |

Mobile Back은 작성 Draft를 보존한다. Virtual List의 Scroll Position은 대화별로 기억하고,
Deep Link로 들어온 메시지는 주변 문맥을 함께 로드한다.

## 11. 필수 상태

- Loading Skeleton, Empty, Error, Permission Denied
- Offline, Reconnecting, Degraded, Resuming
- Pending, Sent, Failed, Retrying
- Message Deleted, Retention Deleted, Moderation Hidden
- Membership Revoked, History Starts Here, Conversation Archived
- File Scanning, Blocked, Expired
- Search Indexing Delay와 결과 재검증 실패

각 상태는 색만으로 구분하지 않고 사용자가 취할 다음 행동을 제공한다.
