# 01. 기획 정의

## 1. 제품 목표

사용자가 `누구와 대화할지`보다 `어떤 일을 끝내야 하는지`를 먼저 파악하고, 대화의 맥락과
권한을 잃지 않은 채 DWP의 업무 앱으로 연결되게 한다.

### 성공 조건

- 사람·Space·업무 객체를 한 검색 흐름에서 찾는다.
- 멘션, 답변 요청, 내 담당, 마감이 있는 대화를 설명 가능하게 우선한다.
- Space 탈퇴나 계정 비활성화가 검색과 실시간 구독에도 빠르게 반영된다.
- 메시지에서 만든 업무가 원본 대화와 양방향 상태 링크를 유지한다.
- 관리와 규정 준수를 제공하되 일반 운영자가 개인 대화를 들여다볼 수 없다.

## 2. 사용자와 역할

| 사용자             | 주요 작업                                  | 허용 범위           |
| ------------------ | ------------------------------------------ | ------------------- |
| 구성원             | DM, Space 채널, 검색, 파일, Thread, Later  | 자신이 참여한 대화  |
| 대화 Owner         | 주제, 구성원, 채널 설정, Moderator         | 해당 대화           |
| Space Owner        | Space 연결 채널 Template과 부분 채널 운영  | 소유 Space          |
| Moderator          | 공지, Reply 제한, 신고·부적절 콘텐츠 조치  | 위임된 대화         |
| Messaging Admin    | Tenant 정책, 운영 상태, Template           | 본문 제외 Metadata  |
| Integration Admin  | Bot, App, Webhook, Scope, Secret Reference | 승인된 Integration  |
| Compliance Officer | Hold, Case Search, Export                  | 승인된 Case 범위    |
| AI Admin           | 모델 공급자, 허용 분류, 기능·지역 정책     | AI 설정과 사용 통계 |

Messaging Admin과 Compliance Officer는 분리한다. Tenant Admin이라는 이유만으로 두 역할을
자동 부여하지 않는다.

## 3. 핵심 사용자 여정

### 사람과 대화

1. `새 대화` 또는 `Cmd/Ctrl+K`를 연다.
2. People Directory에서 이름, 이메일, 조직, 직책으로 검색한다.
3. 사용자 상태와 외부·비활성 여부를 확인한다.
4. 기존 1:1 DM이 있으면 재사용하고 없으면 결정적으로 생성한다.
5. 권한·정책상 대화할 수 없으면 이유와 허용 경로를 표시한다.

### Space와 대화

1. Space 화면의 `대화` Tab 또는 메신저의 Space 섹션을 연다.
2. Space 전체 채널과 자신이 포함된 부분 채널을 확인한다.
3. 멤버십 출처와 이력 시작점을 확인한다.
4. Space 탈퇴 시 해당 채널 접근과 검색 결과가 함께 폐기된다.

### 대화에서 업무 완료

1. 메시지 Action에서 `업무로 전환`, `일정 제안`, `결정으로 기록`, `결재 요청`을 선택한다.
2. DWP는 원문 링크, 대상, 기한 후보를 미리 채운 Preview를 연다.
3. 대상 앱이 현재 권한과 필수 입력을 다시 확인한다.
4. 생성된 객체의 상태가 대화에 안전한 Capsule로 갱신된다.

## 5. 대화 유형

| 유형           | 용도                      | 기본 Membership            |
| -------------- | ------------------------- | -------------------------- |
| `DIRECT`       | 결정적 1:1 DM             | 두 사용자                  |
| `GROUP`        | 소규모 일회성 그룹        | 직접 추가                  |
| `CHANNEL`      | 지속형 주제·프로젝트 대화 | Space 또는 직접 관리       |
| `ANNOUNCEMENT` | 관리자·Owner 중심 공지    | 읽기 중심, Reply 정책      |
| `INCIDENT`     | 장애·위기 대응            | Space Incident Template    |
| `MEETING`      | 회의 전·중·후 지속 대화   | Calendar Event 참석자 정책 |

대규모 전사 공지는 Communications App이 원장이다. 메신저 Announcement는 상호작용이 필요한
팀·Space 공지에 사용하고 전사 News를 중복 생산하지 않는다.

## 6. Space Membership Mode

- `MIRRORED`: 활성 Space 구성원이 자동 포함된다.
- `SCOPED_SUBSET`: Space 구성원 중 명시된 하위 집합만 포함된다.
- `DIRECT`: Space에 연결되지만 채널 Owner가 직접 관리한다. Tenant 정책이 허용한 경우만 쓴다.

기본값은 `MIRRORED`다. 부분 채널은 `SCOPED_SUBSET`이며 Space 비구성원을 추가할 수 없다.
외부 사용자는 R1에서 지원하지 않는다.

## 7. 기능 우선순위

### R1 필수

- 1:1·그룹·Space 채널, 공지
- Message, Thread, Reaction, Mention, 인용, 안전한 Link
- 편집·삭제 정책, 임시 저장, 예약 전송
- 읽음 Cursor, Unread Marker, Presence, Typing
- Activity, Later, 검색, 파일
- People·Space·Calendar·Notification 연동
- 관리자 정책, 운영, 기본 보존, 감사
- 실패 재전송, Offline, Reconnect, Access Revoked 상태

### R2 생산성

- 사용자 정의 Sidebar 섹션과 DnD
- Decision Trail, Action Capsule, 업무 상태 동기화
- Meeting Continuity와 외부 회의 Provider 연결
- Bot, App Card, Slash Command, 승인된 Webhook
- 신고, Moderator Queue, DLP 정책 고도화

### R3 엔터프라이즈 확장

- 외부 Tenant Shared Conversation과 양측 보존 정책
- eDiscovery, Legal Hold, Migration/Import, Data Residency
- Customer-managed Key와 제한형 Confidential Conversation
- 인용 기반 AI Summary, Recap, Translation, Action Proposal

## 8. 알림 원칙

- 온라인 실시간 Event와 Notification은 별개다.
- DM, Mention, 답변 요청만 기본 Interactive Intent를 발행한다.
- 사용자가 이미 해당 대화를 보고 읽음 Cursor가 전진하면 대기 알림을 취소한다.
- `@all`과 대규모 알림은 권한, 업무 시간, 빈도 제한을 적용한다.
- Digest와 Quiet Hours는 Notification Platform이 소유한다.
- 메신저의 Unread Count가 원장이며 Notification 읽음과 자동으로 동일시하지 않는다.

## 9. 비목표

- 음성·영상 SFU, 녹화, 전화망을 직접 구현하지 않는다.
- Mail 내부 댓글을 메시지 DB로 옮기지 않는다.
- Space 콘텐츠, 결재, 일정, 업무 객체를 메시지 JSON에 복제하지 않는다.
- 조직 단위 변경만으로 전사 규모 그룹 DM을 자동 생성하지 않는다.
- AI 점수만으로 사용자의 메시지를 숨기거나 우선순위를 강제하지 않는다.
