## 2. 화면과 상호작용 결정

1. 1280px 업무 화면은 목록과 대화의 2개 Pane을 기본으로 하고, 충분한 폭의 `xl`에서만 구성원·정책
   Context Pane을 함께 표시한다.
2. 모바일은 한 번에 하나의 작업 표면만 표시하며 Composer와 Thread 닫기 동작을 항상 Viewport 안에 둔다.
3. Enter는 전송, Shift+Enter는 줄바꿈으로 사용하고 한글 IME 조합 중 Enter는 전송하지 않는다.
4. Composer와 Reaction은 검색, 분류, 최근 사용, 업무용 빠른 표현을 공유하는 피커를 사용한다.
5. 과거 메시지는 `sequence` keyset cursor로 불러오고, 추가된 높이만큼 Scroll Anchor를 보정한다.
6. Typing은 8초 TTL의 일시 신호로만 표시하고 DB, 검색, Kafka, 감사 본문에 저장하지 않는다.
7. 회의는 장치 사전 점검, 참여, 화면 공유, 대화 Owner·Moderator의 전체 종료를 한 흐름으로 제공한다.
8. 애니메이션은 상태 이해를 돕는 범위로 제한하며 `prefers-reduced-motion`에서 제거한다.
9. 멘션은 본문에서 이름을 추출하지 않고 사용자 ID·표시명 Snapshot·종류를 원장에 저장한다. `@모두`는 Owner·Moderator만 사용한다.
10. 회의는 컴팩트 Lobby, 장치 사전 점검, 몰입형 회의실로 단계적으로 확장하고 종료된 회의를 대화 맥락에 남긴다.

## 3. DWP 고유 차별화

- 일반 앱 권한과 대화 멤버십을 분리해 Tenant 관리자도 자동으로 모든 대화를 읽을 수 없게 한다.
- Space 연결 채널은 `SPACE_MIRRORED` 출처를 보존하며 화면에서 임의 변경하지 못한다.
- 새 구성원은 `history_start_sequence` 이후 기록만 읽고 검색·Thread·Saved·실시간에도 같은 경계를 적용한다.
- 메시지 관리자는 보존 기간과 운영 지표를 관리하지만 본문 열람 기능을 갖지 않는다.
- 성공 응답은 PostgreSQL Commit 이후에만 반환하고 Redis 장애가 메시지 원장에 영향을 주지 않는다.
- 첨부 파일은 격리 저장과 AV/DLP Gate를 통과하기 전에는 UI와 다운로드에 노출하지 않는다.

## 4. 의도적으로 보류한 요소

- 경쟁 제품과 같은 색, Sidebar 구조, 브랜드 장식의 복제
- 검증되지 않은 AI 자동 전송·자동 초대·자동 업무 실행
- 검색과 Compliance를 무력화하는 기본 E2EE
- 원장 복구가 불가능한 Redis 전용 채팅 저장
- Scanner, TURN, HA, WORM이 연결되지 않았는데 정상으로 표시하는 가짜 운영 상태
- 녹화 동의·보존·Legal Hold 정책과 LiveKit Egress 운영 계층 없이 회의 녹화를 노출하는 구현

세부 아키텍처와 출시 Gate는 `R1 Enterprise Messaging Platform ADR.md`와 `07-수용 테스트.md`를
단일 기준으로 사용한다.
