# 01 기획 정의

## 문제와 사용자

Tenant 관리자는 업무 분류와 표시 Label을 Source 배포 없이 운영해야 한다. 개발자가
DB를 직접 수정하면 Tenant 오염, 변경 이력 누락과 Runtime 불일치가 발생한다.

- Persona: Tenant Admin, Compliance Reviewer, Application Operator
- JTBD: “운영 중인 기준정보를 안전하게 변경하고 언제 누가 무엇을 바꿨는지 확인한다.”
- Trigger: 신규 분류 추가, 조직 정책 변경, Label 번역, 항목 폐기
- End state: 활성 Version이 Runtime에 노출되고 변경 Audit이 남는다.

## 범위

- 기준정보 Set·Item 생성, 수정, 활성화와 폐기
- `ko`, `en` 등 Locale Label과 Runtime Locale Fallback
- 검색, 상태 확인, Audit 조회
- Tenant·Admin Role 강제, 동시 수정 충돌 감지

## Non-goal

- 내부 Enum과 Error Code 편집
- 비밀정보, 임의 JSON 설정, Feature Flag와 정책 Rule 저장
- Tenant 간 복사, 일괄 Import·Export와 4-eyes 승인

## KPI와 Event

| KPI                                  | 목표 |
| ------------------------------------ | ---- |
| 무권한·Cross-tenant 조회             | 0건  |
| 활성화 변경의 Audit Coverage         | 100% |
| Runtime의 Draft·Retired 노출         | 0건  |
| Admin 핵심 Flow Axe Critical/Serious | 0건  |

Event는 `reference-set.created|updated|activated|retired`와
`reference-item.created|updated|activated|retired`를 사용한다.
