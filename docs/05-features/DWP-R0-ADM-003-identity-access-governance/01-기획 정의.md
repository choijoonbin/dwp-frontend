# 01 기획 정의

## 문제

Role 변경을 DB에서 직접 수행하거나 현재 Role 이름만 보여주면 Tenant 오염, 관리자 전원 제거,
Group 상속 권한 누락, 기존 Session의 오래된 권한 유지와 감사 누락이 발생한다. 정기 검토가
현재 Assignment와 분리되면 검토 도중 원천이 바뀌어 의사결정 근거도 재현할 수 없다.

- Persona: Tenant Admin, Security Reviewer
- JTBD: “사용자의 유효 권한과 원천을 확인하고 안전하게 변경·검토하며, 외부 IdP 동기화의
  실패와 최근 증적을 한 흐름에서 추적한다.”
- KPI: Cross-tenant 0건, 변경·검토·SCIM Audit 100%, Role 변경 뒤 Active Session 0건,
  Tenant의 Admin 1명 이상, 근거 없는 Access Review 결정 0건

## Non-goal

- UI에서 Local Password 사용자 생성
- Provider Cross-tenant 사용자 관리
- 고객별 IdP 선택·Domain Routing·MFA·복구와 실제 운영 Credential 발급
- 자기 Role 변경과 마지막 Admin 제거
- 자동화된 정책만으로 Privileged Access를 무인 회수
- 고객 승인 없는 Custom Attribute Mapping·대량 Reconciliation
