# 01 기획 정의

## 문제

Role 변경을 DB에서 직접 수행하면 Tenant 오염, 관리자 전원 제거, 기존 Session의 오래된
권한 유지와 감사 누락이 발생한다.

- Persona: Tenant Admin, Security Reviewer
- JTBD: “사용자의 현재 Role을 확인하고 안전하게 변경한 뒤 기존 Session 권한을 회수한다.”
- KPI: Cross-tenant 0건, 변경 Audit 100%, Role 변경 뒤 Active Session 0건,
  Tenant의 Admin 1명 이상

## Non-goal

- UI에서 Local Password 사용자 생성
- Provider Cross-tenant 사용자 관리
- SCIM Server 전체 구현과 임의 Custom Role 생성
- 자기 Role 변경과 마지막 Admin 제거
