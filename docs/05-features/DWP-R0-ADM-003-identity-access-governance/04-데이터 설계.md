# 04 데이터 설계

기존 `com_users`, `com_roles`, `com_role_members`, `sys_auth_sessions`를 재사용한다.

- `com_users.access_revision`: Role Set의 논리 Revision
- `com_users.version`: JPA Optimistic Lock
- `sys_identity_audit_events`: Role 변경 전후 Snapshot, Actor, Tenant, Correlation과 시각
- Role 변경은 Membership Diff, User Revision 증가, 대상 Session 폐기와 Audit를 하나의
  Transaction에서 처리한다.
- `ADMIN` Membership이 바뀌는 Transaction은 Tenant의 Admin Role 행에
  `PESSIMISTIC_WRITE` Lock을 획득한 뒤 인원을 검사해 동시 제거 경쟁에서도 마지막
  Admin 불변식을 유지한다.

Effective Access는 `com_role_members`와 `com_group_role_assignments`를 원천으로 조회하며
Assignment Source와 생성 시각을 사용자 응답에 함께 투영한다.

## Access Review

- `com_access_review_campaigns`: Tenant Scope, 대상 Role·Group, Reviewer 전략, 기한,
  Lifecycle과 낙관적 Version
- `com_access_review_items`: Subject·Role·직접/Group Source와 결정·사유·Remediation
- V35 Snapshot: Source Key·표시명, Assignment 생성 시각, 검토 시작 시점의 마지막 로그인,
  Privileged 여부와 `KEEP|REVIEW|UNAVAILABLE` 권고·근거
- `sys_access_remediation_tasks`: 직접 Role 제거 또는 Group Membership 검토 작업
- Campaign 활성화 시 Item 근거를 고정하고 이후 원천 변경으로 과거 근거를 덮어쓰지 않는다.

## SCIM과 Identity Lifecycle

- `sys_scim_connectors`: Tenant별 Connector Key, Token Prefix·SHA-256 Hash, 허용 Resource,
  `ACTIVE|SUSPENDED|RETIRED`, 마지막 사용과 Version
- `sys_scim_provisioning_events`: Operation, Resource, Outcome, Correlation과 비식별 Summary
- `sys_identity_lifecycle_events`: Joiner·Mover·Leaver·Rehire·Update의 원천과 적용 상태
- Plain Secret은 생성·회전 응답에서 한 번만 전달하고 DB에는 Hash만 저장한다.

Organization·Group Schema는 `DWP-R0-ADM-004`가 소유한다. 실제 IdP Mapping과
Reconciliation 정책은 `D-01` 결정 뒤 별도 Versioned 계약으로 추가한다.
