# DWP-R2-SPC-001 데이터 설계

## Ownership

- System of Record: 신규 `dwp-space-server`와 전용 `dwp_space` Database
- DWP 저장 목적: Space 수명주기, 생성 요청, Membership 의도, Template, DWP Content
  Metadata·Revision, App·외부 자원 Binding, Policy·Provisioning 상태
- Data Owner: Tenant Space Governance Owner, 개별 Space Owner, Content Owner
- Tenant 경계: 모든 업무 Row에 `tenant_id` 필수, Tenant 간 FK·조회·Event 금지
- 기밀등급·PII: Space 이름·목적은 Internal 기본, Membership은 PII, Content는 분류 상속
- 외부 SoR: SharePoint·Teams·Slack·Jira·SAP 등의 원문·ACL은 원본 시스템이 소유한다.

## 저장 원칙

1. 핵심 상태·검색·제약에 쓰는 값은 정규 Column으로 저장한다.
2. Tenant 확장 Metadata는 `extension_schema_version`이 있는 JSONB로 제한한다.
3. Role·Status·Type은 Versioned Catalog 또는 Check Constraint로 검증한다.
4. Business Transaction과 Outbox Event는 같은 Transaction으로 Commit한다.
5. 삭제는 Space DB, Auth Grant, Search, Vector, Cache, Object Storage, Connector에 전파한다.
6. Binary와 Connector Secret은 DB에 저장하지 않는다. Storage Key와 Secret Reference만 둔다.

## 관계와 Lifecycle

- Space Purge는 Child Space를 자동 삭제하지 않는다. Parent Reference를 해제하거나 명시적
  Cascade Plan을 승인해야 한다.
- Published Template Version은 수정하지 않고 새 Version을 만든다.
- Membership·App Binding·Resource Binding은 Hard Delete 대신 상태와 종료 시점을 보존한다.
- Content Revision과 Publication Event는 Append-only다.
- 모든 Mutable Aggregate에 `version`을 두고 `If-Match`와 연결한다.
- `created_by`, `updated_by`, `trace_id`, `correlation_id`는 공통 Audit 계약을 따른다.

## 동기화

- API·Event: Space Outbox → Auth, Approval, Search, Agent, Audit, Notification
- Idempotency Key: 모든 Create·Submit·Approve Result·Provisioning Command에 필수
- Conflict Resolution: Space DB 상태가 Lifecycle SoR, Auth가 Effective Grant SoR,
  외부 Connector가 원문·ACL SoR
- Retry: Exponential Backoff + Jitter, 최대 시도 후 DLQ와 운영 Queue
- Reconciliation: Grant, Approval, Connector ACL, Search Document Count, Storage Object를 주기 비교
- Event Consumer는 `sys_domain_event_inbox`와 동일한 처리 Ledger 계약을 따른다.

## Migration

- Migration ID: `dwp-space-server/V1__create_enterprise_space_domain.sql`,
  `V2__add_space_access_governance.sql`
- Registry Migration ID: `dwp-platform-server/V126__register_enterprise_space_code_contracts.sql`
- Forward: Catalog → Core → Request → Membership → Content → Binding → Lifecycle → Outbox 순서
- Auth Prerequisite: Resource Type·Responsibility·Grant Source·Admin Resource Set Constraint를
  Space 계약으로 확장한 뒤 Space Migration을 실행한다.
- Backfill: 기존 하드코딩 `DWP Workspace`를 Entity로 만들지 않는다. 개인 Home Layout은 My Work
  Context로 유지한다.
- Rollback: G2 전에는 Schema Drop 가능, Pilot 이후에는 Feature Flag + Forward Fix만 허용
- 대용량 Lock: 신규 DB이므로 초기 Lock 없음. 이후 Index는 Concurrent 전략 사용
- Test Data: SKAX Tenant의 내부 프로젝트·운영·커뮤니티·Incident Space를 결정적 Seed로 제공

## Search·Vector

- Search Index: Space Directory, DWP Content Metadata·Body, 연결 원본의 허용 Projection
- Embedding: 승인된 Knowledge Content만 `dwp_aura`에 파생 저장
- Metadata Filter: `tenant_id`, `space_id`, `source_id`, `principal_acl_hash`,
  `classification`, `valid_from/to`, `deleted_at`
- ACL: Query 시 사용자 Effective Principal Set과 Source ACL 교집합을 강제한다.
- 재색인: Membership·Classification·Publication·Source ACL 변경 Event가 재계산을 촉발한다.
- 삭제 전파: Purge Event가 Search, Vector, Cache, Object Storage 삭제 완료 Receipt를 모은다.
- 원문·Vector: Vector는 SoR가 아니며 Model Version·Chunking Version·Source Revision을 기록한다.

### 소유자 복구 Transaction

1. `(tenant_id, space_key)`로 삭제되지 않은 Space를 잠정 식별한다.
2. 유효기간을 포함한 활성 `OWNER`가 이미 있으면 `409`로 중단한다.
3. Auth가 `person_public_id`를 동일 Tenant의 활성 User로 Canonicalize한다.
4. `spc_memberships`를 `OWNER`, `ACTIVE`, `membership_source=RECOVERY`로 Upsert한다.
5. 공통 Audit Outbox와 `SPACE_OWNER_RECOVERY` Policy Evaluation을 같은 업무 Transaction에
   기록한다. 실패 시 Membership을 포함해 전부 Rollback한다.
6. Commit 후 `RECOVERY` Reconciliation이 Owner의 `VIEW·CREATE·UPDATE·APPROVE·MANAGE`
   Desired State를 Queue에 계획한다.

`RECOVERY`와 `SPACE_OWNER_RECOVERY`는 각각 Space V4·V5의 DB Check와 Platform
V129·V130 중앙 Code Registry가 같은 값 집합을 강제한다. 적용된 Flyway Migration은
수정하지 않고 후속 Forward Migration으로만 확장한다.

### 권한 데이터 분리

- `OWNER`: Space 설정·Membership·Policy 관리와 Content Moderation
- `MODERATOR`: Content Moderation, `MANAGE` Desired Grant 없음
- `ADMIN.SPACE_GOVERNANCE`: Tenant 전역 Metadata·Drift·Recovery 제어면
- Auth `com_principal_resource_grants`: 중앙 Effective Grant, Space DB의 복제 원장 아님

Tenant Governance 책임은 비공개 Space Content를 조회하는 Membership으로 변환하지 않는다.
