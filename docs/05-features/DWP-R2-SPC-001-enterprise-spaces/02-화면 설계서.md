# DWP-R2-SPC-001 화면 설계서

## 정보구조

- App Entry: 개인 Home의 `Space` App, Global Search, Context Selector
- Member Routes: `/spaces`, `/spaces/discover`, `/spaces/requests`, `/spaces/new`
- Space Routes: `/spaces/:spaceKey/{overview,activity,content,tasks,people,apps,agent}`
- Owner Routes: `/spaces/:spaceKey/settings/{general,members,content,apps,ai,insights,lifecycle}`
- Admin Routes: `/admin/experience/spaces/{overview,requests,directory,templates,policies,content,apps,lifecycle,reviews,audit}`
- Breadcrumb: Product `Space` → 현재 Space 또는 Admin Area → Page
- Deep Link: 로그인 후 Tenant·Entitlement·Membership을 검증하고 원래 URL로 복귀한다.

## Navigation 원칙

### 구성원 App

1. 개요
2. 내 Space
3. 탐색
4. 요청 내역

현재 Space 선택 후 Sidebar는 `개요, 활동, 콘텐츠, 작업, 구성원, 앱과 도구, Agent`를
표시한다. Owner에게만 `Space 관리` 진입점을 노출한다.

### Tenant Control Center

`사용자 경험 > Space` 아래에 `운영 개요, 생성 요청, Space Directory, Template,
정책, 콘텐츠 거버넌스, 앱·Connector, 수명주기, 접근 검토, 감사`를 Tree로 구성한다.
권한이 없는 메뉴는 숨기고 직접 URL과 API에서도 거부한다.

## 화면별 구조

### SPC-001 Space Launchpad

- Primary task: 자주 쓰는 Space 재진입, 신규 Space 발견·생성, 대기 요청 확인
- Header: `Space`, 생성 권한이 있을 때 `Space 요청` Primary Action
- Body: Favorites, 최근 활동, 내 Space, 초대·승인 대기, 추천 Template
- Insight Rail: Owner 검토 기한, 읽지 않은 중요 Update, 종료 임박 Space
- Search: Global Search와 중복되는 대형 검색창을 만들지 않고 Filterable Command를 제공한다.
- Empty: 추천 Template 3개와 생성 정책을 설명하되 마케팅 Hero를 사용하지 않는다.

### SPC-003 생성 Wizard

- Step 1: 목적·Template
- Step 2: 이름·설명·Owner·공동 Owner·기간
- Step 3: 공개 범위·기밀등급·구성원 Source
- Step 4: App·Connector·Knowledge Source·Agent
- Step 5: Policy 결과·예상 승인자·Provisioning Preview
- Right Rail: 위험 신호와 개선 제안, 승인 경로가 변경된 이유
- Save Draft, Cancel, Back, Continue의 위치를 고정한다.
- 제출 후 같은 화면을 Status Timeline으로 전환하고 중복 요청을 막는다.

### SPC-010 Space Overview

- Context Header: Space 이름, Type, 분류, 접근 수준, Owner, Member 수, Lifecycle 상태
- Canvas: Pinned Update, 내 작업, 최근 Content, 일정, 결정, 활동, 연결 App
- Workspace 편집과 동일한 Widget Composition Engine을 재사용하되 Tenant Template이 필수
  Widget·최대 수·위치를 통제한다.
- 신규 사용자는 `시작 체크리스트`를 보고 Owner는 건강도와 미완료 설정을 함께 본다.

### SPC-011 Content Hub

- Desktop: 구조 Tree 240px, Dense List, Preview·Metadata Panel의 3영역
- Command: 새 Content, Upload, Filter, Sort, View 전환
- Row: Type, Title, Status, Classification, Owner, Updated, Review Due를 안정된 높이로 표시
- Draft·Review·Published·Rejected·Archived 상태를 Text+Icon으로 표시한다.
- 외부 Source는 원본 Badge, Sync Freshness, ACL 상태와 원본 열기를 제공한다.

### SPC-020 Owner Studio

- General: 목적, Icon, Type, 접근, 분류, Owner, 종료일
- Members: User·Group·HR 조직 Source, Role, 기간, 초대·요청, Owner 부재
- Content: Type별 작성·검토·게시·보존·Moderation Policy
- Apps: 사전 승인 App, Pending Request, OAuth Scope, 상태·Last Sync
- AI: 허용 Source, Tool, Classification, Citation·Budget 정책
- Insights: 활성도, 검색 실패, 고아 Content, 위험·Drift
- Lifecycle: 갱신, Archive, 이관, Delete Request

### SPC-030 Admin Overview

- KPI Band: Active, Pending, High Risk, Ownerless, Review Due, External, Failed Sync
- Risk Map: 분류×외부 공유×Connector 위험 Cohort
- Action Queue: 생성·게시·Owner 부재·만료·Policy Drift를 SLA 순으로 제공
- Trend: 생성·Archive·활성도·Template 채택을 비교한다.
- 모든 Metric은 선택 시 Filter된 Directory 또는 Queue로 Drill-down한다.

### SPC-031 Admin Requests

- Queue: 요청 유형, 위험, SLA, Requester, Space, 제출일, 현재 단계
- Detail: 요청 목적, 정책 평가, 구성원·Source·App·Scope Diff, 승인 Chain, Audit Timeline
- Approve·Reject·Request Changes는 서로 분리하고 변경 이유를 필수 기록한다.
- Bulk Approval은 낮은 위험의 동일 Policy 결과에만 허용하고 고위험은 개별 확인한다.

### SPC-032 Template Studio

- 좌측: Draft·Published·Retired Version Tree
- 중앙: Section·Navigation·Widget·Default Content·App Binding Builder
- 우측: 대상 사용자·Space Type·Locale·Policy·Compatibility·Diff
- Draft 작성자와 Publisher를 분리하고 Preview Tenant에서 검증 후 Publish한다.

### SPC-033 Content Governance

- Queue: 공식·외부·규제 Content, DLP Alert, 신고·Moderation Case
- Preview: Rendered Content와 변경 Diff, Source·Classification·Audience
- Evidence: 자동 검사, 이전 결정, 관련 Policy, Reviewer Comment
- 결정 후 원래 Space에 결과를 반영하고 독립 Audit ID를 표시한다.

## Context Selector

- 기본 Context는 `내 작업`이다.
- 최근 Space, Favorite, 검색, Create Request를 제공한다.
- 각 항목에 분류·접근 Badge를 표시하되 Tenant 이름을 Space 이름으로 사용하지 않는다.
- 전환 전 Unsaved Work가 있으면 확인하고 Agent Conversation은 Context를 새로 시작한다.
- 접근 권한이 소멸한 Deep Link는 Permission 화면과 접근 요청 동작을 제공한다.

## 접근성

- Landmark: Global `header`, Product `nav`, Page `main`, Detail `aside`
- Heading: App H1 → Space H2 → Section H3 순서를 유지한다.
- Wizard Error Summary에서 첫 오류 Field로 이동하고 Label·Description·Error를 연결한다.
- Queue와 Data Grid는 Keyboard Row Navigation, Sort Announcement와 Detail Focus 복원을 지원한다.
- Drag & Drop에는 Move Menu와 Keyboard Reorder 대안을 제공한다.
- 200% Zoom·320px에서 Horizontal Page Scroll 없이 List→Detail Flow로 전환한다.
- High Contrast에서 Glass·Blur에 의존하지 않고 Border·Text·Icon으로 상태를 구분한다.
- Reduced Motion은 Context Transition, Reorder, Chart Animation을 즉시 전환으로 바꾼다.
