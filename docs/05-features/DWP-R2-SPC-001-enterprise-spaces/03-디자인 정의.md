# DWP-R2-SPC-001 디자인 정의

## Figma

- File URL: Figma License Gate 해제 후 연결
- Page: `R2 / Enterprise Spaces`
- Flow Section: Member, Owner Studio, Tenant Governance
- Desktop Frame: 1440×1024, 1280×800
- Tablet Frame: 1024×1366, 768×1024
- Mobile Frame: 390×844, 320×568
- Prototype 시작 Node: `SPC-001 Space Launchpad`

Figma 작업 전에도 이 문서, 화면 상태 Matrix와 Design Token을 Source of Truth로 유지한다.
경쟁 제품의 Layout과 Illustration을 복제하지 않고 DWP 정보 구조에 맞춰 설계한다.

## Experience Direction

- Space는 일상적으로 반복 사용하는 운영 Surface이므로 Marketing Hero보다 빠른 Context 인지,
  작업 우선순위와 협업 상태를 전면에 둔다.
- 세련됨은 과도한 장식보다 명확한 계층, 정교한 Motion, 높은 정보 밀도, 일관된 Feedback에서
  만든다.
- Context Header와 Overview의 한두 Surface에만 절제된 Translucency를 사용할 수 있다.
  Data Grid, Form, Queue에는 Blur나 Liquid Glass를 적용하지 않는다.
- Tenant Accent는 선택·Focus·Chart Series 일부에만 사용하고 상태 색상과 충돌하지 않는다.
- Space Type마다 단색을 고정하지 않고 Icon, Label, Template Cover의 조합으로 구분한다.

## Layout

- Shell: 기존 Business App의 248px / 72px Collapsible Navigation 계약을 사용한다.
- Launchpad: 12-column Grid, Main 8 + Insight 4. 중첩 Card를 만들지 않고 Section Band와
  개별 Resource Tile만 사용한다.
- Space Overview: Template이 정의한 안정된 Grid를 사용하고 Widget이 임의로 Container를
  밀지 않게 `minmax`, `aspect-ratio`, `container-type`을 적용한다.
- Admin Queue: Filter Bar → Data Grid → 480~560px Detail Pane. Detail은 Modal 남용 대신
  URL을 가진 Side Pane으로 유지한다.
- Builder: 280px Library + Fluid Canvas + 360px Inspector. 좁은 화면은 각 영역을 Tab으로
  전환한다.

## Responsive Rule

| Breakpoint | Layout          | Priority                       | Hidden·Moved Action            |
| ---------- | --------------- | ------------------------------ | ------------------------------ |
| 1440+      | 3영역·12열      | Context, Action, Evidence 모두 | 없음                           |
| 1280–1439  | 2영역·12열      | Queue·Detail 유지              | Insight 일부 접기              |
| 768–1279   | 2열 또는 Split  | Primary Task·Status            | Filter Drawer, Inspector Sheet |
| 390–767    | 1열 List→Detail | Context·Primary Action         | Secondary Command Menu         |
| 320–389    | 1열 Compact     | Title·상태·Action              | Metadata Disclosure            |

Font 크기를 Viewport Width에 비례해 Scale하지 않는다. 긴 Space 이름은 한 줄 Ellipsis와
Tooltip을 사용하되 Page H1은 두 줄까지 허용한다.

## Density와 Theme

- Compact: Admin Grid 44px, 반복 Queue 중심
- Standard: Member List 52px, 기본값
- Comfortable: Touch·현장 환경 60px
- Light·Dark·High Contrast 모두 Semantic Token으로 제공한다.
- Dark Theme에서 남색 단일 Tone이 지배하지 않도록 중립 Surface, 녹색·청록·황색·적색의
  의미 색을 절제해 사용한다.
- Color만으로 Risk·상태를 전달하지 않고 Icon, Label, Text를 함께 표시한다.

## Interaction

| Trigger        | Feedback                          | Duration | Focus          | Reduced Motion |
| -------------- | --------------------------------- | -------- | -------------- | -------------- |
| Context 전환   | Header Label·Content Crossfade    | 160ms    | Page H1        | 즉시           |
| Favorite       | Icon Fill + Toast                 | 120ms    | 현재 Button    | 즉시           |
| Wizard Step    | Horizontal Content Shift          | 180ms    | Step H2        | 즉시           |
| Policy 평가    | Pass·Review·Block 항목 갱신       | 200ms    | Summary        | 즉시           |
| Queue Row 선택 | Detail Pane Open                  | 160ms    | Detail H2      | 즉시           |
| Drag Reorder   | Lift, Drop Indicator, Auto Scroll | 140ms    | 이동 Item      | Keyboard Menu  |
| Publish        | Progress → Success Timeline       | 단계별   | Result Heading | 동일           |

- Hover 영역은 Content 크기가 아니라 안정된 Tile Box 전체를 사용한다.
- Icon Button은 Lucide 또는 기존 DWP Icon Library를 사용하고 Tooltip과 Accessible Name을
  제공한다.
- Destructive Action은 Danger Menu와 Confirm Dialog를 사용하고 이름을 입력시키는 확인은
  Purge처럼 복구 불가능한 작업에만 쓴다.
- Optimistic UI는 Favorite·개인 정렬처럼 되돌릴 수 있는 작업에만 사용한다.

## Content Design

- 한국어: `Space`, `내 Space`, `Space 만들기 요청`, `Space 관리`, `공개 범위`
- 영어: `Space`, `My spaces`, `Request a space`, `Space settings`, `Access level`
- `Workspace`는 Tenant 전체나 My Work를 뜻하는 사용자 Label로 사용하지 않는다.
- 승인 메시지는 “관리자 확인 필요”가 아니라 어떤 정책 때문에 어떤 역할이 검토하는지
  설명한다.
- 시간은 사용자 Locale과 Tenant Time Zone을 표시하고, 종료일·SLA는 상대·절대 시간을 함께
  제공한다.
- i18n Key는 `spaces.*` Namespace를 사용하고 Type·Status·Role은 Display Dictionary에서
  해석한다.

## Visualization

- Admin Overview Chart는 장식용 Dashboard가 아니라 Drill-down 가능한 운영 지표만 사용한다.
- 위험 Heatmap, Lifecycle Cohort, Approval Lead Time, Template Adoption을 기본으로 한다.
- Pie Chart는 작은 범주 비교에만 사용하고 추세는 Line, Queue 규모는 Bar, 수명주기는 Cohort를
  사용한다.
- 모든 Chart에 Table View와 Accessible Summary를 제공한다.
