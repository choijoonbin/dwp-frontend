# DWP-R2-SPC-001 운영 및 복구 런북

## 목적

Space Membership Intent, 중앙 IAG Grant와 수명주기 상태의 불일치를 탐지하고 최소 권한으로
복구한다. 운영 담당자는 Tenant Space의 본문을 기본 열람하지 않으며 메타데이터와 증적만으로
조치한다.

## 정상 상태

- 전달 대기·Dead Letter 0건
- `OWNERLESS_SPACE`, `EXPIRED_MEMBERSHIP`, `ENTITLEMENT_DELIVERY`, 기한 초과
  `LIFECYCLE_REVIEW` 열린 이슈 0건
- 최근 정기 조정이 `SUCCEEDED`
- Auth Service Identity 연결 활성

## 소유자 없음

1. 관리 센터 → Space 운영 → 운영 정합성에서 `OWNERLESS_SPACE` 증적을 연다.
2. Space 키·이름과 최근 탐지 시각을 확인한다. 본문을 열어 조사하지 않는다.
3. 조직의 책임 승인을 받은 활성 구성원을 이름·이메일·조직으로 검색한다.
4. 선택 근거를 10자 이상 기록하고 `소유권 복구`를 실행한다.
5. 이슈가 해결되고 최근 실행에 `RECOVERY`, 전달 상태에 Owner 권한 5건이 계획됐는지 확인한다.
6. Dead Letter가 발생하면 Error·Principal Ref·Correlation ID를 확인한 뒤 한 번만 수동
   재시도한다. 반복 실패는 Identity 운영 사건으로 Escalation한다.

금지 사항: 활성 Owner가 있는데 교체 수단으로 복구 API를 사용하거나, 비활성·타 Tenant
사용자를 강제 등록하거나, DB Row를 직접 수정하지 않는다.

## 권한 전달 실패

1. `delivery_state=RETRY|DEAD`와 `last_error`, `attempt_count`를 확인한다.
2. Auth Health, Service Token, Circuit Breaker와 대상 Principal 활성 상태를 확인한다.
3. 원인이 해소된 뒤 운영 화면에서 재시도한다.
4. `SUCCEEDED`와 `synchronized_at`을 확인하고 발견사항 자동 해결을 기다린다.

Queue Worker는 Lease 기반으로 항목을 점유하고 지수 Backoff로 재시도한다. 운영자가 DB의
`delivery_state`를 직접 변경하지 않는다.

## 수명주기 기한 초과

운영 발견사항에서 수명주기 검토 대기열로 이동해 활동·접근·보존 증거를 검토한다. 유지,
보관, 삭제 대기 또는 접근 재검토 결정을 기록하며 Legal Hold와 Purge Receipt Gate가 없는
환경에서는 물리 삭제를 수행하지 않는다.

## 증적 확인

- Audit action: `SPACE_OWNER_RECOVERED`, `SPACE_RECONCILIATION_RUN`,
  `SPACE_ENTITLEMENT_RETRY_REQUESTED`
- Policy type: `SPACE_OWNER_RECOVERY`
- Membership source: `RECOVERY`
- Correlation ID로 Space·Auth·Gateway API History를 연결한다.
- 감사 Payload에는 Content Body, Email 원문, Token을 넣지 않는다.

## 외부 Gate

실제 외부 IAG, S3, KMS, DLP, Connector, Search ACL Projection, 부하·침투·장애 주입과 Pilot을
통과하기 전 이 Local 기준선을 Production Ready로 판정하지 않는다.
