## 2. 개발 중 자체 보완 범위

다음 항목은 기존 DWP 디자인 시스템과 상태 컴포넌트로 해결할 수 있으므로 디자인 AI에 다시 맡기지
않는다.

### 14 통합 찾기 및 예약

- Filter Sheet, 모바일 지도, Resource detail Sheet를 기존 02·03 패턴으로 구현
- Loading, Empty, Read-only, Permission denied, Policy blocked, 409, Result unknown, Offline
- 목록·지도 수치와 선택을 같은 Search Projection으로 통일
- `AI 추천`, 집중도 점수는 근거·기준 시각이 있을 때만 표시
- 도면이 없으면 가상 도면을 만들지 않고 완전한 목록 제공
- 아이콘 접근성 이름, 사진 Alt, 최소 글자 크기와 지도 목록 대안
- 자연어 조건 검색은 AI 출시 전 Typed filter만 유지할 수 있도록 Capability 분리

### 15 여러 날짜·대리·팀 예약

- 참가자·날짜·자원별 `성공/정책 거부/자원 없음/결과 불명` Batch result Sheet

- Hold 연장은 실제 정책과 API가 있을 때만 노출
- 내부 `/batch/status` 문구를 사용자 상태 문구로 교체
- 사내 자원에 불필요한 결제 도메인을 만들지 않고 예약 한도로 표현

## 3. 화면에 표현돼 구현 범위가 된 기능

수용된 화면을 단순 시각 복제로 끝내지 않는다. 다음 기능은 실제 API·권한·상태·감사와 함께 제공해야
한다.

1. 다중 자원 Search, Facet, Floor plan, Inspector, Timeline, 즐겨찾기·공유·경로 전달
2. Actor·Beneficiary·Delegation Grant, 여러 날짜 Preview, 팀 인접 좌석 조건
3. 서버 Hold, Batch, 대안, Waitlist, Auto-promote Opt-in과 알림 선호
4. 회의·좌석·주차·사물함·장비·대기열을 합친 Reservation Projection
5. 체크인·노쇼·변경·반납과 Authority별 명령
6. 방문 초대·문서·승인·임시 출입·도착·퇴실과 예외 운영
7. 예약 상세의 방문자·서비스·출입·감사 연결
8. AI BookingIntent Preview와 사용자 확인 뒤의 BookingBatch 실행

화면에 보이는 LPR, Locker 원격 열기, NFC·QR·Wi-Fi 체크인, IoT 환경 센서, Access provisioning,
Slack·Teams 알림은 승인된 Adapter와 실제 Tenant 증거가 있을 때만 활성화한다. Fixture를 정상 운영
데이터로 사용하지 않는다.

## 5. 현재 22번 처리

현재 `정책·SLA·Sentry 예외 관제`는 정의한 14–23 범위의 22번으로 수용하지 않는다. 필요하면 향후
`24. 정책·SLA 예외 운영`으로 재설계할 수 있으나 다음 조건을 먼저 적용한다.

- Raw stack, 사용자 ID, 내부 Class·Server·Payload 제거
- 서로 다른 화재·예약 충돌의 일괄 복구 제거
- Workplace 운영자 명령과 개발자 Telemetry의 권한·화면 분리
- 모든 복구에 영향 Preview, 사유, 재확인, Progress, Recovery, Audit 적용
- Sentry는 관측 Source이며 DWP의 예약·안전 권위 원천이 아님을 명시

이 화면은 대체 21번을 받은 뒤 별도 우선순위로 판단한다.
