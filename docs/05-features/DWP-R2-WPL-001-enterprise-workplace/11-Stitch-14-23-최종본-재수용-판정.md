## 2. 산출물 정합성

14, 18–22 PNG는 실제로 변경됐다. 15–17과 23은 `code.html`만 변경되고 PNG는 이전 압축 파일과
바이트 단위로 동일하다. 따라서 다음 원칙을 적용한다.

- PNG는 Layout·시각 참고 자료다.
- 수정된 HTML의 날짜·상태·Wizard·Batch·권한 문구는 요구사항 참고 자료다.
- HTML의 JavaScript, Alert, Timeout, Fixture를 운영 코드로 재사용하지 않는다.
- 최종 구현의 권위 원천은 09번 아키텍처, Canonical API, Tenant Policy, 실제 Adapter 상태다.
- PNG와 HTML이 충돌하면 Canonical 데이터와 상태 계약을 우선한다.

## 3. 추가 디자인 없이 개발 가능한 화면

### 14–17

기존 판정을 유지한다. 검색·지도·Inspector, Hold·Batch·Waitlist, 통합 예약, 방문·출입의 주 흐름은
충분하다. 다음 사항은 개발 중 교정한다.

- 사용자 Shell에 중복된 관리자 메뉴 제거
- QA 상태 Simulator는 Storybook·테스트 전용으로 격리
- 날짜·요일·수치·사진은 Canonical Resource와 서버 시간으로 통일
- 체크인 Pending과 완료 Toast의 동시 노출 금지
- PIN·Credential 원문, 내부 API 경로, 검증되지 않은 `CONNECTED/COMPLIANT` 문구 금지
- Provider 실증 전 `NOT_CONFIGURED/CONFIGURED_UNVERIFIED` 표시

### 18 Workplace Services

DWP Shell, 사용자 주문 상세, 변경 영향, 서비스 품목, 이행 단계, SLA, 비용센터, 외부 참조와 담당자가
확보됐다. 다음은 기존 DWP Form·Dialog·Operations Table로 자체 보완한다.

- Service Catalog → 옵션·수량·인원·마감·비용센터·특별 요청 → Preview → 주문
- 관리자 Fulfillment Queue와 Inspector
- `NOT_CONFIGURED`, 지연, 부분 이행, 차단, 취소, 결과 불명
- 첨부·메시지·감사 이력
- 사용자 주문과 관리자 이행 명령의 Route·권한 분리
- 장비 PIN은 재인증 뒤 짧은 만료로 Reveal하고 원문을 저장하지 않음

### 21 데이터 연계 운영 관제

7종 Connector, 설정·실행 상태, Freshness·Lag·Cursor, Retry·DLQ, Replay 진행과 감사 구조가
확보됐다. 다음 문구와 명령 계약만 교정한다.

- 남아 있는 `정책·SLA 예외 관제`, `Exception Control` 메뉴명을 `데이터 연계 관제`로 통일
- `NOT_CONFIGURED`, `DISABLED`, `CONFIGURED_UNVERIFIED` 상태 Frame 추가
- `CONFIGURED_UNVERIFIED + HEALTHY` 조합 금지. 검증 전 Runtime은 `UNKNOWN/UNVERIFIED`
- Polling·Restart·DLQ Replay는 영향 Preview → 사유 → Step-up 권한 → 확인 → 진행 → Receipt
- Raw Payload 편집, Vault URI·Cluster·Credential 노출 금지

현재 Connector API는 설정 Metadata만 제공한다. Runtime Health, Checkpoint, Queue, DLQ, Replay는
새 모델·API로 구현한다.

### 22 수요·공간 시나리오

Work plan, 예약, Check-in, 실제 점유, No-show 분리, 신뢰구간, 일부 Coverage·Freshness, 현재안과
제안안, Energy·Carbon이 반영돼 개발 가능하다.

- Source별 Coverage·Freshness·As-of·Availability 추가
- 계산식, 배출계수 Version·Region, Meter Evidence 제공
- `DATA_INSUFFICIENT/STALE/PARTIAL/COMPUTE_FAILED` 상태
- 자동 재배정·자동 배포 제거
- `DRAFT → PREVIEW → SUBMITTED → APPROVED → PUBLISHED` 수명주기
- 예약 이동은 Scenario 승인과 분리된 영향 Preview·명령으로 수행

현재 Report는 예약 기반 이용률이며 Sensor occupancy가 아니다. Forecast, Scenario, Emission 모델과
실제 Source ingestion을 새로 구현한다.

### 23 예약 도우미

AI 제안 → 권위 API 검증 → 사용자 확정 흐름을 수용한다.

- 일반 사용자 화면과 관리자 AI Governance Route 분리
- 특정 모델명, 마스킹 비율, 성능·규정 준수 단정 제거
- `제안/검증/확정 대기/처리/성공/부분 성공/실패/결과 불명` 상태
- Review와 Explicit confirm 뒤 BookingBatch 실행
- Calendar·Workplace·Access의 항목별 결과와 Batch 상태 재조회
- QR·Credential은 Provider 발급 성공 뒤에만 완료 표시

기존 Dwaion에는 Workplace 예약 Action이 없으므로 BookingIntent Preview, BookingBatch, Alternative,
Waitlist용 권위 API와 Agent Tool을 추가한다.

## 4. 남은 디자인 Gate

### 19b Room Display·Status Board·Device Operations

19a는 Published Graph, 배리어프리 경로, Turn-by-turn, 텍스트 대안, Graph 오류 시 안내 데스크
Fallback과 동적 Pass를 제공하므로 길찾기 구현에 사용할 수 있다. 아래 화면은 압축 파일에 없다.

- 16:9 Room Display
- Status Board
- Device Operations 목록·Inspector
- Unregistered, Offline, Stale schedule, Permission denied, Safety takeover 상태
- Device 등록, Site·Floor·Resource Binding, Heartbeat, App·Policy Version, 오류와 원격 설정

### 20 Incident Lifecycle의 앞·뒤 단계

수정본은 Source별 대상, As-of·Freshness, 채널 전달, SOS Queue, PII Masking과 모바일 응답 상태를
보완했다. 아래 단계는 여전히 없다.

- 발령 전 대상·제외 대상·채널·집결지·권한 Preview
- 범위 변경 전 영향 Preview
- 양방향 메시지
- 종료 사유·승인
- 사후보고서와 전체 Audit Timeline
- 모바일 Offline·Delivery error

현재 Summary의 `전체 482, Safe 358, SOS 4, 미응답 82`는 합계가 444로 38명이 분류되지 않는다.
중복 제거·제외 상태를 포함한 AudienceSnapshot 계약으로 계산해야 한다. 일반 사용자에게 팀원 실명과
안전 상태를 표시하려면 별도 Coordinator 권한이 필요하다.
