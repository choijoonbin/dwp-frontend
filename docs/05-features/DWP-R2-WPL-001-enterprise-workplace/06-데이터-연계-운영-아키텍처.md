# 근무공간 데이터 연계 운영 아키텍처

## 1. 목적

근무공간 화면은 예약·카탈로그처럼 DWP가 직접 소유하는 데이터와 센서·출입·방문·차량처럼 외부
시스템이 소유하는 데이터를 함께 사용한다. 관리자는 `근무공간 거버넌스 > 데이터 연계 운영`에서
각 데이터 원천의 제공자와 승인된 설정 참조를 관리한다.

설정 저장, 연결 검증, 최신 신호 수신은 서로 다른 상태다. 제공자 이름과 설정 참조가 있다는 이유로
화면에 실재 인원, 센서 점유, 출입 성공 또는 작업지시 진행 상태를 만들어 표시하지 않는다.

## 2. 데이터 소유권

| 원천                | 소유자                         | 사용하는 화면             | 현재 플랫폼 책임                                           |
| ------------------- | ------------------------------ | ------------------------- | ---------------------------------------------------------- |
| Calendar            | Calendar                       | 홈 일정, 회의실 예약      | 일정·회의 projection을 Calendar API에서 조회               |
| Actual presence     | 승인된 센서/Wi-Fi/RTLS 제공자  | 지도, 운영 현황, 인사이트 | 제공자·설정 참조를 관리하고 미검증 상태를 명시             |
| Access control      | 승인된 출입/배지/QR/NFC 제공자 | 체크인, 접근 운영         | 제공자·설정 참조를 관리하고 예약 체크인과 외부 근거를 분리 |
| Signage             | 디지털 사이니지 제공자         | 공간 안내, 현장 게시      | 제공자·설정 참조와 운영 소유권을 관리                      |
| Visitor             | 방문자 관리 제공자             | 방문 일정, 접근 준비      | 제공자·설정 참조와 운영 소유권을 관리                      |
| Vehicle             | 주차/차량 제공자               | 방문 차량, 주차 상태      | 제공자·설정 참조와 운영 소유권을 관리                      |
| Facility work order | 시설 작업지시 제공자           | 시설 요청, 폐쇄, 운영 큐  | DWP native 요청과 외부 작업지시 소유권을 분리              |

시설 운영 큐의 우선순위, 담당자, 처리 업체, 외부 작업지시 참조, SLA 기한은 DWP의 시설 요청
레코드에 보존한다. 관리자는 같은 요청 상태를 유지한 채 배정 정보만 바꿀 수 있고, 모든 변경은 낙관적
버전과 사유·확인을 요구하며 감사 원장에 남는다. 외부 작업지시 참조가 저장되어도 제공자 연결이
검증됐다는 의미는 아니다.

## 3. 메뉴와 권한

- 메뉴는 `/workplace/admin/governance?area=dataSources`에 있으며 전역 `ADMIN.WORKPLACE` 관리자가
  조회·변경한다.
- 위임 관리자는 물리 공간 범위만 관리하므로 Tenant 전역 자격 증명 참조를 볼 수 없다.
- 화면은 설정 필요, 운영 중지, 설정됨·검증 대기를 별도로 집계한다.
- 변경은 기존 Governance 명령 계약과 동일하게 현재 Version, 변경 사유, 영향 확인을 요구하고
  감사 원장으로 연결한다.

## 4. 보안 및 진실성 계약

- UI와 API에는 비밀값, Token, Provider URL을 저장하지 않는다. 승인된 Secret/Configuration의
  불투명 참조만 저장한다.
- `CONFIGURED_UNVERIFIED`는 실제 연결이나 최신 데이터가 확인됐다는 뜻이 아니다.
- 센서 기반 점유와 예약 시간 기반 활용률을 하나의 지표로 합치지 않는다.
- 공급자 Adapter는 Tenant 격리, 멱등 Event ID, Source Timestamp, 수신 Timestamp, Cursor,
  재시도·DLQ, 보존기간, 감사 주체가 확정된 뒤 활성화한다.
- Adapter가 없는 원천은 화면에서 unavailable/unverified로 유지한다.

## 5. 공급자 활성화 완료 조건

각 공급자는 다음 근거가 모두 있어야 운영 완료로 판정한다.

1. 승인된 공급자와 데이터 처리 계약
2. Configuration Reference 해석 및 Secret Rotation 책임자
3. Canonical Event Mapping과 Tenant/Resource 식별 검증
4. 연결 검사, 마지막 성공·오류, Freshness, Cursor/Checkpoint
5. Retry/Replay/DLQ와 중복 이벤트 멱등성
6. 개인정보 보존·삭제·동의 철회 전파
7. 실제 Tenant에서 populated read/write journey와 장애 복구 증거

이 조건을 충족하지 않은 공급자는 디자인 예시값을 fixture나 하드코딩 값으로 제품 화면에 노출하지
않는다.
