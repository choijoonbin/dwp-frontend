# 2026 글로벌 근무공간 벤치마크·기능 갭 결정서

- 기준일: 2026-09-16
- 상태: Accepted for design and architecture planning
- 제품 범위: 회의실·좌석·주차·사물함·장비를 포함하는 멀티오피스 공간 예약과 현장 경험
- 근거: 글로벌 제품 공식 문서, DWP 프론트엔드·백엔드·API·기존 01–13 Stitch 수용 문서

## 1. 결론

현재 DWP 근무공간은 단순 예약 데모가 아니다. 공간 계층, 자원 카탈로그, 체크인·반납·취소·이동,
노쇼 자동 해제, 팀 근무 계획, 정책·접근·감사, 시설 운영, 활용 분석까지 실제 제품 기반이 구현돼 있다.

그러나 `01–13 화면 구현 완료`를 글로벌 근무공간 제품 전체의 완료로 해석해서는 안 된다. 현재 코드는
회의실과 비회의 자원의 메뉴·조회가 분리돼 있고, 통합 Search·Reservation Projection은 목표
아키텍처로 남아 있다. 대기열, 여러 사람·여러 날짜 예약, 방문자 여정, 예약 연계 서비스, 실제
출입·재실 운영, 실내 길찾기와 비상 대응도 완결된 사용자 여정이 없다.

따라서 다음 제품 결정을 채택한다.

1. 기존 Stitch 01–13은 폐기하거나 다시 그리지 않고 검증된 기초 화면으로 유지한다.
2. 글로벌 제품의 핵심인 `하나의 찾기`, `하나의 내 예약`, `예약 이후 현장 경험`을 먼저 완결한다.
3. 메뉴 수를 늘리기보다 기존 `오늘`, `찾기 및 예약`, `내 예약`, `팀과 오피스`에 기능을 합성한다.
4. 방문자·서비스·안전처럼 독립 운영 책임이 필요한 기능만 관리자 Operations의 하위 업무 화면으로
   확장한다.
5. 외부 공급자가 필요한 출입·센서·사이니지 데이터는 설정 화면만으로 완료 처리하지 않는다. 실제
   Tenant에서 연결, 지연, 재처리, 장애 복구가 검증될 때까지 `미연결` 또는 `검증 대기`로 표시한다.

## 2. 벤치마크 선정 원칙

공개 자료만으로 매출, 활성 사용자, 관리 좌석 수를 같은 기준으로 비교한 객관적 시장점유율
1–3위를 확정할 수 없다. 이 문서에서 `Top 3`는 순위 표현이 아니라 공간 예약과 글로벌
엔터프라이즈 운영 범위가 넓은 **대표 벤치마크 제품군**을 뜻한다.

### 4.4 외부 공급자 선행 조건

다음 항목은 DWP 화면과 Orchestration만으로 정상 동작을 보장할 수 없다.

- QR·NFC·Badge·모바일 Pass의 발급·검증·회수
- Wi-Fi·센서·출입 기록 기반 실제 Presence
- 외부 Visitor, Vehicle, Signage, Facility Work Order 공급자

각 공급자는 Tenant 격리, 멱등 Event ID, Source/Received Timestamp, Cursor, Retry·DLQ·Replay,
보존·삭제 전파와 실제 Tenant 복구 증거를 충족해야 한다. 세부 계약은
[데이터 연계 운영 아키텍처](./06-데이터-연계-운영-아키텍처.md)를 따른다.

## 5. 메뉴와 정보 구조 결정

기능마다 1차 메뉴를 만들지 않는다. 사용자와 관리자의 실제 업무 단위에 다음처럼 배치한다.

### 5.1 사용자

| 목표 메뉴      | 포함 기능                                                           |
| -------------- | ------------------------------------------------------------------- |
| `오늘`         | 다음 예약, 체크인, 대기열 승격, 방문자 도착, 서비스 변경, 안전 알림 |
| `찾기 및 예약` | 모든 자원, 지도·목록, 반복·여러 날짜, 대리·팀 예약, 대기열·대안     |
| `내 예약`      | 회의·좌석·주차·사물함·장비의 통합 Timeline, 방문·서비스 Tab         |

## 6. 우선순위

### P0 — 글로벌 예약 제품의 핵심 완결

1. 전체 사업장 Search Projection과 공통 Resource Inspector
2. Workplace·Calendar를 합친 Reservation Projection과 목표 메뉴 Redirect
3. 반복·여러 날짜·대리·팀 Batch 예약, Expiring Hold와 부분 성공 복구
4. 대기열·대안 제안·승격·알림·자동 확정 동의
5. Connector 운영 상태: Health, Lag, Cursor, Retry, DLQ, Replay
6. 승인 공급자 한 곳을 사용한 체크인 근거·결과 불명·복구 Pilot

### P1 — 글로벌 엔터프라이즈 WEX 완결

1. 방문자·계약자 초대, 승인, 문서, 임시 출입, 도착·퇴실
2. 예약 연계 Catering·AV·Room setup·IT 서비스와 SLA
3. POI·접근 가능한 실내 길찾기·층간 경로
4. 비상 알림·안전 확인·현장 인원 점검·사건 원장
5. Room Display·Kiosk·Signage 장치 Fleet
6. 주차의 차량·EV·방문차량·Entitlement 확장

### P2 — 차별화와 최적화

1. 설명 가능한 자연어 예약 도우미
2. 수요 예측과 배치도 변경 시나리오
3. kWh·CO2e·비용 기준선과 지속가능한 공간 추천
4. 지역별 Data Residency·보존 정책의 자동 검증

P0는 공간 예약 제품의 글로벌 핵심 완료 조건이다. P1은 DWP가 예약 앱을 넘어 통합 Workplace
Experience를 표방할 때 필수 조건이다. P2는 충분한 실제 운영 데이터와 P0·P1 품질 증거 뒤에
활성화한다.

## 7. 출시 완료 정의

화면과 API가 추가된 것만으로 완료하지 않는다. 다음 대표 여정과 운영 증거가 모두 필요하다.

1. 여러 사업장에서 `찾기 → 상세 → 예약 → 체크인 → 변경·취소`가 한 IA에서 끝난다.
2. 회의실과 다른 자원이 하나의 검색·예약 목록에 나타나면서 각 쓰기 권위와 Version을 보존한다.
3. 여러 날짜·대리·팀 예약은 Actor와 Beneficiary를 구분하고 성공·실패·결과 불명을 복구한다.
4. 대기열 승격은 TTL 안에서만 확정되고 중복 명령과 경쟁 승격을 막는다.
5. `방문 초대 → 승인·문서 → 임시 출입 → 도착·퇴실`과 서비스 주문의 정상·실패가 검증된다.
6. Adapter 장애가 `정상 → 지연 → stale → replay → 복구`로 관측되고 데이터가 만들어지지 않는다.
7. 320·390·768·1280·1440px, 200% 확대, 키보드, 스크린리더, 고대비, 긴 한·영 문자열을 통과한다.
8. 다중 시간대, DST, Tenant 격리, 동시 예약, 개인정보 삭제·보존, 부하 SLO 증거를 보존한다.

이 조건 전에는 `Stitch 01–13 수용 완료`와 `글로벌 근무공간 제품 완료`를 같은 의미로 사용하지
않는다.
