# DWP-R2-WPL-001 제품 및 UX 설계

## 1. 제품 경계

Workplace는 본사, 공유오피스, 위성 사무실과 고객사 근무지를 하나의 공간 카탈로그로 제공한다.
계층은 `Tenant > Campus > Building(Site) > Floor > Zone/Section > Resource`이며 사용자는
좌석, 포커스 부스, 사물함, 주차 공간과 공용 장비를 예약한다. 회의실의 일정, 참석자, 반복과
응답은 Calendar가 권위 원천이고 Workplace는 위치와 가용 Projection만 결합한다.

Microsoft Places의 Building-Floor-Section-Desk 계층과 `Reservable`, `Drop-in`, `Assigned`,
`Unavailable` 모드, Google Workspace의 Building/Resource 카탈로그와 Calendar Resource 경계를
채택한다. 3D/BIM은 예약 기준 데이터로 사용하지 않고 검증된 2D 배치도와 정규화 좌표를 사용한다.

## 2. 사용자 경험

1. `Workplace home`은 현재 가용 공간, 향후 예약과 체크인 필요 항목을 요약한다.
2. `Find a space`는 사업장·층·시간·자원 종류를 필터링하고 배치도 또는 목록에서 예약한다.
3. 회의실을 선택하면 Calendar 정책과 초대 흐름으로 전환한다. 정책을 읽지 못하면 조회만 허용하고
   예약은 fail-closed로 차단한다.
4. `My space bookings`는 체크인, 반납, 취소와 미래 예약 변경을 제공한다. 예약 변경은 같은 자원
   종류 안에서 공간 또는 시간을 바꾸며 서버가 충돌과 정책을 다시 판정한다.
5. 고정 배정 공간은 소유자가 공개한 Release Window 안에서만 다른 구성원이 예약할 수 있다.
6. 배경 갱신 실패 시 마지막 정상 데이터는 유지하고 stale 경고와 다시 시도를 함께 제공한다.

## 3. 관리자 경험

관리자는 Campus, Building, Floor, Zone, Section과 Resource를 관리하고 Draft 배치도를 저장,
검토, 게시한다. 게시된 Revision만 사용자 화면에 투영된다. 정책은
`Resource > Zone > Floor > Building > Campus > Tenant` 순서로 상속되며 변경 필드와 출처를
함께 보여준다. 위임 관리자는 자신에게 허용된 Building 또는 Managed Group 범위만 관리한다.

운영 화면은 예약 검색, 사유 기반 강제 취소, Legal Hold와 감사 추적을 제공한다. 조회 권한과
변경 권한은 UI에서도 분리하지만 최종 판정은 Gateway 문맥을 검증한 서버가 수행한다.

## 4. 반응형·접근성 기준

- Desktop, Tablet, Mobile과 200% Zoom에서 명령 누락과 수평 페이지 Overflow가 없어야 한다.
- 작은 화면은 배치도 대신 완전한 목록 보기를 기본값으로 사용한다.
- 아이콘 단독 명령은 접근 가능한 이름과 Tooltip을 제공한다.
- 가용 시간 셀은 키보드로 도달 가능하고 예약 불가 사유를 접근성 이름과 Tooltip으로 제공한다.
- 오류, 빈 상태, 로딩, stale, 읽기 전용 상태를 시각 정보뿐 아니라 텍스트로 구분한다.
- axe serious/critical 위반은 0건이어야 한다.
