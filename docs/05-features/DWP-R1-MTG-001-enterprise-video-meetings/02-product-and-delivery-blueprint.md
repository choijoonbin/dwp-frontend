## 0. 이 문서가 확정하는 것

이 문서는 현재 PoC 기반을 엔터프라이즈 제품으로 전환하기 위한 단일 실행 기준선이다. 기능 이름만 나열하지 않고, 사용자가 겪는 전·중·후 여정, 관리자 통제, 데이터 수명주기, 미디어·제어 평면 경계, 운영 목표와 수용 기준을 함께 고정한다.

핵심 결정은 다음과 같다.

1. DWP 회의는 메신저의 가벼운 허들과 분리된 `FORMAL_MEETING` 제품이며 회의 전 준비부터 회의 후 결과 이행까지 소유한다.
2. 미디어는 검증된 WebRTC/SFU 공급자 포트(LiveKit)를 사용하고, DWP는 회의 제어·권한·정책·감사·아티팩트를 소유한다.
3. 대기실 승인이 끝나기 전에는 메인 룸 미디어 토큰을 발급하지 않는다. 화면상의 대기실만으로는 보안 통제가 아니다.
4. 테넌트 관리자와 회의 운영 관리자는 정책·상태를 관리하지만 녹화·전사·채팅 본문을 자동으로 열람할 수 없다.
5. 녹화, 전사, AI 회의록은 각각 명시적 정책과 상태를 가진 기능이다. 인프라·동의 고지·보존·삭제 증거가 없으면 사용할 수 있다고 표시하지 않는다.
6. AI 회의록은 원문 시간 근거가 붙은 `검토 전 초안`이다. 사람의 검토 없이 공식 기록이나 자동 업무 지시가 되지 않는다.
7. 보안 모드는 `관리형 보안 회의`와 `비공개 E2EE 회의`의 이중 모드로 설계한다. 후자는 서버 측 녹화·전사·AI 회의록을 제공하지 않는다.
8. 외부 게스트, 공동 호스트, 녹화, E2EE 같은 기능은 UI 노출만으로 완료되지 않는다. 신원·공급자 집행·감사·실패 복구가 종단 간 통과해야 한다.
9. P0는 “데모 가능”이 아니라 핵심 회의가 업무 시간에 안전하고 복구 가능하게 끝나는 상태를 의미한다.

## 1. 문제 정의와 현재 상태 판단

### 1.1 관찰과 판단의 경계

제공된 캡처는 카메라·마이크 점검 화면에서 큰 검은 미리보기, 기본 아바타, 이름 입력 필드와 취소 동작만 명확히 보여 준다. 이 한 장만으로 백엔드 또는 숨겨진 회의실 기능 전체가 미구현이라고 단정할 수는 없다. 반대로 사용자는 첫 화면에서 장치 선택, 입력 레벨, 스피커 시험, 권한 오류, 네트워크 준비도, 입장 방식과 개인정보 고지를 확인할 수 없으므로 제품 신뢰를 형성하기 어렵다.

저장소의 기존 문서는 일정·코드 입장·대기실·LiveKit 방·화면 공유·임시 채팅·반응·손들기·정책·운영 화면의 기반을 기록한다. 다만 다음 항목은 여전히 운영 승인 Gate이다.

- 서명된 공급자 웹훅, 재처리와 주기적 조정에 의한 권위 있는 참석 기록
- TLS/WSS, TURN/TLS, Redis HA, 다중 노드 라우팅, 드레이닝, 용량과 장애 시험
- 공급자 방 생성·종료의 내구성 있는 명령 영수증과 보상 처리
- 강제 퇴장, 음소거, 로비 복귀, 공동 호스트 회수의 공급자 측 집행
- 녹화·암호화 저장·전사·AI 회의록·법적 보존·삭제 증거의 실제 워커
- 검증된 외부 게스트 신원, 일회성 초대, 남용 방지와 완전한 감사
- 실제 장치·저품질 네트워크·모바일·WCAG 2.2 AA 인증

따라서 문제는 단순한 “버튼 부족”이 아니다. **사용자 기능, 권한 집행, 데이터 거버넌스, 장애 복구와 운영 증거가 하나의 제품 수명주기로 연결되지 않은 것**이 핵심이다.

### 1.3 제품 목표와 비목표

제품 목표는 다음과 같다.

- 인증된 구성원이 2분 이내에 장치와 정책 상태를 이해하고 회의에 입장한다.
- 주최자가 대기실·참가자·발언 순서·화면 공유·채팅·녹화를 한 화면에서 예측 가능하게 운영한다.
- 회의 종료 후 녹화·전사·AI 회의록이 출처와 권한을 보존한 채 준비되고, 사람이 검토한 결정과 할 일이 업무로 이어진다.
- 관리자는 콘텐츠를 읽지 않고도 실패, 용량, 품질, 보존·삭제 이행과 정책 드리프트를 운영한다.
- 민감 회의는 E2EE를 선택하여 서버가 미디어 내용을 복호화하지 못하게 한다.

비목표는 다음과 같다.

- WebRTC 전송, SFU, 혼잡 제어, TURN, 코덱을 자체 구현하지 않는다.
- Zoom 또는 특정 경쟁 제품의 화면·스타일을 복제하지 않는다.
- AI가 사람 대신 회의 결정을 확정하거나 참석자를 평가하지 않는다.
- 얼굴 인식, 감정 추론, 음성 지문 등록, 생산성 점수화를 기본 기능으로 만들지 않는다.
- 운영 관리자 권한을 콘텐츠 검색 권한으로 확장하지 않는다.
- P0에서 PSTN/SIP, 대규모 웨비나, 공개 라이브 스트리밍까지 동시에 일반 제공하지 않는다.

## 2. 제품 원칙

1. **회의가 아니라 결과까지 소유한다.** 일정, 실시간 협업, 결정, 할 일과 근거가 단절되지 않아야 한다.
2. **안전하지 않은 기능은 숨긴다.** 백엔드 집행과 증거가 없는 토글은 비활성 상태와 이유를 보여 준다.
3. **입장 전에는 아무것도 게시하지 않는다.** 미리보기 미디어는 로컬에만 머물며 사용자가 입장 또는 입장 요청을 확정하기 전 송신하지 않는다.
4. **고정된 조작 위치를 유지한다.** 마이크·카메라·자막·손들기·공유·나가기의 위치가 영상 타일 변화로 흔들리지 않는다.
5. **한 번에 하나의 보조 맥락만 연다.** 데스크톱은 하나의 우측 레일, 모바일은 전체 높이 오버레이를 사용한다.
6. **관리와 열람을 분리한다.** 테넌트 정책, 회의 운영, 주최자 권한, 콘텐츠 보관 권한은 서로 다른 역할이다.
7. **수집은 명시적이고 되돌릴 수 있어야 한다.** 녹화·전사·AI 처리 상태와 보존기간을 시작 전과 실행 중에 알린다.
8. **AI는 근거를 제시하고 사람이 결정한다.** 요약·결정·할 일마다 전사 구간 참조를 제공하고 불확실성을 숨기지 않는다.
9. **저품질 환경도 정상 상태다.** TURN 전환, 오디오 전용, 자동 화질 저하, 재연결과 재입장을 제품 흐름으로 다룬다.
10. **관측하되 대화는 기록하지 않는다.** 운영 로그·트레이스에는 채팅 본문, 전사, 제목, 초대 이메일과 미디어가 들어가지 않는다.
11. **접근성과 국제화를 처음부터 설계한다.** 키보드, 스크린 리더, 자막, 200% 확대, 고대비, 긴 한·영문과 시간대를 릴리스 Gate로 둔다.
12. **공급자는 교체 가능하지만 의미는 DWP가 소유한다.** 공급자 ID·오류·토큰을 제품 도메인 밖으로 누출하지 않는다.

#### 캡처 화면을 대체할 프리조인 계약

프리조인은 `포커스 폼`이며 1440px 기준 중앙 12열 그리드 안에서 왼쪽 미디어 미리보기와 오른쪽 준비도 패널로 구성한다.

- 상단: 회의 제목, 주최자, 시작 시각·시간대, `관리형 보안` 또는 `E2EE` 배지, 녹화/전사 예정 고지
- 미리보기: 실제 비디오 또는 아바타, 마이크 입력 레벨, 미러링·배경, 카메라/마이크 로컬 토글
- 준비도: 카메라, 마이크, 스피커 시험, 네트워크, 브라우저 권한을 `준비/주의/차단`으로 표시하고 해결 동작 제공
- 입장: 인증 사용자 이름은 임의 변경하지 않으며, 게스트만 검증된 초대 범위에서 표시명을 입력
- 주 행동: `바로 참가` 또는 `참가 요청`; 정책상 차단되면 비활성 이유와 관리자에게 전달할 오류 코드를 제공
- 개인정보: 녹화·전사·AI 처리 여부, 목적, 기본 보존기간과 정책 링크를 입장 전에 확인 가능
- 실패 상태: 권한 거부, 장치 없음/사용 중, 보안 정책 차단, 코드 만료, 정원 초과, 호스트 부재, TURN 불가, 브라우저 미지원

390px 이하에서는 미리보기 뒤에 준비도 목록을 배치하며 주요 참가 버튼을 화면 하단 안전 영역에 고정한다. 어떤 폭에서도 가로 스크롤을 만들지 않는다.

### 5.2 관리자 제품 계약

- 운영 개요는 인프라 수치보다 `입장 실패 사용자`, `영향 받는 회의`, `지역`, `시작 시각`을 먼저 보여 준다.
- 모든 운영 데이터는 `실시간/지연/중단`, 마지막 성공 갱신과 시간 범위를 표시한다.
- 정책 변경은 현재값, 변경안, 영향 받는 테넌트/부서/향후 회의, 승인·사유, 진행·롤백, 감사 증거를 제공한다.
- 정책 저장은 버전/ETag를 사용하고 오래된 편집을 거부한다. 활성 회의에 즉시 적용되는 항목과 다음 회의부터 적용되는 항목을 구분한다.
- 관리자는 공급자 자격 증명, 원시 토큰, 채팅·전사·제목을 운영 화면에서 볼 수 없다.
- 콘텐츠 보관 담당자는 일반 관리자 메뉴가 아닌 승인된 사례 워크플로를 통해 최소 범위·기간으로 접근한다.
- 분석은 소규모 집단 재식별을 막는 최소 집계 인원과 반올림/억제 기준을 적용한다.
- 대규모 종료나 지역 차단 같은 고영향 동작은 이중 확인, 영향 미리보기, 사유, 진행 상태, 복구 지침이 필요하다.

## 6. 역할·권한 모델

### 6.1 사람 역할 권한표

범례: `✓` 기본 허용, `P` 테넌트/회의 정책 허용 시, `D` 명시적 위임 시, `C` 승인된 컴플라이언스 사례 범위에서만, `—` 불가.

### 6.2 권한 불변식

- 모든 권한은 인증 주체, 테넌트, 회의 멤버십, 역할, 현재 회의 상태, 정책 버전, 데이터 분류를 함께 평가한다.
- `MEETING_ADMIN` 또는 테넌트 관리자라는 이유만으로 녹화·전사·채팅 본문을 읽을 수 없다.
- 공동 호스트 위임은 회의·기능·만료 범위를 갖고 즉시 회수 가능해야 하며 공급자 권한에도 반영한다.
- 호스트도 참가자의 마이크나 카메라를 동의 없이 켤 수 없다. 음소거·영상 중지 또는 활성화 요청만 허용한다.
- 비상 종료는 서비스 보호 동작이며 콘텐츠 접근을 부여하지 않는다.
- 보관 담당자의 열람·검색·반출은 사건 번호, 범위, 목적, 승인자, 만료, 워터마크, 감사 이벤트가 모두 있어야 한다.
- 외부 게스트는 조직 사용자와 시각적으로 구분하고, 전달 가능한 초대 URL만으로 신뢰하지 않는다.

### 6.3 서비스 주체

| 서비스 주체      | 최소 권한                               | 금지 사항                               |
| ---------------- | --------------------------------------- | --------------------------------------- |
| 미팅 API         | 제어 메타데이터·공급자 명령 생성        | 원시 미디어 저장                        |
| 공급자 조정 워커 | 미완료 명령 재시도·상태 조정            | 사용자 콘텐츠 조회                      |
| Egress 워커      | 특정 회의·출력 버킷 쓰기, 단기 키       | 다른 테넌트 버킷 목록·장기 키           |
| STT 워커         | 승인된 녹화/오디오 읽기, 전사 출력 쓰기 | 범용 검색·모델 학습                     |
| AI 회의록 워커   | 최소 전사 구간 읽기, 구조화 초안 쓰기   | 자동 발행·자동 업무 실행·외부 도구 호출 |
| 보존/삭제 워커   | 만료 인덱스 조회·삭제·증거 기록         | 법적 보존 해제                          |

워크로드 신원은 짧은 수명의 서명된 신원 또는 workload identity를 사용한다. 로컬 정적 서비스 토큰은 운영 신뢰 모델이 아니다.

## 7. 데이터 분류, 보안 모드와 보존

### 7.1 데이터 분류

| 등급          | 예시                                                      | 기본 통제                                                         |
| ------------- | --------------------------------------------------------- | ----------------------------------------------------------------- |
| C0 공개       | 공개 웨비나 제목·공개 설명                                | 무결성, 게시 승인                                                 |
| C1 내부 운영  | 회의 ID, 예정 시각, 상태, 집계 품질, 비식별 통계          | 테넌트 격리, 전송/저장 암호화, 최소 로그                          |
| C2 기밀 협업  | 참석자, 채팅, 파일 링크, 녹화, 전사, AI 회의록, 참석 세부 | 객체 단위 ACL, KMS 키, 감사, 반출 통제, 제한 검색                 |
| C3 고도 기밀  | 법무·인사·M&A·보안사고 등 지정 회의                       | E2EE 또는 강화 관리형 모드, 다운로드 기본 금지, 별도 키·보존·승인 |
| 규제 오버레이 | 개인정보, 민감정보, 법적 보존, 국외 이전 제한             | 등급 위에 목적·법적 근거·지역·처리자·권리 요청 정책 추가          |

음성·영상·전사는 개인을 식별할 수 있는 C2 이상 데이터로 취급한다. 화자 분리는 회의 세션 신원 매핑으로 수행하며, 음성 지문을 등록하거나 생체 식별에 재사용하지 않는다.

### 7.2 공통 보안 통제

- 인증: 기업 IdP의 OIDC/SAML, MFA/조건부 접근, 외부 게스트 일회성 초대와 재인증
- 인가: 서버 측 ABAC/RBAC, 테넌트는 인증 컨텍스트에서 결정하고 요청 본문 값을 신뢰하지 않음
- 토큰: 룸·참가자·미디어 소스별 최소 권한, 짧은 TTL, 대기실 승인 후 발급, 회수·재발급
- 전송: HTTPS/WSS, DTLS-SRTP, TURN/TLS 443 대체 경로, 내부 mTLS 또는 workload identity
- 저장: 테넌트/지역별 KMS envelope encryption, 객체 버전·무결성 해시, 비밀 저장소와 키 회전
- 경계: WAF·속도 제한·코드 대입 방지, 초대 토큰 단일 사용, 서명 웹훅과 replay 방지
- 애플리케이션: OWASP ASVS 기반 위협 모델, 입력/출력 인코딩, CSRF·SSRF·권한 우회·파일 악성 검사
- 공급망: SBOM, 서명 이미지, 취약점/비밀 스캔, 승인된 기반 이미지와 패치 SLA
- 감사: 정책·역할·입장·거절·녹화·열람·반출·보존·삭제를 append-only 증거로 기록
- 개인정보: 목적 제한·최소 수집·기본 비공개·처리자 계약·지역 통제·권리 요청·삭제 증거
- AI: 테넌트 데이터 일반 모델 학습 금지, 승인된 지역/처리자, 입력 최소화, 프롬프트 인젝션을 비신뢰 데이터로 처리

### 7.3 관리형 보안과 E2EE 이중 모드

일반 WebRTC의 DTLS-SRTP 구간 암호화를 E2EE라고 표기하지 않는다. SFU 또는 Egress가 내용을 처리할 수 있는 회의는 `관리형 보안 회의`이다. RFC 9605 SFrame과 별도 검증된 그룹 키 관리로 SFU가 미디어 본문을 복호화할 수 없을 때만 `비공개 E2EE 회의`라고 표시한다.

| 항목                   | 관리형 보안 회의                          | 비공개 E2EE 회의                                                             |
| ---------------------- | ----------------------------------------- | ---------------------------------------------------------------------------- |
| 미디어 보호            | 클라이언트↔SFU 구간 암호화, SFU 처리 가능 | 구간 암호화 + SFrame 미디어 E2EE, SFU 본문 복호화 불가                       |
| 서버 녹화              | 정책·고지·권한 충족 시 가능               | 불가                                                                         |
| 서버 실시간 자막/전사  | 가능                                      | 불가                                                                         |
| AI 회의록              | 전사 기반, 검토 전 초안으로 가능          | 불가                                                                         |
| 화면 공유              | 가능                                      | SFrame 지원 화면 트랙만 가능                                                 |
| 채팅                   | 서버 중계/보존 정책 가능                  | 별도 감사된 E2EE 데이터 프로토콜 없으면 비활성; P2 초기에는 임시 메타 신호만 |
| 검색/eDiscovery        | ACL·사례 승인 범위에서 가능               | 서버 콘텐츠 검색 불가                                                        |
| SIP/PSTN/라이브 스트림 | 정책상 가능                               | 불가                                                                         |
| 참가자 제거/입장 통제  | 가능                                      | 신호 평면에서 가능, 콘텐츠 복호화 권한은 없음                                |
| 키                     | KMS 관리 저장 키                          | 엔드포인트 그룹 키, 서버 미보유; 입·퇴장 시 epoch 회전                       |
| 모드 변경              | 예약/입장 전 확정                         | 회의 중 조용한 하향 전환 금지; 새 회의 필요                                  |

E2EE는 다음 Gate를 모두 통과한 후 P2 제한 제공한다.

1. 검증된 SFrame 구현과 외부 암호 검토를 사용하며 자체 암호 알고리즘을 만들지 않는다.
2. 키 합의·신원 바인딩·장치 추가·분실·입퇴장 epoch 회전·재접속을 포함한 그룹 키 설계를 별도 ADR로 승인한다.
3. 모든 참가자가 상대 신원과 E2EE 상태를 검증할 수 있고, 지원하지 않는 클라이언트는 입장하지 못한다.
4. 녹화·자막·AI·PSTN 등 비호환 기능은 예약·프리조인·회의실에서 동일하게 차단 사유를 표시한다.
5. 서버 또는 참가자가 모드를 조용히 낮출 수 없다. 변경은 모든 사용자에게 보이는 새 세션으로만 가능하다.
6. 키·평문·민감 메타데이터가 로그, 크래시 덤프, 분석 도구에 남지 않는지 검증한다.

### 7.4 기본 보존표

아래 기간은 제품의 제안 기준선이며 법정 보존기간을 선언하지 않는다. 테넌트의 목적, 관할 법률, 계약과 분류에 따라 개인정보/법무 승인을 거쳐 더 짧게 또는 필요한 범위에서 조정한다. 무기한 보존은 제공하지 않는다.

| 데이터                         | 제안 기본값   | 허용 정책          | 만료 시 동작                       |
| ------------------------------ | ------------- | ------------------ | ---------------------------------- |
| 예정/완료 회의 메타데이터      | 종료 후 365일 | 30~2,555일         | 비식별 집계 외 삭제                |
| 권위 있는 참석 기록            | 종료 후 365일 | 30~2,555일         | 세부 삭제, 승인 집계만 유지        |
| 대기실·반응·손들기 원시 이벤트 | 24시간        | 0~30일             | 원시 이벤트 삭제                   |
| 회의 채팅                      | 종료 후 90일  | 0~365일            | 본문·첨부 참조·검색 인덱스 삭제    |
| 녹화                           | 종료 후 90일  | 0~365일            | ACL 즉시 철회 후 객체·파생물 삭제  |
| 전사                           | 종료 후 90일  | 녹화 이하          | 원문·편집본·검색/임베딩 삭제       |
| AI 회의록 초안/발행본          | 종료 후 90일  | 원천 전사 이하     | 초안·버전·임베딩 삭제              |
| 원시 QoE/진단 텔레메트리       | 30일          | 7~90일             | 원시 식별자 삭제, 승인 집계만 유지 |
| 보안·권한·반출·삭제 감사       | 365일         | 조직 감사정책 범위 | 무결성 보존 후 정책에 따라 삭제    |
| 삭제 영수증                    | 365일         | 감사정책 범위      | 콘텐츠 없는 증거만 유지            |

보존 기간은 파생 데이터가 원천보다 길어지지 않도록 상한을 상속한다. 법적 보존은 만료를 일시 중지하지만 새 콘텐츠를 복원하거나 범위를 자동 확대하지 않는다.

## 8. 녹화·전사·AI 회의록 수명주기

### 8.1 전체 흐름

```text
회의 정책/분류/법적 근거 확인
        │
        ├─ E2EE 또는 차단 ──> 기능 비활성 + 이유·감사
        │
        v
녹화 요청 -> 고지/권한 확인 -> Egress 시작 -> 캡처 -> 종료/최종화
                                                   │
                                      암호화 객체 + 해시 + ACL
                                                   │
                                                   v
                                STT 대기 -> 전사 -> 화자/시간 정렬
                                                   │
                                  수정/가림 -> 최종 전사 버전
                                                   │
                                                   v
                             AI 생성 -> 근거 연결 초안 -> 사람 검토
                                                   │
                                기각/수정/발행 -> 승인된 업무 연결
                                                   │
                                                   v
                           보존 만료/삭제 요청/법적 보존 판정
                                                   │
                       접근 철회 -> 객체·색인·임베딩·파생물 삭제
                                                   │
                                             삭제 영수증
```

### 8.2 상태 모델

| 아티팩트  | 상태                           | 허용 전이와 의미                                          |
| --------- | ------------------------------ | --------------------------------------------------------- |
| 녹화      | `DISABLED`                     | 정책, E2EE, 동의 고지, 인프라 중 하나라도 불충족          |
|           | `REQUESTED` → `STARTING`       | 멱등 명령 영수증 생성 후 공급자 요청                      |
|           | `RECORDING` → `FINALIZING`     | 지속 배지·참가자 알림, 중지 후 업로드 검증                |
|           | `AVAILABLE`                    | 객체 해시·길이·암호화·ACL·보존 만료가 확정됨              |
|           | `FAILED`/`PARTIAL`             | 재시도 가능 여부, 손실 구간, 사용자 영향과 운영 사건 연결 |
| 전사      | `QUEUED` → `PROCESSING`        | 승인된 녹화/오디오와 언어로 처리                          |
|           | `DRAFT`                        | 화자·시간 정렬 전 또는 신뢰도 낮은 구간 포함              |
|           | `REVIEW_REQUIRED` → `FINAL`    | 사람의 수정·가림과 버전 이력 유지                         |
|           | `FAILED`/`UNSUPPORTED`         | 언어·오디오·처리자 오류를 구분                            |
| AI 회의록 | `QUEUED` → `GENERATING`        | 최종 또는 정책상 허용된 전사 버전만 입력                  |
|           | `DRAFT`                        | 근거 구간·모델/프롬프트 버전·생성 시각을 가진 비공식 결과 |
|           | `REVIEWED` → `PUBLISHED`       | 검토자, 수정 내역, 대상 ACL과 버전 확정                   |
|           | `REJECTED`/`FAILED`            | 사용자 기각 또는 생성 실패, 자동 재발행 금지              |
| 공통      | `HELD`                         | 승인된 법적 보존으로 만료 일시 중지                       |
|           | `DELETION_PENDING` → `DELETED` | 접근 철회부터 모든 저장소 삭제와 증거 완료                |

### 8.3 수명주기 불변식

- 녹화 시작 전 서버는 회의 분류, 보안 모드, 테넌트 정책, 실행자 권한, Egress 준비도, 저장 지역과 용량을 다시 평가한다.
- 고지 또는 확인이 필요한 관할·정책에서는 참가자에게 이해 가능한 고지와 선택지를 제공한다. 단순한 UI 동의를 모든 관할의 유일한 법적 근거로 가정하지 않는다.
- 중간 파일은 최종 객체와 동일한 등급·지역·키 정책을 적용하고 작업 완료/실패 후 정해진 TTL에 제거한다.
- 전사 편집은 원문 오디오를 덮어쓰지 않고 새 버전과 편집 근거를 만든다. 민감 구간 가림은 재생·검색·AI 입력에도 일관되게 적용한다.
- AI 입력은 의제, 승인된 전사 구간과 최소 참석자 맥락으로 제한한다. 공유 문서와 전사 안의 지시문은 데이터이지 에이전트 명령이 아니다.
- AI 출력 스키마는 `요약`, `논점`, `결정 후보`, `할 일 후보`, `미해결 질문`, `위험`, `sourceSegmentIds`, `confidenceState`를 포함한다.
- 근거가 없는 결정·담당자·기한은 사실처럼 생성하지 않고 `확인 필요`로 표시한다.
- AI 에이전트는 검토 없이 태스크 생성, 메시지 전송, 결재 상신, 외부 API 호출을 실행하지 않는다.
- 열람 때마다 현재 멤버십·ACL·보존·법적 보존·분류를 재평가하며, 과거 공유 링크가 권한을 고정하지 않는다.
- 원천 전사가 삭제되면 그 전사에서 파생된 AI 초안·검색 색인·임베딩도 삭제한다. 독립된 공식 결정 기록은 별도 목적·승인·보존정책으로 복제되어야 한다.

### 8.4 삭제와 법적 보존

1. 만료 또는 적법한 삭제 요청을 수신하면 아티팩트를 `DELETION_PENDING`으로 만들고 신규 공유·다운로드·AI 처리를 1분 안에 차단한다.
2. 법적 보존 인덱스를 확인한다. 일치하면 삭제하지 않고 최소 메타데이터와 제한 사유를 기록한다.
3. 녹화 객체·HLS 조각·썸네일·임시 파일, 전사 원문/편집본, 채팅, AI 버전, 검색 색인, 임베딩, 캐시와 CDN을 계보 순서로 삭제한다.
4. 실패 항목은 지수 백오프와 DLQ로 재시도하고 운영 사건을 연다. 일부 성공을 전체 성공으로 표시하지 않는다.
5. 온라인 저장소 삭제, 키 폐기, 백업 만료 예정일, 삭제된 파생물 수와 해시 없는 증거를 삭제 영수증에 기록한다.
6. 백업은 임의 복원 열람을 막고 정책 주기 안에서 만료 또는 암호학적 삭제한다. 복구 훈련 시 삭제 tombstone을 재적용한다.
7. 법적 보존 해제는 생성자와 다른 승인자 또는 정책상 이중 승인 후에만 가능하며 즉시 원래 만료 평가로 돌아간다.

### 9.2 일관성과 실패 모델

- 공급자 API와 PostgreSQL은 단일 트랜잭션이 아니므로 `PREPARING`, `RUNNING`, `ENDING`, `FAILED` 상태와 내구성 있는 명령 영수증을 사용한다.
- 생성·시작·종료·녹화 명령은 `Idempotency-Key`와 aggregate version을 갖는다. 재시도는 중복 방이나 중복 녹화를 만들지 않는다.
- 공급자 웹훅은 최소 한 번 전달로 가정하고 `eventId`로 중복 제거한다. 웹훅 유실 가능성을 전제로 5분 이내 조정 작업을 수행한다.
- 브라우저의 `connected`/`leave` 알림은 즉시 UX에 쓰되 권위 있는 참석 기록은 공급자 이벤트와 조정 결과로 확정한다.
- 부분 실패를 정상 상태로 덮지 않는다. 예를 들어 회의는 종료됐지만 녹화 최종화가 실패하면 회의와 아티팩트 상태를 분리한다.

```text
Global DNS / CDN / WAF
          │
          v
선택된 데이터 지역(예: KR)
├─ 3개 AZ 제어 평면
│  ├─ API Gateway + Meeting API replicas
│  ├─ PostgreSQL HA + PITR
│  ├─ Kafka/Outbox/Inbox + DLQ
│  ├─ Redis HA(제어 캐시, SFU 클러스터는 전용 분리 권장)
│  └─ OTel Collector + metrics/logs/traces
├─ 미디어 평면
│  ├─ Regional L4 LB
│  ├─ LiveKit SFU nodes(최소 2, room affinity, drain)
│  └─ TURN/TLS 443 + UDP/TCP 경로
├─ 격리 워커 평면
│  ├─ Egress autoscaling pool
│  ├─ STT/redaction pool
│  ├─ AI orchestration pool
│  └─ retention/reconciliation workers
└─ 지역 고정 저장
   ├─ KMS encrypted object storage + lifecycle
   ├─ ACL-aware search/index
   └─ immutable audit evidence
```

### 배포 규칙

- 제어·미디어·Egress·STT/AI 워커 풀을 분리하여 녹화 급증이 실시간 회의를 불안정하게 만들지 않게 한다.
- LiveKit 다중 노드는 Redis 기반 라우팅과 방 affinity를 사용한다. 노드 종료 전 신규 방 배정을 중지하고 활성 방을 드레이닝한다.
- 각 지역에 routable 주소와 TLS/WSS, UDP ICE, WebRTC/TCP, TURN/TLS 443를 제공한다. 로컬 `127.0.0.1` 광고 설정은 운영에 사용하지 않는다.
- 미디어 방은 회의 도중 다른 지역으로 무손실 이동할 수 있다고 가정하지 않는다. 같은 지역 재연결을 우선하고 지역 장애 시 명시적 재입장·새 방 복구 절차를 제공한다.
- 테넌트 데이터 지역은 회의 생성 시 결정해 아티팩트·STT·AI 처리 지역까지 고정한다. 승인 없는 국외 이동을 허용하지 않는다.
- 운영 기본 복구 목표는 제어 메타데이터 `RPO ≤ 5분`, `RTO ≤ 30분`이다. 진행 중 미디어의 무손실 복구는 별도 고가용성 시험 없이는 약속하지 않는다.
- Egress 동시성은 “동시 녹화 회의 수 × 출력 종류 × 트랜스코딩 프로필”로 산정하고 별도 예약 용량과 큐 임계치를 둔다.
- 배포는 canary → 소규모 테넌트 → 단계 확대 순으로 진행하며, join success·reconnect·TURN·crash 지표를 자동 롤백 Gate로 사용한다.

## 11. API와 이벤트 경계

### 11.1 API 원칙

- Gateway 아래 `/api/meetings/**`만 브라우저에 노출하며 공급자 API·SID·비밀을 직접 노출하지 않는다.
- 테넌트는 인증 컨텍스트에서 결정한다. `tenantId` 요청 파라미터로 권한 범위를 바꾸지 않는다.
- 명령은 `Idempotency-Key`, 갱신은 `If-Match`/version, 오류는 일관된 Problem Details 구조와 안전한 오류 코드를 사용한다.
- 목록은 커서 페이지네이션, 서버 필터, 정렬과 스코프를 사용한다. 콘텐츠 본문을 운영 목록 응답에 혼합하지 않는다.
- join credential은 짧은 TTL과 단일 회의/참가자/소스 grant를 가지며 URL, 로그, 분석 이벤트에 기록하지 않는다.
- OpenAPI 계약과 생성 클라이언트가 구현의 권위이며 아래 경로는 경계 정의용 초안이다.

### 12.2 관측 신호

| 계층        | 핵심 신호                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------- |
| 사용자 여정 | 프리조인 완료, 권한 거절, 입장 거절 이유, 대기 시간, 재입장, 안전한 종료                                |
| 제어 평면   | 요청률·오류·지연, DB/Kafka/Redis 포화, outbox/inbox lag, 명령 영수증 age                                |
| 미디어      | ICE 경로, TURN fallback, RTT, jitter, packet loss, audio concealment, freeze, frames dropped, reconnect |
| 공급자      | 방·참가자 드리프트, 웹훅 서명 실패·재시도·DLQ, reconciliation lag                                       |
| 아티팩트    | Egress 큐/성공/부분 실패, 업로드·해시, STT/AI 대기·처리·실패, 삭제 backlog                              |
| 거버넌스    | 무권한 거절, 정책 변경, 반출, hold, 삭제 SLA 위반, 키 회전·비밀 만료                                    |

OpenTelemetry trace/metric/log 상관관계를 사용하되 다음을 금지한다.

- 채팅·전사·AI 출력·회의 제목·초대 이메일·토큰·서명·객체 URL 로깅
- 고카디널리티 원시 참가자 ID의 장기 메트릭 라벨
- 사용자의 동의·목적 없이 원시 IP, 장치 지문, 카메라 사용 행동을 장기 보존
- 운영 대시보드에서 한 명의 발언량·감정·성과 추론

허용되는 상관 키는 제한된 접근의 `traceId`, opaque `meetingId`, 회전 가능한 가명 participant key, tenant/region/browser family, 오류 코드이다. 진단 번들은 사용자가 검토·제출하며 기본적으로 콘텐츠와 미디어를 포함하지 않는다.

### 12.3 대시보드와 경보

- `Join Funnel`: resolve → auth → lobby → token → signal → ICE → first audio 단계와 실패 이유
- `Active Impact`: 영향 사용자/회의/지역, 시작 시각, 마지막 정상, 우회 경로
- `Media Quality`: TURN 비율, packet loss, RTT, reconnect를 지역·브라우저·네트워크 유형별 집계
- `Provider Drift`: DB와 공급자의 방·참석·Egress 차이, 가장 오래된 불일치
- `Artifact Pipeline`: 큐 깊이, 처리 시간, 실패, 저장 용량, 삭제 backlog와 만료 임박
- `Policy & Security`: 정책 변경, 이상 입장, 초대 대입, 권한 거절, 반출·hold·삭제 증거

경보는 사용자 영향과 런북 링크를 포함한다. `입장 성공 급락`, `TURN 전체 실패`, `웹훅 수렴 5분 초과`, `녹화 누락`, `삭제 SLA 위반`, `테넌트 경계 거절 이상`은 호출 대상 경보다. 개별 참가자의 일시적 jitter는 집계·지속 임계치 없이는 호출하지 않는다.

## 15. 개발 착수 체크리스트

- [ ] 제품·보안·개인정보·SRE가 P0 범위와 이중 보안 모드를 승인했다.
- [ ] 데이터 지역, 제안 보존표, 녹화·전사·AI의 처리 목적/법적 근거/처리자가 등록됐다.
- [ ] 회의·멤버십·역할·정책·아티팩트 상태 머신과 이벤트 스키마가 버전 관리된다.
- [ ] 기능별 추적 ID가 화면, API 권한, 공급자 grant, 감사 이벤트, 수용 테스트를 연결한다.
- [ ] 프리조인·룸·리캡·Admin의 1440/1280/390/320px, 200% 확대, light/dark/high-contrast 설계가 검토됐다.
- [ ] LiveKit 운영 토폴로지, TURN 포트, Redis 분리, Egress/STT/AI 용량과 비용 모델이 승인됐다.
- [ ] 공급자 명령 영수증, 서명 웹훅, replay/DLQ, reconciliation과 장애 주입 계획이 정의됐다.
- [ ] 객체 ACL, KMS 키, lineage, 검색, 만료·hold·삭제 영수증의 데이터 계약이 준비됐다.
- [ ] AI 평가셋에 한국어/영어, 중첩 발화, 근거 부족, 잘못된 담당자/기한, 민감정보, 프롬프트 인젝션이 포함됐다.
- [ ] SLO·오류 예산·대시보드·경보·런북·canary/rollback 기준이 릴리스 파이프라인에 연결됐다.
- [ ] E2EE는 별도 ADR·암호 검토 완료 전 feature flag가 fail-closed이다.

## 17. 최종 제품 정의

DWP 화상회의의 완성 기준은 영상 타일과 버튼 수가 아니다. 사용자가 안전하게 입장하고, 호스트가 권한을 예측 가능하게 행사하며, 회의가 장애에도 복구되고, 녹화·전사·AI 회의록이 근거·권한·보존·삭제 수명주기를 지키며, 관리자가 내용을 읽지 않고도 이를 운영할 수 있어야 한다.

P0는 이 기준의 최소 완성형이다. P1과 P2는 그 위에 협업 깊이, 외부 연결, E2EE와 대규모 채널을 추가한다. 각 기능은 화면, 서버 인가, 공급자 집행, 데이터 계보, 감사, 실패 상태, 수용 증거가 모두 연결될 때만 완료로 선언한다.
