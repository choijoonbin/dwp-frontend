# U01–U15 디자인 재감사 · 전체 시안 교차검토

기록일: 2026-09-04. 상태: **30개 프레임 수령 / 교차검토 중 / 퍼블리싱 명세 미확정**.

파일명은 감사 작업의 추적 식별자이며 디자인 승인이나 구현 완료를 뜻하지 않는다.
사용자가 전체 개발을 요청했고, 루트 검토에서 01–15의 데스크톱·모바일 30개 프레임을
확인했다. 00은 별도 화면이 아니라 공통 디자인 계약이다. 공통 정보구조·반응형 계약과
원본 DOM 실측을 교차 검토한 뒤 화면별 퍼블리싱 명세를 확정한다.
이 문서는 UI 계층·공유 컴포넌트·반응형 책임을 소유한다. 데이터·API·DB의 정본 설계는
기획/아키텍처 담당 결과와 연결하되 이 문서에서 임의 확정하지 않는다.
현재 코드·공통 셸·토큰을 변경하지 않았고, 30개 프레임의 세부 검증 완료를 뜻하지 않는다.

## 1. 근거와 완료 판정 정정

사용자 제공 Stitch 프로젝트:
<https://stitch.withgoogle.com/projects/13391261371843159731>

- 데스크톱: `DWP Meetings: Today & Next Action (화상회의 홈 1440px) - Polished`
- 모바일: `DWP Meetings: Mobile Home (화상회의 모바일 390px) - Polished`
- 사용자 첨부: 2026-09-04 오후 2.07.29 / 2.07.36 캡처
- 공통 및 화면별 입력 계약: `output/meeting-design-ai-2026-09-04/prompts/00`–`15` 문서
- 현재 구현 비교: `e2e/video-meeting-visual-quality.spec.ts-snapshots/`의
  `meeting-home-sample-en-1280-light-chromium-darwin.png` 및
  `meeting-home-live-ko-390-dark-chromium-darwin.png`

루트가 확인한 프레임 이름은 데스크톱 `1440px`를 포함하지만 캔버스 node의 실제 폭은
1280px, 모바일은 390px다. 따라서 원본 native 1280px/390px 비교와 1440px 확장 반응형
검증을 구분한다. 이름만 보고 원본을 1440px로 확대하거나 축소한 값을 실측값으로 쓰지 않는다.

현재 비교 이미지의 언어·테마·뷰포트·데이터가 원본과 다르므로 픽셀 일치율을 산출하거나
원본 치수를 추정값으로 확정하지 않는다. 다만 아래 정보구조 차이는 조건 차이와 무관하게
현재 소스와 이미지 양쪽에서 확인된다.

기존 `03-stitch-home-implementation.md`의 기능 테스트 통과 기록은 기능 회귀의 근거다.
그 기록과 새로 생성한 구현 스냅샷만으로 승인 시안과의 시각적 일치 또는 U01 디자인 완료를
입증할 수 없다. 현재 디자인 완료 판정은 철회된 상태다.

## 2. 확인된 차이

| 영역      | 승인 시안에서 보이는 구성                                  | 현재 구현에서 확인한 차이                                  |
| --------- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 상단      | 압축된 맥락·신선도, 제목, 짧은 행동 줄                     | 설명문·갱신 줄·44px 액션 조합이 전체 세로 길이를 늘림      |
| 핵심 회의 | 제목·메타·참가자·구조화된 안건과 진행 상태, 독립 행동 영역 | 참가자 수·일반 안건 문자열로 축소되어 정보의 형태가 다름   |
| 안건      | 작은 순번·제목·시간 등 구조화된 항목                       | 하나의 일반 설명문 박스                                    |
| 오늘 일정 | 시간축, 역할·상태, 짧은 보조 명령의 밀집 목록              | 행 내부 설명·간격과 모바일 세로 분해가 커짐                |
| 처리할 일 | 검토·기한·업무 인수 등 서로 다른 다음 행동                 | 최근 회의의 검토 가능한 초안만 투영                        |
| 하단      | 최근 결과와 템플릿·개인 회의실의 병렬 영역                 | 최근 결과가 전체 폭이며 도구 영역 없음                     |
| 모바일    | 본문 재배치와 전용 하단 탐색                               | 일반 세로 축소이며 하단 탐색 없음                          |
| 빈 상태   | 원본은 데이터가 채워진 대표 상태                           | 큰 중앙 빈 상태가 공간을 차지해 같은 구성을 비교할 수 없음 |

따라서 문제를 색상·테두리·모서리 교체로 축소하지 않는다. 정보의 형태, 우선순위,
공간 비율, 첫 화면에서 보이는 업무량을 먼저 교정해야 한다.

## 3. 화면의 업무 정의

- 주 사용자: 회의 참가자·주최자·명시적으로 지정된 검토자.
- 첫 질문: “지금 어떤 회의에 들어가거나 준비해야 하며, 다음에 어떤 결과를 처리해야 하는가?”
- 주 행동: 현재 또는 다음 회의의 입장·준비.
- 주 유형: command center. 정보 밀도는 structured이며 단순 KPI 나열이 아니다.
- 사용자 메뉴와 관리자 정책·운영 메뉴는 분리한다. 사용자 하단 탐색에 관리자 메뉴를
  대신 넣어 슬롯을 채우지 않는다.

## 4. 전체 시안 교차검토에서 확정할 계약

아래 항목은 홈 단독으로 확정하지 않는다.

1. 확인한 30개 프레임의 최종 번호·이름·데스크톱/모바일 대응 관계와 최신 버전.
2. 홈의 큐·최근 결과·템플릿·개인 회의실에서 이동하는 정확한 목적 화면.
3. 모바일 하단 탐색의 항목·선택 상태·업무 범위. 기존 경로로 임의 대체하지 않는다.
4. 구조화된 안건·진행률·자료·참가 응답·마감·인수 항목의 실제 데이터 소유자와 갱신 주기.
5. 권한별 가시성, 비활성 사유, 기능 미제공과 실제 빈 결과의 구별.
6. 공통 셸의 유지 부분과 사용자 승인으로 바뀌어야 하는 부분.

기능이 아직 없다면 영역을 몰래 삭제하거나 가짜 데이터·동작하지 않는 링크로 채우지 않는다.
전체 설계에서 구현 순서와 중간 상태를 결정하고, 실제 제공 범위를 분명하게 표시한다.

## 5. 원본과 DWP 공통 셸의 경계

현재 정본 토큰은 인라인 사이드바 확장 248px / 축소 72px, 헤더 64px다.
페이지는 공통 `PageCanvas mode="workspace"`의 fluid 폭과 gutter를 사용한다.
이 값은 원본 Stitch를 실측한 값이 아니라 현재 DWP의 공통 계약이다.

- 전역 헤더·검색·사용자·워크스페이스·권한·사이드바를 Meeting에서 중복 구현하지 않는다.
- 전체 시안 교차검토 전 Meeting만 공통 셸 크기나 페이지 최대폭을 바꾸지 않는다.
- 원본 전체 프레임 비교와 셸을 제외한 콘텐츠 프레임 비교를 구분한다. 서로 다른 셸 크기를
  숨긴 채 전체 화면이 같다고 보고하지 않는다.
- 모바일 하단 탐색은 전체 IA와 셸 계약을 검토한 후 책임 영역을 정한다. 이 문서에서
  새 탐색 메뉴·홈 섹션 이동·비활성 버튼 중 하나를 임의로 승인하지 않는다.
- DWP public ActionButton·FormField·SectionHeader·상태·포커스·토큰 계약을 유지한다.
  원본의 작은 글자·터치 영역과 접근성 계약이 충돌하면 차이와 보정 근거를 명시한다.

## 6. 후속 설계의 측정 기준

루트가 원본 Stitch DOM에서 U01과 U10의 좌표·스타일을 수집했다. 아래 일반 비교 항목과
12절의 실측값을 함께 사용한다. 나머지 화면의 세부 측정 및 승인 허용 오차는 미확정이다.

| 기준         | 수집할 근거                                    | 판정 방법                                     |
| ------------ | ---------------------------------------------- | --------------------------------------------- |
| 콘텐츠 폭    | 원본·구현의 canvas 시작/끝 X, 셸과 gutter      | 동일 뷰포트에서 좌우 정렬 비교                |
| 상단 밀도    | 맥락 줄·제목·행동 줄의 Y와 높이                | 원본과 같은 단계·읽기 순서인지 확인           |
| 핵심 회의    | 전체 높이, 정보/행동 열 비율, 내부 padding     | 데스크톱 병렬·모바일 전환 비교                |
| 주요 2열     | 일정/큐 각각의 폭, 열 간격, 상단 정렬          | 현재 임의 비율을 승인값으로 재사용하지 않음   |
| 하단 2열     | 결과/도구 폭과 시작 Y                          | 실제 기능 연결을 포함한 구성 비교             |
| 타이포그래피 | 제목·본문·메타의 계산된 크기·행간·굵기         | 한영 긴 문구에서도 계층 유지                  |
| 반복 행      | 행 높이, 시간 열, 상태, 행동 정렬              | 공간을 빈 설명이나 중첩 카드로 대체하지 않음  |
| 첫 뷰포트    | 보이는 회의·안건·일정·처리 항목의 수           | 단순 전체 페이지 길이가 아닌 업무 노출량 비교 |
| 모바일       | 영역 순서, 콘텐츠 폭, 하단 탐색 높이·safe area | 가려짐·이중 탐색·겹침·수평 넘침 없음          |

색·반경·그림자·폰트는 원본의 역할을 DWP 토큰에 매핑하고, 불일치가 불가피하면
설계 결정으로 남긴다. 임의 숫자나 색을 feature source에 넣어 공통 Gate를 우회하지 않는다.

## 7. 데이터 상태별 구조 검토

전체 화면과 데이터 계약 확정 후 다음 상태를 각각 설계한다.

- **정상 데이터:** 같은 fixture로 원본과 구현의 레이아웃을 비교한다. fixture는 테스트 전용이다.
- **로딩:** 핵심 정보·목록·도구 영역의 실루엣을 유지하고 민감한 이전 데이터를 재사용하지 않는다.
- **진짜 빈 결과:** 제목과 영역 관계는 유지하되, 반복 객체가 없는 이유와 가능한 실제 다음 행동을
  짧게 안내한다. 큰 중앙 일러스트로 구성 자체를 바꾸지 않는다.
- **기능 미제공:** “0건” 또는 “정상”으로 표현하지 않는다. 연동·정책·권한 중 원인을 구분한다.
- **부분 오류:** 실패 영역만 오류와 재시도로 전환하되, 권한이 검증되지 않은 민감 데이터는 숨긴다.
- **권한 변경:** 이전 초안·참가자·회의 정보를 잔존시키지 않는다. 모양 보존을 이유로 캐시를 노출하지 않는다.
- **전체 권한/홈 실패:** 실내용 없는 구조와 명확한 복구 안내를 제공하고 실행 명령은 차단한다.

원본의 장치 정상·참가자 전원 수락·암호화 수준·AI 자동 처리 등 표현은 백엔드가 보장하는
근거가 있을 때만 사용한다. 디자인 충실도는 허위 보안·AI 상태를 표시할 이유가 아니다.

## 8. 전문가 협업과 종료 조건

전체 최종 시안 수령(완료) → 기획/메뉴·데이터 계약 검토 → 디자인 실측 및 차이 승인 →
아키텍처·권한·상태 설계 → 퍼블리싱 → 실제 동작 연결 → 원본 대조와 회귀 검증 순서로 진행한다.

각 역할은 다음 근거를 남긴다.

- 기획: 메뉴 맵, 홈의 각 행동과 목적 화면, 필수/후속 범위.
- 디자인: 원본 측정표, DWP 토큰 매핑, 모바일 전환, 허용된 차이 목록.
- 아키텍처/개발: 실제 Source of Record, API·권한·캐시 경계, 오류·취소·재시도.
- 퍼블리셔: 원본 기준 layout·type·spacing·component 상태 구현.
- 독립 QA: 같은 데이터·언어·테마·뷰포트의 원본/구현 비교와 동작·접근성 회귀.

필수 검증은 1440/1280/390/320px, 200% 확대, light/dark/high contrast/reduced motion,
키보드·포커스·스크린리더·긴 한영 문구·부분 실패다. 먼저 원본 native 1280px/390px 한국어
light의 대표 정상 상태를 비교하고 1440px 확장을 따로 확인한다. 새 구현 이미지를 baseline으로 갱신한 사실만으로
원본 일치를 승인하지 않는다.

**현 단계 결론:** 전체 프레임 수령은 끝났고 세부 교차검토를 진행한다. 원본 측정과 상태별
설계가 끝나기 전에 U01 또는 전체 디자인 완료를 다시 선언하지 않는다.

## 9. 공통 UI 계층과 퍼블리싱 책임

다음은 00 공통 계약과 01–15 전체 프롬프트를 읽은 뒤 정리한 구성 책임이다.
컴포넌트 이름은 개발 분해를 위한 제안이며, 새 Public export나 토큰 승인을 뜻하지 않는다.

### 이미 확인한 공통 컴포넌트 제약

- `SectionHeader`의 기본 제목은 18px/24px line-height, glyph plate 30px, glyph 17px다.
  공통 담당자가 원본 실측에 맞춘 opt-in `density="compact"`·`glyph="plain"` 계약을 추가했다.
  원본의 작은 섹션 제목은 feature CSS나 원시 요소로 우회하지 않고 이 공통 compact
  variant를 사용한다. 기본 크기는 보존하고 공통 담당자가 영향·a11y·회귀를 검증한다.
- `EmptyState`의 compact 크기는 min-height 120px 및 기본 세로 padding 32px다. 실제 빈
  상태를 밀집 행 하나로 표현해야 하는 곳에 무조건 끼우면 시안의 공간 관계가 달라질 수 있다.
  제목/설명만 임의 구현하지 말고 기존 state의 사용 맥락 또는 정식 inline variant를 검토한다.
- 기존 `DetailInspector`의 기본 폭 360px는 구현 기본값이지 원본 측정값이 아니다. 상세 내용과
  실제 프레임을 측정한 후 feature-local 폭을 지정하되, 모바일에서는 단일 전체 pane로 전환한다.

이 제약을 해결하기 위한 공통 컴포넌트 변경은 아직 하지 않았다. 차이를 숨긴 채 “100%”로
보고하지 않고 원본·공통 계약·접근성의 충돌 해소 결정을 승인 명세에 포함한다.

## 11. 시안 세부 승인 전에 닫을 UI 결정

1. 30개 프레임의 대표 정상 상태 외에 위험 상태가 부족한 경우 상태별 명세를 추가한다.
   최소 정상·빈 데이터·부분 실패·권한 제한·버전 충돌·미구성을 실제 화면 형태로 확인한다.
2. 원본 U01 모바일 하단 탐색과 U02–U15의 하단 탐색을 서로 대조한다. 이름·순서·선택·
   추가 화면에 접근하는 방식이 다르면 전체 IA 기준을 먼저 통일한다.
3. U03/U10의 안건 editor와 U01/U04/U06의 안건 preview/progress는 항목 순서·담당·시간의
   같은 의미를 쓰되, 편집 권한과 읽기/진행 제어를 혼합하지 않는다.
4. U01/U07/U08의 게시 요약·검토 초안은 시각적 상태 차이를 유지한다. 색뿐 아니라 text·
   역할·가능한 행동으로 구분한다.
5. U01/U08/U09의 AI 업무 후보와 확정 업무는 동일 완료 체크박스를 공유하지 않는다.
6. U05/U06/U12의 장치 상태는 같은 아이콘과 언어를 쓰되 로컬 점검과 회의 송출을 구분한다.
7. U13–U15는 사용자 홈·하단 탐색과 관리 문맥을 분리한다. 회의 콘텐츠를 운영 증거의
   preview로 노출하지 않는다.
8. 고정 footer/하단 탐색/통화 제어는 상호 배타적 레이어 규칙을 갖고 safe area·가상 키보드·
   브라우저 주소창 변화에서 마지막 control과 본문을 가리지 않도록 한다.

다음 갱신에는 실제 프레임 식별자, 원본 DOM 측정표, 이미지 관찰, token mapping 차이와
publisher 수용 기준을 연결한다. 아직 측정하지 않은 치수의 100% 일치 판정은 하지 않는다.

## 17. U09 정본 업무 소비 구현 및 명시적인 원본 차이

U09는 원본의 목록/선택 상세 구조를 Work 배정 API에 연결한다. 데스크톱은 공통 셸
안에서 7:5 목록/상세와 16px 간격, sticky inspector를 사용하고 모바일은 선택한 행
바로 아래에 같은 상세를 한 번만 렌더링한다. 모바일 검색은 한 줄, 상태 필터와
새로고침은 다음 한 줄로 모아 빈 공간을 줄인다. 공통 셸·navigation은 별도 통합 소유다.

- 실제 범위는 `ASSIGNED_TO_ME`/`ASSIGNED_BY_ME` 두 개다. 요청 범위는 최초 생성자이며
  마지막 재배정자와 혼동하지 않는다. 원본의 후보/진행 업무가 섞인 탭을 복제하지 않는다.
- 검색·완료 필터는 서버 미지원이므로 **현재 페이지에만 적용**됨을 명시한다. 전체 수는
  현재 범위의 서버 total만 사용한다. 원본의 5개 KPI·확신도·AI 후보 수는 만들지 않는다.
- 목록은 source를 조회하지 않고 상세를 선택할 때만 접근 상태를 확인한다. 과거
  AVAILABLE 상세 metadata를 NOT_REQUESTED 목록에 합치지 않는다.
- 상세의 업무 조건은 Work 정본이다. 출처 UNAVAILABLE은 독립 업무의 수락/수행
  권한 철회와 다르다. sourceRoute 문자열 대신 검증된 meetingId/reportId UUID로
  `/meetings/history?meeting=…&reportId=…`를 구성하며, 이동 후 정확한 보고서 ACL을 재검증한다.
- 수락과 시작을 분리하고 서버 capability·업무 version·assignmentRevision을 함께
  검사한다. 응답 유실은 기존 commandId receipt 또는 동일 ID/입력 재시도로 조정한다.
  과거 receipt의 적용 버전으로 현재 업무 상태를 되돌리지 않는다.
- 새 source 검사 이후 늦게 도착한 mutation이 source metadata를 되살리지 않도록
  **Work version과 별도 source-read generation**을 사용한다. 403/계정·범위 변경은
  원문과 명령 결과를 지우고 늦은 성공도 무시한다. 409는 최신 업무 검토 후 새 행동이 필요하다.
- 새 후보 CREATE/REASSIGN은 현재 Auth·대상자 적격성 검증 미구성으로 차단한다.
  업무 앱의 정본 상세 route도 미제공이므로 버튼은 사유와 함께 비활성이다. 원본의 발언
  인용/체크리스트/100% 동기화 표시를 가짜 데이터나 자유 텍스트로 대체하지 않는다.

대상 검증은 model20 + runtime21 + 공용 Work SDK11 = **52/52 PASS**이며,
Chromium6 + mobile6 = **12/12 PASS**다. E2E에는 수락≠시작, receipt 복구, 409 재검토,
거절 사유, 권한 철회 후 늦은 성공, 범위 분리, 후보 미지원, 320px dark/키보드와
serious/critical a11y 0건을 포함한다. 경로는 `e2e/video-meeting-follow-ups.spec.ts`이고
브라우저 증적은 `test-results/meeting-follow-ups-agent/`에 기록한다.

이는 **정본 API 계약을 mock한 실제 브라우저 소비 검증**이다. 운영 Work/Meeting
교차 서비스 승격, 외부 인프라, 원본과 전체 픽셀 일치 또는 모든 디자인 화면 완료를
입증하지 않는다. 실제 1280/390/320 캡처를 육안 확인했으며, 원본의 예시 수치와
미구현 근거 패널을 제외한 위 차이는 운영 연결이 생길 때 별도 설계·검증한다.
