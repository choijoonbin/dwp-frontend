## 역할·인터페이스 설계

- U13의 주 사용자는 회의 운영자다. 질문은 “현재 사용자에게 영향을 주는 회의 서비스는 무엇이며 어떤 진단을 먼저 확인할까?”다. command center의 범위는 현재 테넌트이고 service attention 필터가 같은 4대 서비스 행렬을 변경한다. 사고 선택은 우측 인스펙터의 제목/원인에 즉시 반영된다.
- U14의 주 사용자는 정책 관리 권한을 가진 관리자다. 질문은 “어떤 정책이 바뀌며 현재 버전에 안전하게 저장할 수 있는가?”다. focus form + impact inspector로 구현한다. 승인·보존·게스트·모델 관련 미연결 설정은 저장 patch에 섞지 않는다.
- U15의 주 사용자는 AI/데이터 거버넌스 운영자다. 질문은 “처리 체인의 어느 증적이 준비되지 않았고 콘텐츠 접근 없이 무엇을 확인할 수 있는가?”다. 증적 기반 command center이며 `onRefresh`는 실제 readiness와 policy query를 함께 재조회한다.

`meeting-admin-presentation.tsx`는 이 세 화면의 승인 tonal card/inset와 조밀한 제목·지표 표현만 소유한다. `meetingShape`, `meetingSoftShadow`, `meetingType` 및 정본 typography/foundation color를 소비하며 baseline 상향은 하지 않았다. `meeting-admin-operations.tsx`는 기존 권한/identity scope와 조회 계약을 그대로 사용한다. `meeting-admin-governance-workbench.tsx`는 상태 투영에 기반한 모델/삭제/명령 presentation이다. 공통 셸·Gateway·API·backend·generated 계약은 편집하지 않았다.

최종 재대조에서는 U14의 게스트 도메인, 호스트 부재 제한, 참가자 녹화 동의, 녹화 고지/워터마크 4개 슬롯도 추가 복원했다. 실제 허용 도메인이나 적용 시간을 추정하지 않고 읽기 전용 미보고 상태를 표시한다. 반복되는 긴 연결 경고는 각 설정 묶음의 안내로 압축했다. 또한 API가 `aiNotesConfigured=true`를 보고해도 UI가 꺼짐으로 고정하던 실제 상태 투영 오류를 고쳤다. 이 스위치는 조회 증거만 반영하며 임의로 편집 가능하게 만들지 않는다.

## 검증 및 재현

- 담당 unit: `meeting-admin-model.test.ts`, `meeting-admin.runtime.test.tsx`, `meeting-admin-intelligence-page.test.ts` 3파일 **19/19 통과**. “button이 없어야 안전하다”라는 과거 assertion은 실제 command가 모두 disabled인지 검사하도록 바로잡았다. 권한·409 충돌·늦은 응답의 identity 격리 회귀 및 configured AI 상태 투영을 검증했다.
- 담당 ESLint 통과. 최신 전체 `corepack yarn typecheck --incremental false` **0 오류 PASS**. 공유 Work Hub 중간 편집 오류가 있던 이전 실행과 최종 전체 통과를 구분해 회수했다.
- `video-meeting-admin-stitch-content.spec.ts`와 루트의 `video-meeting-design-review-20.spec.ts` U13/U14/U15를 Chromium에서 실행해 **22/22 통과**. 1440/1280/390/320, 서비스 필터, U14 펼침 및 누락 슬롯, 준비 상태 재조회, 고위험 명령 비활성, overflow, axe critical/serious 0을 검증했다. 320px 글자 확대 200%와 forced-colors, 세 화면 영문 dark, U13/U14 readiness 503 부분 실패도 포함한다.
- 최신 별도 `mobile` 프로젝트 U13/U14/U15는 **3/3 통과**. 원본 검토용 viewport/document PNG 모두 회수했다. 담당 browser 검증은 합계 **25/25**이며 새 golden 승인이나 screenshot baseline 갱신은 하지 않았다.
- 1차 브라우저 회귀는 U13 rail 키보드 접근 및 U15 English dark 대비 실패를 실제 검출했고 보정 후 재실행했다. U14 sidebar 공백은 스크린샷 육안검수에서 추가 검출했다.

### 시각 수용 범위와 남은 차이

6개 원본을 각각 직접 대조해 본문 컴포넌트와 우선순위를 복원했지만 이를 픽셀 100% 일치로 판정하지 않는다. 공통 관리 셸은 현재 솔루션을 유지한다. U14 모바일은 원본에 축약된 접근·녹화·AI·보존만 표시하는 대신 기존 협업·수용인원 및 조직 템플릿 제어를 모두 접근 가능하게 보존하므로 전체 문서 높이가 더 길다. U15는 실제 7단계 검증과 미연결 사유를 노출하며 원본의 가짜 100% 준비·건수·인증·승인자·시계열을 복사하지 않는다. 추가 서비스 계약이 연결돼야 같은 시각 슬롯을 실제 측정값과 실행 가능한 명령으로 채울 수 있다.

부분 커밋 없음. 외부 운영 연결 및 명령 API 미완료를 시각 통과 수치로 숨기지 않는다.
