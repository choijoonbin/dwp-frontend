U02는 현재 권한이 있는 최대 10개 항목만 enrichment한다. 준비·일정 실패 시 이전 민감 query data를 재사용하지 않으며, scope는 identityPlane/tenantId/userId와 결속한다. 실제 서비스의 `NEEDS_RESPONSE`, `RECONFIRM_REQUIRED`와 구 버전 `PENDING`을 미응답으로 구분한다. SELF-only roster를 전체 참석자 명단으로 부풀리지 않고 집계 값만 사용한다. 날짜 연산은 정본 `resolveZonedDateKey`를 사용한다.

RSVP는 현재 invitation revision + response version + 안정된 UUID를 전송한다. 중복 클릭, 권한 철회, 충돌, 불확실한 결과를 구분하고 최신 query 재확인이 끝나기 전 재전송을 열지 않는다. 템플릿/최근 회의 chooser는 명시적으로 연 동안만 조회하고 권한 철회 시 부모 초안 편집도 닫는다.

## 4. 외부 연결/정책 때문에 원본의 예시 값과 다르게 표시하는 부분

- “캘린더 충돌 0건/전원 가능”: 현재 Meeting 예약 API에는 free/busy·그룹 일정 검증 계약이 없다. **가용성 블록 자체는 유지**하고 미연결 상태를 표시한다. 다음 서버 확장은 tenant/user와 참석자 집합·시간 범위에 결속한 가용성 조회 및 결과 TTL·revision을 가진 preview가 필요하다. 초대 대상 검색 결과를 가용성으로 간주하지 않는다.
- “AI 생산성 98점”: 현 계약에 계산 근거가 없다. 원본의 보조 지표 영역에 실제 의제 분 합계/회의 시간 배정률을 제공하며 AI 생산성 점수는 아니라고 명시한다.
- “자동 녹화/전사/AI 실행, E2EE, 메일 발송 완료”: 기존 content-plan/capability/consent가 확인한 값만 표시한다. 회의 예약은 미디어 취득·녹화 시작·외부 전달 완료를 뜻하지 않는다. LiveKit/KMS/STT/LLM 등 운영 NO-GO를 해제하지 않았다.
- 고정 회의 코드: 생성 전 서버 할당이므로 예시 코드를 만들지 않는다.
- 전체 회의 통계/검색 최적화: 현 목록 계약은 page 단위다. 고빈도 운영에서는 권한 범위 내 필터/집계 + 준비/반복 요약을 함께 반환하는 Meeting owner-service projection으로 bounded enrichment 호출을 줄이는 후속 계약을 권고한다. 이번에 공통 API나 DB를 임의 확장하지 않았다.
