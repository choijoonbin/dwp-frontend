## 대표 여정

1. 과거 사건 행이 아니라 owner별 최신 execution summary만 현재 건수로 집계한다. 한 원천 장애 시 성공 원천의 소계를 전체처럼 표시하지 않는다.
2. Work의 네이티브 Task만 `WORK_ITEM` 공통 이력으로 연결한다. Activity 권한이 없거나 외부 projection이면 링크 자체를 제공하지 않는다.
3. 목록 밖 과거 사건·AI run도 exact ID endpoint로 조회한다. 404/403, tenant/user 불일치, 응답 ID 불일치 때 다른 행을 대신 표시하지 않는다.
4. 단건 run 재검증이 실패하면 React Query에 남은 이전 data를 영수증이나 대화 링크로 다시 노출하지 않는다.
5. 원본 열기 직전에 사건을 다시 조회한다. 권한이 철회됐거나 route가 안전하지 않으면 이동을 중단한다.
6. Agent lease 확인 불가는 `UNKNOWN`이며 `FAILED`로 합성하지 않는다. 현재 snapshot을 모든 단계·retry의 불변 lifecycle로 표현하지 않는다.
7. Activity는 읽기·근거 이동만 수행한다. 승인, 취소, 실행 재시도와 같은 command는 원본 앱이 소유한다.

시각 검증 코드는 [activity-stitch-visual-quality.spec.ts](/Users/a10697/Work/DWP/dwp-frontend/e2e/activity-stitch-visual-quality.spec.ts), 구현 추적은 [Stitch 구현 추적표](<08-Stitch 구현 추적표.md>)를 따른다.

## 운영 출시 전 남은 외부 게이트

1. Agent 변경을 커밋한 뒤 실제 GitHub Actions 성공 run으로 v5 PEP attestation을 새로 발급한다. 현재 attestation revision은 `72e991be3d8a2bde2228eb5f52b7c76330686aeb`, 로컬 Agent HEAD는 `beff65372835e8d2087d6150b5ad0f4c291c68ae`라서 canonical release checker가 의도대로 차단한다.
2. 보안 승인 후 `DWP_AGENT_PRODUCT_AUTHORIZATION_V5_ENABLED`를 활성화한다. 그전에는 신규 v5 route가 `110/111`에서도 fail-closed 상태를 유지한다.
3. V222 백업·이행·복구 절차, 원천별 보존 정책, 실제 tenant 권한 표본을 운영 환경에서 승인한다.
4. 전체 워크스페이스의 병행 변경을 합친 CI와 native browser 200% zoom, Product/Design 사용자 수용 검사를 수행한다.

증명 경계를 로컬 파일 수정으로 우회하거나 운영 rollout 완료로 표시하지 않는다.

## 전체 워크스페이스 통합 상태

Activity 대상 검증과 전체 `tsc --noEmit`, source-size는 통과했다. 현재 전체 `architecture:check`와 `yarn build`는 병행 개발 중인 DWAI·ON `artifacts`·`personal-controls`·`routines` 모듈 20개가 production entry에 아직 연결되지 않아 production-reachability에서 중단된다. 디자인 시스템 기준선 ratchet 1건과 `dwaion-routine-inspector.tsx`의 `outcomes.BLOCKED` 한·영 표시 사전 2건도 Activity 밖의 병행 변경에 남아 있다. 병행 작업 통합 후 전체 CI를 재실행해야 한다.
