## 필수 기능 여정

1. native 사건 상세를 열면 사건 ACL을 다시 검사하고, evidence receipt의 연결 상태와 checkpoint 상태를 분리해서 표시한다.
2. `ADMIN.AUDIT_VIEW:VIEW`가 없으면 hash·algorithm·verifiedAt을 숨기고 제한 상태를 명시한다.
3. Agent run은 현재 attempt의 stage, 실측 duration, source 결과, lease, progress를 표시한다. 실패 run을 100% 완료로 합성하지 않는다.
4. Agent audit가 `PENDING`이면 중앙 확인 대기 상태로 표시한다. Platform receipt가 404 또는 `PENDING`일 때 검증 완료 문구를 사용하지 않는다.
5. Mail/Calendar source status는 원본 앱 권한이 있는 resource만 표시하고, 빈 목록·부분 실패·정책 차단을 정상 건강으로 해석하지 않는다.
6. Platform SAMPLE은 local server flag와 고정 계정에서만 보이며 실행 summary에서 항상 제외한다.
7. Agent SAMPLE은 DWAI·ON run list/detail에서만 보이고 공통 Activity feed/detail/KPI에서는 보이지 않는다.
8. 목록 밖 LIVE 사건·run도 exact ID endpoint로 독립 조회한다. 404/403, tenant/user 불일치, 응답 ID 불일치 때 다른 행을 대신 표시하지 않는다.
9. 원본 이동 직전에 사건 또는 run을 다시 조회한다. 권한이 철회됐거나 route가 안전하지 않으면 이동을 중단한다.
10. 한 원천이 실패하면 성공 원천 자료를 유지하되 `partial`/source failure를 표시하고 전체 성공처럼 합산하지 않는다.

## 로컬 fixture 수용 기준

- 대상 identity는 `tenant=1`, `user=900018`, `joonbin@sk.com`으로 고정한다.
- Platform: SAMPLE native work/event 3건, 개인 connector 2건과 stream 3건을 생성한다. 공개 effective status는 primary MAIL `READY`, primary CALENDAR `STALE`, attention MAIL `BLOCKED`다.
- Agent: SAMPLE run 4건으로 완료·정책 handoff·원천 unavailable/not configured·runtime failure와 단계·source latency·audit `PENDING`을 확인한다.
- 두 seed를 다시 실행해 동일한 고정 대상만 유지하고 기존 사용자 편집이나 LIVE 행을 변경하지 않아야 한다. 예약 connector/subject/stream ID에 기존 credential·provider binding·cursor가 있으면 전체 Platform seed가 fail-closed해야 한다.
- 다른 tenant/user, fixture flag OFF, `APP.MAIL:VIEW`/`APP.CALENDAR:VIEW` 제거 조건에서 데이터가 누출되지 않아야 한다.
- seed에는 비밀번호·token·prompt·답변·credential·권한 grant가 없어야 한다.

## 범위 밖 운영 게이트

운영 tenant 표본, 실제 외부 provider 동기화, 운영 보존·복구 승인, GitHub Actions attestation, 커밋·PR·배포, 영구 모니터링은 향후 일괄 운영 전환에서 수행한다. 로컬 fixture timestamp나 `DAILY_CHECKPOINT_REPORTED`를 운영 연결 성공 또는 규제 준수 증명으로 사용하지 않는다.
