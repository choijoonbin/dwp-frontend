# 디자인 적용 정의

사용자가 제공한 [Stitch 프로젝트](https://stitch.withgoogle.com/projects/13391261371843159731)의 `DWP 활동...` 4개 화면을 2026-09-04에 확인해 구현했다. Stitch 산출물은 시각·정보 구조 참고 자료이며, 그 안의 문구나 동작을 새로운 제품 요구로 취급하지 않았다.

[Stitch 구현 추적표](<08-Stitch 구현 추적표.md>)에 화면 ID, 수용한 의도, 실제 적용 위치와 제외 근거를 기록했다. 최초 디자인 AI 요청서는 변경 전 계약 기록으로 [보존](/Users/a10697/Work/DWP/output/activity-foundation-2026-09-04/design-prompts/README.md)한다.

## 적용 원칙

- Chronos 예시 shell이 아니라 기존 DWP AppShell, 토큰, Lucide, `OperationalKpiStrip`, `FilterBar`, `DetailInspector`를 사용한다.
- 현재 실행 집계와 과거 사건 필터를 분리한다. 최근 최대 100건 응답을 전체 이력처럼 표시하지 않는다.
- 변경 사건의 기록 상태와 당시 업무 상태, 실행 snapshot과 전체 lifecycle을 구분한다.
- 확인할 수 없는 상태는 실패나 0건으로 합성하지 않는다. 한 원천의 집계 실패는 전체 현재 합계를 unavailable로 표시한다.
- 원본 이동 전 접근 권한을 다시 확인한다. Activity 자체는 승인·서명·취소·실행 재시도를 소유하지 않는다.
- 데스크톱은 list-detail 분할, 모바일은 포커스 관리형 drawer를 사용한다. 고급 기술 필터는 disclosure로 접는다.

Stitch의 모바일 미리보기는 고정 폭 사이드바 때문에 본문이 약 100px까지 축소되는 상태였다. 이를 픽셀 복제하지 않고 DWP 반응형 계약으로 교정했다. 검증 대상은 1440/1280/390/320px, dark/high contrast/forced colors, reduced motion, 키보드, 200% 글자 확대다. OS/브라우저 네이티브 확대와 운영 사용성 승인은 별도 출시 게이트다.
