# 데이터·이행 계약

기준일 2026-09-07. 활동 앱은 업무·앱·Agent 원본을 복제하는 제2 원장이 아니라, 정보 부속과 권한을 유지한 채 검증된 사건·현재 실행 상태·감사 증적을 연결한다.

## 정본과 읽기 모델

| 데이터                  | 정본                                                           | 활동에서의 의미                                 |
| ----------------------- | -------------------------------------------------------------- | ----------------------------------------------- |
| 업무·앱 변경 사건       | Platform `wrk_activity_events`                                 | 권한이 있는 완료된 `CHANGE`/`USAGE` 사실        |
| 업무 원본·앱 카탈로그   | Platform `wrk_items`, `adm_workspace_apps`                     | 현재 소유권·생애주기·resource permission 재검사 |
| native event audit link | Platform `sys_platform_audit_events`                           | 업무 변경과 동일 트랜잭션에서 생성된 감사 연결  |
| 감사 hash/checkpoint    | Platform `sys_audit_events`, `sys_audit_integrity_checkpoints` | 감사 원장 소유자가 보고한 저장 무결성 관측치    |
| 개인 동기화 원천 상태   | Platform productivity connector/subject/stream ledger          | 현재 사용자의 Mail/Calendar 저장 관측           |
| Agent run               | Agent `ai_agent_runs`                                          | run, lease generation, attempt, 현재 결과       |
| Agent stage             | Agent `ai_agent_run_stages`                                    | 현재 attempt의 실측 단계 전이·지연 시간         |
| Agent run source        | Agent `ai_agent_run_source_health`                             | 해당 run에서 실제 시도한 원천 결과·latency      |

Agent run, stage, source 계측은 Platform으로 복제하지 않는다. `/api/agent/v1/runs`는 현재 run과 현재 attempt의 telemetry를 하나의 repeatable-read snapshot으로 읽어, 재시도 경계에서 서로 다른 generation이 섞이지 않게 한다.

## 사건·실행 상태

- Platform `CHANGE`는 완료된 변경 사실이다. `state=COMPLETED`이며, 당시 업무 상태는 `workStatus`로 분리한다.
- Platform `USAGE`는 앱 실행·고정·해제 사실로, 현재 실행 수 KPI에 포함하지 않는다.
- Platform `EXECUTION`은 불변 실행 사건 계약을 갖추지만 현재 Platform producer가 없다. 따라서 Platform 실행 집계가 0이어도 정상이다.
- Agent `EXECUTION_SNAPSHOT`은 run의 현재 상태다. 과거 retry attempt의 전체 lifecycle을 합성하지 않는다.
- Agent `progressPercent`는 5개 operational stage의 `COMPLETED`/`SKIPPED` 전이를 20% 단위로 계산한다. 경과·평균 시간에 기반한 추정치가 아니다.
- `RUNNING`의 lease를 확인할 수 없거나 만료되면 활동 상태는 `UNKNOWN`이다. 자동으로 `FAILED`로 바꾸지 않는다.

## 감사·원천 관측 의미

native 업무 변경은 업무·`sys_platform_audit_events`·`wrk_activity_events`를 동일 JPA/JDBC 트랜잭션에서 commit/rollback한다. tenant-qualified deferred FK, source event unique 제약, LIVE append-only trigger를 사용한다.

Platform evidence API의 `linkStatus`는 실제 audit record 연결을, `integrityStatus`는 감사 원장의 일별 checkpoint 보고를 뜻한다. 두 값을 섞어 그래프·법적 진본성·규정 준수 보증으로 재해석하지 않는다. `recordHash`, `hashAlgorithm`, `verifiedAt`은 `ADMIN.AUDIT_VIEW:VIEW`이 있을 때만 노출한다.

Agent는 opaque local `auditId`로부터 결정적 UUIDv5 중앙 audit record 주소를 저장하지만, 현재 publisher가 중앙 원장의 ingestion acknowledgement를 받지 않으므로 `auditEvidence.status=PENDING`이다. 중앙 Platform receipt API가 404를 반환하면 아직 ingest되지 않은 것이며, Agent가 `LINKED`나 `VERIFIED`를 합성하지 않는다.

Platform 개인 원천 상태는 자격 증명·provider ID·raw error를 읽지 않고 `lifecycle → policy → consent → health → stream` 우선순위로 현재 관측 상태를 결정한다. `observedAt`은 해당 원장을 읽은 시각이지 외부 동기화 시각이 아니다.

## 분류·SAMPLE 격리

Platform V222는 기존 행을 삭제하지 않고 `LIVE | LEGACY | SAMPLE | QUARANTINED`로 분류한다. 정확한 native 결속을 입증한 이전 기록만 `LEGACY`로, 나머지는 `QUARANTINED`로 보존하고 일반 조회에서 제외한다.

- Platform 로컬 SAMPLE은 서버의 `DWP_ACTIVITY_LOCAL_FIXTURES_ENABLED=true`, 고정 사용자 `900018`, reserved correlation/source marker가 모두 맞아야 목록·상세·증적에 노출된다. 실행 요약은 fixture flag와 무관하게 SAMPLE을 항상 제외한다.
- Agent SAMPLE은 DWAI·ON `/api/agent/v1/runs`의 list/detail에서만 표시한다. 공통 `/api/agent/v1/activity/events`, 상세, 실행 요약은 `data_provenance='LIVE'`만 읽으므로 SAMPLE은 피드·KPI에 섞이지 않는다.

## 로컬 씨드 경계

Platform fixture SQL은 Flyway가 아닌 명시적 스크립트다. 실행자가 로컬 IAM 매핑을 사전 확인하고 transaction에서 `SET LOCAL dwp.activity.seed_profile='local-joonbin'`을 설정해야 한다. Agent fixture는 `DWP_ENVIRONMENT=local`, `DWP_AGENT_LOCAL_ACTIVITY_SEED_ENABLED=true`, `DWP_AGENT_DATABASE_URL`이 모두 필요하다.

두 seed는 `tenant_id=1`, `user_id=900018`(`joonbin@sk.com`)에만 귀속되고 고정 ID·충돌 사전 검사·insert-only 전략으로 재실행을 안전하게 만든다. 비밀번호·token·prompt·답변·connector credential은 씨드하지 않는다.

## 이행·운영 경계

Platform은 V222, Agent는 V31 스키마 이행 후에 해당 코드를 실행한다. 보존 기간·정식 삭제·운영 복구는 기존 원장 소유자의 정책을 따른다. 이번 로컬 고도화에서는 자동 purge, 영구 모니터링, 운영 배포와 운영 검증을 수행하지 않는다.
