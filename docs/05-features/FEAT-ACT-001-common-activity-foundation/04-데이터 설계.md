# 데이터·이행 계약

## 원본과 분류

Workspace 원본은 `wrk_items`, `adm_workspace_apps`, 이력은 `wrk_activity_events`, 증적은 `sys_platform_audit_events`이다. Agent 실행은 기존 `ai_agent_runs`와 실제 실행 중인 메모리 RunStore이며 Workspace에 복사하지 않는다.

V222는 기존 행을 삭제하지 않고 `LIVE / LEGACY / SAMPLE / QUARANTINED`로 구분한다. 알려진 seed를 SAMPLE로, 정확한 native 객체 결속을 입증한 이전 기록만 LEGACY로 분류한다. 나머지는 QUARANTINED로 보존하고 일반 조회에서 제외한다. 신규 앱 사용 `USAGE`는 기본 피드에서 제외하되 명시 옵션으로 조회한다.

## 상태 모델

- `CHANGE`: 완료된 업무 변경 사실. `state=COMPLETED`, 당시 업무 상태는 `workStatus`. 실제 업무 완료와 다름.
- `USAGE`: 완료된 앱 실행/고정/해제 사실. 현재 실행 수에 포함하지 않음.
- `EXECUTION`: 플랫폼에 준비한 불변 실행 사건 계약. 현재 이를 생산하는 플랫폼 실행 writer는 없음.
- `EXECUTION_SNAPSHOT`: Agent 원장의 현재 상태를 읽은 결과. 과거 단계나 이전 attempt를 복원하지 않음.

플랫폼 최신 상태 뷰는 `(tenant, source, executionId)`별 attempt→version 내림차순으로 먼저 선택한 뒤 ACL을 적용한다. 같은 실행의 retry attempt는 이전 시도를 대체한다. 병렬 실행은 별도 executionId이다.

Agent의 `UNKNOWN`은 유효한 작업자 임대를 확인할 수 없다는 관측이다. 실패로 자동 변경하지 않으며, 시계 경과만으로 executionVersion을 올리지 않는다. sourceObservedAt으로 관측 시점을 별도 표현한다.

## 증거·정합성

업무 상태 변경·실제 감사 레코드·활동 사실을 동일 JPA/JDBC 트랜잭션에서 commit/rollback한다. tenant-qualified deferred 감사 FK와 sourceEventId/execution version unique 제약, LIVE 변경·삭제 방지 trigger가 있다. 임의 UUID 감사 문자열을 실제 증적으로 인정하지 않는다.

Keyset은 발생/생성 시각과 UUID를 사용한다. Workspace는 createdAt watermark, Agent는 고정 createdAt watermark 및 조회 시점의 현재 상태다. 장기 트랜잭션 commit 순서까지 고정하는 법정 시점 감사 export 계약이 아니다.

## 운영 이행·보존

배포 전 V222 적용, 동일 버전 API 및 UI 순으로 호환 확인한다. code만 먼저 올리는 방식은 지원하지 않는다. 데이터 보존기간/정식 삭제 정책은 기존 원장 소유자의 정책을 따르며 이번에 자동 purge를 추가하지 않았다. LIVE append-only 보호를 해제하거나 삭제하는 운영 도구도 추가하지 않았다.

이행 실패 시 롤백은 승인된 DB 백업/스냅샷 복구 또는 forward fix 계획으로 처리한다. 신설 열/감사 FK를 임의 삭제하는 down migration은 제공하지 않는다. 이전 UI로 돌려 과거 RUNNING 집계가 재노출되지 않도록 활동 진입을 제한하는 운영 복구 절차를 먼저 승인해야 한다.
