# DWP-R1-CORE-001 기획 정의

## 1. 문제와 Outcome

직원은 업무 시작 시 메일, 일정, 승인, 서비스와 기존 앱을 각각 열어 우선순위를
조합한다. DWP의 첫 경험은 앱 아이콘을 많이 보여주는 Portal이 아니라, 중요한 결과를
파악하고 근거를 확인한 뒤 적절한 업무나 원본 System으로 이동하게 해야 한다.

Reference Flow의 Outcome은 다음과 같다.

- J1 `Start My Day`의 첫 Action까지 정보구조를 검증한다.
- J2 `Ask and Act`의 답변, Source, 불확실성과 후속 Action 패턴을 검증한다.
- J5 `Legacy Task`의 권한 기반 App 탐색과 원본 이동 패턴을 검증한다.
- Shell과 Page Pattern이 Desktop·Mobile·Keyboard에서 동일한 Mental Model을 갖는다.

## 3. Scope

- Global Shell의 P0 Navigation: `Today`, `Work`, `Ask`, `Apps`
- Today: 우선 업무, 일정, Daily Brief Preview와 추천 이유
- Work: 상태·유형·우선순위를 비교하는 업무 Queue Reference
- Ask: 근거 기반 답변, Source와 다음 Action Preview
- Apps: 권한이 부여된 Native·SaaS·Legacy App 검색과 실행
- Empty·Loading·Error·Permission 상태의 표현 계약
- Desktop과 Mobile Responsive Flow

## 4. Non-goal

- 실제 메일·Calendar·HRIS·ITSM·Legacy Connector
- 실제 AI Model, Vector Search, Agent Tool 실행
- 운영 Work·App·Conversation Table과 API
- 자유 배치 Widget Builder와 앱 Marketplace
- Inbox·People·Services·Admin 전체 메뉴
- 사용자가 Font, 임의 Brand Color나 Navigation 구조를 바꾸는 기능

Product·Tenant 관리 기능인 Font, Brand Accent와 Navigation Pattern은 Design System
Capability로 유지하며 일반 사용자 Preferences에는 노출하지 않는다.

## 5. Reference Journey

1. 사용자는 Today에서 마감·승인·일정과 추천 이유를 확인한다.
2. 우선 항목을 열어 Work Queue에서 상태와 원본 정보를 비교한다.
3. Global Ask 또는 Ask 화면에서 정책·업무 질문의 근거 답변을 확인한다.
4. 실행이 필요하면 Plan Preview 또는 원본 App Link를 확인한다.
5. Apps에서 권한이 있는 시스템을 검색해 안전한 Deep Link로 이동한다.

Reference 단계의 모든 Command는 화면 상태만 변경하거나 Preview를 열며 외부 시스템을
변경하지 않는다.

## 6. Analytics 계약

| Event                    | Trigger                | 필수 Property                                  |
| ------------------------ | ---------------------- | ---------------------------------------------- |
| `today_item_opened`      | 우선 항목 선택         | itemType, reasonCode, rank, sourceType         |
| `work_filter_changed`    | Work View 변경         | status, priority, resultCount                  |
| `ask_reference_opened`   | Citation 확인          | sourceType, freshnessState, permissionDecision |
| `ask_action_previewed`   | 후속 Action Preview    | actionType, riskTier, requiresApproval         |
| `app_launched`           | App 실행               | appType, launchMode, entitlementSource         |
| `reference_flow_reached` | 화면 간 목표 경로 완료 | startRoute, endRoute, stepCount                |

합성 Fixture 화면에서는 Event Schema만 검증하며 운영 Analytics로 전송하지 않는다.

## 7. 승인 조건

- 상위 Journey·PRD의 P0 Scope와 충돌하지 않는다.
- 실제 데이터와 합성 Preview가 시각·접근성 Label로 구분된다.
- R1 API와 Data Source 결정 전 영구 Table을 추가하지 않는다.
- Design Partner Test에서 Navigation 용어와 첫 Action 이해도를 검증한다.
