# DWP-R1-CORE-001 수용 테스트

## 1. Acceptance Criteria

| ID    | Given                    | When                  | Then                                                |
| ----- | ------------------------ | --------------------- | --------------------------------------------------- |
| AC-01 | 인증된 사용자            | Shell 탐색            | Today·Work·Ask·Apps와 현재 Route가 일관되게 표시    |
| AC-02 | Mobile Viewport          | Navigation Open       | 동일 목적지가 Drawer에 있고 Content와 겹치지 않음   |
| AC-03 | Today Fixture            | Priority Item 선택    | 이유·Source·기한과 Work Action이 표시               |
| AC-04 | Work Fixture             | Status Filter 변경    | 결과 수와 Queue가 일치하고 Layout Shift가 없음      |
| AC-05 | Ask 질문                 | Submit                | AI Preview, Source, Freshness와 Plan Preview가 표시 |
| AC-06 | 근거 부족 Fixture        | Ask Submit            | 확정 답변 대신 Abstention과 Handoff가 표시          |
| AC-07 | App 검색                 | Keyword 입력          | 이름·설명·Owner 기준 결과만 표시                    |
| AC-08 | App Launch               | 권한 App 선택         | Reference Launch Feedback만 있고 외부 변경이 없음   |
| AC-09 | Keyboard·Screen Reader   | 주요 Journey 탐색     | Heading·Landmark·Focus·Name·State 위반이 없음       |
| AC-10 | Light·Dark·High Contrast | Desktop·Mobile Render | Text·Command 겹침과 Color-only 상태가 없음          |
| AC-11 | Source Tree·Network      | Reference Flow 실행   | 실제 업무 API·Model·Connector 호출이 없음           |
| AC-12 | 일반 사용자 Preferences  | 설정 탐색             | Font·임의 Color·Navigation Layout Control이 없음    |

## 5. 구현 및 검증 증적

- 구현 Route: `/`, `/work`, `/ask`, `/apps`
- Global Shell: Desktop Sidebar·Rail·Top Navigation, Mobile Drawer
- 데이터: `apps/dwp/src/features/work-hub/reference-data.ts`의 합성 Fixture만 사용
- E2E: Today → Work → Ask → Apps 핵심 Journey와 제한 상태 검증
- 접근성: Desktop·Mobile Axe 자동 검사 및 Semantic Heading·Landmark 검증
- Visual: 핵심 4개 Route의 Desktop·Mobile 8개 Baseline 직접 검토
- 외부 영향: Reference Action은 Preview·Feedback으로 종료하며 업무 API를 호출하지 않음
