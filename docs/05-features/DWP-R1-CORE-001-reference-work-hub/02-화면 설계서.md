# DWP-R1-CORE-001 화면 설계서

## 1. Information Architecture

| Route       | Navigation | Primary task                                    |
| ----------- | ---------- | ----------------------------------------------- |
| `/`         | Home       | 권한 App 실행 또는 Today 첫 Action 선택         |
| `/work`     | Work       | 업무 상태·우선순위 탐색과 원본 Context 확인     |
| `/ask`      | Ask        | 권한 내 근거 답변과 다음 Action 검토            |
| `/activity` | Activity   | 사람·시스템·Agent 실행 상태와 감사 Context 확인 |
| `/apps`     | Apps       | 권한이 부여된 업무 App 검색과 실행              |

Desktop Shell은 좌측 Navigation과 고정 Header를 사용한다. Mobile은 Header의 Navigation
Button으로 Drawer를 열며 동일한 네 목적지를 제공한다. Home은 Product Mark와 Account
Menu로 복귀한다. 권한이 없는 목적지는 숨기되 URL
직접 접근은 Route Guard에서 다시 거부한다.

## 2. Global Shell

- 좌측: Product Mark, P0 Navigation, Collapse Control
- Header: Workspace, Global Search·Ask Entry, Notification, Account. 언어는 개인 계정 설정에서 저장한다.
- Active Item: Color 외에도 Icon, Label, 배경과 `aria-current=page` 사용
- Content: Page Header 다음 Primary task, Section은 Page 배경 위의 Unframed Layout
- Context Panel은 R1 실제 Detail 계약 전 고정 Empty Panel을 만들지 않는다.

## 3. Home

### 구조

1. 사용자 Context, 날짜, 실제 데이터 Freshness가 있는 Compact Command Band
2. `Next priority`: Work Queue의 상태·우선순위·기한으로 정렬한 한 개의 다음 행동
3. `Work signals`: 열린 업무·마감 임박·진행 중·응답 대기
4. `Work tools`: Entitlement 기반 목적 그룹, 앱·폴더와 전체 Apps Command
5. `Daily brief`, `Focus`, `Schedule`, `Live activity` 개인화 Widget

### Interaction

- Next Priority는 Keyboard로 `/work?item={id}`를 열고 Work Detail에 Focus를 이어간다.
- Work Queue가 비어 있으면 정상 빈 상태를, 실패하면 Command Band 해당 영역만 오류·재시도로 전환한다.
- 앱 선택은 Native Route 또는 승인된 SSO Deep Link로 이동한다.
- 길게 누르기·Pointer Drag·Keyboard Drag로 그룹 내 순서를 변경하고 앱 중앙 Drop으로
  폴더를 만든다. Arrange Menu에서 이동·폴더·이름 변경·해제를 동일하게 제공한다.
- 개인 배치는 Tenant·User Scope로 저장하고 Entitlement 변경 시 재조정한다.
- `Hide`·`Pin`은 Reference에서 Local State만 변경하고 되돌리기를 제공한다.
- Daily Brief는 권한 범위 Work API만 요약하며 Calendar 미연결 시 실제 일정 대신 Connector 필요 상태를 표시한다.

## 4. Work

### 구조

1. Page Header, 실제 업무 KPI와 결과 수
2. 상태 Segmented Filter: `All`, `Due soon`, `In progress`, `Waiting`, `Completed`
3. Enterprise Data Grid: 다중 선택, ID, 업무, 유형, 우선순위, 상태, 기한, Source
4. 선택 Row의 판단 근거·권장 다음 행동·최근 활동·원본 Link

### Interaction

- Grid의 Library Keyboard Model을 유지한다.
- 검색·상태·열 Preset·선택 업무는 URL로 복구하고 개인·Tenant Saved View를 서버에 저장한다.
- 상태 변경은 `version`을 요구하며 단건 또는 최대 50건을 한 Transaction으로 변경한다. 한 건이라도 충돌하면 전체를 Rollback하고 선택을 유지한다.
- Mobile은 중요 Column을 우선하고 수평 Scroll 또는 Compact List로 전환한다.

## 5. Ask

### 구조

1. 명확한 질문 Input과 Submit Command
2. Answer 상태: 근거 있음, 근거 부족, 권한 거부, Error
3. Source Citation: Title, Owner, Version·최신성, 원본 Link
4. Recommended next Action: 변경 대상, Risk, 승인 필요 여부

### Interaction

- 추천 질문은 명시적 Button 선택 시 제출하며 질문을 `q` URL로 저장해 새로고침·공유 시 동일 요청을 재실행한다.
- 새 질문은 이전 Browser 요청을 취소하고 Runtime 요청을 60초로 제한한다.
- 답변은 실제 Governed Ask Runtime의 정책·권한·근거 계약을 검증하며 실패 시 합성 답변을 만들지 않는다.
- Citation은 새 원본 Context로 이동함을 명확히 표시한다.
- 실행 Command는 `Preview plan`까지만 제공하고 완료처럼 표현하지 않는다.

## 6. Activity

### 구조

1. 실제 Event 기준 Summary: 전체 Source, 실행 중 Agent, Needs input, Policy blocked
2. 주체·상태·검색 Filter와 시간순 Activity Timeline
3. 상태: Running, Needs input, Completed, Blocked
4. 선택 Event Detail: Actor, Work object, Source, Tool, Audit ID, Action Preview

### Interaction

- 주체·상태·검색은 URL과 Saved View로 복구하며 KPI 선택도 동일 Filter 계약을 사용한다.
- 결과가 0이면 빈 Timeline 대신 적용 Filter를 초기화할 수 있는 Healthy Empty를 표시한다.
- Event 선택 시 실행 이유와 감사 가능한 Metadata를 Detail Pane에 표시한다.
- Agent의 내부 추론 과정은 노출하지 않고 입력·정책·도구·결과만 설명한다.
- Running 상태의 Motion은 기능 상태에만 사용하고 Reduced Motion에서 정지한다.

## 7. Apps

### 구조

1. App Search
2. `Pinned`, `Recommended for role`, `All apps` Group
3. 각 App Item: Icon, 이름, Owner, App Type, Launch Mode

### Interaction

- 검색은 이름·설명·Owner를 대상으로 한다.
- App Item은 권한이 있는 경우만 실행하며 Reference에서는 Toast로 Launch Preview를 알린다.
- 자유 배치 대형 Widget보다 Scanner-friendly Grid를 사용한다.

## 8. 상태 Matrix

| 상태              | 표현                            | Command                  |
| ----------------- | ------------------------------- | ------------------------ |
| Loading           | 안정된 높이의 Skeleton·Progress | 취소 가능 시만 제공      |
| Empty             | 적용 Filter와 결과 0을 명시     | Filter Reset             |
| Error             | 짧은 원인과 Correlation ID 자리 | Retry                    |
| Offline           | 마지막 동기화 시각              | Retry                    |
| Permission denied | 요청 범위와 권한 거부           | Home 또는 권한 요청 경로 |
| Stale             | Source 최신 시각과 Owner        | Refresh·원본 열기        |
| Partial           | 성공·실패 Source 범위           | Retry·사람 Handoff       |

## 9. Responsive와 접근성

- 320px, 390px, 768px, 1440px에서 Text·Command가 겹치지 않는다.
- H1 다음 H2 순서를 지키며 스타일용 Heading Element를 사용하지 않는다.
- Mobile의 Primary Command는 최소 44px Target을 유지한다.
- Icon-only Button에는 접근 가능한 이름과 Tooltip을 제공한다.
- WCAG 2.2 SC 2.5.7에 따라 모든 Drag 작업은 단일 Click·Tap Menu 대체 경로가 있다.
- Focus는 Route 이동 후 H1 또는 Main 시작점으로 이동한다.
- Reduce Motion과 High Contrast에서 동일한 정보와 상태를 보존한다.
