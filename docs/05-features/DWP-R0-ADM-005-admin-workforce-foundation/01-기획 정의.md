# 01 기획 정의

## 문제

현재 Tenant Admin 기능은 일반 업무 Shell의 단일 Tab 화면이며, User와 HR Person,
현재 조직과 발령 이력, 직접 Role과 Group Role을 충분히 구분하지 못한다.

## 목표

1. 고객별 Tenant와 People Data가 교차하지 않는 Delivery 기반
2. 외부 HRIS를 유지하면서 DWP에 필요한 Workforce Projection 제공
3. User·Group·Role·Resource·Action·Scope 기반 Effective Permission
4. Experience, People & Access, Platform Setup, Governance를 구분한 Admin Control Center
5. 사람과 Agent가 같은 Typed Admin Command·Approval·Audit 경로 사용

## 성공 기준

- 새 Tenant/HRIS Mapping이 Core Table 변경 없이 추가된다.
- 재입사·복수 관계·미래 발령 이력을 표현할 수 있다.
- 메뉴와 버튼의 권한이 Backend Permission과 동일하다.
- Admin Navigation은 Desktop·Mobile Keyboard와 Screen Reader에서 동작한다.
- Agent Preview는 Mutation을 수행하지 않고 Tenant·Actor·Version을 Hash에 포함한다.
