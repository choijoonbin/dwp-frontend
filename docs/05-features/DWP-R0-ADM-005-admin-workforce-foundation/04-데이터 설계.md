# 04 데이터 설계

## Database

| Database       | 주요 Table                                                      |
| -------------- | --------------------------------------------------------------- |
| `dwp_auth`     | Tenant, User Account, Role, Permission, Group Role, SoD         |
| `dwp_platform` | Reference, Navigation, Locale Override, Registry, Admin Command |
| `dwp_people`   | Person, Worker, Relationship, Assignment, Profile, HRIS Sync    |

## 핵심 불변식

- 모든 업무 Row, Unique와 Parent FK에 Tenant가 포함된다.
- Person과 User Account는 다른 Lifecycle이며 Public ID로 느슨하게 연결한다.
- Assignment는 Effective Date와 Sequence로 이력을 유지한다.
- 민감 식별자는 평문 저장하지 않는다.
- Media는 Object Key·Checksum만 DB에 저장한다.
- 메뉴는 등록된 내부 Route와 Resource Permission만 참조한다.
- Reference Item Parent는 동일 Tenant·Set 안에서만 지정한다.
- Agent Command는 Plan Hash, Expected Version, Expiry와 Approval 상태를 가진다.

상세 ERD와 Privacy 규칙은 상위 ADR을 따른다.

## Effective Organization Graph

| 영역     | Table                                                             | 설계 목적                                                                   |
| -------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 조직     | `ppl_organizations`, `ppl_organization_relationships`             | 유효일 조직과 Supervisory·Matrix·Functional 관계                            |
| 직위     | `ppl_positions`, `ppl_position_relationships`                     | 직위 원장, 보고 체계, Source Provenance와 기간 중첩 방지                    |
| 사람     | `ppl_persons`, `ppl_workers`, `ppl_assignments`                   | 개인·고용·발령 Lifecycle 분리와 재입사·복수 Assignment                      |
| 시나리오 | `ppl_organization_scenarios`, `ppl_organization_scenario_changes` | Live 원장과 분리된 미래 조직 변경 집합, Clone 계보와 Optimistic Version     |
| 승인     | `ppl_organization_scenario_approvals`                             | 작성자·승인자 분리, 만료, 상태 전이와 판단 Validation UUID                  |
| 근거     | `ppl_organization_scenario_validation_runs`                       | 기준선 지문, 전후 지표, Check와 Correlation을 보존하는 Append-only Evidence |

### 불변식

- 관계 Source는 `HRIS`, `POSITION`, `INFERRED`, `SCENARIO`를 구분한다.
- Source별 주 보고 관계 기간은 PostgreSQL Exclusion Constraint로 중첩을 거부한다.
- 시나리오 변경은 순번과 Version을 가지며 DRAFT 외 상태에서는 수정할 수 없다.
- 직위 종료는 시행일 기준 재직자와 하위 직위가 없는 `OPEN` 직위만 허용한다.
- 비용과 통화는 함께 입력하며 여러 통화가 섞이면 통합 비용 판단을 `WARNING`으로 처리한다.
- Validation Run은 Update·Delete Trigger로 변경을 거부하고 최근 50건을 근거 이력으로 조회한다.
- 복제 시나리오는 같은 Tenant의 직전 Source Scenario만 참조하며 자기 참조를 DB에서 거부한다.
- 제출·승인·반려·게시는 각 상태 전이에 사용된 Validation Run을 복합 FK로 결속한다.
- 조직 Health·Change·Quality는 Effective Graph에서 파생한다. 승인 근거만 불변 Snapshot으로 저장해 이중 원장을 만들지 않는다.
