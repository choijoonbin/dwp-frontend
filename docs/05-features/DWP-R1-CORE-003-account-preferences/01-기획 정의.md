# DWP-R1-CORE-003 기획 정의

## 목표

- 구성원이 Profile 원천, 개인 설정, 보안·Session을 하나의 Account 영역에서 이해한다.
- 개인 설정을 Versioned Schema로 자동 저장하고 다음 로그인에 복원한다.
- Tenant 관리 정책과 개인 Override를 분리해 표시한다.
- 관리형 값의 담당자와 예외 가능 여부를 표시하고 요청·취소·결정 이력을 보존한다.
- SSO·MFA·위험 로그인처럼 연결되지 않은 기능을 성공 상태로 가장하지 않는다.

## 포함 범위

- Profile, Appearance, Accessibility, Language & Region, Home Workspace, Managed Settings
- Theme, Contrast, Motion, Density, Locale, Time Zone, Date/Time/Number와 Week Start
- Home Widget 표시·순서, Save State, Version Conflict와 Reset
- 활성 Session 조회·종료와 Tenant Login Policy 상태
- 관리형 설정 정책·경로별 규칙과 사용자 예외 요청, Tenant 관리자 검토·승인·반려

## Principal별 적용 범위

- 위 전체 범위는 Tenant Principal에 적용한다.
- Provider Principal에는 Provider Profile·역할, 보안·Session, Auth `preferredLocale`,
  Appearance·Accessibility·Regional 표시만 적용한다. 개인 홈, Tenant 관리형 설정·예외와 고객
  업무 알림은 숨긴다.
- Provider Appearance·Accessibility·시간대/날짜/숫자 표시는 현재
  `dwp.provider-preference.v1:provider:<realm>:<user>` Browser `localStorage`에 비민감 Enum만
  저장하며 Cross-device Server Sync는 없다. Provider Context에서 Tenant Branding·Personal
  Preference API를 호출하거나 SKAX/지원 대상 Tenant Preference를 생성하지 않는다.
- Provider Principal 범위의 Versioned Server Preference는 후속 Backend Gate이며 현재 Browser
  저장을 서버 동기화로 표현하지 않는다.

## 제외 범위

- 고객 IdP의 실제 MFA 등록·복구·위험 로그인
- 사용자가 Tenant Brand·Navigation·Font를 변경하는 기능
- 예외 승인만으로 관리형 값을 자동 적용하는 기능. 승인은 통제된 변경 작업의 근거다.
- 검증되지 않은 자유 형식 Preference Key 저장
