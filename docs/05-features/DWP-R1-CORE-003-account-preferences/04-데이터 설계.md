# DWP-R1-CORE-003 데이터 설계

`usr_personal_preferences`는 `(tenant_id, user_id)`별 한 행을 저장한다. 조직 정책은 사용자
JSON에 복제하지 않고 별도 Tenant 원장으로 관리한다.

이 Table은 Tenant Principal 전용이다. Provider Principal은 행을 만들거나 SKAX/지원 대상
Tenant의 행을 재사용하지 않는다. 현재 Provider 언어는 Auth `preferredLocale`, 비민감
Appearance·Accessibility·Regional 표시는
`dwp.provider-preference.v1:provider:<realm>:<user>` Browser `localStorage`가 소유한다. Local
Payload는 허용 Enum만 포함하며 Tenant ID, 고객 데이터, Support Session, Secret, 보안 상태를
저장하지 않는다. Provider용 Versioned Server Preference Schema·Table은 후속 Backend Gate다.

| Column                     | 계약                              |
| -------------------------- | --------------------------------- |
| `tenant_id`, `user_id`     | 사용자별 Tenant 격리 Unique Key   |
| `schema_version`           | Preference Migration과 검증 기준  |
| `preference_payload`       | 검증된 개인 확장 설정 JSON Object |
| `version`                  | 낙관적 잠금                       |
| `created_at`, `updated_at` | 자동 저장 시각 근거               |

Schema v2는 Appearance, Accessibility, Regional과 Home 영역을 명시적으로 검증한다. 알 수 없는
최상위 Key, Secret, 업무 본문과 개인정보 원문은 저장하지 않는다. Profile·Identity·Session은 Auth
원장이 소유하고 Preference JSONB에 복제하지 않는다.

관리형 정책과 예외 수명주기는 Platform V51에서 분리한다.

알림 센터의 기본 View·표현 밀도와 검증된 Saved View Filter처럼 본인 화면에만 영향을 주는 UI
Preference는 이 JSONB의 `notifications` Namespace를 사용할 수 있다. 그러나 App·Type·Channel별
구독, Quiet Hours, Digest, Push Endpoint와 관리형 필수 정책은 조회·정책 합성·감사가 필요한 업무 데이터이므로
`DWP-R1-CORE-005-notification-platform`의 정규화 Table에서 관리한다. 같은 값을 두 원장에
중복 저장하지 않는다.

| Table                                | 소유권과 계약                                       |
| ------------------------------------ | --------------------------------------------------- |
| `adm_managed_preference_policies`    | Tenant별 정책 원천, 담당자, 연락 경로와 Version     |
| `adm_managed_preference_rules`       | Preference Path별 관리 값, 표시 Key, 예외 가능 여부 |
| `usr_preference_exception_requests`  | 사용자 요청 값·사유·영향·상태·담당자·낙관적 잠금    |
| `usr_preference_exception_decisions` | 승인·반려·취소·만료의 Append-only 결정 증적         |

한 사용자·경로에는 Pending 요청을 하나만 허용한다. 정책과 Rule Version은 요청 시점에
Snapshot으로 저장하고, 요청 값은 JSONB 크기·깊이·Node 수를 제한한다. 결정은 이유와 수행자를
필수로 기록하며 Update·Delete Trigger로 변경을 거부한다. 만료 Scheduler는 요청 기한이 지난
Pending 항목을 `EXPIRED`로 전환한다.
