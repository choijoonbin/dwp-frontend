이번 검증은 카테고리 조회만 확인하지 않는다. 설계자는 카테고리의 부모·한영 Metadata·
순서·활성 상태를 편집하고 양식 초안을 생성한다. 게시 책임자는 게시된 기본 결재선이 있는
초안만 게시하며, 기안자는 게시 양식을 선택한 뒤 단계 순서·후보 역할·단계 SLA를 확인한다.
운영 재시도와 외부 서명 설정은 Adapter·멱등 원장·비밀 저장소 Gate 전까지 조회 전용으로
유지하며 동작하지 않는 버튼을 노출하지 않는다.

검증용 Request와 임시 인증 Artifact는 완료 후 삭제했다. 이 표는 로컬 기준선 증거이며
아래 미완료 Production Gate를 대체하지 않는다.

로컬 Seed 검증에서는 `Current user`와 가상 `100xxx` 요청자를 0건으로 정리했고, 일반
구성원·Tenant 관리자·Approval Operator·통합 관리자 계정으로 Gateway 로그인 후
`/api/approvals/v1/home` 200과 실제 이름·조직·결재 상태를 확인했다.

## 규모·성능 기준

- Reference Scale: Tenant당 활성 Task 100,000건, 이력 10,000,000건, 동시 결정 500 TPS
  후보를 부하 시험 시작점으로 사용하고 실제 고객 상한으로 재승인한다.
- Inbox P95 400ms, Detail P95 600ms, Decision commit P95 800ms.
- Queue 첫 Interaction은 2.5초 이내, Filter 반응은 300ms 이내 목표.
- 대량 목록은 Server Cursor와 Virtualization을 사용하고 브라우저에 전 이력을 적재하지 않는다.
- 외부 Fulfillment와 AI 시간은 별도 SLI이며 내부 Decision commit SLO를 오염시키지 않는다.
