# 01. 개인 전자결재 홈

화면 ID: `APR-01` · 경로: `/approvals/home` · 우선순위: D1

## Design AI에 전달할 원문

당신은 복잡한 엔터프라이즈 결재 제품을 설계하는 시니어 Product Designer다. DWP의 기존
전자결재 홈을 고도화하라. 이 요청은 디자인과 상호작용 명세를 만드는 단계이며 React·API·DB
코드를 만들지 않는다.

DWP 글로벌 헤더, 제품 사이드바, 테넌트·사용자·접근 범위, 공통 검색·알림·DWAI·ON 진입,
Noto Sans KR 계열 타이포와 기존 design-system을 그대로 유지한다. 별도 Chronos 브랜드,
별도 헤더, 별도 사이드바를 만들지 않는다. 참고 이미지의 빠른 정보 파악과 정밀한 정렬은
수용하되 외관을 복제하지 않는다.

가장 중요한 경계: `전체 대기 / 긴급 결재 / 오늘 마감 / 고위험`은 홈 본문 메뉴가 아니다.
전자결재 사이드바의 `결재함` 아래에서 접고 펼치는 하위 메뉴이며 이 홈에는 재구현하지 않는다.

### 목적·사용자·권한

- 사용자: `APP.APPROVALS:VIEW`가 있고 자신의 Task·Request를 볼 수 있는 구성원·결재자.
- 질문: “오늘 무엇을 먼저 검토하고, 내 결재 흐름에 어떤 조치가 필요한가?”
- 주 행동: 우선 Task 열기 또는 새 결재 시작.
- 보조 행동: 결재함, 내 기안, 보완 요청, 위임으로 이동.
- archetype: action-oriented personal command center. 관리 dashboard가 아니다.
- 권한이 없는 메뉴·데이터는 숨기는 데서 끝내지 말고 직접 URL/API도 동일하게 거부된다는
  전제로 설계한다.

### 현재 구현 사실

현재 API는 개인 metrics, focus queue, recent requests, stage flow, policy/SLA insights와 생성
시각을 제공한다. 홈 layout 개인화도 존재한다. 조회 실패 시 기본 layout은 보이지만 저장은
닫고 명시적 재시도를 제공한다. 이 기능을 `EXISTING`으로 표기하라.

### 1440px 구성

1. 페이지 상단은 한 줄 인사·현재 범위·짧은 설명과 `새 결재 작성`, `전자결재 전문가에게
묻기`, `홈 편집`을 배치한다. 큰 환영 hero나 그림은 만들지 않는다.
2. 첫 업무 band는 “오늘의 결재 브리핑”이다. 생성 시각, 대기/오늘/초과 요약, 현재 가장
   중요한 항목 한 건의 번호·위험 근거·기한·현재 단계와 `우선 결재 검토`를 제공한다.
3. metrics는 비교 가능한 compact signal strip로 구성한다. `검토 대기`, `오늘 기한`,
   `진행 중인 내 기안`, `평균 결재 시간/SLA`의 범위와 기준 시각을 명시한다. 숫자만 큰 카드
   네 개를 만들지 않는다.
4. 본문 주 열은 `우선 심의 큐`와 `내 기안 진행 추적`이다. 각 행은 제목, 번호, 요청자,
   현재 단계, 기한/지연, 위험 근거, 정확한 다음 행동을 담는다.
5. 보조 열은 `신속 실행`, `의사결정 내비게이터`, `최근 결재 활동`을 낮은 시각 무게로 둔다.
   `실시간`이라는 단어는 실제 push/시계열이 있을 때만 사용한다.
6. stage flow는 장식 funnel이 아니라 제출→검토→보완→승인의 현재 개인 범위 건수와 위험
   건수를 읽을 수 있는 compact tracker로 만든다.
7. 첫 900px 높이 안에서 브리핑, 핵심 지표, 우선 큐 첫 항목과 내 기안 일부가 보여야 한다.

### 상태 전이와 인라인 행동

- 우선 항목 선택 → `/approvals/inbox?task=...`에서 정확한 Task를 연다.
- 지표 선택 → 대응하는 기존 route/queue로 간다. 홈 안에 목록을 중복해서 펼치지 않는다.
- 홈 편집 → 현재 widget 순서·표현 높이를 바꾸는 dialog/toolbar. 저장 성공 전 optimistic
  완료를 표시하지 않는다.
- 개인화 조회 실패 → 기본 구성 + 설명 + `다시 시도`, 편집 disabled.
- 개인화 409 → 서버 최신 layout과 사용자 변경을 비교하고 다시 적용/취소.
- Task 권한 회수 → 제목·금액·사람 등 민감 요약을 제거하고 안전한 홈 상태로 재조정.
- DWAI·ON은 근거 기반 질문/딥링크만 제공하며 승인·게시·재처리를 자동 실행하지 않는다.

### 필수 상태 프레임

- populated 정상
- 실제 대기 0건이지만 진행 중 내 기안은 있는 empty variant
- home API 전체 loading과 전체 error
- personal preference만 partial failure
- 한 섹션만 503인 partial state
- 403/권한 회수 직후 민감 항목 제거 상태
- 긴 제목·긴 영문 workflow·큰 금액·기한 없음
- stale 생성 시각과 재조회 중

실패를 `0건`으로 표현하지 말고, 마지막 성공 값을 보여 줄 경우 시각과 읽기 전용 범위를
명시한다.

### 반응형

- 390px에서는 인사/행동, 브리핑, 우선 큐, 내 기안, 보조 신호 순으로 한 작업면에 재배치한다.
- metric은 2열 고정 카드가 아니라 내용 길이에 따라 1~2열로 안전하게 reflow한다.
- 320px와 200% 확대에서 버튼 문구·숫자·상태가 겹치지 않고 page 가로 overflow가 없어야 한다.
- 모바일 하단에 새 전역 navigation을 추가하지 않는다. 제품 메뉴는 기존 DWP drawer를 쓴다.

### 접근성

- h1 하나, 섹션별 h2, landmark와 목록 의미를 제공한다.
- 버튼의 접근 이름에 대상 업무 제목 또는 목적을 포함한다.
- 새 데이터와 저장 성공은 `role=status`, 실패·권한 상실은 적절한 `role=alert`로 알리되
  focus를 임의로 빼앗지 않는다.
- focus order는 상단 행동→브리핑→지표→우선 큐→내 기안→보조 신호 순으로 논리적이어야 한다.
- 본문 4.5:1, 경계·focus·상태 3:1, 색 외 텍스트/아이콘을 병기한다.
- reduced motion에서는 카드 이동·progress 변화 애니메이션 없이 같은 의미를 전달한다.

### 반환물과 수용 기준

- `APR-01-1440-light-populated`, 390px 모바일, 320px, 200% 확대 설명
- dark 정상과 forced-colors 중요 상태
- 정상 외 최소 5개 상태 프레임
- 컴포넌트 anatomy와 responsive rules
- 클릭 흐름과 focus/scroll 복귀 규칙
- 각 요소에 `EXISTING`, `REDESIGN_ONLY`, `CONTRACT_FIRST`, `EXTERNAL_GATE` 주석

홈 본문에 결재함 하위 메뉴를 넣거나, 관리자 지표를 섞거나, 큰 hero와 카드 수프로 첫 화면을
채우거나, risk score를 AI 자동 승인 추천으로 바꾸면 실패다.
