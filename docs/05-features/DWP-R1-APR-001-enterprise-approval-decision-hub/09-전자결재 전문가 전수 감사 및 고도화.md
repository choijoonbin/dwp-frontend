# 전자결재 전문가 전수 감사 및 고도화

- 감사 기준일: 2026-08-19
- 대상: DWP 전자결재 사용자 앱, 관리 기능, Auth/RBAC, PostgreSQL 원장, Governed Agent
- 판정: `R1 audited baseline`; Production Release와 법적 전자서명 완료를 의미하지 않음

## 1. 결론

코드·권한·DB·화면·Agent를 전수 대조한 결과 즉시 악용 가능한 P0 결함은 남아 있지 않다.
이번 감사에서 확인한 개인 데이터 범위, 개인 처리 완료함, maker-checker, 정책 변경 비교,
위임 재검증, 보완요청 데이터 버전, 딥링크·상세 추적, UI/API 권한 계약, AI 데이터 등급 및
감사 분류, 결정자·단계 증적 표현 결함은 구현과 자동검증까지 완료했다.

현재 기준선은 순차 `ANY` 결재를 실제 업무에 적용할 수 있는 R1 내부 의사결정 Hub다.
다만 병렬·정족수 엔진, 게시 자산의 차기 Revision 분기, 법적 전자서명 Provider,
KMS·Object Storage, PostgreSQL RLS와 대규모 부하 증적은 별도 Product Gate다. 이 항목을
구현하지 않은 상태에서 UI나 문서만으로 지원한다고 표시하지 않는다.

## 4. RBAC와 직무 분리

| 역할                 | 허용 책임                                                       | 명시적 금지                          |
| -------------------- | --------------------------------------------------------------- | ------------------------------------ |
| `WORKSPACE_MEMBER`   | 자신의 요청 생성·편집·상신·회수, 후보 Task 조회·결정, 본인 위임 | 관리 정의·게시·운영 재처리           |
| `APPROVAL_DESIGNER`  | Workflow·Form 생성·편집, Policy 변경안 제출                     | 자신이 편집한 자산 게시, 운영 재처리 |
| `APPROVAL_PUBLISHER` | Workflow·Form·Policy 독립 검토·게시                             | Draft 내용 수정, 운영 재처리         |
| `APPROVAL_OPERATOR`  | 운영 Pulse·SLA·통합 전달 조회와 통제된 재처리                   | Workflow·Form·Policy 편집·게시       |
| `AUDITOR`            | 전자결재 앱과 읽기 전용 운영 증적                               | 설계·게시·재처리·결정 변경           |
| `TENANT_ADMIN`       | Tenant 범위 관리 상태 조회와 역할 위임                          | 전자결재 전문 직무의 자동 상속       |

Auth Migration은 다음 조합을 `DENY`한다.

- `APPROVAL_DESIGNER` + `APPROVAL_PUBLISHER`
- `AUDITOR` + `APPROVAL_DESIGNER|APPROVAL_PUBLISHER|APPROVAL_OPERATOR`
- `APPROVAL_OPERATOR` + `APPROVAL_PUBLISHER`

`V72__verify_effective_role_conflicts.sql`은 직접 역할, 활성 그룹 역할, 유효한 고권한 Grant를
합산한 View를 만들고 활성 위반이 있으면 Migration을 실패시킨다. 화면 숨김은 보조 수단이며
Gateway와 Approval API가 동일 Permission·Tenant·resource 상태를 다시 검사한다.

## 6. 데이터·감사 증적

- Approval DB Migration: `V1`~`V11`
- 양식 분류 무결성: 기존 미분류 양식을 `GENERAL`로 보정한 뒤 `apr_forms.category_id NOT NULL`
- 레거시 호환: 신규 Tenant가 먼저 관리형 카탈로그를 초기화하고 구형 Writer는 `GENERAL`로만 보정
- 상세 조회 계약: 요청 당시 `form_version_id`에 고정된 `formSchema`와 Payload를 함께 반환
- Auth DB Migration: 전자결재 권한 기준 `V52`, 보강 `V70`~`V72`
- 정책 게시 이력: `apr_policy_rule_versions` append-only
- 요청 보완 이력: `apr_request_payload_versions` append-only
- 업무 흐름: `apr_request_events`, `apr_steps`, `apr_tasks`
- 통합 전달: `apr_integration_outbox`와 수동 재처리 actor·횟수·시각
- 공통 감사: Audit Outbox, `targetType`, action, actor, role, correlation, 분류
- API 관측: `sys_api_history`의 route template, status, latency, trace·correlation

감사 Event에는 민감한 전체 Payload를 복제하지 않는다. 보완 Event는 변경 Field 이름만
기록하고 값은 Tenant·요청 권한이 적용되는 버전 원장에서 조회한다.

## 8. 완료 판정 규칙

R1 audited baseline은 다음을 모두 만족할 때 유지한다.

1. Approval/Auth 단위·권한 테스트가 통과한다.
2. 사용자·설계자·게시자·운영자 12개 Chromium·12개 iPhone 13 흐름이 통과한다.
3. Agent 전체 테스트와 조회 전용·등급 fail-closed 검증이 통과한다.
4. OpenAPI 생성물과 Frontend 계약이 일치한다.
5. Auth 유효 역할 충돌 0, 위임 Principal 누락 0, Payload Version 누락 0이다.
6. 위 Product Gate를 구현하지 않고 지원한다고 표시하지 않는다.

2026-08-19 최종 로컬 증적은 Approval JUnit 38건, Frontend TypeScript·대상 ESLint,
Navigation 권한 계약 3건, Chromium 12건과 iPhone 13 12건의 E2E, Gateway 실계정 API와
브라우저 상세 화면을 통과했다. 김민서 계정에서 본인 제출·보완·초안 범위만 조회되며,
본인이 실제 승인한 완료 Task 3건만 읽기 전용으로 표시된다. 상세 Payload는 요청 시점에
고정된 양식의 한국어 라벨과 번역된 Event명으로 표시되고 영문 모드와 Axe 위반 0도 확인했다.
각 승인 사건에는 당시 단계·실제 처리자·대리 여부 Snapshot과 서로 다른 처리 시각이 함께 표시된다.
Approval 런타임 OpenAPI와 Gateway의 전자결재 Path·Schema도 다시 생성해 `COMPLETED` Enum과
고정 `formSchema` 계약이 일치함을 검증했다.

Production Release는 위 조건만으로 선언하지 않는다. 7절의 필수 Gate와
[07-수용 테스트.md](07-수용%20테스트.md)의 P0 항목을 Staging 증적으로 종료해야 한다.
