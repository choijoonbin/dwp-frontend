# DWP-R1-APR-001 디자인 정의

## Experience Direction

결재 앱의 고급스러움은 장식이 아니라 **판단 근거의 정돈, 일관된 밀도, 확실한 상태와
신뢰 가능한 행동**에서 만든다. 운영 도구이므로 Marketing Hero, 장식형 Gradient,
Glass Card 묶음과 과도한 Dashboard를 사용하지 않는다.

## Figma

- File URL: 라이선스 Gate 대기
- Page: `Approval Decision Hub`
- Flow Section: `Inbox`, `Decision`, `Draft`, `Delegation`, `Admin Studio`, `Operations`
- Desktop Frame: 1440x1024
- Tablet Frame: 1024x1366
- Mobile Frame: 390x844
- Prototype 시작 Node: `APR-001 Inbox`

Figma 연결 전까지 코드 Token과 이 문서를 기준 원장으로 사용하며 별도 임시 디자인
Library를 만들지 않는다.

## Visual System

| 영역              | 표현                                                             |
| ----------------- | ---------------------------------------------------------------- |
| App identity      | `FileCheck2` 계열 Icon, DWP Product Blue가 아닌 독립 Teal Accent |
| Primary surface   | 중립 White·Near-white, Dark에서는 Neutral Ink Surface            |
| Text              | 높은 대비의 Ink, 보조 정보는 Neutral Gray                        |
| Approval          | Primary Accent와 Check Icon                                      |
| Attention         | Amber + Clock·Alert Text                                         |
| Rejection·failure | Red를 위험 Action과 실패에만 제한                                |
| Completed         | Green을 결과 Badge에 제한                                        |
| Source app        | 각 App Icon은 작은 Source marker로만 사용                        |

Tenant Accent는 Focus ring, 선택 Bar와 작은 강조에만 적용한다. 의미 상태색과 Action
위계는 Tenant Branding이 덮어쓰지 못한다.

## Information Hierarchy

### Queue row

1. 위험·SLA Marker
2. 제목과 Source App
3. 요청자·대상·금액 등 한 줄 핵심 사실
4. 현재 Stage와 Due
5. 위임·그룹 후보·정보 요청 상태

### Detail

1. 결정 질문과 내 역할
2. AI를 포함한 근거 요약
3. 핵심 필드와 변경 Diff
4. 문서·첨부 Preview
5. 결재선과 정족수
6. 정보 요청·의견
7. 불변 Timeline

Card 안에 Card를 넣지 않는다. Section은 배경 Band, Heading, Divider와 여백으로
구분하고 Card는 실제 반복 문서·첨부·후보 항목에만 사용한다.

## Responsive Rule

| Breakpoint | Layout          | Priority            | Hidden·Moved Action                        |
| ---------- | --------------- | ------------------- | ------------------------------------------ |
| ≥1440      | 3-pane          | Queue와 Detail 동시 | More만 Menu                                |
| 1024~1439  | 3-pane adaptive | Detail 폭 우선      | Secondary filter Drawer                    |
| 768~1023   | 2-pane          | Queue 또는 Detail   | Product nav Drawer                         |
| <768       | Stack           | 판단 근거와 Action  | Route·Timeline Accordion, Action 하단 고정 |

Desktop에서 Sidebar를 접으면 확보된 폭을 빈 Margin으로 남기지 않고 Queue와 Detail이
동적으로 사용한다. Mobile에서 Action Bar는 Safe Area를 포함하고 본문을 가리지 않는다.

## Interaction

| Trigger       | Feedback                    |       Duration | Focus                    | Reduced Motion |
| ------------- | --------------------------- | -------------: | ------------------------ | -------------- |
| Queue 선택    | 선택 Bar·Detail 교체        |          160ms | Detail heading 선택 가능 | 즉시 교체      |
| Filter 변경   | 수량·목록 갱신              |          180ms | Filter 유지              | Fade 없음      |
| 결정 제출     | Button progress·Action 잠금 | 서버 응답 기준 | 결과 Alert               | Spinner만      |
| Route 확장    | Stage detail reveal         |          180ms | 첫 세부 항목             | 즉시 표시      |
| Conflict      | Diff Dialog                 |          180ms | Dialog heading           | 즉시 표시      |
| Workflow 연결 | Edge·Validation 갱신        |          220ms | Node 유지                | 이동 효과 제거 |

중요 결정에는 Optimistic complete를 사용하지 않는다. 중복 클릭은 UI와 Idempotency Key로
막고, 서버 확정 후 결과와 다음 Task를 보여준다.

## Content Design

- `승인`, `반려`, `보완 요청`, `정보 요청`, `위임`, `재지정`, `회수`를 섞어 쓰지 않는다.
- `완료`는 원업무 반영까지 끝난 경우에만 사용한다.
- `승인됨·반영 중`, `승인됨·반영 실패`를 독립 상태로 표현한다.
- `왜 내가 결재자인가`에는 조직·직책·Role·정책 Version을 사람이 읽을 수 있게 설명한다.
- 금액·날짜·시간대는 사용자 Locale로 표시하되 Evidence에는 UTC 원시 시각을 유지한다.
- 한국어·영어뿐 아니라 독일어 수준의 긴 Label에서도 Button과 Table이 깨지지 않게 한다.

## Document Preview

- PDF·Image는 실제 비율을 보존하고 어두운 Blur 배경으로 내용을 가리지 않는다.
- Preview와 Metadata를 분리해 파일명·Revision·Hash·Scan 상태를 확인할 수 있게 한다.
- 비교가 필요한 문서는 Side-by-side 또는 Overlay Diff를 제공한다.
- Preview 실패가 전체 Detail을 막지 않으며 안전한 Download와 재시도를 제공한다.
