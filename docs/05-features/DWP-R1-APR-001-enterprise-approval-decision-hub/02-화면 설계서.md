# DWP-R1-APR-001 화면 설계서

> Product Surface 개정(승인 대기):
> [DWP-R1-CORE-006 화면 설계서](../DWP-R1-CORE-006-product-surface-separation/02-화면%20설계서.md)의
> Approvals Pilot IA를 적용한다. Canonical Route와 결재 기능은 유지하고 Work와 Management의
> Shell·Sidebar만 분리한다.

## 정보구조

- App Route: `/approvals`
- 기본 Route: `/approvals/home`
- Menu·Entry Point: Home `업무 시작 > 결재`, Work 승인 요약, 알림 Deep Link
- Page Title: `결재`
- Breadcrumb: Detail에서는 목록 Filter·Scroll·선택 상태를 복원한다.
- Return URL: 권한 확인 후 내부 경로만 허용한다.

### 관리 메뉴

`/approvals/admin` 아래에 운영 개요, 프로세스 설계, 양식 카탈로그, 결재 정책,
SLA·전달 운영, 전자서명 연계를 권한별로 제공한다. 관리 Route는 별도 Product Management
Shell과 관리 전용 Sidebar를 사용하며 사용자 결재 메뉴를 같은 Navigation Tree에 합치지
않는다. Header의 `결재 업무`·`결재 관리` Link와 `내 결재로 돌아가기`로 문맥을 전환한다.

## 화면별 구조

### APR-001 내 결재함

- Primary task: 처리할 결재를 찾고 충분한 근거를 확인해 결정한다.
- Header: App context, Compact Search trigger, Filter, Saved View, Queue freshness.
- Product sidebar: 사용자 메뉴와 수량 Badge.
- Queue toolbar: `나에게 할당`, `위임받음`, `그룹 후보`, `지연`, `고위험` Segmented Filter.
- Queue row: 위험 Bar, 제목, Source App, 요청자, 금액·대상 요약, 현재 단계, SLA.
- Detail: Decision Brief, 핵심 사실·Diff, 문서, 경로, 의견, Timeline.
- Default focus: Queue heading 후 첫 Task.
- Keyboard: 화살표로 목록 이동, Enter로 Detail, Escape로 목록 복귀. 화면에 단축키 설명을
  상시 노출하지 않는다.
- Mobile: 목록과 상세를 분리하며 Filter는 Bottom Sheet로 제공한다.

### APR-002 결재 상세

- Sticky header: 제목, Source, Revision, 위험, Due, `왜 내가 결재자인가`.
- Decision Brief band: AI 사용 시 Label·출처 수·생성 시각 표시.
- Key Facts: 업무 유형별 Schema가 중요 필드 순서를 제공한다.
- Change Diff: 이전 Revision·기준 데이터와 현재 값을 표로 비교한다.
- Document: 실제 PDF·이미지 Preview와 접근 가능한 Download.
- Route: 완료·현재·예정 Stage, 정족수, 위임·재지정 이력.
- Conversation: 정보 요청과 답변을 일반 댓글과 구분한다.
- Sticky action bar: `승인`, `보완 요청`, `정보 요청`, `반려`, `더 보기`.
- 위험 Action: 사유와 `expectedTaskVersion` 확인 후 서버 응답을 기다린다.
- 서버 확정 전 완료 화면으로 이동하지 않는다.

### APR-003 기안하기

- Step 1: 양식 또는 Source App 선택
- Step 2: 구조화 필드·첨부 작성과 자동 저장
- Step 3: 결재선 Preview, 조건·SoD·누락 증거 확인
- Step 4: 제출 요약과 최종 확인
- Form은 한 화면의 과도한 Card 묶음이 아니라 Section heading과 Divider로 구성한다.
- 자동 저장 상태와 마지막 저장 시각을 표시하며 충돌 시 두 Revision을 비교한다.

### APR-004 내가 올린 문서

- 상태: 진행 중, 정보 필요, 보완 필요, 승인됨·반영 중, 완료, 반려, 반영 실패.
- Detail 상단에는 현재 담당 Stage와 예상 Due를 우선 표시한다.
- 보완은 기존 Revision 수정이 아니라 새 Revision 생성으로 진입한다.
- 승인 후 반영 실패는 결정 실패처럼 보이지 않게 별도 위험 상태로 표시한다.

### APR-006 위임 설정

- 활성·예정·종료 위임을 구분한다.
- 생성 Form: 대리자, 기간, 업무 범주, 제외 업무, 사유.
- Preview: 영향을 받을 예정 Task 유형과 SoD 경고.
- 위임과 재지정의 차이를 Action 문구와 결과 Preview로 구분한다.

### APR-A01 Workflow Studio

- 좌측 Palette: Step 유형과 승인된 Subprocess.
- 중앙 Canvas: 방향성이 명확한 Flow, Zoom·Minimap.
- 우측 Inspector: Routing, Quorum, Due, Outcome, Error policy.
- 하단 Validation: Dead end, Cycle, 후보 없음, SoD와 미등록 Code.
- Draft와 Published Version의 Diff를 승인자가 검토한다.
- Drag만 요구하지 않고 Step 추가·순서 이동의 Keyboard·Dialog 대안을 제공한다.

### APR-A02 양식 카탈로그

- 상단: 전체·게시·초안·기본 결재선 연결 수를 같은 높이의 운영 지표로 표시한다.
- 좌측: 임의 깊이의 테넌트 카테고리 Tree와 하위 분류를 포함한 양식 수를 표시한다.
- 중앙: 이름·키·설명 검색, 상태·카테고리·버전이 고정된 순서로 보이는 양식 목록이다.
- 우측: 양식 Metadata, 필드 Schema, 기본 결재선 단계, 후보 역할, SLA와 게시 준비 상태를
  한 문맥에서 검토한다.
- 설계자는 카테고리와 양식 초안을 생성·수정하고, 게시 책임자는 별도 권한으로 게시한다.
- 카테고리는 활성·비활성으로 운영하며 비활성 카테고리의 양식은 신규 기안 카탈로그에서
  제외된다. 기존 요청과 증적은 삭제하지 않는다.
- 양식 편집기는 한영 이름·설명, 소유 역할, 동적 필드와 게시된 기본 결재선을 함께 저장한다.
- 게시된 자산을 화면에서 직접 덮어쓰지 않는다. 새 Revision·Retire는 별도 수명주기
  Command로 제공하기 전까지 운영 Gate로 취급한다.

### APR-A04 운영 Queue

- 장애·후보 없음·SLA 초과·Fulfillment 실패를 우선순위로 정렬한다.
- Operator는 재시도·재지정·중단만 가능하고 결정 Outcome은 변경할 수 없다.
- 원인, 마지막 시도, 다음 Retry, Correlation, 원업무 상태를 한 화면에 보여준다.

## 접근성

- `nav`, `main`, Queue `listbox`, Detail `article`, Action `toolbar` Landmark를 구분한다.
- 선택 행과 Detail 제목을 `aria-controls`·`aria-labelledby`로 연결한다.
- 결정 결과, stale, 오류와 Queue 수 변경은 적절한 Live Region으로 알린다.
- Focus는 Dialog 종료 후 원 Action, Detail 종료 후 원 Queue row로 복원한다.
- 상태는 색만 사용하지 않고 Icon·Text·위치로 함께 표현한다.
- 200% Zoom에서 Queue와 Detail을 Stack으로 전환하고 가로 Scroll을 만들지 않는다.
- PDF에 접근 가능한 Text Layer가 없으면 대체 문서 또는 다운로드 안내를 제공한다.
