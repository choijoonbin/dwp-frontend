# DWP-R1-CORE-007 화면 설계서

> 상태: Home v2 implemented — integrated automated verification passed, final design approval pending
>
> 기준 화면: Personal Home `/`
>
> 원칙: 한 문서 흐름, 한 세로 Scroll, 명시적 업무 우선순위, 제한된 개인화

## 1. Route와 Shell

| Route                               | Shell               | 역할                                                          |
| ----------------------------------- | ------------------- | ------------------------------------------------------------- |
| `/`                                 | Personal Home Shell | Daily Work Launch & Triage Context, Dock, Work Stage, Updates |
| `/apps`                             | Business App Shell  | Pinned·Recent·Assigned·All 검색 및 전체 앱 관리               |
| 원본 업무 Route                     | Business App Shell  | Now·Flowline·Signal·Next에서 선택한 실제 업무 처리            |
| `/admin/experience/home-experience` | Business App Shell  | Tenant Presentation·Policy·Preview·게시·Rollback              |

Header는 Tenant Logo와 DWP Product Mark, Workspace, Search, Notification과 Account를 유지한다.
Home에는 Sidebar와 Mobile Drawer Trigger, 영구 Assistant Rail을 표시하지 않는다. DWAI·ON은
Entitlement이 있을 때 우측 하단 Floating Launcher로 제공하며 원래의 부유·인사 모션을 유지한다.
Footer 조작 요소와 겹치면 위로 자동 회피하고 `prefers-reduced-motion`에서는 모션을 정지한다.
Tenant Logo가 없거나 Load·Decode에 실패하면 Logo Slot과 Divider를 제거하고 DWP Product Mark만
자연스럽게 남긴다.

## 2. 화면 구조

```text
Personal Home Shell
├─ Global Header
└─ main#dwp-main-content
   ├─ Compact Context
   ├─ My App Dock
   ├─ Required/Critical Notice Rail (eligible만)
   ├─ Updates (normal communications)
   ├─ Work Action Stage
   │  ├─ Now (governed)
   │  ├─ Today Flowline (default first personal)
   │  ├─ Work Signals
   │  └─ Next
   └─ Footer / freshness summary
```

문서, DOM, Keyboard와 Mobile의 읽기 순서는 이 구조와 동일해야 한다. CSS `dense` 또는 시각적
좌표로 순서를 바꾸지 않는다.

## 3. 첫 진입 흐름

1. Header와 Compact Context에서 Workspace, 역할, 날짜와 최근 성공 갱신 시각을 확인한다.
2. 자주 사용하는 앱을 실행하려면 My App Dock에서 한 번에 연다.
3. 확인 필수·Critical Rail이 있으면 업무 Stage 진입 전에 한 줄로 확인한다.
4. 일반 소식을 먼저 훑고, 필요한 경우 전체 소식 또는 상세로 이동한다.
5. Now의 첫 항목에서 실제 처리 Route로 이동하거나 Today Flowline으로 즉시 맥락을
   파악한다.
6. 변화는 Work Signals, 이후 준비는 Next에서 확인한다.
7. 필수 Rail 항목은 Updates에 중복하지 않는다.
8. 각 Section의 초과 항목은 `전체 보기` 또는 `+N`을 통해 해당 목적 화면에서 연다.
9. Product Mark 또는 Account Menu의 Home을 사용하면 `/`와 이전 Home Scroll 위치로 돌아온다.

## 4. Section 상세

### 4.1 Compact Context

- 날짜, 짧은 인사, 역할·대리 Context, 최근 성공 갱신 시각을 제공한다.
- Desktop에서 Content Height 96px 이하를 목표로 하며, 큰 Hero로 첫 Viewport를 점유하지 않는다.
- Tenant 배경 이미지는 선택적 Accent로만 사용하고 본문·Control 대비를 방해하지 않는다.
- 전체 Home이 Partial 또는 Stale이면 이 영역에 짧은 요약과 `다시 시도`를 제공한다.

### 4.2 My App Dock

- Desktop의 각 업무 그룹은 고정 5열×2행을 제공하며 모든 행을 1열부터 연속 배치한다.
  첨부 화면의 저장 순서에서 메신저·화상회의는 소식·캘린더 바로 아래 1·2열, 서비스 2개는 1·2열,
  시스템 앱 4개는 1~4열을 사용한다. 읽기·편집 모두 첫 행의 동일한 열 기준선을 유지한다.
  이 정렬 변경으로 Tenant 기본 순서나 사용자 저장 순서를 재정렬하지 않는다.
  Mobile은 같은 DOM·저장 순서를 좁은 Grid로 Reflow하고 `모든 앱`은 별도 Action으로 둔다.
- 앱 Badge는 실제 미확인·처리 필요 수치만 표시하고 99를 넘으면 `99+`로 축약한다.
- Badge는 `totalUnread`, `actionableUnread`, `urgentUnread`를 보존하고 `urgent > actionable >
unread`를 시각 Tone과 접근 가능한 이름에 반영한다.
- Notification Summary Query의 Cache Stale·Refetch 예산은 각 30초다. `generatedAt`이
  현재 기준 30초 범위를 벗어나거나 권한·최초 Load·Refetch가 실패하면 이전 숫자를
  남기지 않고 Badge 전체를 숨긴다.
- Fresh·Healthy `partial=true` 응답은 성공 App Count만 유지하고
  `unavailableSources`의 Badge만 숨긴다. Home Overview의 다른 Count를 실패한
  Notification Badge의 대체값으로 사용하지 않는다.
- 외부 앱은 새 창·SSO 이동을 실행 전에 표시한다.
- Dock 자체에는 가로·세로 Scroll을 만들지 않는다.
- 추가 앱은 Folder 또는 `/apps`에서 제공하며, 내부 Scroll로 숨기지 않는다.
- 비편집 상태의 앱은 실행, 편집 상태의 앱은 이동 대상으로 동작한다.

### 4.3 필수·Critical Notice Rail

- 대상·게시기간이 유효하고 `acknowledgementRequired=true` 또는 `severity=CRITICAL`인
  공지만 표시한다.
- 사용자 편집 Outline과 Drag Context에 등록하지 않는다.
- 공지가 없으면 공간을 남기지 않는다.
- 한 건을 얇은 Rail로 요약하고 상세 경로를 제공한다. Carousel을 자동 재생하지 않는다.
- 같은 항목을 아래 Updates에 반복하지 않는다.
- 필수 Rail이 보이면 `narrowViewport || compactPreview`에서 `priorityCompact`를
  적용한다. 즉 실제 Mobile 화면뿐 아니라 Desktop 편집기의 390px Mobile Preview에서도
  Context 설명·Now 도입 문구를 축약하고 Dock 4개·필수 Rail·첫 업무 Action을 우선한다.

### 4.4 Now

- 최우선 1건을 제목, 이유, 마감·영향, Source와 명확한 행동으로 강조한다.
- 나머지 최대 2건은 압축 목록으로 제공한다.
- 같은 비중의 `Now·Next·Later` Card를 나열하지 않는다.
- 처리할 항목이 없으면 `지금 처리할 긴급 업무가 없습니다`와 가장 가까운 다음 일정만 짧게 표시한다.
- 업무 상세에서 돌아오면 선택 항목 또는 Now Heading으로 Focus를 복원한다.

### 4.5 Today Flowline

- 일정, 업무 마감, 준비와 후속 행동을 실제 시간 순서로 연결한다.
- Desktop은 읽을 수 있는 시간축과 최대 6개 Anchor, Mobile·실제 200% 글자 크기는 세로
  Timeline을 쓴다.
- 같은 시각에 항목이 많으면 가장 중요한 항목과 `+N`을 표시한다.
- `+N`으로 숨겨진 Source가 Calendar 하나면 `/calendar/schedule`, Work 하나면
  `/work`로 이동한다. 복수 Source일 때만 Section의 기본 상세 Route를 사용한다.
- Node 선택은 실제 상세 Route 또는 연관된 Inspector를 연다.
- 색만으로 상태를 구분하지 않고 Label, Icon과 Pattern을 함께 사용한다.
- 데이터가 없으면 `오늘 예정된 일정이 없습니다`와 Calendar·Work 경로를 제공한다.

### 4.6 Work Signals

- 실제 Aggregate가 있는 변화, 임계치 초과 또는 기준 대비 차이만 Signal로 표시한다.
- 기본 최대 3~4개이며 각각 값, 비교 의미, Scope·기간, Freshness와 Drill-down을 가진다.
- Trend 데이터가 없으면 Chart를 만들지 않고 `비교 데이터 없음`을 표시한다.
- Signal 선택은 같은 Scope로 원본 상세를 열거나 관련 목록을 Filter한다.

### 4.7 Next

- 다음 일정, 준비 항목, 기한이 먼 업무와 설명 가능한 추천 중 최대 3건을 제공한다.
- 추천에는 `왜 표시되었나요`, Source, 신뢰 수준, `관련 없음`과 Undo를 제공한다.
- 준비할 항목이 없으면 큰 Empty Card 없이 짧은 완료 상태로 축소한다.

### 4.8 Updates

- 일반 소식을 필수·Critical Rail 직후, Work Action Stage 앞에 놓아 조직 정보를 먼저 접하게 한다.
- 전체 폭을 쓰되 대표 1건과 보조 최대 2건으로 높이를 제한해 업무 진입을 밀어내지 않는다.
- Featured story 1건과 보조 최대 2건을 낮은 밀도로 제공하고, Cover image가 있을 때만
  실제 Asset을 사용한다.
- 읽지 않음 수, Publisher, 실제 게시일과 예상 읽기 시간을 제공한다.
- Communications가 `FORBIDDEN`이면 민감한 제목·수치를 노출하지 않고, `UNAVAILABLE`이면
  실패·Retry를 밝힌다.

## 5. 단일 Scroll 계약

Home의 세로 Scroll Owner는 Document 하나뿐이다.

- Home Section, App Dock과 Widget Content에서 `overflow-y: auto|scroll`을 금지한다.
- Home Section에서 `overscroll-behavior-y: contain`을 사용하지 않는다.
- 고정 `max-height` 때문에 콘텐츠가 넘치지 않도록 행 예산과 요약 Variant를 사용한다.
- 초과 데이터는 `전체 보기`, `+N`, 목적 Route 또는 명시적으로 연 Dialog·Drawer에서 제공한다.
- Dialog·Drawer는 사용자가 연 동안 배경 문서를 잠그고, Focus Trap과 닫은 뒤 Focus 복원을 제공한다.
- App Folder의 이름 변경 Action은 별도 Header를 재구현하지 않고 공통
  `ContentDialog.titleEnd`에 배치해 Title·닫기·Busy·키보드 계약을 공유한다.
- Pointer가 Dock, 링크, Button 또는 어떤 Section 위에 있어도 Wheel·Trackpad의 수직 입력은
  문서 Scroll로 이어진다.

자동 검증 계약:

```text
Given document가 아래로 더 이동할 수 있다
When 각 Home Section의 중앙에 Pointer를 두고 wheel(0, 600)을 수행한다
Then 2 animation frame 안에 document.scrollTop이 증가한다
And Home subtree에서 scrollHeight > clientHeight이며 overflowY가 auto|scroll인 요소는 0개다
```

위 검증은 상단·중간·하단, 편집·비편집, Mouse·Trackpad 입력으로 반복한다.

## 6. 홈 편집 진입

세 진입 방법은 동일한 Draft를 연다.

1. Compact Context 또는 Dock의 `홈 편집` Button
2. App 또는 편집 가능한 Widget을 550ms Long press
3. 항목 더보기 Menu의 `홈 편집`

Keyboard 사용자는 Button 또는 Menu로 진입한다. Long press는 Shortcut이며 유일한 방법이 아니다.
Long press가 성립하면 원래 App 실행 Click을 취소하고 짧은 Haptic·Visual Feedback 뒤 편집 모드로
전환한다. Reduced Motion에서는 위치 이동 없이 Outline과 상태 문구만 바꾼다.

## 7. 편집 모드 흐름

1. 진입 시 현재 서버 Version과 Layout을 Edit Base로 복사한다.
2. 상단 또는 Safe Area를 침범하지 않는 Toolbar에 `추가`, Preset, `Undo`, `Redo`, `Reset`,
   `취소`, `저장`을 제공한다.
3. App은 Pin·Hide·Reorder·Folder, Widget은 Add·Hide·Restore·Reorder·Width·콘텐츠 밀도를 조정한다.
4. Pointer·Touch Drag 외에 `앞으로`, `뒤로`, `Section 이동`, `크기`, `숨기기` Menu를 제공한다.
5. 모든 변경은 Draft에만 반영하며 Dirty 상태와 변경 수를 표시한다.
6. `Reset`은 조직 기본값 Preview이며 저장 전까지 Undo·취소할 수 있다.
7. `저장` 성공 후 새 Version을 반영하고 편집 진입 Control로 Focus를 복원한다.
8. 저장 실패 시 Draft를 유지하고 Retry와 취소를 제공한다.
9. `409` 충돌이면 최신 구성과 내 변경 요약을 보여주고 `최신 버전 보기`, `내 변경 다시 적용`,
   `취소`를 제공한다. 조용히 덮어쓰지 않는다.

정책 잠금 항목은 잠금 Icon, 관리 주체, 변경 불가 이유와 필요한 경우 문의 경로를 제공한다.

## 8. Keyboard와 Focus 흐름

- `Tab`: 문서의 논리 순서로 Control 이동
- `Enter`·`Space`: App 실행, Button·Menu 활성화
- 편집 Handle에서 `Space`: Keyboard Drag 시작·종료
- Keyboard Drag 중 방향키: 허용된 순서로 이동
- `Escape`: Drag 취소, 열린 Menu·Dialog 닫기, 편집 모드 전체 종료는 확인 후 수행
- 대체 Menu: 앞/뒤/Section 이동, 크기, 숨김
- 이동 후 `aria-live="polite"`로 항목명과 새 위치를 알린다.
- Add·Restore 후 추가된 항목 Heading, Remove 후 다음 항목 또는 Gallery Trigger로 Focus를 옮긴다.
- Floating Toolbar가 현재 Focus와 콘텐츠를 가리지 않아야 한다.

## 9. 상태 설계

| 상태             | Page                        | Section 동작                                          |
| ---------------- | --------------------------- | ----------------------------------------------------- |
| Initial loading  | Header·IA 즉시 표시         | 최종 구조와 유사한 Skeleton, Layout Shift 최소화      |
| Healthy empty    | 정상 Context 유지           | 짧은 완료·비어 있음 설명과 필요한 경우 한 개의 행동   |
| No comparison    | 정상 수치 유지              | Chart 대신 `비교 데이터 없음`                         |
| Partial          | 정상 Section 유지           | 실패 Section만 Inline Error·Retry, 상단에 짧은 요약   |
| Error            | Shell·Dock 가능한 범위 유지 | 재시도와 목적 Route 제공, 전체 Blank 금지             |
| Stale            | 마지막 성공 데이터 유지     | 마지막 성공 시각과 `업데이트 지연` 표시               |
| Offline          | Cache가 있으면 유지         | Offline 상태와 기준 시각, Network Action만 비활성     |
| Forbidden        | 허용 데이터만 표시          | 빈 상태로 위장하지 않고 제목·수치·원천 ID 미노출      |
| Date mismatch    | 실제 기준일 표시            | 현재 Home 기준일과 다른 항목을 `오늘`로 표시하지 않음 |
| Save failure     | 기존 Home 유지              | Draft 보존, Retry·Cancel                              |
| Version conflict | 기존 Home 유지              | Diff·Reload·재적용 선택                               |
| AI unavailable   | 결정적 정보 유지            | 추천만 조용히 축소 또는 Unavailable 표시              |

## 10. Responsive 계약

### 10.1 Desktop 1440·1280

- 콘텐츠는 최대 1600px 안정 Grid 안에 둔다.
- `1440×900`, `1280×800`을 첫 Viewport 검증 기준으로 삼는다. Context 96px, Dock 128px
  목표로 이 경계 안에 Now의 주 Action을 노출한다.
- `>=1200px`에서 12-column Guide를 사용한다. 기본 첫 행은 `Now 8 + Today Flowline
4`, 둘째 행은 `Work Signals 4 + Next 8`이다.
- 첫 visible personal Section이 달라지면 Now가 보완 폭을 사용하며, 안전한 Pair가 아니면
  한 열로 전환한다.
- Flowline은 가로 시간축, Signals는 관계가 유지되는 3~4개 Grid를 사용한다.
- Widget 폭은 승인된 60단 논리 Grid를 사용하되 고정 높이 내부 Scroll을 만들지 않는다.

### 10.2 Mobile 390·320

- 모든 Section은 단일 열로 재배치한다.
- Dock App은 4열 2행, `모든 앱`은 Grid 밖의 별도 Action으로 두고 Flowline은 세로 Timeline으로
  바꾼다.
- Mobile 검증 기준은 `390×844`, 최소 `320×568`이다. 2×4 Grid에는 앱 최대 8개만 배치하고
  `모든 앱`은 별도 Action으로 둔다.
- Desktop 편집기의 Mobile Preview는 실제 Viewport가 넓어도 390px Canvas·단일 열·
  Mobile 콘텐츠 예산을 사용한다. 필수 Rail이 있으면 `priorityCompact=true`다.
- App Group을 82vw 가로 Snap으로 숨기지 않는다.
- Editor Toolbar는 Safe Area를 존중하고 Focus·저장 상태를 가리지 않는다.
- 긴 Label은 두 줄까지 허용하고 전체 접근성 이름을 유지한다.
- Header Assistant 진입점은 본문 폭을 예약하지 않으며 Floating Assistant가 닫혀 있을 때
  영구 우측 여백이 없어야 한다.

### 10.3 실제 200% 글자 크기

- Browser의 실제 `html font-size: 200%` 상태로 검증한다.
- Desktop 고정 폭·높이와 2D 배치를 해제해 단일 열 Document Flow로 전환한다.
- 수평 Scroll, Control 겹침, 잘린 필수 문구와 가려진 Focus를 허용하지 않는다.

## 11. 접근성 계약

- 문서 첫 Keyboard Target은 `본문으로 건너뛰기`다.
- `h1`은 하나, 주요 Section은 `h2`, 항목 제목은 `h3`를 사용한다.
- 모든 Icon Button은 접근 가능한 이름과 필요한 Tooltip을 가진다.
- 최소 Pointer Target은 44×44px다.
- 본문 Text 대비 4.5:1, 큰 Text·그래픽·Focus 대비 3:1 이상을 유지한다.
- Drag 없이 모든 편집 기능을 완료할 수 있어야 한다.
- Flowline·Chart는 Screen Reader 요약과 동일 데이터의 List·Table 대안을 제공한다.
- 색만으로 상태·선택·위험을 구분하지 않는다.
- Forced Colors에서 Gradient·배경 이미지 없이 의미와 Focus가 유지된다.
- Reduced Motion에서는 Jiggle, Pulse, 위치 이동과 연속 Animation을 제거한다.
- 일반 모드에서도 장식용 무한 Animation과 자동 Carousel을 사용하지 않는다.

## 13. 기존 화면에서의 Migration 의미

- 기존 App Launchpad는 `My App Dock`의 권한·실행·Folder 원천으로 재사용한다.
- 기존 `command-rail`은 개인 `Action Queue(우선 업무)`의 저장 정본으로 재사용하고,
  `schedule`은 Today Flowline으로 재구성한다.
- 기존 `daily-brief`, `focus`, `schedule`, `activity` 데이터는 Work Signals와 Next의 Source로
  재구성하되 Preference Key Migration은 데이터·Architecture 문서에서 확정한다.
- Tenant Background·Logo, 관리형 공지와 Personal Home Shell은 삭제하지 않는다.
- 기존 내부 Scroll과 470px 이미지 중심 Hero는 새 화면 계약에서 사용하지 않는다.
