# DWP-R1-CORE-007 개발 백로그 및 추적 매트릭스

> 상태: Phase 1·2 기능 보존·Home v2 구성 구현 완료, integrated automated verification
> passed, 승인·수동 QA·출시 대기
>
> 원칙: `approved`·`implemented`·`auto-verified`·`verified`는 실제 증거 링크가 있을 때만 사용한다.

## 1. 추적 상태

| 상태            | 의미                                                  |
| --------------- | ----------------------------------------------------- |
| `prepared`      | 문서·수용 기준이 준비됐으나 Owner 승인이 없음         |
| `approved`      | 승인자·일자·근거가 기록됨                             |
| `implemented`   | Source·Migration·계약 변경이 연결됨                   |
| `auto-verified` | 연결된 자동 Test 범위가 통과함. 수동·운영 Gate는 별도 |
| `partial`       | 코드 또는 검증의 일부와 남은 범위가 함께 기록됨       |
| `verified`      | 자동·수동 증거와 결과가 모두 연결됨                   |
| `deferred`      | 후속 Phase와 진입 조건이 명시됨                       |

## 6. Definition of Ready

- [x] 문제, Non-goal과 1차·2차 경계를 문서화했다.
- [x] 기존 기능 보존과 부분 대체 범위를 결정 기록으로 분리했다.
- [x] 화면 상태·데이터·API·권한·AI·접근성·Rollout 계약을 문서화했다.
- [x] Requirement와 Acceptance ID를 구현 Issue에 연결할 구조를 준비했다.
- [x] Desktop Default Figma를 시각 검증했다.
- [x] Design draft OpenAPI·Event Schema·대표 Test Fixture를 작성했다.
- [ ] Edit·Mobile Figma Frame과 Node URL을 채운다.
- [ ] 각 Gate 승인자·일자·증거를 기록한다.
- [ ] 구현 Issue URL과 실제 Owner를 각 Backlog 행에 연결한다.
- [ ] Canonical OpenAPI·Schema 변경 여부와 Migration 실행 ID를 승인한다.

위 미완료 항목이 남아 있는 동안 Package는 `code implemented / automated verification
passed`이지만 `release-ready`로 표시하지 않는다. 구현 범위와 실제 자동 증거, 남은 수동·외부
조건은 [구현 및 검증 결과](10-구현%20및%20검증%20결과.md)를 따른다.
