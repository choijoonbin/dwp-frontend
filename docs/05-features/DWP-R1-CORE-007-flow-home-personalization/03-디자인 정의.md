# DWP-R1-CORE-007 디자인 정의

> 상태: Home v2 implemented — integrated visual/accessibility automation passed; final Design approval pending
>
> 방향명: `Calm Workstage / Soft Editorial`
>
> Component 기반: DWP Design System, Material UI, Emotion, Lucide
>
> 구현 검증일: 2026-08-24

이 디자인은 우주 배경과 Glass Card를 더 많이 쓰는 방향이 아니다. 흐름, 변화, 우선순위와
연결 관계를 실제 데이터로 시각화해 **부드럽지만 업무 판단이 정확한 Home**을 만든다.

## 0. Home v2 구현 결과

- `Compact Context → My App Dock → 필수 Rail(해당 시) → 4+8 Work Stage → Updates`의
  계층으로 소식 Portal과 Card soup를 피했다.
- Desktop `1200px` 이상에서 첫 행은 `Now 8 + 첫 visible personal Section 4`, 기본
  둘째 행은 `Work Signals 4 + Next 8`로 연결한다. 그보다 좁은 화면과 실제
  `html font-size: 200%` 화면에서는 동일 DOM을 단일 열로 재배치한다.
- Context는 96px 이하, Dock은 128px 이하·최대 8개를 Desktop 목표로 해 첫 Viewport에
  앱 실행과 Now 주 Action을 노출한다.
- 일반 소식은 Work Stage 뒤의 Soft Editorial Updates로 내리고 확인 필수·Critical
  항목만 얇은 Rail로 즉시 노출한다.
- Signal Chart는 실제 시간순 비교 데이터가 4개 이상일 때만 표시한다. 기간·충돌 범례와 접근
  가능한 원본 Data Table을 함께 제공한다.
- Home의 DWAI·ON은 우측 하단에서 최초 Aura·Float·Greeting Motion을 유지한다. Panel이 열리면
  Float 주기를 늦추고 Greeting은 정지하며, `prefers-reduced-motion`에서는 모든 반복 모션을
  제거한다.
- Home 본문에는 영구 우측 Rail·예약 여백을 두지 않는다. Launcher가 Footer 조작 요소와 겹치면
  위치를 위로 자동 보정하고 Modal보다 낮은 Layer를 사용한다.
- Tenant Logo 실패 시 빈 Slot·Divider를 제거하고 DWP Product Mark로 자연스럽게 Fallback한다.
- Forced Colors에서는 inverse 장식을 제거하고 System Canvas·CanvasText·명확한 Border로
  전환해 Browser text backplate와 겹쳐 글자가 사라지지 않게 한다.
- Architecture, UI/UX, Accessibility, Interaction·Concurrency 관점의 내부 전문 Agent Review와
  공식 글로벌 제품·플랫폼 Reference를 반영했다. 외부 상용 Design AI의 독립 승인을
  받았다고 주장하지 않으며 최종 Design 승인 Gate는 별도로 유지한다.

## 1. 시각 원칙

1. **Work before decoration**: 첫 Viewport에서 앱 실행과 실제 우선 업무가 보인다.
2. **Flow, not card soup**: Section 관계는 여백·시간축·연결선·표면 Tone으로 만들고 모든 항목을
   같은 Card에 넣지 않는다.
3. **Meaningful delight**: Flowline, Trend와 상태 변화가 시각적 즐거움의 원천이다.
4. **Calm hierarchy**: 강한 색·그림자·Glass는 선택·위험·실제 Floating Layer에만 사용한다.
5. **Curated freedom**: 표현 Preset은 달라도 정보 의미, 상태색과 접근성은 바뀌지 않는다.
6. **One document rhythm**: 고정 높이 Widget과 내부 Scroll 없이 Page 전체가 하나의 리듬으로 흐른다.

## 2. Soft Aurora Language

### 2.1 Canvas와 Color 역할

| 역할          | Token 후보           | 사용                                                 |
| ------------- | -------------------- | ---------------------------------------------------- |
| Warm canvas   | `flow.canvas.pearl`  | Light Home의 기본 바탕. 순백보다 부드러운 Pearl Tone |
| Dark canvas   | `flow.canvas.ink`    | Dark Home의 저채도 Ink Tone                          |
| Primary       | `flow.accent.cobalt` | 주 Action, 현재 선택, Flowline의 현재 시점           |
| Informational | `flow.accent.cyan`   | 보조 비교, 예정 흐름, 정보 상태                      |
| Success       | Foundation Teal      | 완료·검증·건강 상태                                  |
| Warning       | Foundation Saffron   | 주의·임박·용량 소진                                  |
| Risk          | Foundation Coral     | 실패·고객 영향·즉시 대응에만 사용                    |

Aurora Gradient는 Today Flowline의 실제 진행·시간 범위 또는 Section 경계의 낮은 Tone에만
사용한다. 전체 Page Wallpaper, Glow Blob, 가독성을 낮추는 빛줄기와 색만 있는 장식은 금지한다.
고객 Accent가 상태색의 의미를 덮어쓰지 않게 한다.

### 2.2 Surface

- `canvas`: Home 전체 바탕
- `section-soft`: Dock, Now, Signals처럼 관계를 묶는 낮은 Tone Surface
- `item`: 선택·경계가 필요한 반복 객체만 사용
- `floating`: Menu, Dialog, Inspector, Editor Toolbar

첫 Viewport의 Elevated Surface는 최대 두 계층으로 제한한다. Card 안의 Card는 금지하고,
Section 내부 반복은 Divider, Row, Timeline과 Tone 변화로 구분한다.

### 2.3 Radius와 Elevation

| 요소                       |                     Radius | Elevation                         |
| -------------------------- | -------------------------: | --------------------------------- |
| App Dock·주요 Soft Section |                    24~28px | 0 또는 낮은 Ambient Shadow        |
| Now 강조 영역              |                    20~24px | 선택·위험이 있을 때만 낮은 Shadow |
| Row·Signal·Control Group   |                    12~16px | 기본 0                            |
| Button·Chip                | Foundation Component Token | 개별 임의값 금지                  |
| Dialog·Floating Toolbar    |                    20~24px | 실제 Floating 계층에만 사용       |

Glass는 이미지 위 Control 또는 Floating Editor Toolbar에만 제한적으로 사용한다. 긴 본문,
데이터 목록과 Form 전체에 Blur를 사용하지 않는다. Reduced Transparency와 Forced Colors에서는
불투명 Foundation Surface로 교체한다.

## 3. Layout와 리듬

- Home Section의 시각 정렬은 최대 1600px의 12 Column Guide를 사용한다. 저장되는 Widget 폭은 기존
  60-unit Composer Grid(`12|15|20|30|40|60`)를 유지한다. 12 Column은 시각 Guide이고 저장 계약이
  아니므로 fifth·quarter 폭을 임의 반올림하지 않는다.
- Desktop Page Inline Padding은 Foundation Workspace Token을 사용한다.
- Section 간 Vertical Rhythm은 32~~48px, 관련 항목 간격은 8~~20px 범위의 Token을 사용한다.
- Compact Context는 Desktop 96px 이하를 목표로 하고 Mobile은 콘텐츠 높이를 사용한다.
- My App Dock은 Desktop 128px 이하와 visible App·Folder 8개를 목표로 하며 `모든 앱`을
  독립 Action으로 둔다.
- 12-column Visual Guide의 4+8 Pair는 60-unit 저장 Grid의 compact+large로 구현한다.
- 고정 Height Token은 최소 공간과 콘텐츠 예산을 뜻하며 `overflow-y:auto`를 만들지 않는다.
- `1440×900`, `1280×800` 첫 Viewport에는 My App Dock과 Now의 주 Action이 노출돼야 한다.
- 390·320과 실제 200% 글자 크기에서는 단일 열과 Document Flow로 전환한다.
- Required Notice가 있는 실제 Narrow Viewport·Desktop Editor Mobile Preview는 동일
  `priorityCompact`를 사용한다. Context·Now 보조 설명을 축약하되 App·Rail·첫 CTA의
  의미·접근성 이름·Focus 순서는 유지한다.

## 4. Typography와 Icon

- 현재 DWP Product Font Stack과 Type Scale을 재사용한다.
- Home `h1`은 큰 Marketing Display가 아니라 28~32px 범위의 업무 Context Heading으로 쓴다.
- Section `h2`는 20~~24px, 항목 `h3`는 16~~18px 범위에서 Foundation Token으로 확정한다.
- 날짜·Freshness·수치는 Tabular Number를 사용할 수 있으나 긴 본문에 Monospace를 쓰지 않는다.
- 독립 Section Header는 승인된 `SectionHeader` 패턴을 사용한다.
- Lucide Icon은 승인된 Wrapper와 1.8px Stroke를 사용하고 장식 Icon은 접근성 Tree에서 숨긴다.
- Icon Button은 접근 가능한 이름과 뜻이 명확하지 않을 때 Tooltip을 가진다.

## 5. Section별 시각 계약

### 5.1 Compact Context

- 큰 배경 Hero를 만들지 않고 날짜·인사·역할·Freshness를 한 시선 흐름으로 묶는다.
- Tenant 이미지는 우측의 낮은 Contrast Crop 또는 얇은 Accent Layer로 선택 제공한다.
- 필수 Text를 이미지에 합성하지 않는다.
- Partial·Stale는 짧은 상태 문구와 Icon을 사용하며 경고 Banner를 과도하게 키우지 않는다.

### 5.2 My App Dock

- 하나의 부드러운 Dock Surface 안에 App Glyph, 1~2줄 Label, 실제 Badge를 정렬한다.
- App마다 임의색 Card를 만들지 않고 Glyph Tone과 Badge 의미로 구분한다.
- `모든 앱`은 마지막에 안정적으로 유지해 추가 앱을 찾는 Escape Hatch가 된다.
- 편집 전에는 Handle·Remove Control을 숨긴다.
- 편집 진입 시 전체 Tile을 무한히 흔들지 않고 한 번의 160~220ms Settle과 명확한 Outline을 쓴다.
- Folder는 미니 Glyph Stack과 이름을 제공하고 중앙 Drop 또는 Menu로 생성한다.

### 5.3 중요 공지

- 중요도에 따라 Coral을 남용하지 않고 Icon, Label과 얇은 상태 Edge를 사용한다.
- 긴 공지는 제목·한 줄 요약·Action으로 압축하고 본문은 상세에서 읽는다.
- 자동 전환 Carousel, Marquee와 반복 Pulse를 사용하지 않는다.

v2에서 이 영역은 확인 필수 또는 Critical 항목 한 건의 얇은 Rail이다. 일반 소식은 업무
Stage 뒤 Updates에서 표시하고 같은 항목을 중복하지 않는다.

### 5.4 Now

- 최우선 1건은 넓은 Row 또는 단일 Soft Surface로 강조한다.
- 이유, 마감, 영향과 주 Action이 제목보다 먼저 경쟁하지 않게 계층을 분명히 한다.
- 나머지 최대 2건은 Divider Row로 압축한다.
- 세 개의 같은 크기 Card로 Now·Next·Later를 나열하지 않는다.
- Healthy Empty는 Teal Check와 짧은 문장으로 축소하고 큰 빈 면적을 남기지 않는다.

### 5.5 Today Flowline

- Desktop은 실제 업무 시간축을 따라 Node·Label·상태와 연결선을 배치한다.
- 현재 시점은 Cobalt, 예정 구간은 Cyan, 완료는 Teal, 위험은 Saffron·Coral로 표현한다.
- Glow는 현재 선택 또는 실제 위험 Node 주변의 짧은 Focus 표현에만 사용한다.
- Mobile·실제 200% 글자 크기에서는 같은 DOM 정보를 세로 Timeline으로 재배치한다.
- Flowline과 별도로 Screen Reader가 읽을 수 있는 요약·목록 또는 표를 제공한다.
- 정보가 6개를 넘으면 중요 항목과 `+N`을 표시하며 내부 가로·세로 Scroll을 만들지 않는다.

### 5.6 Work Signals

- 동일한 KPI Card 묶음 대신 값, 변화, 기준과 작은 Trend를 한 Connected Surface 안에 배치한다.
- Sparkline은 추세가 실제로 존재할 때만 사용하며 Summary와 Data Table 대안을 제공한다.
- 건강한 반복은 압축하고 위험 Signal이 있으면 원인·영향을 더 크게 노출한다.
- 색상은 범주 장식이 아니라 상태·비교 의미에만 사용한다.

### 5.7 Next

- 다음 일정·준비·추천을 낮은 밀도의 목록으로 제공한다.
- AI 또는 규칙 추천은 일반 업무와 같은 척하지 않고 `추천`, 이유, Source와 Feedback을 표시한다.
- `관련 없음` 처리 후 즉시 사라지되 Snackbar의 Undo로 복원할 수 있다.

### 5.8 Updates

- 일반 소식은 업무 흐름을 방해하지 않는 Soft Editorial Surface에 둔다.
- Cover image는 실제 Asset이 있을 때만 쓰고, 없을 때 장식 이미지를 생성하지 않는다.
- Featured 1건과 보조 최대 2건을 기본 예산으로 하고, Publisher·게시일·읽기 시간·읽지
  않음 수를 실제 데이터로 표시한다.
- 시각적 흥미는 영상 Carousel이 아니라 실제 소식 Asset, Typography, 여백과 요약·목록의
  관계에서 만든다.

## 6. 개인화 표현 Preset

Preset은 업무 의미, 권한, 상태색, DOM 순서와 필수 콘텐츠를 바꾸지 않는다.

| Preset       | 목적                  | 허용 변화                                        |
| ------------ | --------------------- | ------------------------------------------------ |
| `balanced`   | 기본 업무 시작        | 표준 간격, 표준 정보량, Soft Aurora 기본         |
| `focused`    | 반복 업무와 높은 밀도 | 좁은 간격, 축약 보조 문구, 장식 최소화           |
| `expressive` | 개인적인 색감과 여유  | 넓은 간격, 승인된 Soft Scene, Flowline 표현 강화 |

사용자는 Preview에서 Desktop·Mobile을 전환할 수 있다. Dark·High Contrast와 Reduced Motion은
Preset보다 우선하는 접근성·시스템 정책이다.

## 7. Component 전략

현재 React·MUI·Emotion·DWP Design System을 유지한다. 전체 Component Platform 교체는 범위가 아니다.

재사용 대상:

- `ShellHeader`, `BrandLockup`, `SectionHeader`
- DWP `ActionButton`, `ActionIconButton`, `LoadingState`, `EmptyState`, `ErrorState`
- DWP `ContentDialog`의 `titleStart`·`titleEnd`·`headerContent` Slot
- App Registry, App Glyph, Entitlement·Launch Adapter
- Workspace Composer의 Registry Reconcile, DnD Sensor와 비 Drag 이동 Model
- Home Overview Query와 Section 상태 격리

고도화 또는 신규 Composite 후보:

- `FlowHomeContext`
- `MyAppDock`
- `PriorityNow`
- `TodayFlowline`
- `WorkSignalGroup`와 `SignalMetric`
- `NextActionList`
- `HomeEditToolbar`의 Undo·Redo·Conflict 상태
- `ScrollSafeContentBudget`

새 외부 UI Library는 기존 Platform으로 해결할 수 없는 검증된 Gap, Bundle·License·접근성 영향과
Design System Mapping이 있을 때만 도입한다.

| 선택지                                      | 1차 결정      | 적용 조건                                                                  |
| ------------------------------------------- | ------------- | -------------------------------------------------------------------------- |
| MUI·MUI X·Emotion·Lucide·DWP DS             | 유지·고도화   | Token, State, Composite와 Story Coverage를 먼저 보강                       |
| DWP Flow Home Composite                     | 신규 작성     | 위 목록의 Composite를 DWP DS 공개 API와 Storybook으로 제공                 |
| `@mui/x-charts` 같은 기존 생태계 Chart 후보 | 조건부 Spike  | 실제 비교·추세 요구, 접근 가능한 Table 대안, Bundle·License Gate 통과      |
| Base UI·React Aria 계열 Headless Primitive  | 예외적 평가   | 기존 Primitive로 해결되지 않는 Keyboard·Collection·국제화 Gap을 POC로 입증 |
| Radix·shadcn·Tailwind·Framer 전면 전환      | 채택하지 않음 | 중복 Primitive·Token·Style Runtime과 Migration 비용을 만들지 않음          |

즉, 현재 품질 문제를 Library 이름만 교체해 해결하지 않는다. Phase 1은 DWP Composite·Token·상태·
Motion·Chart 품질을 높이고, 조건부 Spike가 실제 Gap과 이점을 입증한 경우에만 작은 범위로 새
의존성을 승인한다.

## 8. 상태 표현

| 상태          | 시각 규칙                                                       |
| ------------- | --------------------------------------------------------------- |
| Loading       | 최종 구조와 유사한 Skeleton, 과도한 Shimmer 금지                |
| Healthy Empty | Teal 또는 중립 Icon + 짧은 설명, 큰 Empty Card 금지             |
| No Data       | 현재값과 구분되는 중립 Tone, 원천 연결·설정 행동 제공           |
| Partial       | 해당 Section의 낮은 Warning Surface와 Retry, 정상 Section 유지  |
| Error         | Coral은 실패 상태와 실패 Action에만 제한                        |
| Stale         | 중립·Saffron Label과 마지막 성공 시각, 데이터 자체는 유지       |
| Offline       | Offline Icon·기준 시각, Network 의존 Action만 비활성            |
| Forbidden     | 민감한 제목·수치 없이 일반 제한 문구 또는 Section 생략          |
| Date mismatch | `오늘`로 위장하지 않고 실제 날짜·지연 상태를 중립 Tone으로 표시 |
| Saving        | Toolbar Progress와 Control Disable, 기존 Layout 유지            |
| Save failed   | Draft 유지, Inline 설명과 Retry                                 |
| Conflict      | Diff Dialog, 선택 전 기존 서버 설정 유지                        |

## 9. Motion과 Feedback

- Hover·Press: 80~120ms
- Selection·Inspector·편집 상태 전환: 160~220ms
- 큰 Pane 전환: 220~280ms
- 새 데이터는 Layout Shift 없이 짧게 Highlight 후 안정 상태로 돌아간다.
- Drag 중 원래 Slot과 Drop Preview의 공간 관계를 보여준다.
- 편집 진입 Jiggle과 Pulse는 1회성 Feedback으로 제한한다.
- Continuous Glow, 자동 Carousel, 장식 Particle과 무한 Animation을 금지한다.
- `prefers-reduced-motion` 또는 개인 Reduced Motion 설정에서는 위치 이동·Scale·Jiggle·Pulse를
  제거하고 Outline·Text 상태로 대체한다.

## 10. 접근성 시각 Gate

- Normal Text 4.5:1, Large Text·Graphical Object·Focus 3:1 이상
- 색과 Gradient가 없어도 Label·Icon·Pattern으로 상태 구분
- Focus Ring은 모든 Surface·Theme 위에서 식별 가능하고 Floating Toolbar에 가려지지 않음
- Touch·Pointer Target 44×44px 이상
- 320px와 실제 200% 글자 크기에서 필수 Text·Action이 잘리거나 겹치지 않음
- 긴 한국어·영어 App·업무명은 최대 두 줄과 전체 접근성 이름 제공
- Forced Colors에서 Background Image·Blur·Gradient 없이 Border와 CurrentColor로 계층 유지
- Reduced Transparency에서 Glass를 불투명 Surface로 변경
- Flowline·Chart의 Text Summary·List·Table 대안 제공

## 12. Visual QA Matrix

- Viewport: `1440×900`, `1280×800`, `390×844`, `320×568`, `html font-size: 200%`
- Locale: 한국어, 영어, 긴 App·사용자·Workspace·업무명
- Appearance: Light, Dark, High Contrast, Forced Colors, Reduced Transparency
- Motion: Normal, Reduced Motion
- Data: Loading, Healthy Empty, No comparison, Partial, Error, Stale, Offline, Forbidden,
  Unavailable, Date mismatch, urgent·actionable·unread Badge
- Editor: Default, Long press entry, Keyboard move, Dirty, Saving, Save failed, Conflict

각 Frame은 첫 Viewport 실제 업무 노출, 내부 세로 Scroll 0, 수평 Overflow 0, Focus 비가림,
장식용 데이터 0건과 Section 간 시각 계층을 검토한다.
