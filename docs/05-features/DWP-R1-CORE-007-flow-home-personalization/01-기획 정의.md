# DWP-R1-CORE-007 기획 정의

> 상태: Home v2 product contract — integrated automated verification passed, approval pending
>
> 대상 Release: R1 Flow Home Phase 1, R2 Personalization Phase 2
>
> 선행 기능: `DWP-R1-CORE-002-personal-home-experience`
>
> Owner 후보: DWP Product Experience, Platform Control Plane

이 문서는 기존 Personal Home의 Shell·권한·앱 실행·개인 설정·관리형 공지 계약을 보존하면서,
로그인 직후 경험을 **Daily Work Launch & Triage형 DWP Flow Home**으로 고도화하기
위한 제품 범위를 정의한다. Source 구현, 자동 검증, 사람 승인과 운영 활성화를
별도 상태로 기록하며, 체크되지 않은 항목은 출시 완료를 의미하지 않는다.

## 1. 해결할 문제

현재 Home은 다음 문제가 함께 존재한다.

1. Desktop App Group과 Widget이 고정 높이 내부 Scroll을 사용한다. 사용자가 문서 Scroll 중
   Pointer를 그 영역에서 멈추면 다음 Wheel 입력이 내부 영역에 소비되어, Home 아래로 계속
   이동하려면 Pointer를 빈 공간으로 옮겨야 한다.
2. 앱 실행, 우선 업무, 일정, 활동과 추천이 비슷한 사각형 Surface에 분산되어 사용자가
   `지금 무엇을 해야 하는가`를 빠르게 판단하기 어렵다.
3. 큰 Tenant 이미지 Hero와 텍스트 중심 Widget은 시각적 면적에 비해 업무 정보가 적고,
   데이터의 변화·시간·연결 관계를 충분히 표현하지 못한다.
4. 기존 편집은 앱·Widget 이동, 숨김, 크기와 표현 모드를 제공하지만, 사용자가 기대하는
   Undo·Redo, 충돌 복구, 장치 Preview와 더 세밀한 구성 자유도는 제품 계약으로 고정돼 있지 않다.
5. 과도한 자유 배치형 Canvas는 접근성, 반응형, 성능과 조직 정책을 훼손할 수 있으므로,
   자기표현 욕구와 Enterprise 통제를 함께 만족하는 경계가 필요하다.

## 3. Persona와 JTBD

### 3.1 구성원

- 업무 시작 시 자주 사용하는 앱을 검색 없이 실행하고 싶다.
- 여러 시스템의 마감, 일정과 후속 행동 중 지금 가장 중요한 항목을 놓치지 않고 싶다.
- 내 업무 습관에 맞게 Home을 구성하되 회사의 필수 공지와 정책은 명확히 구분하고 싶다.

### 3.2 Manager

- 개인 업무 구조를 유지하면서 내 팀에 영향을 주는 승인·일정·주의 신호를 추가로 보고 싶다.
- 역할이 바뀌어도 기존 개인 배치가 불필요하게 삭제되지 않기를 원한다.

### 3.3 Operator

- 운영 권한으로 제공되는 항목이 일반 구성원 정보와 섞이지 않고 출처와 Scope가 분명하길 원한다.
- Stale·Partial·Permission 상태를 정상값과 오인하지 않고 싶다.

## 4. 목표와 Outcome

- Home 내부 세로 Scroll Container를 제거해 Pointer 위치와 관계없이 문서 Scroll이 연속되게 한다.
- 로그인 직후 앱 실행이라는 기존 App Launcher 목적을 `My App Dock`으로 보존한다.
- `Now → Today Flowline → Work Signals → Next`로 우선순위·시간·변화·후속 행동을 연결하되,
  Desktop은 4+8 Pair로 관계있는 영역을 배치한다.
- 일반 소식을 필수·Critical Rail 직후에 배치해 조직 소식을 업무 Widget보다 먼저 접하게 한다.
- `FORBIDDEN`, `UNAVAILABLE`, `PARTIAL`, 날짜 불일치와 알림 의도를 실제 상태대로 다른
  문구·조작으로 표현한다.
- 실제 데이터가 만드는 Flowline, 상태 변화와 작은 Trend로 시각적 즐거움을 제공하되 장식용 Chart와
  가짜 수치를 만들지 않는다.
- 기존 편집 기능을 제거하지 않고 명시적 Button, Long press, Pointer·Touch·Keyboard·Menu 조작을
  모두 유지한다.
- Phase 1에서 구조 개인화 전체와 선별된 시각 개인화를 제공하고, Phase 2 확장이 가능한
  Registry·Preference·정책 경계를 설계한다.

## 5. 고정 Information Architecture

Home의 기본 문서·DOM 읽기 순서는 다음과 같다.

1. **Compact Context**: 날짜, 역할 Context, 인사 문구, 최근 성공 갱신 상태
2. **My App Dock**: Pin·폴더·개인 순서를 반영한 빠른 앱 실행
3. **필수·Critical Rail**: 확인 필수 또는 Critical 공지가 있을 때만 표시
4. **Updates**: 일반 소식·Featured story·읽지 않음 요약을 compact Editorial Row로 표시
5. **Work Action Stage**: Now와 가장 먼저 보이는 개인 Section을 한 작업 단위로 배치
6. **Today Flowline·Work Signals·Next**: 저장 순서를 존중하는 제약형 개인 Section

Shell Header, My App Dock의 상단 위치, 필수 Rail과 Now의 우선 위치는 개인 설정이 변경하지
못한다. 개인화 가능한 하위 Section도 DOM·Keyboard·Mobile 순서가 저장 배열 순서와 같아야
한다. 일반 Updates는 저장 Widget이 아닌 앱·필수 Rail 직후의 Editorial Zone이다.

### 5.1 Desktop 기본 Composition

- Compact Context: 목표 96px 이하
- My App Dock: 목표 128px 이하, App·Folder 최대 8개
- 12-column Guide 첫 행: `Now 8 + 첫 visible personal Section 4`
- 기본 둘째 행: `Work Signals 4 + Next 8`
- 가로 폭이 부족하거나 조합이 안전하지 않으면 동일 DOM을 전체 폭 한 열로 배치

시각 12-column은 기존 60-unit 저장 Grid의 `compact(20)`·`large(40)`에 대응하며 새
저장 Schema를 만들지 않는다.

## 6. Section 정책

| Section            |                       기본 콘텐츠 예산 | 주 행동               | 개인화 경계                                      |
| ------------------ | -------------------------------------: | --------------------- | ------------------------------------------------ |
| My App Dock        | 그룹별 5열×2행 + 별도 `모든 앱` Action | 앱 실행               | 위치 고정, App Pin·Hide·Reorder·Folder 허용      |
| 필수·Critical Rail |                 확인 필수·Critical 1건 | 공지 열기             | `GOVERNED`; Hide·Move·Resize 금지                |
| Now                |             최우선 1건 강조 + 최대 2건 | 처리 화면 열기        | 위치 고정, 정책이 허용한 Compact·Expanded만 선택 |
| Today Flowline     |           최대 6개 Anchor, 초과는 `+N` | 일정·업무 상세        | 정책에 따라 표시·이동 가능                       |
| Work Signals       |               최대 3~4개 검증된 Signal | 근거·상세 Drill-down  | Hide·Reorder·승인된 표현 밀도                    |
| Next               |                               최대 3건 | 준비·상세·추천 피드백 | Hide·Reorder 허용                                |
| Updates            |             Featured 1 + 보조 최대 2건 | 소식 상세·전체 보기   | 필수 Rail 직후, 필수 Rail과 중복 금지            |

콘텐츠 예산은 내부 Scroll을 만들지 않기 위한 기본값이다. 권한으로 노출할 수 없는 App·업무·수치는
DOM, 접근성 이름과 Analytics Payload에도 포함하지 않는다.

App Badge는 `totalUnread`, `actionableUnread`, `urgentUnread`를 구조적으로 유지하고
`urgent > actionable > unread` 의도를 색·Label·접근 가능한 이름에 함께 반영한다.
일부 원천 실패가 성공한 App의 Badge까지 제거하지 않는다. 단, Summary 권한 없음·
Query 오류·Refetch 오류·`generatedAt` 30초 Freshness 실패는 이전 성공 Badge를
재사용하지 않고 전체 Fail Closed한다. Query Cache Stale·Refetch 예산도 각각
30초다.

- 모든 Home Section의 단일 문서 세로 Scroll
- 요약 콘텐츠 예산과 `전체 보기`·`+N` 경로
- App Dock Pin·Unpin·Reorder·Hide·Folder 생성·이름 변경·해제

## 9. Phase 2 범위

- Widget별 Source·Filter·기간·표시 필드 설정
- 여러 개인 Home Profile과 이름·복제·전환
- 조직·팀 공유 Template와 개인 사본
- 장치별 별도 Layout
- 개인 설정 Revision History와 특정 버전 복원
- 고급 Curated Theme·배경 Scene
- AI Workstyle Composer

AI 제안은 `제안 이유 → Preview → Diff → 사용자 승인 → 적용 → Undo`를 거친다. AI는 권한을
확대하거나 필수 항목을 숨기거나 사용자 확인 없이 배치를 저장하지 않는다.

## 10. 제외 범위

- 임의 `x/y` 좌표와 픽셀 단위 자유 Canvas
- 사용자 CSS, HTML, JavaScript와 등록되지 않은 외부 Widget
- Tenant별 임의 Font·전체 Navigation·브랜드 Theme Builder
- 업무 데이터가 없는 장식 Chart, 합성 Trend와 Stock Illustration
- 사용자 확인 없는 AI 자동 구성·자동 실행
- 개인 성과 평가, 감정·건강 추론과 과도한 행동 감시
- Phase 1에서 여러 Home Profile 또는 장치별 독립 Layout 제공

## 11. 우선순위와 신뢰 정책

초기 Now 정렬은 검증 가능한 규칙을 사용한다.

```text
priority = deadline + businessImpact + approvalBlocking + explicitPin
           + assignedRole + recency - dismissed - completed
```

- 결과에는 마감, 영향, 차단 관계 또는 명시적 Pin 중 실제 적용된 이유를 표시한다.
- Signal은 현재값과 함께 Baseline·Threshold·Trend·`비교 데이터 없음` 중 하나를 제공한다.
- AI 항목은 생성 시각, Source 범위, 누락 Connector, 신뢰 수준과 `왜 표시되었나요`를 제공한다.
- `0`, Healthy Empty, No Data, Partial, Error, Forbidden을 서로 다른 상태로 표현한다.

### 11.1 날짜·부분 실패 계약

- `FORBIDDEN`은 빈 상태가 아니며 민감한 제목·수치·원천 ID를 노출하지 않는다.
- `UNAVAILABLE`은 다시 시도 가능한 실패로 표시하고 정상 Section을 보존한다.
- `PARTIAL`은 성공한 데이터를 유지하고 누락 Source만 설명한다.
- 원천 항목의 날짜가 현재 Home 기준일과 다르면 `오늘`로 표시하지 않고 실제 날짜 또는
  지연 상태를 제공한다.

## 14. 기존 계약과 변경 관계

- `DWP-R1-CORE-002`의 Personal Home Shell, Co-branding, Entitlement, App 실행, 관리형 공지,
  Preference·Revision·Audit는 유지한다.
- `CORE-002/02-화면 설계서.md`의 `App Hero + Today`, Desktop 네 Group, Mobile 가로 Snap은
  이 Feature의 IA와 반응형 계약으로 대체한다.
- `CORE-002/03-디자인 정의.md`의 Tenant 이미지 중심 470px Hero와 8px 이하 Group Radius는
  Compact Context와 Calm Workstage·Soft Editorial 계약으로 대체한다. Tenant Media 관리 기능은
  삭제하지 않는다.
- `R1 Multi-Surface Personal Home Composer ADR`의 고정 Block Size와 넘침 시 Widget 내부 Scroll은
  신규 Architecture Decision이 명시적으로 Supersede해야 한다.
- 기존 완료 체크와 Test는 회귀 근거일 뿐 이 Feature의 구현 완료 증거로 재사용하지 않는다.
