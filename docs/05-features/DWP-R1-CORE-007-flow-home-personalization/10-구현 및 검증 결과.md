## 2. 구현된 Phase 1

- [`home.tsx`](../../../apps/dwp/src/pages/home.tsx)가 Server의
  `effectiveExperienceVariant=FLOW_V1`을 확인한 경우에만 Flow Home을 선택하고, 응답이 없거나
  조건이 맞지 않으면 Classic Home으로 Fail Closed 한다.
- [`flow-home.tsx`](../../../apps/dwp/src/features/home/flow-home/flow-home.tsx)에
  `Compact Context → 자주 쓰는 앱 → 필수 Rail(해당 시) → Work Action Stage → 일반 Updates`
  구조와 Section별 목적 화면 이동을 구현했다.
- Desktop Context 96px, Dock 128px·visible App/Folder 8개를 기본 목표로 한다. Expressive
  `>=1800px`의 untouched 기본 구조는 `우선 업무 5/12 + 오늘 일정 3/12 + support stack 4/12`로
  실제 재구성하고, Dock은 1760px 내부 rail에서 최대 12개를 고정 cadence로 표시한다.
- 개인이 순서·표시·폭을 변경하면 adaptive template를 끄고 저장한 footprint를 그대로 유지한다.
  조직 News의 `size`와 `height`도 실제 grid 폭, 표시 건수와 geometry에 반영한다.
- [`flow-updates.tsx`](../../../apps/dwp/src/features/home/flow-home/flow-updates.tsx)가 확인 필수·
  Critical 항목을 얇은 Rail로, 일반 소식을 Work Stage 뒤 Updates로 분리하고 중복을
  제거한다. `required`의 기존 의미는 유지하고 권위 `criticalUnread`·`actionable`과 일반
  소식 표본에 독립적인 `actionableItems`를 우선 사용한다.
- [`communication-action-rail.tsx`](../../../apps/dwp/src/features/communications/communication-action-rail.tsx)는
  Home CTA의 목적 화면에서도 Action 항목을 별도 Rail로 이어 보여준다. ID 병합·중복 제거,
  Critical·확인 필수 의미 분리와 5건 이상 더 보기·접기를 제공하며 일반 소식 DOM에서는 같은
  항목을 제거한다.
- [`my-app-dock.tsx`](../../../apps/dwp/src/features/home/flow-home/my-app-dock.tsx)와
  [`app-launchpad.tsx`](../../../apps/dwp/src/features/home/app-launchpad.tsx)가 Entitlement 기반 앱,
  실제 앱별 `totalUnread`·`actionableUnread`·`urgentUnread` Badge, Pin·Folder와 `모든 앱`
  경로를 재사용한다. Partial 응답의 정상 App Count도 보존한다.
- [`home-app-badge-policy.ts`](../../../apps/dwp/src/features/home/home-app-badge-policy.ts)는
  Notification Summary의 Cache Stale·Refetch를 각 30초로 제한하고 `generatedAt` ±30초
  Freshness를 독립 검사한다. 권한 없음·최초 Load·Refetch 오류·오래된 성공
  Cache에서는 이전 Badge·Metadata를 모두 제거하고 다른 Count로 Fallback하지
  않는다.
- Today Flowline은 숨겨진 Overflow Source가 Calendar 하나면 `/calendar/schedule`, Work
  하나면 `/work`를 선택하며 해당 회귀를 Unit Test로 고정했다.
- Flow Model은 `FORBIDDEN`, `UNAVAILABLE`, Partial, Source Label과 Home 기준일 불일치를
  빈 상태·`오늘`로 위장하지 않는다.
- Home은 영구 Assistant Rail과 Header Assistant를 예약하지 않고 우측 하단의 Entitlement 기반
  DWAI·ON Floating Launcher를 사용한다. 최초 Aura·Float·Greeting Motion을 복원하고,
  Reduced Motion·Footer 조작 요소 자동 회피·Modal보다 낮은 Layer를 유지한다. `BrandLockup`은
  Tenant Logo를 제품명 우측에 유지하고 실패 시 조직명을 표시한다.
- Home 본문은 같은 축의 Widget 내부 세로 Scroll을 만들지 않고 Document가 Y Scroll을 소유한다.
  콘텐츠는 행 예산 안에서 요약하며 목적 화면으로 연결한다.
- [`home-draft-history.ts`](../../../apps/dwp/src/features/home/home-draft-history.ts)가 Home Editor의
  Undo·Redo를 제공하고, Desktop·Mobile Preview와 `409` 충돌 보존·재시도 경로를 보강했다.
- Long press, Pointer Drag, Keyboard Drag, Context Menu·`Shift+F10`, 비 Drag 이동 메뉴와 44px
  조작 Target을 제공한다.
- Keyboard Drag 중에는 active handle과 focus를 유지한다. 최종 위치를 live announcement로
  전달하고 취소 시 원래 순서와 편집 진입 focus를 복원한다.
- 흰색 같은 tenant accent에서도 사라지지 않도록 표면 대비 기반 semantic focus token을 Dock,
  필수 공지, 일정, 업무, News와 Home launcher에 적용한다.
- App Folder 이름 변경 Action은 공통 Design System
  [`ContentDialog.titleEnd`](../../../libs/design-system/src/components/dialogs/content-dialog.tsx)를
  사용해 별도 Dialog Header 구현을 제거했다.
- 실제 비교 데이터가 없는 Signal을 장식 Chart로 꾸미지 않으며, Flowline·상태 시각화는 Text
  대안을 유지하고 Reduced Motion을 존중한다.

  적용하지 않는다.

## 8. 알려진 환경 제약

- System 기본 Node는 `20.20.2`지만 검증과 현재 Frontend Runtime은 Bundled Node `24.19.0`을
  명시해 Repository 요구 범위 `>=24.18 <25`에서 실행했다.
- 전체 Repository의 기존 범위와 분리해 이 Feature 변경 문서를 Prettier 검증 대상으로 확인했다.
- Home Footer를 [`home-footer.tsx`](../../../apps/dwp/src/features/home/home-footer.tsx)로 분리해
  편집 Session·저장 Adapter도 Runtime Module로 추출했다. 최종 `home.tsx`는 996줄이다.
- Widget Frame을
  [`workspace-widget-frame.tsx`](../../../apps/dwp/src/components/workspace-composer/workspace-widget-frame.tsx)로
  분리해 `workspace-widget-canvas.tsx`는 887줄, 목적 화면 `communications.tsx`는 994줄이며
  모두 Source Size와 Architecture Gate를 통과했다.
- Tenant Branding이 Logo URL을 반환하더라도 Binary 0×0·Load·Decode 실패 시 `BrandLockup`은
  깨진 Slot과 Divider를 제거한다. Media 원천 수정은 별도 운영 책임이며 Fallback 독립
  Visual·Keyboard 회귀는 수동 Gate에 남아 있다.
- Notification Runtime이 `sources.APPROVALS` 번역 누락 Warning을 기록한다. Home Layout을
  차단하지 않지만 Notification 공통 번역 Owner가 별도 수정해야 한다.
- Figma Desktop Edit·Mobile Frame 생성은 Starter MCP 할당량 제약으로 보류됐다. Text 계약과 구현
  완료가 Figma 승인이나 수동 Design QA를 대신하지 않는다.
