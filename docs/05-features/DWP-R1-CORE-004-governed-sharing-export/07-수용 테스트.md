# DWP-R1-CORE-004 수용 테스트

## 자동 검증

- People Flyway `V34`~`V36`이 기존 DB에 적용되고 Dataset·제약·Index가 생성된다.
- 허용되지 않은 Selection Key, 비활성 Dataset과 부족한 Field Group을 거부한다.
- 같은 Idempotency Key의 동일 요청은 재사용하고 다른 Payload는 충돌 처리한다.
- 명시적 권한 세션은 Role 문자열만으로 Tenant 전체 요청을 볼 수 없다.
- 실행 중 취소는 Artifact 게시 전에 반영되고 생성된 staging Artifact를 폐기한다.
- TTL이 정책보다 길거나 이미 만료된 Artifact를 폐기하고 재시도한다.
- 자동 Retry Budget 소진 후 실패하고 Governor의 수동 Retry Budget을 초과하지 않는다.
- 완료 상태와 Audit Outbox, 실패 상태와 Audit Outbox가 동일 서비스 Transaction에서 기록된다.
- 만료 Scan은 저장소의 멱등 삭제가 성공한 경우에만 Reference를 제거하고 Hash·크기와
  append-only 만료 Evidence를 남긴다. 삭제 실패 시 상태와 Reference를 보존해 재시도하며,
  동시 실행의 Version 충돌은 중복 만료 감사로 이어지지 않는다.
- `e2e/workforce-export-governance.spec.ts`가 Desktop·Mobile 생성, 차단 근거, Hash,
  취소와 Timeline을 검증하고 Axe 위반이 없다.

## Release Gate

- 기본 설정 `execution-enabled=false`, Blocker `D-09,D-12`를 유지한다.
- KMS-backed Writer, 비공개 Object Storage, Malware/DLP, Signed URL, Queue 복구,
  재배포 통제와 삭제 증거가 승인되기 전 실제 Artifact를 만들지 않는다.
- 보안·개인정보 Owner가 역할, Masking, Watermark, TTL, 수신자와 감사 정책을 승인한다.
- 장애 주입으로 중복 0건, 취소 경쟁, Worker 재시작, 만료·삭제와 Audit 재전송을 검증한다.

내부 계약 완료와 실제 반출 출시 승인은 별도 상태로 관리한다.
