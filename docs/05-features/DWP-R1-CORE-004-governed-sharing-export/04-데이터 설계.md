# DWP-R1-CORE-004 데이터 설계

## People DB

- `ppl_workforce_access_policies`: Subject별 Population, Field Group과 허용 Action 경계
- `ppl_workforce_export_datasets`: Dataset, 필수 Field Group, 허용 Selection Key와 Version
- `ppl_workforce_export_requests`: 요청자, 경계 Snapshot, Lifecycle, 정책·산출물 Hash,
  Retry, 취소, 완료·만료와 낙관적 잠금 Version
- `ppl_workforce_export_attempt_events`: Worker 선점, 재시도, 실패, 취소, 완료와 만료의
  append-only Timeline

## 무결성

- 모든 요청 조회·변경은 `tenant_id`와 요청자 또는 명시적 Governor 권한을 포함한다.
- Dataset은 활성 상태와 필수 Field Group을 모두 만족해야 한다.
- Selection은 Dataset에 등록된 Key만 허용하고 정렬·정규화 후 SHA-256에 포함한다.
- `(tenant_id, requested_by, idempotency_key)`는 유일하며 같은 Key의 다른 Payload를
  거부한다.
- 완료 상태는 Artifact Reference, SHA-256, 크기, 만료와 완료 시간이 모두 있어야 한다.
- 만료 시 Artifact Reference는 제거하되 Hash·크기·Timeline은 감사 근거로 보존한다.
- 처리 이벤트 Update/Delete는 DB Trigger가 거부한다.
- Worker Claim은 `FOR UPDATE SKIP LOCKED`를 사용한다. 만료 Scan은 후보를 짧게 조회한 뒤
  관계형 Transaction 밖에서 멱등 Artifact 삭제를 수행하고, 원래 Version과 완료 상태가
  일치할 때만 `EXPIRED`로 전이한다. 다중 Worker의 중복 삭제는 안전하며 DB 전이와 만료
  Event는 한 번만 기록된다.
- Artifact 삭제가 실패하면 완료 상태와 Reference를 보존해 다음 Scan에서 재시도한다.
  삭제 성공 전 DB만 만료시키거나 실제 Binary가 남은 상태를 성공으로 기록하지 않는다.

## Migration

- People `V34`: Workforce Population·Field·Action 경계
- People `V35`: Dataset, Export Request와 append-only Attempt Event
- People `V36`: 자동·수동 재시도 주기, 만료 Event·Index와 조직 Intelligence Selection

실제 Artifact Binary, KMS Key와 임시 Credential은 관계형 Core 테이블에 저장하지 않는다.
