# 01 기획 정의

## 문제

서비스가 늘어나면 장애가 어느 Hop에서 발생했는지, Tenant별 오류와 지연이 어떻게
변하는지 공통 기준으로 확인하기 어렵다. 로그 원문을 검색하는 방식은 개인정보 노출,
형식 불일치와 운영자 숙련도 의존이 크다.

## 목표

- Gateway와 모든 Backend Hop을 하나의 Trace로 연결한다.
- Tenant 관리자가 호출량, 5xx 오류율, p95/p99와 상위 Route를 빠르게 판단한다.
- Payload를 저장하지 않고도 운영 진단에 필요한 최소 메타데이터를 제공한다.
- 수집 장애가 업무 API 가용성에 영향을 주지 않는다.

## KPI

- 대상 Runtime 수집 적용률 100%
- Query·Body·Credential 원문 저장 0건
- 정상 환경 Collector 수락률 99.9% 이상
- Tenant 교차 조회 0건
- 24시간 범위 Overview p95 응답 2초 이하를 초기 목표로 측정
