# DWP-R0-SEC-001 데이터 설계

## Source of Record

`sys_auth_sessions`가 Browser Session Registry의 원본이다. JWT는 서명된 전달
Credential이며 Session 활성 상태의 원본이 아니다.

## Migration

기존 Table에 다음 Column을 추가한다.

| Column                  | Type        | 책임                                        |
| ----------------------- | ----------- | ------------------------------------------- |
| `session_family_id`     | UUID        | Rotation 전후의 하나의 Browser Session 식별 |
| `session_started_at`    | TIMESTAMPTZ | 최초 로그인 시각                            |
| `issued_at`             | TIMESTAMPTZ | 현재 Token ID 발급 시각                     |
| `last_seen_at`          | TIMESTAMPTZ | Throttle된 실제 인증 API 활동               |
| `idle_expires_at`       | TIMESTAMPTZ | Idle Timeout 시각                           |
| `superseded_at`         | TIMESTAMPTZ | Rotation으로 이전 Token이 된 시각           |
| `superseded_expires_at` | TIMESTAMPTZ | 이전 Token Grace 종료 시각                  |

각 Rotation은 새 Row를 만들고 동일 `session_family_id`를 유지한다. 이전 Row는
`superseded_at`으로 표시하며 원문 Token은 저장하지 않는다.

새 JWT는 Session Family를 검증하기 위해 `sid` Claim을 필수로 사용한다. 이 Migration
전에 발급된 JWT에는 `sid`가 없으므로 배포 시 기존 Browser Session을 종료하고 사용자가
다시 로그인하도록 안내한다. 신규 프로젝트 Baseline에서는 의도한 보안 전환이며,
무중단 전환이 필요한 운영 환경에서는 별도 호환 기간과 강제 로그아웃 공지가 필요하다.

## 활성 조건

다음을 모두 만족해야 한다.

- `revoked_at IS NULL`
- `expires_at > now`
- `idle_expires_at > now`
- 현재 Row이거나 `superseded_expires_at > now`인 Grace Row
- JWT의 user·tenant와 Registry Row가 일치

## Index

- `token_id` Unique 유지
- `(tenant_id, user_id, last_seen_at DESC)`
- `session_family_id`
- 만료되지 않은 현재 Row 조회용 Partial Index

## 보존·삭제

- 운영 Session Row는 절대 만료 후 최소 기간만 보관하고 Audit Event와 분리한다.
- 보존기간은 Pilot Security·Privacy 승인 후 Configuration한다.
- 사용자 삭제 시 법적 보존 근거에 따라 식별자를 비식별화하거나 함께 삭제한다.
- 원문 IP·User Agent는 보안 목적과 보존기간을 명시한다.

## Rollback

Application Rollback 동안 새 Column은 기존 코드에 영향을 주지 않는다. Column 삭제는
새 코드가 완전히 제거되고 Session이 만료된 뒤 별도 Migration으로만 수행한다.
