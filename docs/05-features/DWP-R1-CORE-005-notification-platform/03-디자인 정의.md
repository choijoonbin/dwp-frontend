# DWP-R1-CORE-005 디자인 정의

## 경험 방향

알림은 시선을 빼앗는 장식이 아니라 사용자가 중요한 변화를 빠르게 판단하고 끝낼 수 있게 하는
`calm action layer`다. SAP식 대형 Form이나 Monitoring Table을 사용자 화면에 옮기지 않고,
업무 밀도는 유지하되 Source·이유·상태·행동의 시각 계층을 명확히 한다.

## Design System Mapping

| 영역             | Component                  | Variant·Token              | 규칙                        |
| ---------------- | -------------------------- | -------------------------- | --------------------------- |
| Header Bell      | `IconButton`, `Badge`      | 36px, `radius.1`           | Badge는 Actionable Unread만 |
| Glance           | `Popover` / Mobile `Sheet` | 400px max, 8px radius 이하 | 중첩 Card 금지              |
| View 전환        | `SegmentedControl`         | compact                    | `우선`, `전체`만            |
| Notification Row | 신규 `NotificationItem`    | dense·standard             | 고정 Icon·상태 Column       |
| Thread           | `NotificationThread`       | Count + latest preview     | 중복 Row 억제               |
| Priority         | Icon + Label               | semantic status            | 색만으로 표시 금지          |
| Bulk Action      | `SelectionToolbar`         | sticky in flow             | 본문 가림 금지              |
| Empty            | `EmptyState`               | compact                    | 장식 Illustration 필수 아님 |
| 운영 Trend       | 기존 Chart Primitive       | 최소 Grid·Tooltip          | 의미 있는 비교만            |
| Template Preview | Channel Frame              | desktop·mobile·email       | 실제 PII 금지               |

Badge의 시각 숫자는 `조치 필요 미확인`이며 전체 미확인 수와 다르다. Tooltip, Screen Reader Label과
Popover Summary는 두 수치를 명시해 사용자가 숫자의 의미를 오해하지 않게 한다.

## Notification Item Anatomy

```text
[Source icon] [Unread marker] Title                         [Time]
              Preview or latest thread update              [More]
              Reason · Source · Actor             [Primary action]
```

- Source Icon Container는 32px, 목록 Row 최소 높이는 Standard 76px, Compact 60px다.
- Title은 한 줄, Preview는 Standard 두 줄·Compact 한 줄에서 잘라낸다.
- 상대 시각에는 Hover·Focus 시 절대 시각과 Timezone Tooltip을 제공한다.
- Unread는 작은 점과 Title Weight를 함께 사용한다.
- Urgent는 좌측 Border가 아니라 Icon·Label·텍스트를 사용해 다른 Layout과 섞여도 의미가 유지된다.
- Action Button은 최대 하나만 Row에 노출하고 나머지는 Overflow에 둔다.

## 시각 언어

- Surface는 Page Background, Row Surface, Selected Surface의 세 단계만 사용한다.
- 사용자 Feed를 카드 격자로 만들지 않는다. 연속 목록과 분리선을 사용해 Scan을 빠르게 한다.
- Tenant Accent는 선택, Link, Focus에만 사용하고 Priority 색을 덮지 않는다.
- `URGENT`, `HIGH`, `NORMAL`, `LOW`는 Error·Warning·Info·Muted Semantic Token을 사용하되 붉은색
  남용을 막는다.
- App별 Source Color는 Icon 안에서만 사용해 하나의 Platform 경험을 유지한다.
- Shadow보다 Border·Surface Contrast를 우선하며 Popover·Sheet에만 낮은 Elevation을 적용한다.
- 한 화면에 상태 Badge를 과도하게 쌓지 않고 이유·Priority·Managed 중 필요한 두 개 이하만 노출한다.

## 실시간 Interaction

| Trigger              | Feedback                               | Duration | Reduced Motion |
| -------------------- | -------------------------------------- | -------- | -------------- |
| Background 새 항목   | Count Crossfade, `새 알림 N개` Control | 180ms    | 즉시 교체      |
| 사용자가 Insert 허용 | 목록 위치 보존 후 상단 병합            | 220ms    | 즉시 병합      |
| 읽음                 | Marker Fade, 제목 Weight 전환          | 160ms    | 즉시           |
| Done                 | Row Collapse 후 Undo Snackbar          | 200ms    | 즉시 제거      |
| Save                 | Bookmark Icon 상태 변경                | 140ms    | 즉시           |
| Snooze               | Time Menu, 완료 후 Row 제거            | 180ms    | 즉시           |
| Urgent Toast         | 8px Slide + Fade                       | 220ms    | Fade 또는 즉시 |
| SSE 재연결           | 화면을 흔들지 않는 Status Text         | 없음     | 동일           |

새 알림이 여러 건 연속 도착해도 Animation과 Live Region을 건별로 반복하지 않는다. 500ms 내 변화는
한 번의 Count·Status 갱신으로 합치고 현재 Scroll Anchor, Selection과 Keyboard Focus를 보존한다.

Animation은 Interruptible하며 깜박임, Bounce, 무한 Pulse와 자동 Carousel을 금지한다.

## Toast 정책

- Toast는 `URGENT`와 Tenant가 승인한 `HIGH immediate`만 생성한다.
- 화면당 최대 3개, 동일 `thread_key`는 기존 Toast를 갱신한다.
- Urgent는 사용자가 닫기 전 유지하고 나머지는 최소 6초 후 자동 종료한다.
- `Undo`, `승인`, `거절` 등 결과가 명확한 Inline Action만 허용한다.
- 민감정보, 상세 오류 Stack, 긴 본문은 표시하지 않는다.
- 사용자가 이미 관련 업무 화면을 보고 있으면 Toast를 생략하고 해당 데이터만 갱신한다.

## Density와 Responsive

| Breakpoint | Layout                            | 유지 Priority       | 이동                          |
| ---------- | --------------------------------- | ------------------- | ----------------------------- |
| 1440+      | View Rail + List + Preview        | 전체 Context        | 없음                          |
| 1024~1439  | 좁은 Rail + List + Preview        | Action·Reason       | Filter 일부 Menu              |
| 768~1023   | View Menu + List, Overlay Preview | List                | Preview Sheet                 |
| <768       | 단일 List·Detail Route            | Title·Reason·Action | Filter Sheet, Bulk Bottom Bar |

- Compact는 Row 높이와 Preview 줄 수만 줄이며 Action 의미를 제거하지 않는다.
- Comfortable은 Touch Target과 행 간격을 늘리되 목록을 카드로 바꾸지 않는다.
- Dark와 High Contrast에서 Source Icon·Unread·Priority의 Contrast를 별도 검증한다.

## Content Design

### Title 공식

```text
Actor + 발생한 변화 + 대상
예: 박현우님이 휴가 요청 승인을 요청했습니다
```

- `새 알림이 있습니다`, `확인하세요` 같은 정보 없는 제목을 금지한다.
- Preview는 중요성 판단에 필요한 변화와 기한을 한 문장으로 제공한다.
- CTA는 `결재 열기`, `요청 검토`, `Space에서 보기`처럼 도착 위치를 명시한다.
- Source App 이름, 수신 이유, 날짜·시간은 Localized Format을 사용한다.
- 기한은 상대 표현과 절대 시각을 함께 제공해 모호성을 줄인다.
- Push·Toast에는 기밀 원문을 넣지 않는다.
- 번역이 없는 Locale은 검증된 Tenant Fallback Locale로 전환하고 Key·원문 변수·빈 CTA를 화면에
  노출하지 않는다.

## 외부 UX 검토 반영

| 검토 기준                   | DWP 반영                                                             | 그대로 따르지 않는 부분                |
| --------------------------- | -------------------------------------------------------------------- | -------------------------------------- |
| Apple Notification HIG      | 적시성·고가치·민감정보 배제, Foreground의 조용한 목록 갱신           | OS Lock Screen 형태 복제               |
| Microsoft Teams Activity    | 관련성, 정확한 Deep Link, Type 설정, Chain Update, 사용자 Rate Limit | Bot과 Feed의 중복 전달                 |
| GitHub Inbox                | 수신 이유, Saved·Done, Filter와 Bulk Triage                          | 개발자용 Query 문법을 기본 UI에 노출   |
| Slack Notification Controls | Focus Schedule, Channel Override, Activity와 외부 Channel 분리       | 모든 메시지 중심의 복잡한 설정 구조    |
| WAI-ARIA Status·Alert       | 집계 Status, 제한적 Assertive Alert, Focus 비이동                    | 새 항목마다 Screen Reader Announcement |

DWP는 위 제품의 시각 스타일을 복제하지 않는다. 사용자 Feed는 조용한 연속 목록, 명확한 이유와 Action,
제한된 Accent를 사용하고 Admin·Provider 화면만 운영 밀도와 Chart를 높인다.
