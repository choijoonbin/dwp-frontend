# DWP-R1-CORE-005 수용 테스트 및 출시 Gate

## Gate 상태

| Gate                 | 조건                                                | 현재                                                        |
| -------------------- | --------------------------------------------------- | ----------------------------------------------------------- |
| G0 Discovery         | 현재 Gap, 사용자·운영 Persona, Benchmark            | 완료                                                        |

Foundation Pilot은 구현·자동화·실브라우저 증거가 있으므로 `implemented`로 판정한다. 다만 아래
Production 부하·실패 Drill과 외부 Provider 승인이 끝나기 전에는 `released` 또는 전체 옴니채널
`operational` 상태를 사용하지 않는다.

## 2026-08-24 Foundation·Governance 검증 증거

- `/notifications` 최초 진입, 목록·상세·검색·Filter·Bulk Triage를 실제 로컬 데이터로 검증

  Surface로 Redirect한다. 표시 Privacy, Banner, Channel, Quiet Hours, Digest, App·Type 규칙과
  관리형 잠금을 같은 Effective Policy 응답으로 처리한다.
- `/notifications/admin/overview`, `contracts`, `policies`, `templates`, `operations`,
  `suppressions`를 Resource Permission별로 분리했다.
- `/notifications/admin/policies`에서 Effective Source, 영향 Preview, Draft 작성과 독립 승인 경계를
  구현하고 Backend 단위·Security·Migration 테스트로 검증

## 기능 수용 기준

### User Inbox

- [x] 새 Domain Event가 한 번의 User Notification으로 Materialize된다.
- [x] 같은 Event 재전달은 중복 Row·Badge·외부 Delivery를 만들지 않는다.
- [x] 같은 `thread_key` 변화는 Count·Preview를 갱신하고 목록을 오염시키지 않는다.
- [x] Read, Unread, Saved, Done, Snoozed 상태 조합이 서로 손실되지 않는다.
- [x] Bulk 100건의 부분 성공·재시도·Undo가 명확하다.
- [x] Deleted·Revoked Target을 열 때 안전한 410 상태와 설명을 제공한다.
- [x] 정확한 수신 이유와 Effective Policy Source를 표시한다.
- [x] Search·Filter가 Tenant·User Scope를 벗어나지 않는다.
- [x] Badge Counter Drift를 Reconciliation Job이 탐지·복구한다.
- [x] Redis·SSE를 모두 재시작해도 `change_version` Sync가 누락된 상태 변경을 복구한다.
- [x] 보존 Watermark 이전 Cursor는 전체 재동기화를 요구하고 일부 Delta를 정상으로 오인하지 않는다.

### Preference

- [x] Global → App → Type → Channel Override가 예상 순서로 합성된다.
- [x] Tenant 관리 정책으로 비활성화한 Channel을 사용자가 켤 수 없다.
- [x] Mandatory Type은 잠금·Owner·사유를 표시한다.
- [x] Banner와 Preview Privacy는 정책 조회 전 Fail Closed이며 관리형 설정 오류 중 수정할 수 없다.
- [x] 개인 설정은 `/notifications/settings` 한 곳에서만 편집하고 자동 저장 상태를 접근성 Status로 알린다.
- [x] Quiet Hours, Timezone, DST Spring·Fall 경계와 Urgent 우회가 검증됐다.
- [ ] Tenant 휴일 캘린더의 권위 원본과 개인·회사 일정 합성 우선순위를 결정하고 통합한다.
- [x] 설정 자동 저장의 409 충돌·실패 Rollback·재시도가 동작한다.
- [ ] 권한을 잃은 App Type은 Delivery되지 않고 설정은 안전하게 비활성 보존된다.

### Admin·Provider

- [x] Draft → Review → Publish 역할 분리와 작성자 자기 승인이 Backend에서 차단된다.
- [x] Published Contract·Template·Policy를 Update·Delete할 수 없다.
- [x] 전달 억제는 Preview 없는 생성, 중첩 기간, 만료 없는 차단과 권한 없는 Mutation을 거부한다.
- [x] Notification 운영 감사는 제품 전용 복제 메뉴가 아닌 중앙 `ADMIN.AUDIT_VIEW`를 사용한다.
- [x] Policy Simulation과 실제 Runtime 결과가 Contract Test로 일치한다.
- [x] Provider Secret·Push Token·본문이 Tenant 운영 목록과 Log에 노출되지 않는다.
- [ ] Replay는 Preview, 사유, 승인, 제한 Batch, Reconciliation과 Audit을 가진다.
- [x] Tenant Admin은 다른 Tenant Metadata·Queue·Content를 조회할 수 없다.
- [x] Provider Operator는 Support Session 없이 사용자 본문을 조회할 수 없다.
- [ ] 승인된 Support Session의 본문 가시성·TTL·사유·승인·Redaction 정책을 확정하고 통합한다.

## 성능 시험

Capacity Profile은 `D-NTF-06`에서 다음 입력을 확정한다.

```text
tenants
active users per tenant
peak domain events/sec
average and p99 recipients/event
actionable vs broadcast ratio
concurrent SSE connections
email/push channel ratio
retention days
```

### 필수 Load Scenario

- Normal Mix 60분 Soak
- 월요일 로그인·업무 시작 Spike
- 100k Audience Batch Fan-out
- SSE 10k부터 목표 동시 연결까지 단계적 Ramp
- Provider 429·500과 Retry Storm
- One Hot Tenant가 다른 Tenant SLO에 미치는 영향
- Critical·Interactive·Bulk QoS Lane별 독립 Saturation과 예약 Headroom
- 180일 Data Volume에서 Feed·Unread·Filter Query
- Partition Maintenance·Backup 중 Online Traffic
- Kafka Consumer Rebalance와 Rolling Deployment
- Regional Cell 장애, Warm Standby Restore와 Residency 검증

### 합격 Target

- Event → Inbox p95 2초, p99 5초
- Event → 열린 Browser p95 3초
- Inbox Query p95 200ms, Error 0.1% 미만
- Summary p95 100ms
- Duplicate Visible Notification 0.1% 미만, Lost Notification 0건
- DB Connection·CPU·IO, Kafka Lag, Redis Memory가 승인 Headroom 안에 있음
- Critical Lane은 Peak Pilot에서 50% 이상 Headroom, Bulk Saturation 중에도 Critical SLO 유지
- Hot Tenant 시험에서 정상 Tenant p95가 승인 Baseline 대비 20% 이상 악화되지 않음

Target은 Pilot Capacity 승인 후 환경별 수치로 고정한다.
