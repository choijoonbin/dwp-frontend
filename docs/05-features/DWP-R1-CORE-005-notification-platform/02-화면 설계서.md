# DWP-R1-CORE-005 화면 설계서

2026-09-04 현행 구현은 [수신 분류·홈 기준](09-recipient-views-and-action-home.md)을 우선한다.
아래 Provider·일부 고급 운영 항목은 목표 설계이며 전체 구현/출시 완료를 뜻하지 않는다.

## `NTF-U01` Header Glance

### 구조

- Header Bell은 `전체 미확인` Count를 `99+`까지 표시한다. Accessible
  Name과 Tooltip은 `조치 필요 알림 4건, 전체 새 알림 12건`처럼 두 의미를 구분한다.
- Count가 0이면 빈 Badge를 숨기고, 연결 장애 자체를 붉은 Badge로 오인시키지 않는다.
- Popover Header: `알림`, `현재 보기 모두 읽음`, 설정 Icon. 일괄 처리는 적용 범위와 Undo를 제공한다.
- Segmented View: `우선`, `전체`. Type별 Tab을 늘리지 않는다.
- 최대 6개 항목을 표시하고 아래에 `알림 센터 열기`를 둔다.
- 각 항목은 Source Icon, 제목, 한 줄 Preview, 상대 시각, unread 표시, 하나의 주 Action을 가진다.
- 항목을 읽음 처리해도 업무 완료로 간주하지 않는다.

### 실시간 도착

1. SSE Signal 수신
2. Summary와 변경 ID를 Background Fetch
3. Count와 목록을 180~240ms Fade로 갱신
4. `URGENT` 또는 정책상 `HIGH`만 Toast 후보
5. 현재 사용자가 원업무 화면을 보고 있으면 Toast 대신 화면 Data와 Feed를 조용히 갱신

Popover가 열린 동안 새 항목을 맨 위로 즉시 밀어 Scan 위치를 바꾸지 않는다. 상단에 `새 알림
3개` Insert Control을 표시하고 사용자가 누를 때 병합한다.

Badge·Popover가 연결되지 않았다는 이유로 Error 색이나 경고 수를 표시하지 않는다. 연결 문제는
기존 항목을 유지한 채 Popover Footer의 조용한 동기화 상태로만 노출한다.

## `NTF-U02` 알림 센터

### Desktop

```text
Context Bar: 알림 센터 | Search | Density | Settings
View Navigation: 받은 알림 / 조치 필요 / 나를 멘션 / 저장됨 / 나중에 / 정리됨
Filter Bar: 검색 / 읽음 상태 / 앱 / 수신 이유 / 우선순위
Main: 업무 맥락별 Notification List + Keyset 더 불러오기
Preview: 선택 항목 상세, 수신 이유, Action, 원업무 열기
Selection Bar: 읽음 / 저장 / 완료 / 나중에 / 구독 설정
```

- 기본 View는 `조치 필요`이며 서버의 활성 `action_required` 항목이다. 긴급도와 수신 이유는 별도 축이다.
- 모든 View는 안정적인 `last_activity_at DESC, notification_id DESC` Keyset 순서다.
  SLA·AI Ranking이나 구독 스레드 분류가 구현된 것처럼 표시하지 않는다.
- 같은 `thread_key`는 한 Row에 묶고 최근 변화와 누적 Count를 보여준다.
- `Done`은 Inbox에서 치우되 별도 View에서 복원 가능하다. `Saved`는 Done과 독립 상태다.
- `Snooze` 만료 시 같은 항목이 다시 나타나며 새 Notification을 만들지 않는다.
- Search는 제목·안전한 Preview·Source·Actor Snapshot만 검색한다. 원업무 전체 검색은 Global Search로
  넘긴다.
- Context Bar에는 카드형 KPI 대신 `조치 필요 N · 나중에 M · 집중 시간 종료 14:00`의 간결한
  Attention Summary를 선택적으로 표시한다. 알림 소비량·읽기 연속일 같은 Gamification은 금지한다.

### Mobile

- View Rail은 상단 View Menu로 접는다.
- 목록과 상세를 한 화면에 겹치지 않고 Route 전환한다.
- Swipe는 Optional Shortcut이며 모든 기능을 Overflow Menu와 Keyboard로도 제공한다.
- Bulk Mode는 Long Press와 `선택` 명령으로 진입한다.

## `NTF-U03` 알림 상세

- Source App, Type, Actor, 발생·수신 시각, 최신 상태를 구분한다.
- 제목과 Preview 아래에 주 Action 한 개, 보조 Action 최대 두 개를 둔다.
- `왜 이 알림을 받았나요?`는 `직접 지정`, `역할`, `조직`, `구독`, `필수 정책` 중 실제 이유를
  설명한다.
- Thread Timeline은 같은 업무의 변화만 보여주며 Audit Log 전체를 노출하지 않는다.
- 원업무가 삭제·권한 박탈·만료되면 Action을 비활성화하고 이유와 복귀 경로를 제공한다.
- 민감 Type은 본문 대신 `보호된 인사 알림이 있습니다`와 안전한 이동만 제공한다.

## `NTF-U04` 알림 설정

### Navigation

- `전달 방식`: In-app, Email, Browser·Mobile Push
- `집중 시간`: Quiet Hours, Timezone, 휴일, 긴급 우회
- `요약`: 즉시·일간·주간 Digest와 발송 시각
- `앱별 알림`: 권한이 있는 App → 활성 Notification Type
- `기기`: Push Endpoint, 마지막 사용, 철회

### Setting Row

각 Row는 Label, 짧은 설명, Effective Value, 상속 Source, Control, 저장 상태를 가진다. 관리형
값은 `관리됨` 표시와 정책 Owner를 제공한다. 설정은 자동 저장하되 실패 시 Optimistic 값을
되돌리고 Row 단위 재시도를 제공한다.

App·Type 설정은 실제 Notification을 한 번 이상 보냈거나 Tenant가 활성화한 Type만 노출해
초기 화면의 과도한 복잡성을 피한다. `고급 설정`에서 전체 Catalog를 볼 수 있다.

## Tenant Admin 화면

### `NTF-A01` 운영 개요

- KPI: 생성량, Actionable 비율, p95 Materialization, Channel 성공률, DLQ, Noise Indicator
- Trend: Type·App·Channel별 Volume과 Failure, 전주 비교
- Action Queue: Schema Quarantine, Provider 장애, Template 미번역, Policy 충돌, Replay 승인
- `사용자 참여율`을 목표로 과도한 발송을 유도하지 않는다. Mute·Unsubscribe·중복률을 함께 본다.

### `NTF-A02` Type Catalog

- 행: Type, App Owner, Source Event, Priority, Channel, Mandatory, 상태, 최근 Volume, Contract Health
- 상세: Schema Range, 변수, Deep Link, Audience, Dedupe, 종료 Event, Retention, Runbook
- Flow: Draft → Contract Review → Security·Privacy Review → Active → Deprecated → Retired
- Active Contract는 직접 수정하지 않고 새 Version을 생성한다.

### `NTF-A03` Policy Studio

- 왼쪽 Scope: Tenant Default → App → Type.
- 가운데 Effective Policy와 변경 Form.
- 오른쪽 사용자 Persona·Timezone·Focus 상태별 Simulation.
- 저장 전 영향받는 Type·예상 대상·Channel·Quota·비용과 기존 정책 Diff를 Preview한다.
- Mandatory·Urgent·대규모 Broadcast는 4-eyes Approval을 요구한다.

### `NTF-A04` Template Studio

- Code Editor가 아니라 검증된 Field Editor를 사용한다.
- Locale별 Title, Preview, Body, Action Label을 작성한다.
- 실제 PII가 아닌 Synthetic Data로 Desktop·Mobile·Email·Push Preview를 제공한다.
- 변수 Schema, 길이, 누락 번역, 금지 민감 Field, 외부 URL을 게시 전 검증한다.
- Draft, Review, Publish, Rollback과 Revision Diff를 제공한다.

### `NTF-A05` Delivery Operations

- Provider Health, Kafka Lag, Oldest Job, Retry Queue, DLQ, Circuit Breaker를 한 화면에서 연결한다.
- `Critical`, `Interactive`, `Bulk` Lane별 Backlog·Oldest Age·예약 용량과 Tenant Fairness를 비교한다.
- 실패 목록은 `재시도 가능`, `결과 불명`, `영구`, `정책 차단`, `Endpoint 만료`, `Quota`로
  분류한다. `결과 불명`은 Provider 상태 조회·Callback 증거와 중복 위험을 먼저 보여준다.
- Replay는 Filter → 영향 Preview → 사유 → 승인 → 제한 Batch → 결과 Reconcile 순서다.
- 사용자 본문 대신 ID, Type, Channel, 오류 분류와 Redacted Provider Code를 기본 표시한다.
- Email 운영은 SPF·DKIM·DMARC 검증 상태, Bounce·Complaint 추이와 Suppression Workbench를
  제공하되 원문 주소는 노출하지 않는다.

## Provider Fleet

- Region·Cell·Tenant별 p95 지연, Lag, 실패율, Channel Provider 상태와 Quota를 비교한다.
- Region Failover 상태, Data Residency, Notification Pool·Silo 배치와 DR Drill 증적을 표시한다.
- Tenant Drill-down은 Metadata와 운영 상태만 보여준다.
- Global Kill Switch는 Channel·Provider·Type 범위와 TTL을 요구한다.
- Support Session 없이는 사용자 ID, 제목, Preview, 원업무 Reference를 열람하지 않는다.

## 접근성

- Landmark: Header, Navigation, Main, Complementary Preview를 명시한다.
- 새 알림마다 읽어주지 않고 `새 알림 3개`처럼 집계한 `role="status"`·`aria-live="polite"`를
  사용한다. 즉시 생명·보안 조치가 필요한 승인 Type만 `role="alert"`를 사용할 수 있다.
- 목록 Virtualization은 DOM Focus와 Screen Reader 위치를 보존한다.
- Virtualization이 `aria-setsize`, `aria-posinset`, Focus 복원을 보장하지 못하면 접근성 Mode에서는
  더 보기 방식의 점진 Rendering으로 전환한다.
- 모든 Hover·Swipe·Drag 기능은 Button·Menu·Keyboard 대체 수단을 가진다.
- Bulk Selection은 선택 Count와 수행 결과를 읽어준다.
- 200% Zoom과 320px에서 수평 Scroll 없이 단일 열로 Reflow한다.
- High Contrast에서 Read 상태, Priority와 Failure를 색만으로 전달하지 않는다.
- Reduce Motion에서는 Insert·Toast 이동 Animation을 제거한다.
