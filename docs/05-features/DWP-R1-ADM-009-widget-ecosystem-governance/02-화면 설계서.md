# DWP-R1-ADM-009 화면 설계서

## 1. Surface와 도입 원칙

| Surface          | 1차 위치                                                   | 미래 전용 화면                      | Archetype                         |
| ---------------- | ---------------------------------------------------------- | ----------------------------------- | --------------------------------- |
| End user         | Home `/`의 기존 편집 Dialog·Studio                         | 필요 시 `/home/studio` Route        | Library / Studio                  |
| Tenant Admin     | 기존 `/admin/experience/home-composition` 확장             | `/admin/experience/widgets` 후보    | List-detail / Workflow            |
| Provider Control | 기존 Code Contract의 `PLATFORM.HOME_WIDGET` 조회 Deep Link | `/provider/widget-definitions` 후보 | Registry / Release command center |

1차에는 Route Ledger의 광범위한 변경을 피하고 기존 Surface를 확장한다. 실제 Provider·Tenant Mutation
API가 없는 상태에서 조작 가능한 가짜 관리 화면을 만들지 않는다.

## 2. End-user 화면

### 2.1 Home 편집 Toolbar

- Primary user: 자신의 Home을 구성하는 사용자
- 질문: 무엇을 추가·이동·숨기고 어떤 변경을 저장할 것인가?
- Library Flag On 주 행동: `항목 추가`
- Library Flag Off 주 행동: `숨긴 항목 복원`. 복원 대상이 없으면 Trigger는 포커스를 유지한
  `aria-disabled` 상태로 두고 `현재 홈 초안에 복원할 숨긴 항목이 없습니다`를 접근 가능한 사유로 제공한다.
- 제공: 추가, Undo, Redo, Reset, Device Preview, 취소, 저장
- 정책 잠금 Widget은 잠금 주체·이유를 표시하고 이동·숨김·크기 조작을 제거한다.

### 2.2 Widget Library

기존 숨김 항목 전용 Dialog를 다음 두 View로 분리한다.

1. `라이브러리`: 현재 사용자에게 유효한 전체 App·Widget. Dialog를 열 때마다 기본 View다.
2. `숨긴 항목`: App·Widget을 합친 복원 전용 View다.

App/Widget은 상위 Tab이 아니라 항목 유형 Filter다. 배치 상태와 항목 유형을 같은 Navigation 축에
섞지 않는다. Phase 0에는 Preset Capability가 없으므로 Preset 항목이나 생성·공유 CTA를 노출하지
않는다.

1차 Frontend Vertical Slice에서는 전체 유효 항목을 행 또는 Compact List로 표시한다.

- 검색: 이름, 설명, App, Owner
- Filter: App, Widget, 추가됨, 추가 가능
- 사용자 Metadata: `앱` 또는 `위젯 · 소유 앱`. Definition Key, Data Source와 내부 권한 Key는 숨긴다.
- 상태: `ADD | RESTORE | ADDED | LOCKED | FORBIDDEN`
- `추가됨`은 비활성 Button과 Text를 함께 제공한다.
- `추가`와 `복원`은 Home Draft만 변경하며 `편집 완료/저장` 전에는 Server에 반영하지 않는다.
- 검색은 Unicode NFKC, 대소문자·연속 공백 정규화 후 이름·설명·표시용 소유 앱을 대상으로 한다.

Empty State:

| 조건             | 제목                                         | 행동                              |
| ---------------- | -------------------------------------------- | --------------------------------- |
| 모두 추가됨      | 지원되는 모든 항목이 이미 홈에 있습니다      | 검색·설정 또는 숨김               |
| 숨긴 항목 없음   | 복원할 숨긴 항목이 없습니다                  | On: 라이브러리 / Off: 비활성 사유 |
| 검색 결과 없음   | 검색 조건에 맞는 항목이 없습니다             | Filter 초기화                     |
| Tenant 정책 차단 | 조직 정책상 추가 가능한 항목이 없습니다      | 정책 안내·문의 경로               |
| 권한 없음        | 현재 권한으로 사용할 수 있는 항목이 없습니다 | App 접근 요청 경로                |
| Catalog 오류     | 항목을 불러오지 못했습니다                   | 재시도·Correlation ID             |
| Capability 꺼짐  | 고급 Widget Library를 사용할 수 없습니다     | 기존 복원 기능 유지               |

### 2.3 Widget 만들기 Wizard — 후속 Backend 범위

```text
App 선택
→ Widget Definition 또는 공유 가능한 Saved View 선택
→ Source·Field·상대 Filter 설정
→ 승인된 표현·크기 선택
→ Desktop·Mobile·상태 Preview
→ Home에 추가 / 개인 Preset 저장 / 공유 요청
```

- Step마다 필요한 Permission·Data Class·Freshness·원본 화면을 표시한다.
- Preview는 현재 사용자 또는 승인된 Sample Data만 사용한다.
- 사용자 고정 ID, Token, Credential, 임의 Query를 입력받지 않는다.
- Chart 조건이 충족되지 않으면 List·Metric으로 축소하고 이유를 표시한다.

### 2.4 Preset Detail·공유

- Provider·작성자·검토 상태·Definition 버전·요구 App/권한
- 공유되는 설정과 공유되지 않는 데이터의 명시적 설명
- 수신자 호환성: 완전 적용, 선택 항목 누락, 적용 불가
- 기본 Action은 `새 개인 사본으로 적용`이다.
- 기존 Home 전체를 교체할 경우 Diff·Preview와 별도 확인이 필요하다.

## 5. 상태 계약

Catalog와 Runtime은 다음을 혼합하지 않는다.

- `LOADING`: 최종 구조와 같은 Skeleton
- `EMPTY`: 대상 자체가 없음
- `ALREADY_ADDED`: 유효하지만 현재 Home에 있음
- `FORBIDDEN`: 제목·수치·원천 ID를 노출하지 않음
- `BLOCKED_BY_POLICY`: 정책 Owner·일반화된 이유·문의 경로
- `INCOMPATIBLE`: Device·Surface·Version 요구와 대체 항목
- `PARTIAL`: 성공 항목을 유지하고 실패 Source만 설명
- `UNAVAILABLE`: Retry 가능한 원천 실패
- `STALE`: 마지막 성공 시각·업데이트 지연 표시
- `REVOKED`: 데이터 렌더링 중단, 대체·제거 제공
- `VERSION_CONFLICT`: Draft 유지, 최신 Diff·재적용 제공

## 6. Responsive·접근성

- 검증 Viewport: 1440, 1280, 390, 320 CSS px와 실제 200% 글자 크기
- Desktop Dialog는 최대 안정 폭 안에서 List-detail을 사용하고 Mobile은 Full-screen Dialog로 전환한다.
- 긴 한국어·영문 Label은 고정 높이·Line Clamp 없이 자연스럽게 확장하고 전체 접근성 이름을 제공한다.
- Tab, Filter, List, Detail, Add와 Close를 Keyboard만으로 완료할 수 있어야 한다.
- Drag 없이 이동·크기·숨김·복원을 완료한다.
- Focus는 Dialog 진입 Trigger → 검색 → 변경된 행 또는 다음 복원 대상/빈 상태 → 닫은 뒤 Trigger로 복원한다.
- 최소 Target 44×44px, 본문 대비 4.5:1, Focus·그래픽 대비 3:1을 유지한다.
- 상태는 색만으로 전달하지 않고 Icon·Text·`aria-live`를 함께 사용한다.
- Reduced Motion에서는 이동 Animation을 제거하고, High Contrast에서 배경 이미지 없이 의미를 유지한다.
- Library·Home Widget 본문에 같은 축의 내부 세로 Scroll을 만들지 않는다. Dialog 자체 Scroll만 허용한다.
