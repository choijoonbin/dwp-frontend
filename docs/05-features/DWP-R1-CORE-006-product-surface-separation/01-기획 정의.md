## 1. 문제

앱 관리자도 일반 구성원이므로 두 권한을 동시에 보유하는 것은 맞다. 문제는 권한이 아니라 현재
Frontend가 권한 있는 업무 메뉴와 관리 메뉴를 한 Sidebar에 합집합으로 투영한다는 점이다.
작은 Group Title만으로 구분하면 권한이 많을수록 사용자는 다음을 계속 판단해야 한다.

- 지금 개인 업무를 처리하는지 제품 정책을 바꾸는지
- Action이 본인·팀·회사 전체 중 어디에 영향을 주는지
- 현재 보이는 Tenant·Resource Scope가 무엇인지
- 관리 권한이 만료되거나 지원 세션인지를 어디서 확인하는지

이 인지 오류는 단순 탐색 불편을 넘어 잘못된 범위의 운영 Action, 정책 변경과 민감정보 노출
위험을 높인다.

## 3. 목표 Outcome

1. Work Sidebar에 Product Management Menu를 한 개도 표시하지 않는다.
2. Management Sidebar에 개인 Work Menu를 한 개도 표시하지 않는다.
3. 사용자가 5초 안에 현재 Product Surface와 Scope를 식별한다.
4. Direct URL, Refresh와 Back/Forward가 같은 Surface를 보존한다.
5. Surface 분리 전후 Effective Authorization을 넓히지 않는다.
6. 권한·Scope 만료와 회수를 다음 요청부터 즉시 반영한다.
7. Tenant Governance와 Product Management의 소유 기능을 중복 구현하지 않는다.

- Surface 전환으로 권한을 부여·활성화하지 않는다.

## 7. 핵심 Journey

### 7.1 구성원 겸 App Admin

1. 사용자가 App을 열면 Work Surface와 Work Sidebar가 보인다.
2. Header의 `앱 관리` Link에서 관리 가능 여부와 Scope를 확인한다.
3. 관리 Link를 선택하면 Canonical Management URL로 이동한다.
4. Header와 Sidebar가 Management Context로 전체 전환된다.
5. 사용자는 Scope와 권한 만료를 확인하고 작업한다.
6. `업무로 돌아가기`로 마지막 허용 Work Route에 복귀한다.

### 7.2 Tenant Admin

1. `/admin`에서 앱 책임자와 유효기간·Resource Set을 지정한다.
2. Product 설정을 확인해야 하면 해당 App Card의 Deep Link를 선택한다.
3. 명시적인 Product Capability가 없으면 Product Management는 권한 없음 상태를 표시한다.
4. Tenant Admin Role만으로 고객 업무 데이터나 Product Mutation을 열지 않는다.

### 7.3 만료 중 관리 작업

1. Header가 만료 5분 전 한 번만 경고한다.
2. 사용자가 저장 또는 실행하면 서버가 최신 Context와 Object Version을 재검사한다.
3. 만료됐으면 Mutation을 거부하고 민감 Query Cache를 제거한다.
4. 화면은 만료 시각, 재요청과 안전한 Work 복귀를 제공한다.

## 9. Analytics Event

PII, Raw URL, 사람·결재·요청·초안·Scope 식별자를 수집하지 않는다. `attemptId`는 한 Journey
안에서만 사용하는 회전 가능한 비식별 ID이며 사용자·Tenant 식별자로 재사용하지 않는다.

| Event                            | 최소 속성                                             |
| -------------------------------- | ----------------------------------------------------- |
| `surface.exposed`                | app, surface, deviceClass, cohort, attemptId          |
| `surface.switch.started`         | app, fromSurface, toSurface, attemptId                |
| `surface.switch.completed`       | app, fromSurface, toSurface, attemptId, elapsedBucket |
| `surface.switch.failed`          | app, targetSurface, attemptId, reasonCode             |
| `surface.returned`               | app, fromSurface, toSurface, attemptId, elapsedBucket |
| `surface.route.denied`           | app, surface, routeId, reasonCode                     |
| `surface.scope.switch.started`   | app, surface, scopeKind, attemptId                    |
| `surface.scope.switch.completed` | app, surface, scopeKind, attemptId, elapsedBucket     |
| `surface.scope.switch.failed`    | app, surface, scopeKind, attemptId, reasonCode        |
| `surface.scope.invalid`          | app, surface, scopeKind, reasonCode                   |
| `surface.assignment.expired`     | app, surface, readOnly                                |
| `surface.policy.lock.viewed`     | app, surface, policyKind                              |
| `surface.task.started`           | app, surface, taskKind, attemptId                     |
| `surface.task.completed`         | app, surface, taskKind, attemptId, elapsedBucket      |
| `surface.task.failed`            | app, surface, taskKind, attemptId, reasonCode         |
| `surface.task.abandoned`         | app, surface, taskKind, attemptId, elapsedBucket      |

Audit는 Actor, Target, Before/After, Capability, Scope, Policy Revision과 Correlation ID를
보존한다. Analytics와 Audit Store·Retention·Access 권한을 합치지 않는다.

계산식을 다음처럼 고정한다.

- Critical Task 성공률 = 유효 `completed attempt` / 유효 `started attempt`
- 관리 Task 발견 시간 = Surface `exposed|switch.completed`부터 첫 `task.started`까지
- 빠른 복귀율 = Surface 노출 후 `task.started` 또는 Scope 전환 완료 없이 30초 안에
  `surface.returned` / 전체 해당 Surface 노출
- Task 완료 시간 = `completed`된 같은 `attemptId`의 started→completed 구간만 집계
- `failed`, `abandoned`, 중복·Bot·QA Traffic 제외 규칙은 Analytics Schema Version에 고정
