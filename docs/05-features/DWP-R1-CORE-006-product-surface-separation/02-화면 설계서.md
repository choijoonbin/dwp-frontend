# DWP-R1-CORE-006 화면 설계서

## 1. 공통 정보 구조

```text
Global Header
├── Application Context: 결재 / 인사 / ...
├── Surface Navigation: 업무 | 팀 | 운영 | 관리
├── Scope Context: 현재 Tenant·Resource Scope
└── Global Utilities

Current Surface Shell
├── Product identity
├── Current-surface-only navigation
├── Access mode / expiry / policy state
├── Return or surface-switch action
└── Page canvas
```

Surface와 Scope를 한 Control에 합치지 않는다. Surface는 `무슨 일을 하는가`, Scope는
`어느 대상을 다루는가`를 답한다. Sidebar Group Title만으로 Work와 Management를 구분하지
않고 Route 전환 시 Navigation Collection 전체가 바뀐다.

- Header의 Product 이름, Surface Label과 Scope는 Route가 깊어져도 유지한다.
- Product Management는 같은 Product Accent를 사용하되 Shield Icon, `운영/관리` Text,
  별도 Sidebar와 복귀 동작으로 구분한다.
- Work/Management 구분을 배경색 하나에 의존하지 않는다.
- 권한 만료 시각은 필요한 경우 Scope Context 옆에 표시한다.
- Support Mode이면 Tenant, 승인 Scope, Read-only/Write, 사유와 만료가 있는 지속 Banner를
  Header 아래에 둔다.

## 4. Surface Switcher

### Desktop

- Work Context는 허용된 Work Surface와 최대 한 개의 `앱 관리` Link만 표시한다. 세부
  Management Surface를 Work Header에 직접 나열하지 않는다.
- Management Context는 `업무로 돌아가기` Link와 허용된 세부 운영·설정 Surface를 표시한다.
- 투영 결과가 하나면 현재 Label은 Text로만 표시하고, 둘 이상이면
  `<nav aria-label="제품 작업 영역">` 안의 Native Link로 제공한다.
- 현재 Link는 `aria-current="page"`를 사용한다.
- Surface Link에는 권한 수나 역할명을 Badge로 나열하지 않는다.
- 만료 임박은 현재 Management Surface에만 한 번 경고하고 Work Link를 방해하지 않는다.

### Mobile 390·320px

- Header에는 `<button aria-expanded aria-controls>`인 현재 Surface Disclosure Trigger를 유지한다.
- Disclosure는 ordinary `<nav><ul><li><a>` Link List를 열고 `role=menu/menuitem`을 사용하지 않는다.
- Tab은 Link를 순서대로 이동한다. Route 선택 후 Disclosure를 닫고 `tabindex=-1`인 Main H1로,
  Escape·취소로 닫으면 Trigger로 Focus를 이동한다.
- Management Sidebar Drawer는 현재 Surface Menu만 포함하고, 열려 있을 때 Background를 `inert`로
  처리하며 Focus Trap, Accessible Name과 닫기 Control을 제공한다.
- Touch Target은 WCAG 최소 24×24 CSS px를 충족하고 DWP 제품 기준은 44×44px를 권장한다.

## 5. Scope Selector

- `Scope`가 하나면 Selector를 숨기고 `현재 범위: {name}` Text만 표시한다.
- 하나면 해당 Scope를 Canonical URL로 `replace`한다. 둘 이상이고 서버가 정확히 하나를
  `isDefault=true`로 지정한 경우에만 자동 선택한다.
- 복수 Scope에 기본값이 없으면 `범위를 선택하세요` 상태에서 Product Query·Mutation을 시작하지
  않는다. 기본값이 둘 이상이면 서버 Contract Error로 Fail Closed한다.
- 둘 이상이면 Header에 `운영 범위` 또는 `관리 범위` Button을 제공한다.
- Option은 서버가 허용한 Opaque Scope Key, Label, Kind, Read-only, 만료로 구성한다.
- URL `?scope=`가 권위이고 선택은 History에 남긴다.
- Product API에는 OpenAPI `contextScopeKey` Parameter로 전달하고 Client Scope Header를 만들지
  않는다.
- Scope 변경 시 호환 가능한 기간·정렬 Filter는 유지한다.
- Scope 변경은 in-flight Request를 먼저 취소하고 사람·Task·Request·Draft·Selection과 민감
  Content를 제거한 뒤 URL을 바꾸고 새 Query를 시작한다.
- 만료·회수된 URL Scope를 다른 Scope로 자동 치환하지 않는다.

## 6. 상태 계약

인가 판정, URL 해석과 Page Content 상태를 하나의 Enum으로 합치지 않는다. 각 상태군의 Owner와
Telemetry Schema도 분리한다.

### 6.1 Authorization Decision State

Owner는 Identity·Platform이고 Event는 `surface.access.decision`이다.

| 상태                       | Title 예시                              | 정보                                     | Action                    |
| -------------------------- | --------------------------------------- | ---------------------------------------- | ------------------------- |
| `app-denied`               | 이 앱을 사용할 수 없습니다              | App, 요청 정책, 소유자                   | 접근 요청·앱 목록         |
| `surface-denied`           | 이 관리 영역을 열 수 없습니다           | 필요한 업무 책임, 현재 권한, 안전한 복귀 | 권한 요청·업무로 돌아가기 |
| `route-denied`             | 이 관리 기능을 열 수 없습니다           | Route Contract, 공개 가능한 요청 경로    | 권한 요청·관리 홈         |
| `scope-selection-required` | 관리 범위를 선택해 주세요               | 허용 범위 종류, 선택 전 데이터 미조회    | 범위 선택                 |
| `scope-invalid`            | 이 관리 범위를 사용할 수 없습니다       | 만료·회수 여부, 허용 범위                | 범위 선택·재요청          |
| `expired`                  | 관리 권한이 만료되었습니다              | 만료 시각, Assignment 종류               | 재요청·업무로 돌아가기    |
| `activation-required`      | 권한 활성화가 필요합니다                | Risk, 승인·Step-up 요건, 최대 활성 시간  | 활성화 요청               |
| `step-up-required`         | 본인 확인이 다시 필요합니다             | 요구 Assurance, 유효 시간                | 안전한 Step-up            |
| `sod-conflict`             | 이 작업은 직무 분리 정책으로 제한됩니다 | 정책 Reference, 허용 가능한 다음 단계    | 다른 담당자 요청          |
| `support-scope-denied`     | 지원 범위에 포함되지 않습니다           | Tenant, Session, 승인 Scope, 만료        | 지원 세션으로 돌아가기    |
| `authority-unavailable`    | 지금 권한을 확인할 수 없습니다          | Correlation ID, 데이터 비노출            | 다시 시도·안전한 복귀     |

### 6.2 Resolver State

Owner는 Shared Experience이고 Event는 `surface.route.not-found`다. 알려진 Surface 경계 안의
미등록 Path는 `surface-not-found`, 어느 Surface에도 소유되지 않은 Product Path는
`product-not-found`로 구분한다. 접근 권한이 확인되지 않으면 Surface 이름·메뉴를 노출하지 않는다.

### 6.3 Content State

Owner는 각 Product이고 Event는 `surface.content.state`다.

| 상태            | Title 예시                      | 정보                                             | Action              |
| --------------- | ------------------------------- | ------------------------------------------------ | ------------------- |
| `policy-locked` | 회사 정책에서 관리합니다        | 정책명, Owner, 적용 Scope, 발효일                | 정책 보기·예외 요청 |
| `partial`       | 일부 정보를 불러오지 못했습니다 | 성공 Section Freshness, 실패 Section Correlation | 국소 재시도         |

`partial`은 같은 Decision Revision 안의 비인가성 Section 실패에만 사용한다. Auth·Scope 실패는
민감 Content 전체를 제거한다.

Access State에서 권한 밖 Object의 이름·본문·수량을 노출하지 않는다. 권한 없음과 404를 같은
Home Redirect로 감추지 않는다.

## 7. Approvals Pilot IA

### 7.1 Surface

| Surface     | Canonical Route Family                                                                                            | Index                                     | Sidebar  |
| ----------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | -------- |
| `결재 업무` | `/approvals/home`, `/approvals/inbox`, `/approvals/completed`, `/approvals/requests/**`, `/approvals/delegations` | `/approvals/home`                         | 업무 9개 |
| `결재 관리` | `/approvals/admin/**`                                                                                             | `/approvals/admin`가 첫 허용 Child로 이동 | 관리 6개 |

`/approvals`는 Work 접근이 있으면 관리 권한 보유 여부와 무관하게 `/approvals/home`으로 이동한다.
Work가 없고 Management만 있으면 첫 허용 관리 Child, 둘 다 없으면 App Access State로 이동한다.

### 7.2 Work Navigation

| Group   | Menu                                                                                                 |
| ------- | ---------------------------------------------------------------------------------------------------- |
| 시작    | 전자결재 홈                                                                                          |
| 내 결재 | 결재함, 내 처리 완료함, 새 결재 작성, 임시 저장, 내가 올린 결재, 보완할 결재, 완료 보관함, 결재 위임 |

Approval Home에 제품 운영 Health나 관리 Queue를 섞지 않는다. Work Home은 사용자에게 실제로
할당되거나 본인이 만든 결재만 우선한다.

### 7.3 Management Navigation

| Group    | Menu                         |
| -------- | ---------------------------- |
| 현황     | 운영 개요                    |
| 설계     | 프로세스 설계, 양식 카탈로그 |
| 거버넌스 | 결재 정책, 전자서명 연계     |
| 운영     | SLA 및 전달 운영             |

Management Index는 Manifest 순서에서 첫 허용 Route를 찾는다. Pilot 고정 순서는 `overview →
workflows → forms → policies → operations → signatures`이며 권한이 없는 항목은 건너뛴다.

### 7.4 진입·복귀

- Work → Management: 유효한 마지막 `routeId`, 없으면 첫 허용 Route
- Management → Work: 유효한 마지막 Work `routeId`, 없으면 `/approvals/inbox`, Inbox 권한이
  없으면 `/approvals/home`
- Work 권한이 없는 Management-only 사용자는 `업무로 돌아가기` 대신 `앱 목록으로`를 본다.
- 기존 `task`, `request`, `draft` Deep Link Query를 Browser URL에서는 유지하되 편의 저장소에는
  저장하지 않는다.

## 8. HCM Pilot IA

### 8.1 Surface

| Surface    | Route Family                                                                                                                                  | 기본 Route                           |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `나`       | `/hr/home`, `/hr/me`, `/hr/time`, `/hr/absence`, `/hr/benefits`, `/hr/pay`, `/hr/talent`, `/hr/services`, `/hr/directory`, `/hr/organization` | `/hr/home`                           |
| `내 팀`    | `/hr/team`, `/hr/team/time`, `/hr/team/absence`                                                                                               | `/hr/team`                           |
| `HR 운영`  | `/hr/operations`, `/hr/operations/**`                                                                                                         | `/hr/operations` 또는 첫 허용 Domain |
| `HCM 관리` | `/hr/manage`, `/hr/design/**`, `/hr/data/**`                                                                                                  | `/hr/manage`가 첫 허용 Child로 이동  |

기존 경로를 유지하고 Manifest Route Matcher로 Surface를 판정한다. 현재 Registry에 명시된 11개
`/people/**`, `/workforce/**` Legacy Source만 Query와 Hash를 보존해 한 번 Redirect한다. 그 외
미등록 Subpath는 HCM-local 404로 종료한다.

### 8.2 `/hr` Resolver

1. `hcm.personal` Access Policy가 Allow면 `나`로 진입한다. Person Binding은 필요
   조건이지 단독 Allow 근거가 아니다.
2. Personal은 Deny이고 `hcm.team` Relationship Policy만 Allow면 `내 팀`으로 진입한다.
3. 허용된 Work Surface가 없고 `hcm.operations`가 Allow면 `HR 운영`으로 진입한다.
4. 위 Surface가 없고 `hcm.management`만 Allow면 `HCM 관리`의 첫 허용 Route로
   진입한다.
5. 어느 것도 없으면 Identity/Access State를 표시한다.

`/hr/home` Direct URL에서 Person Binding이 없다고 자동으로 Operations로 이동하지 않는다.
Identity 오류와 허용 Surface Link를 표시한다.

### 8.3 `나`

기존 개인·조직 메뉴 10개만 표시한다. Manager·Operator·Configurator 권한을 가졌더라도 이
Sidebar에는 팀·운영·관리 메뉴를 추가하지 않는다.

### 8.4 `내 팀`

- 실제 유효일 Reporting Relation 또는 승인된 위임이 있는 사용자만 진입한다.
- `내 팀`, `팀 근태 승인`, `팀 휴가 승인`만 표시한다.
- Scope 기본값은 실제 직속 팀이며 위임이 있으면 서버가 허용한 팀만 선택지로 제공한다.
- Team Surface는 Tenant Admin이나 Role 문자열만으로 열지 않는다.

### 8.5 `HR 운영`

- 운영 현황, 도메인 운영 5개, 인력 정보와 발령 현황을 표시한다.
- Scope는 조직·법인·지역·HR Domain Target Population이다.
- Support `WORKFORCE_READ`는 Read-only로만 이 Surface에 들어올 수 있다.
- Support Banner가 없는 일반 권한과 Support Scope를 합산하지 않는다.

### 8.6 `HCM 관리`

- 조직 설계, 인력 기준정보, 연계·정합성, 통제형 반출을 표시한다.
- `canOperate` 또는 `ADMIN|HR_ADMIN` 문자열로 진입·쓰기 여부를 계산하지 않는다.
- 조직 설계는 전용 `ACTION.WORKFORCE_ORG_DESIGN` Capability가 승인된 뒤 연다.
- 통제형 반출은 Step-up, 사유, Export Scope, Watermark·감사와 만료를 요구한다.
- 상위 Tenant 정책이 잠근 값은 숨기지 않고 Policy Lock 상태로 표시한다.

기존 HCM Home의 `나 / 내 팀 / HR 운영` Local Toggle은 Product Header의 Route Link
Navigation으로 승격하고 `HCM 관리`를 추가한다. Home Widget만 바꾸던 Local State는 제거한다.

## 9. Keyboard·Screen Reader Flow

1. Skip Link로 Main에 이동할 수 있다.
2. Header의 Surface Navigation은 Link 목록으로 읽힌다.
3. 현재 Link에는 `aria-current`가 있다.
4. Scope Dialog는 Trigger에서 열리고 선택·취소 후 Trigger로 복귀한다.
5. Route 전환 완료 후 Document Title과 H1을 갱신한다.
6. Browser History 복귀는 원래 Focus 복원 정책을 지키고 매 전환마다 강제로 H1에 이동하지 않는다.
7. 만료 경고와 완료는 `role=status` Polite, 권한 회수로 Action이 중단되면 한 번만 Assertive하게
   알린다.
8. 200% Zoom과 320px에서 가로 Page Scroll을 만들지 않는다.
