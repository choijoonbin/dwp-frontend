# 01 기획 정의

## 문제

기존 감사 목록은 관리 변경 몇 건을 시간순으로 보여줄 뿐, 무엇이 위험하고 누가 어떤
대상에 영향을 주었는지, 관련 사건을 어떻게 조사했는지 설명하지 못했다. API 호출량과
오류를 다루는 운영 Telemetry와 법적·보안 증적도 분리되지 않았다.

## 제품 목표

- 사용자·서비스·Agent의 중요 행위를 하나의 Versioned Event 계약으로 추적한다.
- 위험 점수와 정책 Rule로 주의가 필요한 Event를 Finding으로 전환한다.
- 조사자가 Event와 Finding을 Case에 연결하고 담당·상태·해결 근거를 남긴다.
- 조사자가 Note·Task·SLA로 조치를 협업하고 모든 Task 완료와 Resolution을 종결 조건으로 강제한다.
- 종결 시 Case Workspace 전체를 SHA-256이 포함된 Append-only 종료 보고서로 동결하고,
  Case·Finding·Evidence·Entity·Task·Note를 읽기 전용으로 전환한다.
- 개인·공유 조사 보기를 저장해 반복 감사의 검색 조건과 업무 맥락을 재사용한다.
- Tenant별 보존, 반출 사유, 반출 한도와 무결성 검증 정책을 통제한다.
- 원문 Secret, Token, Body, Raw IP와 Raw User-Agent는 저장하지 않는다.

## 사용자와 핵심 Journey

| 사용자          | 목적              | 핵심 흐름                                                                                 |
| --------------- | ----------------- | ----------------------------------------------------------------------------------------- |
| Tenant 감사자   | 이상 행위 조사    | Overview -> 저장 보기 -> Event 상세 Diff -> Case 연결                                     |
| 보안 운영자     | 위험 Finding 처리 | Findings -> 담당·Task -> 증적 연결 -> Resolution -> 불변 종료 보고서 -> 필요 시 후속 Case |
| 감사 관리자     | 정책 통제         | 보존·반출·무결성 정책 -> Checkpoint -> Export                                             |
| Platform 운영자 | 수집 상태 확인    | Source health -> 실패 Source 식별 -> 운영 Telemetry 이동                                  |

## Information Architecture

`거버넌스` 아래에 `감사 개요`, `이벤트 탐색`, `탐지 및 조사`, `보존 및 무결성`을 둔다.
`API 모니터링`은 성능·가용성 Telemetry이므로 별도 운영 메뉴를 유지한다.

## 성공 지표

- 중요 관리·인증·권한·AI Action의 수집 누락률 0%
- Collector 정상 상태에서 Outbox 전달 지연 p95 10초 이하
- High/Critical Finding의 Owner 지정률과 평균 해결시간
- Export에 사유·Actor·Hash가 남는 비율 100%
- Tenant 간 조회·수정·반출 격리 위반 0건
