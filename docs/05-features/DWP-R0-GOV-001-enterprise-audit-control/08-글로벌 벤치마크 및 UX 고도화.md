# 08 글로벌 벤치마크 및 UX 고도화

## 결론

감사 기능을 대량 로그를 조회하는 단일 표가 아니라 `관제 → 우선순위 분석 → 사건 조사 →
증적 탐색·보존 → 수명주기·무결성`으로 이어지는 운영 제품으로 정의한다. API 호출 이력은
성능·오류·Trace를 보는 운영 Telemetry이고, 감사 증적은 책임·판단·변경·반출을 재현하는
보안 기록이므로 저장 목적과 권한을 분리하되 Correlation ID로 연결한다.

## 정보 구조

### 1. 감사 관제

- 위험 노출, 미처리 Finding, SLA 위험 Case, 수집 상태를 한 화면에서 판단한다.
- 위험 추세·도메인·Identity·수집 보증을 함께 제시해 단순 건수의 오해를 줄인다.
- 우선 조치 Queue에서 조사 워크벤치로 바로 이동한다.

### 2. 조사 워크벤치

- 좌측은 Risk Finding과 Case 우선순위 Queue다.
- 중앙은 선택 대상의 원인, Actor → Action → Target, 상관 Timeline, 증적·Entity 범위다.
- 우측 Action Rail은 배정, 상태, Case 전환, Task, Note를 맥락을 잃지 않고 처리한다.
- Case는 Severity 기반 SLA, 책임자, 증적 수, Entity 수, Task 진행률을 상시 표시한다.

### 3. 증적 탐색기

- Tenant·시간 범위가 항상 포함된 서버 Filter와 Pagination을 사용한다.
- Source·Actor 저장 보기, 상세 Event, 사유 필수 반출, Case 증적 보존을 지원한다.
- 원문 Secret·Token·Raw Body는 탐색 대상에 포함하지 않는다.

### 4. 증적 거버넌스

- 수집 → 보존 → 무결성 확인 → 반출 → 폐기의 Lifecycle을 한눈에 관리한다.
- Source Health, Retention Class, Export 제한, 일별 Root Hash 검증을 분리해 보여준다.
- 정책 변경 자체도 감사 Event와 조사 저널 대상이다.

## 핵심 사용자 여정

1. 감사자는 관제 화면에서 SLA 위험과 고위험 Finding을 확인한다.
2. 조사 워크벤치에서 상관 Event, Actor, Target, Source와 기존 Case를 검토한다.
3. 오탐이면 사유를 남기고 종결하고, 실재 위험이면 Case를 생성·연결한다.
4. Case에서 담당자·기한·Task를 지정하고 Note와 증적을 변경 불가 저널에 남긴다.
5. 추가 증적은 탐색기에서 검색해 Case에 보존하며, 반출은 사유와 SHA-256을 기록한다.
6. 증적 거버넌스에서 보존·수집·무결성 상태를 확인하고 생산 환경 Gate를 관리한다.

## UX·접근성 기준

- 표는 정밀 탐색에만 사용하고 의사결정은 Metric, Queue, Dossier, Timeline으로 구성한다.
- 행·카드·Toolbar는 고정된 밀도와 높이 규칙을 사용해 화면 이동을 방지한다.
- 색만으로 상태를 전달하지 않고 Label·Icon·Text를 병행한다.
- 모든 Queue와 Action은 Keyboard로 이동·실행할 수 있고 Focus Ring을 제공한다.
- Progress와 Timeline Region에는 접근 가능한 이름을 제공하며 Heading 계층을 지킨다.
- Desktop은 3-pane을 우선하고 폭이 줄면 Action Rail을 본문 아래로 이동한다.
- Mobile은 Queue와 Dossier를 순차 배치하고 가로 Lifecycle은 이름 있는 Scroll Region으로 둔다.

## 구현 범위

- DB: Case SLA, Entity Scope, Investigation Task, Append-only Activity Journal
- API: Finding Context, Case Workspace, Note·Task, Event Preservation
- UI: Audit Command Center, Investigation Workbench, Evidence Explorer, Evidence Governance
- 검증: 실제 PostgreSQL Migration·API Smoke, Unit Test, Desktop·Mobile E2E, Axe

## 생산 환경 Gate

현재 구현은 제품·데이터·권한·로컬 운영 계약까지 포함한다. 다음 항목은 외부 인프라 준비 전
완료로 표시하지 않는다.

- Workload Identity 또는 mTLS 기반 Source 인증
- KMS/HSM 서명과 Object Lock WORM Archive
- SIEM/SOAR Export, Alert Rule 운영, On-call 연계
- PostgreSQL RLS와 감사자 직무 분리, Legal Hold 승인
- OTel Collector HA·Durable Buffer와 누락·지연 SLO Alert
