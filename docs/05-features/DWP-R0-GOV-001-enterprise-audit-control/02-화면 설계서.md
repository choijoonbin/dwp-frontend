# 02 화면 설계서

## 공통 Shell

- Control Center의 기존 Header, Tenant Scope와 2단계 Inline Navigation을 유지한다.
- 모든 화면은 권한 Resource가 없으면 Navigation과 Route 양쪽에서 차단한다.
- 표, Filter와 Detail Drawer의 높이는 공통 Design Token을 사용해 행이 흔들리지 않는다.

## 감사 개요

- KPI: 전체 Event, High-risk, 거부·실패, 열린 Finding, 활성 Case, 정상 Source
- 시간 Trend와 Category·Outcome 분포
- 즉시 확인할 Finding과 Source Health
- 시간 범위는 `24시간`, `7일`, `30일`, `90일` Segment로 제공

## 이벤트 탐색

- 개인·Tenant 공유 저장 보기를 선택·저장·삭제하고 동일한 상대 기간 Filter를 재적용
- Category, Severity, Outcome, Source, Actor, 자유 검색을 한 줄 Filter Bar로 제공
- 고정 높이 Enterprise Data Grid와 서버 Pagination 사용
- 행 선택 시 Drawer에서 Actor·Target·Correlation·정책·변경 Field·Before/After를 표시
- CSV·JSONL Export는 Format과 감사 사유를 입력한 뒤 실행
- 현재 Local 계약은 제한 행 동기 Export다. 대량 비동기 Job은 `D-12`의 Worker·WORM 저장소 결정 전까지 표시하지 않는다.

## 탐지 및 조사

- 좌측 Finding Queue와 우측 Case Workspace를 같은 화면에서 비교
- Finding 상태는 Open, Acknowledged, Investigating, Resolved, Dismissed
- Case 상태는 Open, Investigating, Contained, Resolved, Closed
- Case에는 Owner, Severity, Resolution, 연결 Event·Finding 수를 표시
- Case 우측 Action Rail에서 Note와 담당·우선순위·기한을 가진 Task를 기록하고 SLA 상태를 확인
- 미완료 Task 또는 빈 Resolution이 있으면 Closed 전환을 차단
- Closed 이후 Report Version·생성 시각·SHA-256을 표시하고 JSON 종료 보고서를 다운로드
- Closed Case와 연결 Finding의 Action Rail은 잠금 안내와 함께 읽기 전용으로 전환한다.
  추가 작업은 기존 Case 재개가 아니라 별도 후속 Case에서 수행한다.

## 보존 및 무결성

- Standard·Extended 보존일, Export 행 제한, 사유 필수, High-risk 임계값 관리
- Source별 마지막 Event, 24시간 수집량과 상태 표시
- 일별 Checkpoint의 Record 수, Root Hash, 서명 방식과 검증 상태 표시
- 정책 저장과 Checkpoint 생성은 확인 Dialog와 성공·실패 Toast를 제공

## 반응형

Desktop에서는 비교와 조사 밀도를 우선한다. Tablet 이하는 Filter와 저장 보기를 세로로
재배치하고 표 대신 Keyboard 접근 가능한 Event 목록을 제공하며 상세 Drawer는 전체 폭으로
전환한다.
