# DWP-R1-ADM-007 화면 설계서

| Route                                 | Archetype  | 대표 사용자                          |
| ------------------------------------- | ---------- | ------------------------------------ |
| `/admin/platform/navigation`          | Studio     | Tenant Admin                         |
| `/admin/identity/app-governance`      | Governance | App Catalog Admin / App Owner        |
| `/admin/identity/app-access-requests` | Workflow   | Approver / Access Manager / Reviewer |
| `/apps`                               | Catalog    | 구성원                               |

Navigation Studio는 게시 Version에서 Draft를 만들고 Tree·Label·권한을 편집한다. Desktop·Mobile,
Locale, Role Preview와 Validation을 확인한 뒤 게시한다. 취소·복원은 확인과 감사 근거를 요구한다.

사용자는 앱 상세에서 목적·기간을 입력해 요청하고 Pending 요청을 취소한다. Approver는
요청자·앱·근거·기간을 비교해 승인 또는 반려한다. Access Manager는 승인된 요청만 실제
권한으로 이행하고 실패를 재시도하거나 활성 권한을 회수한다. Reviewer는 읽기와 정기
검토를 담당한다. 결정 상태와 이행 상태를 서로 다른 Signal로 표시한다.

No Draft, Validation Error, Stale Version, Empty Queue, Pending, Approved, Fulfillment
Pending, Fulfilled, Failed, Revoked, Rejected, Cancelled, Expired와 Permission 상태를
구분한다. App Catalog Admin은 Queue를 읽을 수 있지만 결정·이행 Action은 보이지 않는다.

App Governance의 `앱 관리자 Preset` 영역은 제품별 최소 책임·Scoped Duty 묶음을 표시한다.
요청자는 대상·앱 Resource Set·Preset·검토기한·만료·사유를 지정하고, 화면은
`PENDING_APPROVAL → APPROVED → ACTIVE`를 서로 다른 상태로 표시한다. 정확한 Scope의
Approver에게만 승인·반려, Access Manager에게만 활성화·회수, Reviewer에게만 검토 결정을
표시한다. 요청자·승인자·활성자 또는 대상 사용자가 겹치면 Action을 숨기되 서버 거부가 최종
경계다. 제품 계약이 준비되지 않은 Preset은 이유와 함께 비활성 표시하며 요청할 수 없다.

`APP_OWNER` 지정·회수는 App Catalog Admin의 별도 Ownership Workflow다. App Catalog Admin의
Read-only 규칙은 앱 **접근 요청 Queue**에 적용되며 Ownership Action에는 적용하지 않는다.
일반 통제면 책임 Assignment 화면은 `APP_OWNER`, `APP_ACCESS_APPROVER`,
`APP_ACCESS_MANAGER`, `APP_ACCESS_REVIEWER`만 받는다. `APP_CONFIG_ADMIN`과 제품 전문 Duty는
반드시 3단계 Preset 화면을 사용한다.
