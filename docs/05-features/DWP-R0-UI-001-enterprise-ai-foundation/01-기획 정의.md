## 문제와 근거

- 대상 사용자: R1 기능 개발자·Designer, 데이터 중심 업무 사용자, Agent 승인자
- 현재 업무와 Trigger: Work·Approval·Service·Admin과 Agent Action 구현 시작 전
- Baseline: 공통 Enterprise Grid와 Citation·Plan·Trace Pattern이 없어 기능별 분기 위험
- 근거: `프론트엔드 UI UX 기술검토.md`의 P1 Gap과 R0.5 Exit Gate

## 목표

- JTBD: Feature 팀이 검증된 공통 Component로 고밀도 데이터와 AI 실행 상태를 표현
- 기대 Outcome: 접근성·Theme·Density·권한 표시가 기능별로 달라지지 않음
- Target: R1 Reference 화면의 공통 Pattern 사용률 100%, 중복 Grid·Agent Action UI 0건

## 범위

- In scope: `EnterpriseDataGrid`, `SourceCitationList`, `AgentPlanPreview`,
  `AgentExecutionTimeline`, Storybook Reference와 자동 검증
- Non-goal: 실제 업무 메뉴, Connector, Model 호출, Tool 실행, 영구 데이터 저장
- Horizontal Core와 Industry Pack 경계: 산업 독립 Foundation만 포함
- 결정: 복잡한 Grid Engine은 MUI X Community를 사용하고 DWP 계약만 얇게 적용

## Journey

1. 사용자가 권한 범위 안의 업무 목록을 탐색·정렬·선택한다.
2. AI가 제안한 계획과 Source, Risk, 변경 대상을 확인한다.
3. 승인 필요 계획은 사용자가 승인·반려하고 실행 상태를 추적한다.
4. 실패·부분 성공은 Retry, 중단 또는 사람 인계로 전환한다.

## 정책과 위험

- 개인정보·기밀등급: Component는 Data를 저장하지 않고 Consumer가 Masking 책임을 명시
- 보존·삭제: UI State는 Session 범위, 원본과 Audit 보존은 System of Record 계약 적용
- AI 정책: Citation 없는 사실 답변과 승인 없는 고위험 실행을 완료 상태로 표시하지 않음
