## 0. 문서 역할

이 문서는 저장소 내부 구현이 끝난 뒤 남은 출시 증거, 외부 결정과 차기 제품 후보를
한눈에 설명하는 보조 문서다. 상태와 출시 판정의 단일 원장은 Delivery 문서와 JSON 증거
원장이며, 이 문서와 충돌하면 두 원장을 우선한다.

## 1. 현재 결론

- `R0-01`~`R0-04` 저장소·문서·재현성 기반은 완료됐다.
- `R1-01`~`R1-23`과 이후 Notification·Messaging·Workplace·Agent 내부 보강 범위는 완료됐다.
- `R1-24` Flow Home Personalization vNext는 후속 제품 증분이다. G0~G3 후보 산출물은
  `DWP-R1-CORE-007-flow-home-personalization`에 준비됐으며 Owner 승인과 구현은 시작 전이다.
- 보안 정책 감사에서 `R3-02-KMS`를 명시적 후속 TODO로 승인했다. Provider 독립
  `KeyProvider`, 로컬 파일 어댑터와 환경별 시작 검증은 구현 대기이며, 실제 관리형
  KMS/HSM 연결과 운영 증거는 외부 인프라 Gate다.
- Production Release는 아직 승인되지 않았다. `R2` 5건, `R3` 5건, `A` 5건이 실제
  환경·사용자·책임자 증거를 기다린다.
- `D-01`~`D-18`은 결정 전 성공 상태를 가장하지 않으며 모두 fail-closed 또는 기능
  비활성 상태로 등록되어 있다.
- `P3-01`~`P3-06`은 잔여 결함이 아니라 별도 PRD와 Pilot 승인이 필요한 신규 제품 범위다.

증거 원장 현재 집계는 `BLOCKED_EXTERNAL` 15건, `FEATURE_DISABLED` 18건이다.
따라서 `corepack yarn release:evidence:check`는 통과하고, 실제 출시를 승인하는
`corepack yarn release:gate`는 의도적으로 종료 코드 2로 차단된다.

#### 3.2.1 `R3-02-KMS` 실행 TODO

정책 SSOT는 Backend의
`docs/architecture/cryptographic-key-and-secret-management-policy.md`다.

| 단계               | 상태      | 종료 조건                                                                                              |
| ------------------ | --------- | ------------------------------------------------------------------------------------------------------ |
| Provider 독립 계약 | 구현 대기 | Backend·Agent 공통 `KeyProvider`, 버전·AAD·Envelope metadata 계약과 회귀 테스트                        |
| Local 개발 기준선  | 부분 완료 | `devctl.py` 평문 기본값은 유지; ignored Local 설정·파일을 공통 `KeyProvider`로 수용하고 Git·Image 제외 |
| 환경 프로파일      | 구현 대기 | `local`만 평문·파일 허용, `dev/qa/prod`는 관리형 Provider·Workload Identity 강제, 불일치 시 시작 차단  |
| 관리형 KMS/HSM     | 외부 Gate | Provider·계정·지역·키 정책 승인, Sandbox 통합과 최소 권한·회전·장애·복구 증거                          |
| 운영 수명주기      | 외부 Gate | Rotation·Rewrap·폐기 보호·감사·SIEM·RTO/RPO와 침해 대응 승인                                           |

Git에서 제외된 `application-local.yml`과 `.env.local`에는 개발 편의를 위해 실제 로컬 키와
토큰을 평문으로 둘 수 있다. 공유 `dev/qa/prod` YML에는 Provider, key ID 또는 alias,
version과 mount path만 기록하며 실제 키와 자격증명은 KMS/Secret Manager 또는 런타임
Secret volume이 제공한다. `dev/qa/prod`에서 로컬 값으로 자동 대체하는 동작은 금지한다.

## 6. 재개 절차

1. 외부 입력의 Owner, 승인 문서와 비민감 Evidence URI를 증거 원장에 등록한다.
2. 해당 `D-*` 결정으로 실행 계약이 바뀌는 경우에만 별도 PRD·ADR과 작업 ID를 발급한다.
3. Sandbox에서 정상·권한 거부·부분 장애·재시도·철회·복구를 검증한다.
4. `R2`, `R3`, `A`의 실제 증거가 승인된 항목만 `COMPLETE`로 변경한다.
5. 전체 자동 회귀와 `release:gate`를 실행하고 배포 Commit·SBOM·SHA-256을 함께 보존한다.

외부 증거가 들어오기 전에는 `R3-02-KMS`처럼 승인된 실행 ID 없이 저장소 내부 잔여를
임의로 만들지 않는다. 이후 신규 요구는 Delivery SSOT의 기존 ID와 먼저 대조해 중복
구현을 막는다.
