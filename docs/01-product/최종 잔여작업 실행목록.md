## 0. 문서 역할

이 문서는 현재 구현 상태에서 앞으로 확보할 제품 역량과 장기 확장 순서를 설명한다.
작업 ID, 현재 상태, 우선순위와 출시 완료 판정은 Delivery의
`DWP 최종 실행 백로그 및 출시 조건 2026-08-12.md`에서만 관리한다. 두 문서가 충돌하면
Delivery Backlog를 우선하고, 이 문서는 전략적 묶음과 의존성을 설명하는 보조 자료로 사용한다.

상태는 다음 네 가지로만 구분한다.

| 상태             | 의미                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| `완료 기준선`    | 로컬 제품 범위와 자동 검증이 완료되어 잔여작업으로 다시 세지 않는 항목    |
| `즉시 진행`      | 고객 계정이나 운영 인프라 없이 현재 저장소에서 구현·검증할 수 있는 작업   |
| `외부 Gate`      | 고객 정책, Sandbox, Credential, 인프라 또는 라이선스가 있어야 활성화 가능 |
| `후속 제품 확장` | R1 기반을 닫은 뒤 검증할 Capability와 Business Pack                       |

화면이 존재하거나 Demo가 동작한다는 이유만으로 완료로 판정하지 않는다. Schema, API,
Tenant·권한, 감사, 실패 상태, 운영 계약과 위험에 맞는 검증 증거가 함께 있어야 한다.

### P2. R1 제품 결과 완성

1. **Durable Workflow:** 승인, Timer, Retry, Idempotency, Compensation, Human Task와
   장기 실행 Version Migration을 실제 Journey로 검증한다.
2. **Governed Agent Action:** Plan Preview, Approval Token, 최소 권한 Tool Grant,
   실행·취소·보상 Timeline, Evaluation·Budget·Rate Limit·Kill Switch를 연결한다.
3. **Service Catalog와 Common Pack:** HR·IT·Workplace·구매·법무 요청을 공통 Contract와
   Case·SLA로 제공하고 기존 System of Record에 연결한다.
4. **조직 설계 확장:** Scenario 협업·Bulk·HCM 실행 Bridge, Budget·Finance 조건부 승인,
   Skill·Capability와 개인정보를 보호하는 Collaboration Graph를 검증한다.
5. **Employee Productivity 확장:** Inbox, Meeting, People Context와 업무 중 협업을
   Microsoft 365 또는 Google Workspace 기준으로 연결한다.
6. **Productization:** Private·Hybrid Data Plane, Connector SDK·Certification,
   Capacity·DR·Support와 사용량·비용 통제를 완성한다.
7. **Industry Pack:** 공통 Core와 Pilot Gate 통과 후 통신, 이어서 반도체 Pack을 검증한다.

## 3. 실행 순서와 병렬화

```text
Baseline 정리
  -> Typed Config + Identity Governance
  -> Event Backbone + Data Governance
  -> Localization + Shared View/Export
  -> UI 일관성 + 접근성/규모/복구 증거
  -> SSO + HRIS + Productivity + Knowledge + Model 활성화
  -> Durable Workflow + Governed Agent Action
  -> Common Pack + Productization + Industry Pack
```

- `dwp-backend`는 Config, Identity, Event, Data, Integration Control Plane을 선행한다.
- `dwp-frontend`는 해당 계약이 확정된 순서대로 Admin Workbench와 사용자 Journey를
  연결하고 공통 Pattern·접근성 증거를 누적한다.
- `dwp_agent`는 Tool 실행을 먼저 늘리지 않고 Policy, Approval Token, Evaluation과
  Compensation 계약이 준비된 Capability만 소비한다.
- 외부 Gate Lane은 P0와 병렬로 준비하되 Credential이나 인프라가 없으면 활성화하지 않는다.

## 4. 공통 완료 조건

각 작업은 다음 조건을 모두 만족해야 완료 처리한다.

1. Product Scope, Non-goal, Owner, 개인정보·보안 영향이 정의된다.
2. Schema·Migration, API·Error·Version, Tenant·RBAC·감사 계약이 일치한다.
3. 정상, Empty, Loading, Partial, Stale, Error, Permission 상태가 구현된다.
4. Frontend·Backend·Agent 중 영향받는 저장소의 Contract Test가 통과한다.
5. 위험에 맞는 Unit·Integration·E2E·Axe·성능·복구 검증이 존재한다.
6. 실제 Database와 Gateway 경로를 검증하고 임시·검증용 객체를 제거한다.
7. 운영 Secret·SLO·RLS·고객 승인이 남으면 `외부 Gate`로 표시하고 완료로 숨기지 않는다.
8. 문서, 메뉴 Registry, 다국어 Key, 권한 Seed와 운영 Runbook을 같은 변경에서 갱신한다.
