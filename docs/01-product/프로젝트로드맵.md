## 1. 전략 방향

### 1.1 제품 정의

DWP는 특정 산업용 업무 애플리케이션이 아니라 모든 산업에서 사용할 수 있는
**Governed Agentic Work Platform**이다.

> 직원이 여러 시스템을 찾아다니지 않고, DWP에서 업무를 파악하고, 묻고,
> 요청하고, 승인하고, AI 에이전트와 함께 안전하게 결과를 완료하게 한다.

### 1.2 우선순위 원칙

제품은 다음 순서로 확장한다.

1. **Enterprise Foundation**: 인증, 조직, 권한, 감사, 정책과 운영 기반
2. **Universal DWP Core**: 모든 산업의 직원에게 필요한 통합 업무 경험
3. **Common Business Packs**: HR, IT, Workplace, 구매, 법무 등 공통 서비스
4. **Agentic Work Platform**: 통제된 에이전트 실행과 업무 오케스트레이션
5. **Industry Packs**: 통신, 반도체 등 산업별 데이터·Connector·업무 패턴

통신과 반도체는 중요한 목표 시장이지만 제품 구조와 초기 기능의 결정 기준은
아니다. 공통 DWP Core가 실제 고객에서 검증된 뒤 Industry Pack으로 확장한다.

### 1.3 시장 판단

글로벌 DWP는 단일 포털보다 기존 업무 도구 위에 통합 경험을 제공하는 방향으로
진화하고 있다.

- Microsoft Viva는 Microsoft 365와 Teams 위에서 커뮤니케이션, 지식, 학습,
  인사이트와 파트너 앱을 연결한다.
- ServiceNow Employee Center는 IT, HR, Workplace, Legal 등의 서비스와 기존
  시스템을 하나의 직원 경험으로 통합한다.
- Google Workspace는 Gmail, Drive, Meet 안에서 메일·문서·회의를 요약하고 후속
  행동을 연결한다.
- Slack, SAP와 주요 Enterprise Agent 플랫폼은 대화 자체보다 기업 맥락, 업무
  실행, 권한과 Agent Governance를 경쟁 영역으로 이동시키고 있다.

따라서 DWP는 메일 서버, 화상회의 엔진, HRIS, ERP를 새로 만드는 Suite가 아니라
이들을 연결하고 업무 맥락과 AI 실행을 통제하는 플랫폼이 되어야 한다.

## 2. North Star와 성공 조건

### 2.1 North Star

**Governed Work Outcomes per Active User**

정책과 권한을 준수하고 필요한 승인을 거쳐 감사 가능한 상태로 완료된 유효 업무
결과와 사용자당 절감 시간을 핵심 지표로 사용한다.

대화 수, 토큰 수, 화면 체류시간, 등록된 에이전트 수는 단독 성공지표로 사용하지
않는다.

### 2.2 제품 성공 조건

- 사용자가 업무 시작을 위해 방문해야 하는 시스템과 탐색 시간을 줄인다.
- 이메일, 일정, 업무, 지식과 서비스 요청을 하나의 개인 맥락으로 연결한다.
- AI 답변에는 출처, 권한, 최신성과 불확실성이 드러난다.
- 중요한 실행에는 계획 미리보기, 사람 승인, 취소와 감사가 제공된다.
- 기존 System of Record를 교체하지 않고 재사용한다.
- 산업별 기능을 공통 Core 변경 없이 Pack과 Connector로 추가할 수 있다.

### 3.5 Agentic Work Platform

- Agent Registry, Owner, Identity, Version과 Lifecycle
- Agent Risk Tier와 허용 Tool·Data·Budget

- Plan Preview, Approval, Tool Execution Timeline과 Human Handoff

- Prompt·Context·Tool·Result·Approval Trace와 Evaluation

- Agent Studio는 운영 기반과 재사용 패턴이 검증된 뒤 제공

### 3.6 Industry Packs

공통 Core와 Agent Platform Gate를 통과한 뒤 다음 Pack을 별도 로드맵으로 연다.

- Telecom Operations Pack: NOC, OSS/BSS, Field Service, Contact Center
- Semiconductor Engineering and Fab Pack: Fab 운영, 장비, 품질, EDA, 공급망

Industry Pack은 메뉴 묶음이 아니라 다음을 포함한다.

- 표준 용어와 Entity Model
- 검증된 Connector와 권한 Mapping
- Domain Workflow와 Agent Template
- 위험등급, 승인, 평가 데이터와 KPI
- 배포, 데이터 주권, 운영 Runbook과 계약 패키지

### 4.1 Legacy 연결 우선순위

`표준 API -> Event/Webhook -> MCP Tool -> Embedded UI -> RPA`

RPA는 마지막 수단이며 화면 변경에 취약하므로 핵심 거래의 기본 통합 방식으로
사용하지 않는다.

## 5. 목표 Information Architecture

### 5.1 Global Shell

- Home 복귀: Product Mark와 Account Menu의 `Home`
- 좌측 Navigation: `Work`, `Ask`, `Activity`, `Apps`에서 시작해 `Inbox`, `People`,
  `Services`, `Knowledge`, `Agents`로 확장
- 권한 Navigation: `Admin`
- Header: Workspace, Global Ask/Search, 빠른 생성, 알림, 도움말, 계정
- 우측 Context Panel: Agent, 상세정보, Activity, Collaboration을 현재 업무 맥락에
  따라 전환
- Mobile: 핵심 4개 목적지와 More Navigation, Context Panel은 Bottom Sheet

Home은 권한이 부여된 Assigned Apps를 목적별 그룹으로 먼저 제공하고 바로 아래
Today에서 마감 업무, 승인, 요청, 일정과 중요 커뮤니케이션을 결과 중심으로 통합한다.
`/apps`는 Native·Legacy·SaaS 앱의 전체 검색과 상태 확인을 담당한다. 관리자가 정의한
그룹 안에서 사용자 Reorder·폴더를 허용하되 자유 크기 Widget Portal은 기본 경험으로
삼지 않는다.

개인화의 우선순위는 `보안·필수 정책 -> 역할·조직 -> 사용자 명시적 선호 ->
마감·현재 맥락 -> 사용 패턴 -> AI 추천`이다. AI 추천에는 이유, 숨김과 초기화
Control을 제공한다. 상세 계약은 `개인화 홈 및 앱 경험 기획.md`를 따른다.

메뉴는 기능 조직도가 아니라 사용자의 업무 목적을 기준으로 구성한다. HR, IT,
구매 등의 부서명은 `Services` 내부 Topic과 권한 기반 Shortcut으로 제공한다.

### 5.2 핵심 사용자 Journey

#### Start My Day

1. Home에서 일정, 중요 메일, 마감 업무, 승인과 공지를 확인한다.
2. AI Daily Brief에서 우선순위와 근거를 확인한다.
3. 사용자가 선택한 항목만 Work에 추가하거나 담당자에게 공유한다.

#### Ask and Act

1. Ask에서 사내 규정, 문서, 메일, 회의와 업무를 질의한다.
2. DWP가 사용자 권한을 적용한 근거와 답변을 제시한다.
3. 실행이 필요한 경우 Service 또는 Workflow를 추천한다.
4. 사용자가 계획과 변경 내용을 확인하고 실행 또는 승인을 요청한다.

#### Employee Service

1. 사용자가 HR·IT 서비스를 검색하거나 자연어로 요청한다.
2. DWP가 Self-service 해결, Form 또는 Agent 지원을 제시한다.
3. 요청, 승인, 담당자 처리와 결과를 하나의 Timeline으로 추적한다.

#### Meeting to Outcome

1. 회의 전 관련 메일, 문서, 결정과 열린 Action을 정리한다.
2. 회의 Provider를 통해 녹취와 메모를 가져온다.
3. 결정사항과 할 일을 사람이 확인한 뒤 Work와 Calendar에 반영한다.

#### Legacy Task

1. 사용자가 Apps 또는 Ask에서 기존 시스템 업무를 찾는다.
2. DWP가 SSO·Deep Link 또는 승인된 Action을 제공한다.
3. 실행 결과와 원본 시스템 링크를 Work Timeline에 남긴다.

### 5.3 Admin Control Plane IA

관리 기능은 일반 사용자 메뉴와 분리하고 다음 순서로 확장한다.

Provider 운영자, Tenant 관리자, 위임 관리자와 사용자 개인 설정은 동일 권한 Surface를

`R0 Platform Control Plane 및 Admin Governance ADR.md`를 따른다.

### 13.1 현재 판정

- Wave 1·2·3의 내부 구현 가능 범위와 2026-08-13 기준 53개 메뉴·106개 시각 기준선은 완료됐다.
- HRIS와 서비스 운영, 회사 캘린더 관리 메뉴를 포함한 현행 관리 Manifest는 60개이며, 신규 경로는 메뉴 계약 Test와 목적별 Desktop·Mobile 브라우저 검증을 통과한다.
- DWP 소식은 개인화 피드, 필수 확인, 반응, 편집·게시 직무 분리와 게시 후 불변 계약까지 내부 Reference를 완료했다.
- 직원 서비스 센터는 IT·People·Workplace·Finance·Procurement 5개 분야, 서비스 9종, 동적 양식, 임시 저장·원자적 제출, SLA·처리 타임라인, 카탈로그·운영 직무 분리까지 내부 Reference를 완료했다.
- 전자결재는 글로벌 10개 제품 비교를 거쳐 내부 Approval Decision Hub와 외부 법적
  전자서명을 분리했으며, 제품·화면·데이터·API·권한·Agent·수용 기준 설계를 완료했다.
  소스·Database 구현은 `DWP-R1-APR-001`의 G2 승인 후 착수하는 신규 필수 범위다.
- Access Review, HRIS Reference Adapter, Productivity Control Plane, Grounded Ask,
  Catalog·Navigation Studio와 App Access Request는 신규 미완료 항목이 아니다.
- 즉시 다음 작업은 `DWP-R1-APR-001` G2 승인과 Workflow Engine Spike, Typed Config,
  Identity Governance 심화, Event Backbone, Data Governance, Localization Lifecycle,
  Team View·안전 반출, 접근성·규모·복구 증거다.
- SSO, 고객 HRIS, 실제 Productivity·Knowledge·Model, Provider Provisioner,
  KMS·Object Storage·RLS·SIEM, Figma는 외부 Gate가 열릴 때 활성화한다.
