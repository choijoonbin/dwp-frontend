# DWP 홈 전면 개편·설정·관리콘솔 설계 판단

기준 2026-09-14, 프런트엔드 `dwp-dev` HEAD `8b9975e4e69a80e653618beae71305e91dd0d969`와 읽은 작업 트리. 제품 소스 수정·신규 디자인 구현·배포를 뜻하지 않는 디자인 의뢰 준비 문서다. 현재 구현 근거, 실행 확인 후보, 전문가 설계 판단을 구분한다.

## 사용자 요구를 설계 결정으로 고정

1. **Classic은 전면 개편한다.** 현재 Classic 구조를 그대로 사용할 수 없다는 사용자 판단을 따른다. 소규모 색상·간격 보정으로 완료하지 않는다.
2. **Classic과 Flow의 목적과 첫 화면이 한눈에 달라야 한다.** Classic은 조직 포털, Flow는 개인 업무 실행 경험으로 설계한다. 공통 데이터가 있어도 위계·표현·주 행동이 다르다.
3. **첨부한 내 앱은 양쪽 모두 보존한다.** 그룹 4개·5열×2행·둘째 줄 왼쪽 정렬·전체 높이는 승인 기준이다. 이 영역의 여백을 결함으로 몰아 줄이지 않는다.
4. **별도 제3 모드 Adaptive / AI Stage(가칭)**는 AI를 핵심 주 행동으로 삼아 사용자 의도→실제 근거→앱/자료→초안/계획→검토·원본 행동→결과/이어하기를 연결한다. 놀라운 문맥 장면 전환과 직접 조작, 빠른 피드백을 설계한다. 현재 모드 enum·설정에 추가하는 작업은 디자인 반환 이후다.
5. 홈에 아직 존재하지 않는 위젯도 수용한다. 카탈로그·추가·편집·버전·권한·정보량·갱신·저장한 보기 호환성을 처음부터 설계한다.
6. 기존 홈 개인화·계정설정·중앙 관리콘솔의 전체 메뉴를 포함한다. 필요한 신규 기능은 기존 메뉴의 탭·상세·흐름과 신규 메뉴를 구분한다.
7. 제3 모드를 뒷받침할 **18개 앱 각각의 확장 메뉴와 신규 앱 후보**까지 검토한다. 기존 DWAI·ON을 재사용하고 홈 문맥·handoff·공유 작업 공간·지식 source·러닝의 필요한 신규 계약을 설계한다.

## 확장형 홈은 위젯 수가 아니라 등록 계약으로 설계

현재 7개 개인 위젯과 조직 announcements가 있다. 미래 위젯은 카탈로그에 안정 ID·버전·지원 모드·표현 유형·크기·정보량·owner·조회 scope·permission·설정·상태·갱신·접근성·원본 도착점으로 등록한다. 조직은 검증·게시·철회하고 개인은 찾기→미리보기→추가→설정→배치→저장→복원으로 사용한다. 기능 flag가 꺼진 항목과 아직 설치되지 않은 항목을 재시도 가능한 조회 실패처럼 취급하지 않는다.

확장성은 모든 위젯을 네모 카드에 넣는 뜻이 아니다. 편집 콘텐츠, 업무 큐, 타임라인, 진척 목록, 자료 실행, 보조 인사이트 등 표현을 수용한다. 같은 source 요청을 공유하고 느린 위젯 하나가 전체 홈을 막지 않게 한다. 신규 버전·지원 종료·권한 변경에도 기존 보기 전체를 잃지 않고 수정·대체·제거·복원한다. 위젯 추가가 사용자의 저장 순서를 자동으로 바꾸지 않는다. 자세한 명세는 [위젯 확장 계약](contracts/widget-extensibility-contract.md)이다.

## 다른 앱에서 가져올 콘텐츠의 판단

Work·결재·Calendar·Activity·인사·서비스·근무공간·알림에는 공통 홈 contribution 기반이 있다. Mail·Messaging·Space·화상회의의 앱 홈 API는 공통 홈 연결과 구분한다. 새 위젯 후보는 응답 필요한 메일·멘션, 협업 공간 업데이트, 다음 화상회의 준비, 지식 재방문, 근무공간 이용 준비, 서비스 요청 추적 등이다. 원본 조회권한과 개인정보 범위, 업무 의무 중복, 클릭 도착점을 먼저 정한다. ERP/레거시 지표와 외부 상태는 connector 계약 없이 실제 수치를 만들지 않는다.

인사 원천의 REFERENCE/UNKNOWN 정보는 확정 급여·잔여휴가·출근 상태로 표시하지 않는다. 일정·회의·공간 예약의 같은 제목이나 시간만으로 같은 객체라고 합치지 않는다. 집중 시간·회의 부하를 개인 계획 지원에서 관리자 생산성 감시로 바꾸지 않는다. 홈 직접 승인·취소 등은 owner 명령 계약이 실제 있을 때만 기본안에 넣는다. 상세는 [source 매트릭스](contracts/widget-source-matrix.md)와 P11 교차 앱 위젯 프롬프트다.

이번에는 Flow → Classic 전면 개편 → Adaptive 선택안을 먼저 차례로 검토하고, 개인화 → 계정설정 → 관리콘솔 → 교차 앱 위젯으로 진행한다. 화면 수는 신규 최상위 메뉴 수가 아니다. 과거 작업의 구조 수정 최대 1회·기능 보류·테스트 합격 수·완료 기록은 현재 요청의 제한이나 검증으로 가져오지 않는다. 원본 다운로드 누락을 캡처 대체로 처리하면 그 프레임의 원본 100% 반영 근거가 부족해질 수 있어 반환 시 원본 무결성을 먼저 확인한다.

## 최종 반영을 위한 조건

사용자가 반환한 디자인을 화면 ID·원본 버전·상태·행동·데이터·권한·토큰으로 추적한다. 누락 원본, 모바일 미정, 신규 API 미정, 가짜 활성 기능은 반영 전 설계를 완결한다. 이후 실제 제품 변경과 검증을 수행하고 원본 대응 결과를 보고한다. 현재 산출물은 디자인 의뢰 준비이며 새 구현 완료나 새로운 회귀 테스트 PASS가 아니다.
