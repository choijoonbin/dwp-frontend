# DWAI-ON 새 대화 / 내 대화 디자인 적용

## 범위와 정본

- 대상: `/dwaion/new`, `/dwaion/conversations`, 기존 대화 상세 진입.
- 참고: 사용자가 제공한 2026-09-04 Stitch 새 대화 스튜디오와 대화 보관함 스크린샷.
- 프로젝트: https://stitch.withgoogle.com/projects/13391261371843159731
- Stitch 웹 프로젝트의 상세 캔버스는 브라우저 로딩/연결 문제로 직접 읽지 못했다. 첨부된 두 화면과 기존 디자인 AI 브리프, 실제 API 계약을 기준으로 구현했다.
- 공통 DWP 셸, 기존 권한 판정, 일회성 질문 전달, Agent API는 유지했다. 다른 앱이나 서버 권한을 변경하지 않았다.

## 새 대화: 질문 스튜디오

사용자는 질문을 작성하고 검색 범위를 선택한 뒤 근거와 응답 상태를 확인한다.

- 2열 스튜디오: 인사 영역, 독립 질문 입력창, 4개 빠른 질문, 최근 업무 목록과 우측 검색 범위/업무 신호/검증 원칙.
- 기존 캐릭터 이미지 자산을 유지하되 질문 입력창을 감싸던 중첩 컨테이너와 반복 스캔 애니메이션을 제거했다.
- 업무 항목/메일/일정 선택과 실제 요청의 `sourceScopes`가 일치한다. 최소 1개 소스를 유지한다.
- 모바일에서도 입력창에서 검색 범위를 바로 선택할 수 있다. 우측 범위 패널은 좁은 화면에서 아래로 이동한다.
- 음성 입력은 전사문 검토 후 전송한다. 자동 전송하지 않는다. 기존 중단/재시도/근거 기반 대체 응답/출처 패널을 유지했다.
- 최근 업무는 공통 `rankWorkspaceWorkItems` 규칙을 소비하고 완료 업무를 제외한다. 열기는 공통 `workspaceWorkItemRoute`를 사용한다.
- 업무 조회 실패와 대화 접근 확인 실패를 빈 데이터로 표현하지 않는다. 확인되지 않은 대화에는 이어쓰기 입력창을 노출하지 않는다.
- 간이 대화 메뉴의 즉시 삭제를 제거했다. 대화 관리와 삭제 확인은 내 대화 화면으로 통일했다.

## 내 대화: 보관함

사용자는 최근 대화를 찾고 이어가며 필요하면 삭제한다.

- 제목 검색, 최근 24시간/7일/30일 필터, 최신순/오래된순/메시지 많은순 정렬.
- 대화 제목, 마지막 메시지 시각, 메시지 수와 이어가기 링크를 표시한다. 검색어를 URL에 넣지 않는다.
- 실데이터에서 계산한 대화 수/메시지 수/최근 7일 활동 대화 수/마지막 메시지 시각을 표시한다.
- API의 현재 기본 조회 범위인 최근 30개를 명시한다. 필터와 통계가 전체 보관함을 대표한다고 주장하지 않는다.
- 실패한 재조회에서는 이전 캐시 제목을 숨긴다. 재시도로 회복할 수 있다.
- 삭제는 대상 제목을 확인한 뒤 실행한다. 성공 시 목록/상세 캐시를 정합화한다. 409 보존 제한, 404 미존재, 일반 실패를 구분한다.
- 내 대화의 원문을 일괄 선조회하지 않는다. 목록용 요약이나 태그를 만들기 위한 N+1 상세 조회도 추가하지 않았다.

## 디자인 시스템과 정리

- 기존 토큰/테마, 공통 FormField/SelectField/ActionButton/ConfirmDialog/ErrorState/LoadingState를 사용한다.
- 새로운 스타일은 theme typography/shape/shadows/transitions를 사용한다. 다크 모드의 빠른 질문 아이콘도 semantic palette를 따른다.
- 카드에는 개별 대화/빠른 질문만 담고, 페이지 구역과 보조 정보는 중첩 카드로 감싸지 않는다.
- 감소 모션과 강제 색상 모드에서 주요 정보를 유지한다. 동작은 상태 변화와 사용자 조작에 한정한다.
- 삭제: `dwaion-conversation-menu.tsx`, 해당 전용 번역 키, 기존 IdleContext, 스캔/부유 keyframes, 중복 업무 정렬 구현.
- 책임 분리: studio-header/rail, archive-model/list/insights. 수정한 DWAI 제품 파일은 500줄 이하로 유지한다.

## 실제 서비스 확인

2026-09-04 로컬 4200의 기존 로그인 계정(박현우)으로 새 대화 진입, 오늘 업무 브리핑 요청, 대화 저장, 내 대화 1건/메시지 2건 표시를 확인했다. 이번 요청에서는 403을 재현하지 않았다. 다른 계정의 권한 문제가 모두 해소됐다는 의미는 아니다.

응답은 `근거 기반 대체 응답`이었다. AI 추론 연결이 정상이라는 주장을 하지 않으며, 모델 호출 없음/낮은 신뢰도/원본 근거 직접 정리를 화면에서 구분한다. 실제 대화를 삭제하거나 보존 정책을 변경하지 않았다.

## 별도 계약이 필요한 시안 요소

1. 전체 보관함 서버 검색/페이지네이션: 현재 목록은 최근 30개다. 본문 검색, 전체 개수, 커서 계약이 있어야 한다.
2. 일괄 내보내기: 원문 공개 범위, 감사, 다운로드 수명, DLP 및 보존 정책을 포함한 서버 명령 계약이 필요하다. 버튼만 추가하지 않았다.
3. 자동 요약/업무 토픽/소스별 태그: 권한으로 필터링된 목록 메타데이터 API가 필요하다.
4. 저장 용량/쿼터/법적 보존 활성 상태: 사용자에게 공개 가능한 서버 정본이 필요하다. 시안의 임의 수치나 활성 배지를 복제하지 않았다.
5. Live/모델 버전/AI 분석 진행률: 실제 모델 및 런타임 상태 계약이 제공될 때만 표시한다. 현재 추론 연결의 운영 점검은 디자인 적용과 별개다.
