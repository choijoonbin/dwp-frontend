# DWP 근무공간 홈 디자인 AI 전달 브리프

작성 기준: 2026-09-04 공유 작업 트리의 실제 구현.

이 문서는 DWP 전체 앱을 모아 보여주는 공통 홈이 아니라, **근무공간(Workplace) 앱의 첫 화면 `/workplace/home`**을 설명한다. 현재 동작과 데이터 의미를 보존하면서 시각적 완성도와 사용성을 높이기 위한 디자인 입력 문서다. 새로운 UI 시안 요청이며, 아래의 확장 아이디어를 이미 구현된 기능으로 간주해서는 안 된다.

## 1. 디자인 AI에게 전달할 핵심 요청

기업용 디지털 업무 플랫폼 DWP의 근무공간 앱 홈을 재디자인해 주세요. 이 화면의 주인공은 회사 전체 공간을 운영하는 관리자가 아니라, 오늘 출근하거나 회의에 참여하고 적합한 업무 공간을 찾으려는 구성원입니다.

사용자가 진입 후 짧은 시간 안에 다음 질문에 답할 수 있어야 합니다.

- 지금 체크인하거나 확인해야 하는 예약이 있는가?
- 오늘 어느 장소에서 어떤 일정으로 일하는가?
- 필요한 좌석이나 회의실 등 공간을 어디서 찾을 수 있는가?
- 이번 주 회의와 집중 시간이 어떻게 분포하는가?
- 놓치기 전에 처리해야 하는 항목은 무엇인가?

일반적인 관리자 대시보드, 회사 소개 페이지, 카드가 반복되는 포털로 만들지 마세요. **오늘의 행동과 시간·장소 맥락이 연결된 개인 근무 준비 화면**으로 설계해 주세요. 고급스러움은 큰 빈 공간, 과한 장식, 유리 효과보다 정보의 선명한 위계, 읽기 좋은 타이포그래피, 비교 가능한 시각화, 안정적인 인터랙션에서 나와야 합니다.

현재 사각형 구획과 반복적인 행·막대 표현은 그대로 따라 할 필요가 없습니다. 아래 콘텐츠와 행동 계약을 유지한다면 배치, 밀도, 컴포넌트 형식, 시각적 강조 방식은 재구성해도 됩니다.

## 2. 제품과 사용자 맥락

### 2.1 제품 정의

DWP는 회사별 테넌트를 지원하는 디지털 업무 플랫폼이다. 근무공간 앱은 여러 사업장과 건물·층에 등록된 업무 공간을 찾아 예약하고, 자신의 공간 예약과 회의 예약을 관리하는 앱이다.

회사 본사뿐 아니라 다른 오피스와 공유 근무장소를 수용하는 구조다. 단, 화면에는 해당 테넌트에 실제 등록되어 있고 사용자가 접근 가능한 정보만 표시한다.

앱에서 다루는 자원 유형은 다음과 같다. 모든 회사에 모든 유형이 등록되어 있는 것은 아니다.

| 자원        | 의미                                     |
| ----------- | ---------------------------------------- |
| 좌석        | 구성원의 개인 업무용 자리                |
| 포커스 부스 | 집중 업무를 위한 분리된 공간             |
| 폰 부스     | 통화·짧은 온라인 대화 등에 사용하는 공간 |
| 회의실      | 회의 일정과 연결되는 공유 공간           |
| 사물함      | 개인 물품 보관 자원                      |
| 주차 공간   | 예약 대상으로 등록된 주차 자원           |
| 공용 장비   | 예약 대상으로 등록된 업무 장비           |

### 2.2 주 사용자와 화면 유형

- 주 사용자: 일반 구성원, 이동 근무자, 회의 주최자.
- 보조 사용자: 조회만 가능한 구성원, 공간 관리 권한을 가진 운영자.
- 핵심 질문: “오늘 어디서 무엇을 하고, 지금 무엇부터 처리해야 하는가?”
- 주요 행동: 체크인, 다음 일정 열기, 공간 찾기, 내 예약 확인.
- 화면 유형: 개인 업무 중심의 커맨드 센터. 관리자용 통계 대시보드가 아니다.
- 관리자에게도 이 홈은 개인 근무 경험이다. 전체 공간 운영 지표와 정책 편집은 별도 관리 화면에 둔다.

## 3. 앱 내 위치와 주변 메뉴

홈에서 근무공간 앱을 실행하면 `/workplace/home`이 첫 화면이다. 공간 찾기를 앱의 기본 화면으로 되돌리지 않는다.

현재 구성원 메뉴와 목적:

| 메뉴              | 경로                     | 목적                                                           |
| ----------------- | ------------------------ | -------------------------------------------------------------- |
| 근무 공간 홈      | `/workplace/home`        | 오늘의 행동·일정·공간 현황·주간 흐름 요약                      |
| 공간 찾기 및 예약 | `/workplace/explore`     | 사업장·층·시간·유형을 선택하여 공간 탐색과 예약 진행           |
| 회의실 시간표     | `/workplace/rooms`       | 회의실의 시간대별 가용성을 확인하고 예약 진행                  |
| 개인 공간 예약    | `/workplace/my-bookings` | 자신의 좌석 등 공간 예약과 허용된 체크인·취소·반납·이동 관리   |
| 회의 예약 관리    | `/workplace/my-meetings` | 자신의 접근 가능한 회의 예약 확인과 허용된 편집·취소·참석 응답 |

관리 메뉴는 권한에 따라 별도로 제공된다: 운영 현황, 예약 운영·감사, 공간 거버넌스, 사업장 및 배치도, 공간 예약 정책, 회의 승인 운영, 회의 예약 정책.

공통 앱 셸의 브랜드·앱 이름·내비게이션 접기·검색·알림·계정 및 DWAI·ON 진입 영역과 공존해야 한다. 홈 본문에 같은 전역 도구를 다시 만들지 않는다. 모바일에서는 접힌 내비게이션과 보조 도구가 주요 행동을 가리지 않아야 한다.

## 4. 현재 홈의 콘텐츠 구조

현재 실제 구성 순서는 다음과 같다.

1. 페이지 제목과 정보 갱신 상태.
2. 가장 중요한 다음 행동과 공간 맥락 요약.
3. 오늘의 흐름과 선택한 층의 자원 유형별 공간 현황.
4. 이번 주 근무 리듬.
5. 확인하면 좋은 항목.

넓은 화면에서는 오늘의 흐름과 공간 현황을 좌우로 보여주고, 주간 리듬과 확인 항목은 아래 전체 폭으로 표시한다. 작은 화면에서는 세로로 쌓인다. 이는 현행 구현 설명이지, 새 시안이 그대로 지켜야 하는 고정 레이아웃은 아니다.

### 4.1 페이지 제목과 정보 갱신 상태

현재 문구:

- 상위 문맥: “오늘의 근무 공간”.
- 제목: “오늘의 근무 흐름을 준비하세요”.
- 설명: 다음 일정, 체크인, 향후 60분 공간 정보를 연결한다는 내용.
- 상태: 근무 공간 정보 / 최종 검증 시각 / 일부 정보 확인 필요 / 마지막 검증 정보.
- 행동: 새로고침.

설계 요구:

- 이 화면이 근무공간 홈이라는 정체성을 보여주되 긴 사용 설명이 첫 화면을 차지하지 않게 한다.
- 갱신 상태는 작지만 읽을 수 있어야 한다. 정상 상태를 거대한 KPI처럼 강조하지 않는다.
- 자동 갱신은 약 60초 간격이며 시간 경계에서도 재확인한다. 센서 기반 실시간 스트리밍을 의미하지 않는다.
- “방금 확인”과 “이전 확인 정보”를 구분한다. 일부 정보 실패를 초록색 정상 표시로 덮지 않는다.
- 사용자별 개인 정보를 합친 화면이므로 회사 전체 수치를 암시하지 않는다.

### 4.2 가장 중요한 다음 행동

이 영역은 고정된 환영 문구나 광고 배너가 아니라 현재 사용자 상태에 따라 내용과 버튼이 달라지는 핵심 영역이다. 한 번에 하나의 주요 행동을 강조한다.

| 상황                                     | 표시할 핵심 정보                           | 현재 행동                                        |
| ---------------------------------------- | ------------------------------------------ | ------------------------------------------------ |
| 체크인 가능한 예약 있음                  | 자원명, 사업장·층, 체크인 마감 시각        | “지금 체크인”; 조회 전용이면 “예약 보기”         |
| 다음 또는 진행 중 일정 있음              | 일정 제목, 시작 시각, 장소                 | 해당 일정 또는 예약 상세로 이동                  |
| 예약 사전 확인 통과 자원 있음            | 선택 층, 확인 시간 범위, 사전 확인 통과 수 | 공간 찾기로 이동                                 |
| 물리적 공석은 있으나 사전 확인 통과 없음 | 비어 있는 공간 수와 조회 맥락              | 공간 현황 조회로 이동; 즉시 예약을 보장하지 않음 |
| 접근 가능한 사업장 없음                  | 사업장 구성 또는 접근 권한 확인 안내       | 관리 권한이 있는 사용자에게만 구성 버튼          |
| 사업장은 있으나 활성 층 없음             | 층 구성 또는 접근 권한 확인 안내           | 관리 권한이 있는 사용자에게만 층 구성 버튼       |
| 층에 등록 자원 없음                      | 공간 등록 필요 안내                        | 관리 권한이 있는 사용자에게만 공간 추가 버튼     |
| 즉시 처리할 항목 없음                    | 차분한 정상 상태                           | 필요할 때 공간 찾기                              |
| 최신 정보를 확인할 수 없음               | 확인되지 않은 정보라는 안내                | 최신 정보 확인 / 재시도                          |

현재 선택 순서는 체크인 → 오늘의 아직 끝나지 않은 첫 일정 → 사업장·층·자원 설정 확인 → 사전 확인 통과 공간 → 공석 조회 → 즉시 행동 없음이다. 데이터의 완결성과 권한에 따라 실제 문구와 행동은 다시 제한된다.

체크인 영역에서 필요한 데이터:

- 자원명. 예: “집중 좌석 D-1208”.
- 위치. 예: “판교 본사 · 12층”.
- 체크인 마감. 단순 시각보다 의미가 명확한 마감 표현을 권장한다.
- 주요 버튼, 처리 중 상태, 성공 또는 실패 피드백.
- 체크인 불가 이유와 예약 보기 대체 행동.

다음 일정 영역에서 필요한 데이터:

- 일정 또는 자원의 실제 이름.
- 일정 시작 시각. 종료 시각도 모델에 있으며 새 시안에서 시간 구간을 표현하는 데 활용할 수 있다.
- 장소 또는 일정 종류.
- 원래 일정·예약으로 이동하는 버튼.

현재 홈에서 실제 예약 상태를 바꾸는 직접 명령은 체크인이다. 새 예약 완료, 반납, 취소, 회의 편집은 각각의 원래 화면으로 이동하여 처리한다. 모든 기능을 홈의 즉시 실행 버튼으로 표현하면 현재 기능 범위를 넘어선다.

### 4.3 공간 기준과 확인 범위

상단 핵심 행동 아래에는 다음 맥락 정보가 있다.

| 필드               | 실제 의미                                                                    |
| ------------------ | ---------------------------------------------------------------------------- |
| 공간 기준          | 현재 응답에서 선택된 사업장과 층                                             |
| 확인 범위          | 한 번 검증한 시작 시각부터 60분 구간                                         |
| 물리적 공석        | 해당 구간의 점유 정보와 자원 상태 기준으로 비어 있는 자원 수                 |
| 예약 1차 확인 통과 | 현재 권한·상태·알려진 정책 조건에 대한 클라이언트 사전 검사를 통과한 자원 수 |

중요한 표현 규칙:

- 현재 홈의 숫자는 **선택한 한 층** 기준이다. 전사·모든 사업장·건물 전체의 공석으로 표기하지 않는다.
- “물리적 공석”은 센서가 사람이 없음을 증명했다는 뜻이 아니다. 예약 점유와 시스템 자원 상태에 기반한 값이다.
- 비어 있어도 타인의 고정 좌석, 권한 제한, 정책 제한, 연결 미완료 회의실 등은 예약할 수 없을 수 있다.
- “예약 1차 확인 통과”도 최종 예약 성공 보장이 아니다. 실제 예약 서버가 충돌과 정책을 다시 검사한다.
- 원한다면 사용자 친화적 명칭으로 바꿀 수 있지만, “공석”과 “최종 예약 확정”을 같은 의미로 합치면 안 된다.
- 현재 홈에는 사업장·층·기간을 직접 편집하는 필터가 없다. 공간 찾기 화면에서 변경한다.
- 시작 시각은 요청 시 다음 분 경계로 정규화하고 정확한 60분을 사용한다. 예: 09:20:38에 조회하면 09:21–10:21.
- 홈에서 공간 찾기를 열면 검증된 사업장·층·날짜·시각·기간·선택 자원 유형을 전달한다. 클릭 후 전혀 다른 조건이 보이는 디자인을 만들지 않는다.

추천 시각 방향: 별도 KPI 박스 네 개보다 위치·시간 문맥과 간단한 상태 요약으로 자연스럽게 연결한다. 실제 범위 “판교 본사 · 12층 / 09:21–10:21”를 짧게 보여주면 추상적인 숫자보다 이해하기 쉽다. 이는 기존 데이터를 활용한 표현 개선안이다.

### 4.4 오늘의 흐름

오늘의 개인 일정과 공간 예약을 시작 시각 순서로 모아 보여주는 목록이다. 일정 종류는 다음과 같다.

- 근무 공간 예약.
- 회의.
- 집중 시간.
- 캘린더의 할 일.
- 캘린더의 외부 근무 일정.
- 캘린더의 알림 일정.

위의 할 일과 외부 근무는 캘린더 일정 유형이다. 별도 업무 앱의 전체 할 일이나 HCM의 근태·재택 상태를 모두 조회한다는 뜻이 아니다.

행마다 현재 표시하는 정보는 시작 시각, 종류 아이콘, 제목, 위치 또는 종류 설명, 상세 이동 표시다. 모델에는 시작·종료 시각이 모두 있다. 같은 회의가 캘린더와 회의 예약에서 동시에 들어오면 중복을 제거한다.

현재 홈은 최대 6개 항목을 표시한다. “공간 예약 보기”는 개인 공간 예약 화면으로 이동하며, 모든 캘린더 일정을 통합 편집하는 버튼이 아니다.

| 선택한 항목               | 이동 대상                                    |
| ------------------------- | -------------------------------------------- |
| 개인 공간 예약            | `/workplace/my-bookings?booking={bookingId}` |
| 회의 예약에서 제공된 회의 | `/workplace/my-meetings?event={eventId}`     |
| 캘린더에서 제공된 일정    | `/calendar/schedule?event={eventId}`         |

디자인 요구:

- 시간·장소·종류를 빠르게 훑을 수 있게 한다. 좌석 예약과 회의가 같은 카드처럼 읽히지 않게 한다.
- 타임라인 표현은 가능하지만 가상의 이동 시간, 자동 계산된 업무 동선, 충돌 없는 시간표를 만들어내지 않는다.
- “진행 중/다음”을 시각적으로 구분하는 제안은 가능하다. 해당 시각은 실제 일정에서 파생해야 한다.
- 빈 상태와 조회 실패를 구분한다. “등록된 일정 없음”은 필요한 소스를 모두 확인한 경우에만 사용한다.
- 긴 회의명과 장소명은 줄바꿈 또는 접근 가능한 상세 확인을 제공한다.

### 4.5 선택한 층의 공간 현황

공간 현황은 개별 추천 좌석의 사진 목록이 아니라 **자원 유형별 요약**이다. 등록된 유형만 표시한다.

유형별 데이터:

- 유형 이름과 아이콘.
- 전체 표시 대상 자원 수.
- 물리적으로 비어 있는 자원 수.
- 예약 1차 확인 통과 수.
- 접근성 지원 특성이 있으며 사전 확인을 통과한 자원 수.
- 해당 유형으로 공간 찾기 화면을 여는 링크.

현재 표시 순서는 좌석 → 포커스 부스 → 폰 부스 → 회의실 → 사물함 → 주차 공간 → 공용 장비다. 데이터가 없는 유형을 가상의 0개 카드로 채우지 않는다.

“접근성 지원”은 자원 데이터의 접근성 속성이다. 사용자에게 해당 공간의 이용 권한이 있다는 의미와 혼동하지 않는다. 현행 해당 수치는 접근성 속성과 예약 사전 확인을 함께 만족하는 자원만 센다.

디자인 요구:

- 자원 유형별 가용 비율과 숫자를 읽을 수 있어야 한다.
- 막대를 사용한다면 분모는 그 유형의 전체 자원 수다. 주간 회의 시간 막대와 다른 의미임을 명확히 한다.
- 공석과 예약 사전 확인 결과를 하나의 초록색 “예약 가능” 배지로 합치지 않는다.
- 재검증 실패 상태에서는 마지막 값을 확정 정보처럼 사용하지 않고 재확인 동작을 제공한다.
- 현재 홈은 배치도를 렌더링하지 않는다. 배치도는 공간 찾기 경험에 있다. 모델에 배치도 경로가 있다는 이유만으로 홈에 완성된 지도 기능이 있다고 해석하지 않는다.

### 4.6 이번 주 근무 리듬

현재 주의 월요일부터 금요일까지, 일정의 회의·집중 시간과 실제 공간 예약을 함께 보여준다. 월간 캘린더나 주간 예약 편집기가 아니라 요약 시각화다.

각 요일에 실제로 제공되는 데이터:

- 날짜와 요일.
- 오늘 여부.
- 회의 시간 합계, 단위 분.
- 집중 시간 합계, 단위 분.
- 공간 예약 건수. 개인 공간 예약과 회의 예약의 유효한 항목을 합산한다.
- 예약이 있는 사업장 이름, 현재 최대 두 개.

데이터 해석 주의:

- 회의·집중 시간은 캘린더의 주간 집계다. 공간 점유 센서나 근태 실적이 아니다.
- 공간 예약 건수는 출근 인원·출근 일수·좌석 수가 아니다.
- 사업장 이름은 예약 장소다. 그 장소에 실제로 도착했다는 증거가 아니다.
- 회의·집중 막대의 현재 기준은 주간 최대 값과 최소 60분 기준의 비교 스케일이다. 8시간 근무 대비 생산성·가동률·업무 과부하 퍼센트가 아니다.
- 모델에 `loadPercent`가 있지만 현재 이 주간 컴포넌트에서 표시하지 않는다. 검증 없이 임의의 생산성 점수로 바꾸지 않는다.
- 요일 셀의 클릭, 드래그 일정 이동, 주 변경, 근무장소 선택은 현재 없다. 추가한다면 새 인터랙션으로 별도 표시한다.
- 캘린더 권한이 없거나 응답이 일부만 들어온 경우, 실제로 확인하지 못한 전체 활동을 “0” 또는 “완전히 비어 있음”으로 단정하지 않는다.

디자인 요구:

- 5개의 칸에 작은 막대만 붙이는 대신, 날짜·현재 날짜·회의와 집중의 대비·예약·위치를 직관적으로 묶는다.
- 회의와 집중은 색상 외에 라벨·아이콘·수치로도 구분한다.
- 비교 기준은 같은 주의 모든 요일에 일관되게 적용한다.
- 모바일에서는 5열을 억지로 줄이지 않는다. 세로 일별 행 등으로 가독성을 유지한다.
- 한 주 전체에 활동이 없으면 동일한 “없음”을 다섯 번 반복하는 대신 하나의 간결한 빈 상태를 사용할 수 있다.
- 부분 응답일 때는 “확인된 활동만 표시”를 한 번 명확히 안내하고 정상 빈 주간으로 확정하지 않는다.

### 4.7 확인하면 좋은 항목

이 영역은 일반 공지나 AI가 생성한 조언이 아니다. 실제 예약·일정에서 사용자가 처리할 수 있는 후속 항목을 최대 5개 보여준다.

| 종류             | 표시 이유                                                            | 현재 클릭 결과               |
| ---------------- | -------------------------------------------------------------------- | ---------------------------- |
| 체크인           | 체크인 가능한 예약                                                   | 해당 개인 공간 예약으로 이동 |
| 공간 반납        | 현재 이용 중이며 반납 가능한 예약                                    | 해당 개인 공간 예약으로 이동 |
| 회의실 필요      | 편집 가능한 미래 회의에 오프라인 장소·회의실·온라인 회의 링크가 없음 | 해당 캘린더 일정으로 이동    |
| 캘린더 확인 항목 | Calendar가 제공한 중요도·제목·설명·대상                              | 원래 캘린더 동작으로 이동    |

현재 정렬은 높은 중요도 우선, 같은 중요도에서는 관련 시각이 빠른 순서다. 체크인은 높은 중요도, 회의실 필요는 중간, 반납 제안은 낮은 중요도를 가진다.

회의실 필요 항목의 제한:

- 아직 시작되지 않은 회의만 대상이다.
- 사용자가 상세를 볼 수 있고 편집할 수 있는 회의여야 한다.
- 종일 일정, 참석 거절한 일정, 마스킹된 일정, 조회 전용 일정은 제외한다.
- 온라인 회의 URL이 있으면 단순히 회의실이 없다는 이유로 경고하지 않는다.

반납 제안은 “예약하지 말았어야 했다”거나 “사용자가 자리를 비웠다”는 의미가 아니다. 실제 센서 기반 미사용 탐지처럼 표현하지 않는다.

디자인 요구:

- 긴급 체크인과 선택적인 공간 반납을 같은 강도로 경고하지 않는다.
- 정상 상태는 짧게, 조치가 필요한 예외는 명확하게 표현한다.
- 큰 경고 카드가 홈 전체를 압도하지 않게 한다.
- 상단 주요 행동과 중복되는 항목은 위계를 정리할 수 있지만 중요한 작업을 숨기지 않는다.
- 항목이 없다는 정상 상태와 확인할 수 없다는 장애 상태를 다르게 디자인한다.

## 5. 반드시 함께 디자인할 상태

정상 데이터가 많은 화면 하나만으로 완료하지 않는다.

| 상태                              | 필요한 표현과 동작                                              |
| --------------------------------- | --------------------------------------------------------------- |
| 최초 로딩                         | 최종 구조와 유사한 스켈레톤; 빈 데이터로 오해하지 않게 함       |
| 정상·행동 있음                    | 현재 최우선 행동이 첫 화면에서 읽힘                             |
| 정상·행동 없음                    | 차분한 빈 상태와 공간 탐색 경로; 거대한 0 KPI 반복 금지         |
| 데이터 일부 실패                  | 확인된 정보와 확인 불가 영역 구분; 전체가 정상이라는 문구 금지  |
| 이전 데이터만 있음                | 마지막 확인 정보임을 표시; 최신 권위가 필요한 직접 명령은 닫음  |
| 권한 회수·계정 변경               | 이전 사용자·이전 권한의 보호 정보를 계속 노출하지 않음          |
| 체크인 처리 중                    | 중복 클릭 방지와 처리 중 표시                                   |
| 체크인 성공·실패                  | 명확한 피드백과 현재 정보 재조회; 실패를 성공처럼 표시하지 않음 |
| 예약 종료 경계                    | 체크인·반납 가능 상태를 즉시 종료 상태로 전환                   |
| 조회 전용 권한                    | 실행 버튼 대신 조회 경로 또는 이유; 관리자처럼 보이지 않게 함   |
| 사업장 없음 / 층 없음 / 자원 없음 | 원인이 다른 설정 상태를 구분; 관리자만 설정 CTA 제공            |
| 좁은 화면·큰 글자·긴 이름         | 주요 행동과 장소·시간 정보가 잘리거나 겹치지 않음               |

입력과 권한이 검증되기 전에 활성 버튼을 보여주는 시안은 피한다. 재시도 후 복구된 경우에만 다시 활성화할 수 있다. 상태 전환은 스크린리더에 전달하되 자동 새로고침마다 과도한 안내와 포커스 이동을 발생시키지 않는다.

## 6. 다른 앱과의 실제 연결 범위

현재 홈은 프론트에서 여러 API 결과를 조합한다. 모든 소스가 동시에 확정된 하나의 서버 통합 홈 응답이나 센서 스트림은 아니다.

| 소스                       | 홈에서 사용하는 내용                                  | 쓰기 책임                                    |
| -------------------------- | ----------------------------------------------------- | -------------------------------------------- |
| Workplace                  | 접근 가능한 사업장·층, 자원·점유·정책, 개인 공간 예약 | 공간 예약과 체크인 등 Workplace 명령         |
| Rooms / Calendar 자원 예약 | 회의 예약과 회의실 정책                               | 회의실 예약 생성·수정·취소 및 회의 정책 검사 |
| Calendar                   | 오늘 일정, 주간 회의·집중 집계, 확인 항목             | 원래 캘린더 일정 처리                        |
| 공통 인증·권한             | 계정, 테넌트, 앱 조회·실행·관리 권한                  | 허용된 기능만 노출                           |

현재 홈에는 메일 목록, 회사 뉴스, 시설 서비스 요청 현황, 팀원 실시간 위치를 본문 콘텐츠로 결합하지 않는다. 공통 셸의 알림 아이콘과 AI 진입 도구가 있다고 해서 해당 서비스가 이 홈의 추천·점유·일정 데이터를 생성하는 것은 아니다.

대표 조회: `/api/platform/v1/workplace/explore`, `/workplace/bookings`, `/rooms/bookings`, `/rooms/policy`, `/calendar/home`. 앞의 축약 경로들은 모두 `/api/platform/v1` 아래다. 기술 경로는 UI 문구로 노출하지 않는다.

| 9/9 수 · 오늘 |  90분 | 180분 |       2건 | 판교 본사     |
| 9/10 목       |  60분 | 240분 |       1건 | 판교 본사     |
| 9/11 금       | 120분 | 120분 |       0건 | 표시하지 않음 |

금요일에 공간 예약이 없다고 재택근무로 표시하면 안 된다. 근무 계획은 현재 별도 데이터가 없다.

### 7.3 반드시 추가할 변형 시안

- 체크인 완료: 직접 체크인 버튼이 사라지고 현재 상태에 맞는 다음 행동 표시.
- 일정만 있고 공간 예약 없음: 다음 일정과 공간 탐색이 중심.
- 조회 전용: 공석은 보이지만 즉시 예약·체크인으로 오해하지 않는 버튼 구성.
- Calendar 부분 장애: 확인된 예약은 보존하되 오늘·이번 주 전체가 비었다고 확정하지 않음.
- 사업장 없음: 구성원에게는 안내, 관리자에게만 설정 진입.
- 모바일: 동일 데이터를 390px와 320px에 재배치.

## 8. 권장 디자인 개선 방향

아래는 현재 데이터로 구현 가능한 표현 개선 제안이다. 현재 화면 모양을 그대로 재현하지 말고 이 방향을 탐색한다.

1. **행동 우선의 첫 화면.** 반복되는 제목·설명을 줄이고, 현재 필요한 행동·마감·장소를 하나의 시각적 중심으로 만든다.
2. **자연스러운 공간 맥락.** 사업장·층·시간 범위를 문맥으로 연결하고, 이를 별도의 통계 카드 군으로 만들지 않는다.
3. **시간과 장소의 연결.** 오늘 일정은 읽기 좋은 시간축 또는 일정 스트립으로 비교한다. 장소가 달라지거나 일정 유형이 바뀌는 지점을 인식하기 쉽게 한다.
4. **주간 비교의 가독성.** 회의와 집중의 분포, 오늘, 예약 위치가 한눈에 읽히게 한다. 5개 동일한 빈 사각형이나 매우 작은 막대에 의존하지 않는다.
5. **예외는 강하게, 정상은 간결하게.** 마감 임박 체크인과 선택적인 반납 제안의 시각적 강도를 구분한다.
6. **공간 앱다운 표현.** 검증된 장소 이름·층·자원 유형과 일정을 중심 소재로 사용한다. 별 의미 없는 stock 사무실 사진으로 공간 정보를 대체하지 않는다.
7. **업무에 맞는 밀도.** 여백은 그룹 간 위계를 만드는 데 사용한다. 한 화면이 긴 설명·큰 빈 패널 때문에 주요 행동 없이 끝나지 않게 한다.

스타일 가이드:

- 단정하고 현대적이며 빠르게 읽히는 기업용 도구. 지나치게 딱딱한 관리 콘솔이나 과장된 소비자 앱 모두 피한다.
- 중립 배경 위에 행동·시간·상태에 의미 있는 색을 사용한다. 모든 영역을 같은 청색이나 회색으로 구분하지 않는다.
- 카드 안에 카드, 거대한 테두리 박스 반복, 상단의 인위적인 좌우 칸막이, 장식용 그라디언트·광원·유리 패널은 피한다.
- 의미 있는 종류 아이콘, 버튼 아이콘, 명확한 텍스트 계층을 사용한다. 구현 기준 아이콘은 Lucide다.
- 숫자는 비교 단위와 범위와 함께 보여준다. 막대와 수치를 중복해 보여주더라도 의미가 선명해야 한다.
- 현재 콘텐츠가 요약형이라는 이유로 읽기 어려운 작은 글자를 사용하지 않는다.
- 환영 배너보다 실제 개인 예약·일정·다음 행동이 첫 화면에 보여야 한다.

## 9. 현재 구현으로 간주하면 안 되는 확장 아이디어

다음은 별도 개발·계약·정책이 필요한 제안이다. 기본 시안에 필수 기능처럼 넣지 말고, 필요하면 “확장안” 페이지로 분리한다.

| 아이디어                             | 추가로 필요한 것                                               |
| ------------------------------------ | -------------------------------------------------------------- |
| 출근·재택·공유오피스 주간 계획 편집  | 근무 계획 데이터와 저장 API, 개인 설정 정책                    |
| 동료의 현재 위치·동료 근처 자리 추천 | 회사 정책과 개인 공개 동의, 위치 정보 목적·보존 정책           |
| 홈에서 2D/3D 공간 지도 직접 선택     | 홈 지도 컴포넌트 통합, 등록 도면·배치 데이터, 권한·리비전 처리 |
| 공간 사진 중심 추천                  | 실제 공간별 미디어 자산, 추천 근거·선호·정렬 계약              |
| 홈에서 날짜·사업장·층 즉시 변경      | 선택 상태·URL·재조회와 모든 섹션 범위의 정합                   |
| 주간 셀 클릭·일정 드래그 편집        | 날짜별 상세 이동 또는 Calendar 편집 권한·충돌 검증             |
| AI 자동 좌석 배정·주간 최적화        | 사용자 승인, 근거, 취소·감사, 실제 추천/명령 API               |
| 시설 고장·서비스 요청 추적           | Services와 공간 ID 기반 연결 및 해당 접근 권한                 |
| 실제 실내 점유·혼잡도·도착 감지      | 센서 연계·신선도·개인정보·정확도 계약                          |
| 홈 위젯 추가·제거·재배치             | 근무공간 홈 전용 개인화 계약; 현재 공통 홈 편집 기능과 별개    |

팀 근무 위치, 시설 서비스, 공지 등의 새 콘텐츠로 빈 공간을 채우는 것은 데이터 계약이 없는 상태에서는 허용하지 않는다. 현재 데이터로 충분히 완결된 기본 시안을 먼저 만들고 확장 방향을 별도로 제안한다.

## 10. 반응형·접근성·상태 전환 요구

- 데스크톱 1440px와 1280px, 모바일 390px와 320px 시안을 제공한다. 태블릿 768px의 변형 규칙도 명시한다.
- 첫 화면에 화면 목적과 실제 주요 행동이 보여야 한다. 큰 제목만 보이고 버튼이 화면 아래로 밀리지 않게 한다.
- 모바일에서는 중요도 순서가 유지되는 단일 열을 우선한다. 긴 제목과 장소는 안전하게 줄바꿈한다.
- 200% 텍스트 확대 시 정보 손실·수평 페이지 스크롤·버튼 겹침이 없어야 한다.
- 밝은 테마, 어두운 테마, 고대비와 색각 차이를 고려한다.
- 색상만으로 회의·집중·경고·현재 날짜를 구분하지 않는다.
- 키보드 포커스, 링크와 버튼의 차이, 터치 영역을 명확히 한다. 중요한 조작은 약 44px 이상의 터치 영역을 권장한다.
- 숫자·차트에는 텍스트 요약이 필요하다. 날짜·회의 분·집중 분·예약 수를 스크린리더로 읽을 수 있어야 한다.
- 새로고침과 데이터 도착으로 레이아웃이 갑자기 바뀌지 않게 한다. 움직임 감소 설정을 존중한다.
- 체크인 처리 중·성공·실패·권한 소멸·예약 종료 상태를 각각 정의한다.
- 실사용 문구는 한국어를 기본으로 하고, 긴 한국어·영문을 모두 수용한다.

## 11. 디자인 AI에게 요청할 결과물

1. 현재 사각형 위주의 구성과 다른, 일관된 정보구조를 가진 주력 시안 한 개.
2. 정상 출근일 데스크톱 1440px 화면과 1280px 변형.
3. 390px 및 320px 모바일 화면과 768px 배치 규칙.
4. 주요 행동 영역, 오늘 일정, 자원 현황, 주간 리듬, 확인 항목의 컴포넌트 상세.
5. 체크인 우선·다음 일정 우선·일정 없음·사업장 없음·조회 전용·부분 장애·전체 오류 상태.
6. 주요 버튼과 항목 클릭 후 실제 도착 화면을 명시한 인터랙션 흐름.
7. 밝은/어두운 테마, 강조색·타이포그래피·간격·포커스·모션 원칙.
8. 각 요소를 “현재 데이터로 구현 가능 / 표시 방식 개선 / 추가 API 필요”로 구분한 표.
9. 화면에 들어간 모든 숫자·차트·추천의 데이터 의미 설명. 장식용 수치 금지.
10. 채택하지 않은 대안과 이유. 특히 카드 반복, 가짜 실시간 상태, 확인되지 않은 동료 위치를 제외한 이유.

## 12. 수용 기준

- 사용자가 5초 안에 다음 행동과 관련 시간·장소를 찾을 수 있는가?
- 공간 수의 사업장·층·기간이 명확한가?
- 공석과 최종 예약 확정을 혼동시키지 않는가?
- 체크인 직접 명령과 상세 화면 이동을 구분하는가?
- 오늘 흐름과 주간 리듬이 중복된 큰 카드처럼 보이지 않는가?
- 주간 회의·집중 정보를 읽고 요일 간 비교할 수 있는가?
- 정상 empty와 정보 미확인을 다르게 표현하는가?
- 구성원과 관리자, 조회 권한과 실행 권한이 섞이지 않는가?
- 모바일 첫 화면에서도 중요한 행동이 분명한가?
- 구현되지 않은 기능을 이미 존재하는 것처럼 넣지 않았는가?
