# 새 대화·내 대화 좌우 여백 보정 검증 · 2026-09-08

## 원인과 수정

공통 `PageCanvas`의 운영 화면 정책은 가용 너비 전체와 반응형 공통 거터를 사용한다. `/dwaion/new`와 `/dwaion/conversations`의 첫 번째 자식에만 `maxWidth: 1480`과 자동 좌우 마진이 추가되어 1920px 이상에서 다른 메뉴보다 안쪽으로 좁아졌다.

두 화면의 별도 최대 너비와 자동 마진을 제거하고 `minWidth: 0`만 유지했다. 이제 콘텐츠 시작점과 끝점은 공통 `PageCanvas`의 좌우 패딩에 맞으며, 긴 콘텐츠의 축소와 모바일 재배치는 유지된다.

## 최종 검증

| 범위                                       | 결과                     |
| ------------------------------------------ | ------------------------ |
| 변경한 제품·E2E 파일 Prettier / ESLint     | 통과                     |
| 변경한 제품 진입 파일 격리 TypeScript 검사 | 통과                     |
| `PageCanvas` 운영·집중 모드 단위 계약      | 2/2 통과                 |
| 1920px 공통 workspace 폭 계약              | 새 대화·내 대화 2/2 통과 |
| 대화 디자인 전체 E2E                       | 23/23 통과               |
| 대화 제어·정규 경로·선택 업무 회귀 E2E     | 31/31 통과               |

최종 디자인 E2E는 2560, 1920, 1440, 1280, 390, 320px와 640px에서 200% 글자 확대를 검사한다. 두 화면 모두 실제 루트 경계와 공통 캔버스의 계산된 콘텐츠 경계 차이가 좌우 각각 1.5px 이내인지 확인한다. 다크 모드, 강제 색상, 모션 감소, 한국어·영어, axe 심각·치명 접근성 위반, 가로 문서 넘침도 함께 검사했다.

검색·기간 필터·정렬·대화 이어가기·이름 변경·삭제 확인·보존 정책 충돌·접근 실패·재시도와 새 질문 응답 흐름까지 같은 변경본에서 통과했다. 최종 캡처는 `final-conversation-design`, 정확한 1920px 폭 증거는 `width-contract`, 기능 회귀 캡처는 `conversation-regression` 폴더에 있다.

초기 전체 작업 트리 TypeScript 검사는 당시 병행 중이던 Work 파일 3건의 오류로 종료됐고,
DWAI·ON 진입 파일과 의존 그래프는 별도 검사에서 먼저 통과했다. 병행 변경이 정리된 뒤 현재
작업 트리 전체 non-incremental TypeScript 검사를 다시 실행해 통과했다. 최신 1920px 수치·캡처와
전체 완료 검증은 [Live 35 최신 완료 검증](../../2026-09-09/live-35-completion/verification.md)에
보존한다.
