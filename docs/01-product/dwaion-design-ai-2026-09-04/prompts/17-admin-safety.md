# A05 · 정책 및 안전 제어

DWP DWAI·ON의 권한 있는 관리자 화면을 설계하라. 공통 00-common-design-contract.md와 확정한 사용자 홈 디자인 체계를 유지하되 관리 작업에 맞는 정보 밀도를 사용한다. 사용자 메뉴와 별도 관리 표면이며, 관리 권한이 개인 대화 원문 열람 권한을 뜻하지 않는다.
앱 코드는 아직 만들지 않는다. 데이터·명령이 있는 현행 기능과 신규 계약을 주석으로 구분한다. 장식 글로우/오로라, 카드 안 카드, 허구의 Live·정확도·가용률은 금지한다. 예시 값은 가상 데이터다.

## 목적과 현재

사용자: 안전 정책 담당자. 질문: “어떤 요청을 차단하고 어떤 요청을 검토로 넘길까?” 주 행동: 영향 확인 후 정책 저장. Archetype: policy editor.
경로 /dwaion/admin/safety. 특권 데이터·변경 요청의 HANDOFF/DENY, 소스 범위 수, 도구 호출 설정. 주입 차단·근거 필수·공개 웹 차단은 현재 화면에서 고정된 원칙이다.

## 설계

1. 고정 원칙과 수정 가능한 정책을 시각적으로 구분한다. 보안 원칙을 장식 스위치로 만들지 않는다.
2. 요청 종류별 처리 방식, 소스 수/도구 호출 설정을 익숙한 select/stepper로 제공.
3. 각 항목은 운영 의미와 적용 버전, 변경 사유. 저장 후 현재 서버 값으로 확인.
4. 영향 예시는 민감정보 없는 가상 요청으로 제시한다. 실제 직원 질문을 사례 갤러리로 노출하지 않는다.
5. 저장된 설정과 실행 중 실제 강제는 다르다. 실제 연결 증거가 없는 도구 예산/allowlist를 “강제 보장”으로 표현하지 않는다.
6. 정책 시뮬레이션, 변경 영향 비교, 별도 승인 흐름은 신규 계약 프레임. 시험 결과는 운영 승인과 구분한다.

## 위험 상태

변경 없음, 사유 부족, 값 범위 오류, 저장 실패, 다른 담당자가 변경함, 런타임 적용 상태 미확인.
가상 정책: 특권 데이터 질문은 권한 있는 원본 업무로 인계. 거부와 인계가 같은 빨간 오류로 표현되지 않아야 한다.

## 반환물

1440px 정상, 390px 주요 관리 흐름, 위험 상태 최소 2개. 1920/1280/320px·200% 확대·dark/고대비/reduced motion, 키보드/visible focus/표 대체 읽기, 긴 한/영 텍스트 대응을 주석 표시한다. 표는 비교 가능한 실제 필드와 필터/선택/상세/오류를 갖춘다. 고위험 저장은 영향→사유→확인→서버 결과→감사 연결 흐름을 번호로 설명하라. 신규 승인/검사 API는 구현된 것으로 표시하지 않는다.
