# A02 · 에이전트 및 게시 관리

DWP DWAI·ON의 권한 있는 관리자 화면을 설계하라. 공통 00-common-design-contract.md와 확정한 사용자 홈 디자인 체계를 유지하되 관리 작업에 맞는 정보 밀도를 사용한다. 사용자 메뉴와 별도 관리 표면이며, 관리 권한이 개인 대화 원문 열람 권한을 뜻하지 않는다.
앱 코드는 아직 만들지 않는다. 데이터·명령이 있는 현행 기능과 신규 계약을 주석으로 구분한다. 장식 글로우/오로라, 카드 안 카드, 허구의 Live·정확도·가용률은 금지한다. 예시 값은 가상 데이터다.

## 목적과 현재

사용자: Agent 편집자/게시 승인자/운영자. 질문: “무엇을 어떤 버전과 범위로 제공할까?” 주 행동: 초안 수정 또는 권한 있는 상태 전환. Archetype: versioned registry list-detail.
경로 /dwaion/admin/agents. 레지스트리 생성·초안 편집·리비전·활성화·퇴역. 이름·설명·담당자·위험도·아티팩트 버전·수명주기를 제공한다. 첫 100건 조회 범위를 숨기지 않는다.

## 설계

1. 수명주기/담당자/위험 필터, 테이블 행 선택 후 상세 inspector.
2. 상세에는 사용자에게 보이는 설명과 운영 메타데이터, 현재/이전 리비전, 변경 이력을 구분.
3. 초안만 수정 가능. CREATE/UPDATE/APPROVE/MANAGE 권한별 행동. 버튼 숨김만으로 권한이 보장되는 것처럼 표현하지 않는다.
4. 활성화/퇴역 전 영향 요약과 확인을 추가하는 안. 현재 별도 승인 요청 수명주기·영향 분석 API가 없으므로 다단계 승인 완료 배지를 만들지 않는다.
5. 저장 충돌에서 변경 내용을 보존하고 현재 버전과 비교. 게시된 버전을 조용히 덮어쓰지 않는다.
6. 레지스트리 활성화와 실제 모델 연결 정상은 별도. “배포 성공”은 실제 증거가 있을 때만.

## 별도 Studio 확장

프롬프트·모델·소스·도구 연결 편집, sandbox 시험, 고정 버전 평가, 게시/롤백은 별도 신규 계약이 필요하다.
이 확장안은 선언형 폼과 미리보기로 시작하며 자유 코드 실행/secret 입력 창을 기본 제공하지 않는다. 설정 노드만 예쁘게 연결한 가짜 실행 그래프 금지.

## 위험 상태

초안 없음, 목록 실패, 승인 권한 없음, 버전 충돌, 활성화 요청 실패, 퇴역 버전으로 시작한 대화, 연결 미구성.
