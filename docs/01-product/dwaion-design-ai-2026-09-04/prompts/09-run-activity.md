# U09 · AI 실행 이력과 실행 상세

DWP 내부 DWAI·ON 화면의 디자인과 상호작용 명세를 작성하라. 기존 글로벌 헤더·사이드바·캐릭터·토큰을 유지한다. 공통 계약 00-common-design-contract.md를 함께 적용한다. 제품 코드는 아직 만들지 않는다.
현재 기능과 확장은 프레임 주석에서 구분한다. 가짜 Live/정확도/분석 진행률, 장식 오로라·글로우, 카드 안 카드, 큰 환영 히어로를 만들지 않는다. 한국어 기본이며 아래 예시는 모두 디자인용 가상 데이터다.

## 목적과 현재

사용자: 자신의 요청 결과를 확인할 구성원. 질문: “무엇이 처리됐고 왜 실패했나?” 주 행동: 결과 확인/대화 복귀. Archetype: operational list-detail.
경로 /dwaion/activity, 선택 상세는 ?run=opaque-id. 일반 활동 앱·알림 앱·관리자 감사의 복제 화면이 아니다.

## 설계

1. 기간/상태/소스 필터와 조회 범위, 마지막 조회 시각. 현재 조회된 목록에 대한 집계를 전체 생애 통계로 표현하지 않는다.
2. 목록: 시작 시각, 요청 종류 또는 안전한 라벨, Agent, 실행 상태, 소요 시간, 소스·정책 결과. 민감한 질문/메일 원문을 열 제목으로 복제하지 않는다.
3. 행 선택→같은 화면의 실행 inspector. 대화 열기는 별도 행동. 모바일 상세는 전체 화면.
4. inspector: 실행 ID의 짧은 표시/복사, 단계별 알려진 결과, 정책 사유, 소스 범위, 응답 유형, 연결 대화.
5. AI 처리 완료와 실제 업무 결과를 따로 표시. 원본 receipt가 없으면 “대상 앱에서 확인”, 성공으로 추정하지 않는다.
6. 로딩/실패/접근 민감 캐시를 분리. 목록 필터에 없는 run도 권한 있는 상세 API가 확인해야 열 수 있다.
7. 재시도는 현재 권한을 재검증하는 새 요청 또는 서버 계약에 따른 재시도. 모든 FAILED에 “그대로 재실행” 버튼을 만들지 않는다.

## 신규 장기 실행 프레임

향후 durable workflow에서만 단계 체크포인트/대기 승인/재시도/취소/보상 상태를 추가한다. 현재 짧은 Ask 실행에 허구의 하위 Agent 작업 트리를 그리지 않는다. 내부 chain-of-thought는 실행 증거가 아니다.

## 위험 상태

결과 없음, 필터 결과 없음, 접근 불가 run, 삭제/보존 만료, 503, 정책 차단, 대체 응답, 취소 요청과 실제 중단의 차이.
예시: 회의 준비 요청은 AI 응답 완료이나 메일 초안은 아직 발송되지 않음.

## 반환물

1440px 정상과 390px 모바일, 위 위험 상태 최소 2개를 제공하라. 1280/320px·200% 확대, dark/고대비/reduced motion, 키보드·focus·긴 한/영 문자열 대응을 주석으로 제시한다. 주요 터치 44px, 고정 입력/도우미의 겹침 방지. 클릭→다음 상태→실패 복구를 번호로 연결하고 기존 UI/신규 UI/신규 API/운영 조건부를 구분하라. 정상 그림 한 장으로 끝내지 않는다.
