# U05 · AI 제안함과 분석 결과

DWP 내부 DWAI·ON 화면의 디자인과 상호작용 명세를 작성하라. 기존 글로벌 헤더·사이드바·캐릭터·토큰을 유지한다. 공통 계약 00-common-design-contract.md를 함께 적용한다. 제품 코드는 아직 만들지 않는다.
현재 기능과 확장은 프레임 주석에서 구분한다. 가짜 Live/정확도/분석 진행률, 장식 오로라·글로우, 카드 안 카드, 큰 환영 히어로를 만들지 않는다. 한국어 기본이며 아래 예시는 모두 디자인용 가상 데이터다.

## 목적과 현재

사용자: 본인에게 제시된 업무 후보를 검토하는 구성원. 질문: “무엇을 왜 제안했고 지금 볼 가치가 있나?” 주 행동: 제안 검토. Archetype: triage list-detail.
경로 /dwaion/proposals. 목록, 상태 필터, 상세, 수락/미루기/해제, 분석 허용, 지금 분석, 데이터 비우기가 있다.

## 설계

1. 제목과 검토 필요 상태를 우선. 대기·미룬 항목·처리 이력은 실제 API 수명주기에 맞는 탭/필터.
2. 행에는 제안 제목, 최소화한 이유, 중요도, 원본 종류, 분석/만료 시각, 상태. 사내 메일 원문이나 비공개 문서를 복제하지 않는다.
3. 선택한 제안은 06 상세. 일괄 수락은 제공하지 않는다. 높은 영향 행동은 한 항목씩 검토한다.
4. “지금 분석”은 사용자가 분석을 허용한 경우의 명시적 실행이다. 상시 모니터링 스위치로 이름을 바꾸지 않는다.
5. 분석 중/완료/부분 실패/제한을 보여준다. 요청한 소스 중 사용 불가 개수와 생성 결과를 구분한다. 세부 소스 진단은 API가 허용하는 수준으로만 보여준다.
6. 허용 해제와 “제안 데이터 비우기”는 서로 다른 행동. 설정은 12 문맥 패널로 확장 가능하다.
7. 새로운 제안 도착은 실제 데이터 변화가 있을 때만 강조. 로딩 spinner로 살아 있는 AI를 연출하지 않는다.

## 예시와 연결

“내일 회의 준비 항목 확인”, 일정·메일 근거, 오늘 검토 권장, 미실행.
행 선택→06 검토. 수락 후 원본 앱 검토는 08이며 수락 즉시 업무 완료가 아니다.
현재 수락 후 링크는 일반 행동 카탈로그다. 제안 입력값과 revision을 그대로 이어주는 연결은 신규 provenance 계약이 필요한 개선으로 주석 처리한다.

## 위험 상태

제안 없음/분석 미허용/분석 0건/소스 실패로 판단 불가/429 제한/503/동시 분석/권한 철회/만료 제안.
실패한 소스를 근거로 과거 제안을 다시 “유효”하게 만들지 않는다. 재시도는 동일 명령의 중복 제안을 만들지 않아야 한다.

## 반환물

1440px 정상과 390px 모바일, 위 위험 상태 최소 2개를 제공하라. 1280/320px·200% 확대, dark/고대비/reduced motion, 키보드·focus·긴 한/영 문자열 대응을 주석으로 제시한다. 주요 터치 44px, 고정 입력/도우미의 겹침 방지. 클릭→다음 상태→실패 복구를 번호로 연결하고 기존 UI/신규 UI/신규 API/운영 조건부를 구분하라. 정상 그림 한 장으로 끝내지 않는다.
