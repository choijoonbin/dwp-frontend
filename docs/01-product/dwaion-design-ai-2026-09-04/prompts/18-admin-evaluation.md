# A06 · 응답 품질과 평가

DWP DWAI·ON의 권한 있는 관리자 화면을 설계하라. 공통 00-common-design-contract.md와 확정한 사용자 홈 디자인 체계를 유지하되 관리 작업에 맞는 정보 밀도를 사용한다. 사용자 메뉴와 별도 관리 표면이며, 관리 권한이 개인 대화 원문 열람 권한을 뜻하지 않는다.
앱 코드는 아직 만들지 않는다. 데이터·명령이 있는 현행 기능과 신규 계약을 주석으로 구분한다. 장식 글로우/오로라, 카드 안 카드, 허구의 Live·정확도·가용률은 금지한다. 예시 값은 가상 데이터다.

## 목적과 현재

사용자: 평가 담당자/검토자. 질문: “어떤 조건에서 무엇이 통과했고 무엇이 부족한가?” 주 행동: 실패 사례 확인 또는 평가 실행. Archetype: evaluation workbench.
경로 /dwaion/admin/evaluation. 세트·케이스 작성, 활성화, 실행, 최근 이력, 직전 비교, CSV. CREATE/UPDATE/EXECUTE/EXPORT/MANAGE를 분리한다.

## 설계

1. 평가 세트 목록과 선택 세트의 목적/상태/케이스/최근 실행.
2. 케이스 편집: 질문, 기대 조건, 원천 범위. 실제 개인정보가 포함되지 않은 fixture 사용.
3. 활성 세트만 실행. 실행 중 중복 시작 방지. 실제 단계/시간을 표시하되 임의 퍼센트 금지.
4. PASS/FAIL/설정 필요, 인용 여부, 기대어 일치, 지연, 모델 참조를 표로 비교. 현재 통과는 제한된 규칙 검사이며 “AI 정확도”가 아니다.
5. 직전 비교는 데이터셋·모델·정책·평가 규칙의 버전이 동일한지 확인돼야 유효하다. 현재 동등성 계약이 부족하므로 비교 불가/조건 변경 프레임을 포함.
6. 실패 상세는 기대와 관측, 안전한 근거, 재시험 행동. 운영 대화 원문을 자동 펼치지 않는다.
7. 이력 기본 20건 범위와 CSV의 실제 내보내기 범위/권한/실패를 표시한다.

## 신규 계약

고정 버전 실행 명세, 시계열, 통계적 품질 기준, 비동기 진행/취소/복구, 데이터셋 간 동등성 판정은 별도다. 현재 이력 폴링이 없는데 실시간 결과가 흐르는 듯 꾸미지 않는다.

## 위험 상태

빈 세트, 비활성 세트, 케이스 검증 실패, 실행 권한 없음, 구성 필요 결과, RUNNING 정체, 비교 불가, CSV 실패.

## 반환물
