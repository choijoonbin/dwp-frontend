# U03 · 답변·근거·후속 질문 작업면

DWP 내부 DWAI·ON 화면의 디자인과 상호작용 명세를 작성하라. 기존 글로벌 헤더·사이드바·캐릭터·토큰을 유지한다. 공통 계약 00-common-design-contract.md를 함께 적용한다. 제품 코드는 아직 만들지 않는다.
현재 기능과 확장은 프레임 주석에서 구분한다. 가짜 Live/정확도/분석 진행률, 장식 오로라·글로우, 카드 안 카드, 큰 환영 히어로를 만들지 않는다. 한국어 기본이며 아래 예시는 모두 디자인용 가상 데이터다.

## 목적과 현재

사용자: 답변을 검증하고 다음 행동을 정할 구성원. 질문: “이 답을 믿을 근거와 내가 할 일은?” 주 행동: 근거 확인 후 후속 질문/행동 검토. Archetype: evidence studio.
새 요청 결과 또는 /dwaion/conversations/:conversationId. 현재는 답변, 인용, 정책/신뢰 수준, 피드백/복사/TTS, 후속 질문, 행동 shelf가 있다.

## 설계

1. 대화 transcript와 현재 응답을 한 흐름으로 읽는다. 최근 답변을 별도 화면처럼 중복 표현하지 않는다.
2. 처리 중에는 실제 이벤트에 대응하는 단계와 중단 버튼. “생각 중 83%”와 비공개 추론 과정 출력은 없다.
3. 모델 답변/근거 기반 대체 응답/근거 부족/정책 제한/연결 필요의 구분을 본문 가까이에 둔다. 성공 색으로 모두 통일하지 않는다.
4. 답변 옆 근거 rail: 출처 종류, 제목, 원본 시스템, 확인 가능한 정보, 원문 열기. 인용 번호와 답변 문장 매핑은 현재 계약으로 보장되는 부분만 사용한다. 정밀 span 매핑은 신규 계약 프레임이다.
5. 근거 선택→검증된 내용 또는 원본 앱. 질문 문맥을 잃지 않고 닫기/뒤로 가기. 모바일은 근거 전체 화면, 대화로 focus 복귀.
6. 답변 도구는 복사, 읽어주기/중지, 도움됨/아쉬움, 재시도. 원문 전체 내보내기나 외부 공유를 이미 구현된 도구처럼 추가하지 않는다.
7. 행동은 “메일 초안 검토”, “일정 계획 검토”처럼 영향이 드러나는 문구. 08로 연결한다. 답변을 그대로 발송하지 않는다.

## 예시와 제한

가상 질문에 근거 2건, 확인 필요 1항목이 있는 회의 준비 답변. “메일을 확인했고 일정은 조회하지 못함”의 부분 실패도 그린다.
낮음/보통/높음 등 제공되는 신뢰 구분을 임의 정확도 %로 변환하지 않는다.
현재 후속 요청은 대화 기록과 별개인 요청 단위 검증을 거친다. 기억하지 못하는 과거 사실을 자동 학습한 메모리로 표현하지 않는다.

## 위험 상태

일부 소스 실패, 근거 철회/만료, 대체 응답, 모델 거절, 이전 대화 접근 실패, 중단, 재시도 중복.
접근 확인 실패 시 과거 제목/내용과 이어쓰기 composer를 보호한다. 취소가 서버의 모든 업무를 원복했다는 뜻은 아니다.

## 반환물

1440px 정상과 390px 모바일, 위 위험 상태 최소 2개를 제공하라. 1280/320px·200% 확대, dark/고대비/reduced motion, 키보드·focus·긴 한/영 문자열 대응을 주석으로 제시한다. 주요 터치 44px, 고정 입력/도우미의 겹침 방지. 클릭→다음 상태→실패 복구를 번호로 연결하고 기존 UI/신규 UI/신규 API/운영 조건부를 구분하라. 정상 그림 한 장으로 끝내지 않는다.
