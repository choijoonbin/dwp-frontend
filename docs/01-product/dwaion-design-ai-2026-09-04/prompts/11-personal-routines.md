# X01 · 내 AI 루틴: 예약 브리핑과 조건형 제안

DWP 내부 DWAI·ON 화면의 디자인과 상호작용 명세를 작성하라. 기존 글로벌 헤더·사이드바·캐릭터·토큰을 유지한다. 공통 계약 00-common-design-contract.md를 함께 적용한다. 제품 코드는 아직 만들지 않는다.
현재 기능과 확장은 프레임 주석에서 구분한다. 가짜 Live/정확도/분석 진행률, 장식 오로라·글로우, 카드 안 카드, 큰 환영 히어로를 만들지 않는다. 한국어 기본이며 아래 예시는 모두 디자인용 가상 데이터다.

## 목적과 상태

사용자: 반복적인 확인 업무를 줄일 구성원. 질문: “언제 무엇을 확인하고 어떤 결과만 받을까?” 주 행동: 범위와 조건을 검토한 뒤 루틴 켜기. Archetype: workflow + list-detail.
신규 기능 후보다. 현재 proposal의 “지금 분석”을 예약 엔진으로 오해하지 않는다. 라우트·메뉴·API는 아직 확정하지 않았다.

## 목록

내 루틴, 활성/일시중지/재확인 필요/오류, 다음 실행, 마지막 실제 결과. 처음에는 아침 브리핑·회의 준비처럼 읽기/제안 생성만 지원하는 단계로 설계한다. 공개 발송/대량 변경 자동 실행은 넣지 않는다.

## 생성/변경 흐름

1. 목적: “평일 아침 오늘 일정과 임박 업무를 정리”.
2. 범위: 사용자 권한이 있는 앱/소스, 포함·제외.
3. 시점: 한 번/반복, IANA 시간대, 업무 시간, 휴일 정책. 다음 실행을 사용자 시간으로 미리 보여준다.
4. 결과: 제안함/검토할 초안. 알림 채널과 조용한 시간은 공통 알림 설정을 참조한다.
5. 제한: 실행 빈도·비용/시간 예산·만료일·중단 조건.
6. 요약 확인→명시 동의→저장. 활성화 결과는 서버 확인 후만 표시.

## 안전과 복구

실행 시점 권한 재검증, 소스 stale/403/503에서 제안 재활성화 금지, 중복 이벤트/언어 변경 dedupe.
일시중지는 미래 실행 중지, 현재 실행 취소는 별도. 삭제 후 감사 메타데이터 처리 범위를 구분한다.
권한 변경으로 멈춘 루틴은 자동 재승격하지 않고 재확인한다. 재시도 예산 소진 시 사용자에게 다음 행동을 준다.

## 예시와 홈 연결

“평일 09:00 업무 브리핑”, 결과는 제안함, 다음 실행 9월 7일 09:00 Asia/Seoul.
홈에는 활성 루틴이 있을 때만 다음 브리핑 1건을 표시. 결과 클릭은 실행 이력/제안으로 이동한다.

## 필요한 서버 계약

durable scheduler/event intake, encrypted inputs, consent revision, idempotency/lease, user+tenant identity, budget, outbox 결과 전달, pause/cancel, retention. 모든 항목은 구현 전 조건이며 시안 성공 상태는 운영 증거가 아니다.

## 반환물

1440px 정상과 390px 모바일, 위 위험 상태 최소 2개를 제공하라. 1280/320px·200% 확대, dark/고대비/reduced motion, 키보드·focus·긴 한/영 문자열 대응을 주석으로 제시한다. 주요 터치 44px, 고정 입력/도우미의 겹침 방지. 클릭→다음 상태→실패 복구를 번호로 연결하고 기존 UI/신규 UI/신규 API/운영 조건부를 구분하라. 정상 그림 한 장으로 끝내지 않는다.
