# U02 · 새 대화 질문 스튜디오

DWP 내부 DWAI·ON 화면의 디자인과 상호작용 명세를 작성하라. 기존 글로벌 헤더·사이드바·캐릭터·토큰을 유지한다. 공통 계약 00-common-design-contract.md를 함께 적용한다. 제품 코드는 아직 만들지 않는다.
현재 기능과 확장은 프레임 주석에서 구분한다. 가짜 Live/정확도/분석 진행률, 장식 오로라·글로우, 카드 안 카드, 큰 환영 히어로를 만들지 않는다. 한국어 기본이며 아래 예시는 모두 디자인용 가상 데이터다.

## 목적과 현재

사용자: 질문할 구성원. 질문: “무엇을 어떤 근거로 요청할까?” 주 행동: 범위 확인 후 전송. Archetype: studio.
경로 /dwaion/new. 이미 반영한 새 대화 시안의 구조와 홈 디자인을 유지한다.

## 설계

1. 선택된 Agent 정체성과 간단한 용도, 새 대화임을 표시한다. 모델의 확인되지 않은 제품 버전·Pro 배지는 없다.
2. composer는 본문의 중심 도구다. 여러 줄, 길어진 입력, 전송 중 취소, 글자/입력 유효성 오류, 복구를 설계한다.
3. 업무 항목/메일/일정을 toggle로 선택하며 최소 1개를 유지한다. 선택 범위는 실제 요청 sourceScopes와 일치한다. 결재 전문가에서는 별도 결재 문맥을 사용한다.
4. 바로 시작하기: 오늘 브리핑, 막힌 업무, 회의 준비, 정책·접근 확인. 동일 장식 카드를 과도하게 반복하지 않는다.
5. 최근 업무는 출처·기한·제목과 “원본 열기”. 업무 기반 질문을 만들면 어떤 문맥이 전달되는지 확인 가능하게 한다.
6. 보조 rail에는 검색 범위와 의미 있는 업무 신호만. 정상 연결을 추정한 녹색 점, 실제 계약 없는 전체 검색 개수는 금지.
7. 마이크는 녹음→전사→검토→수정→전송. 음성 세부 상태는 10과 일치한다. 무조건 음성 대화로 표시하지 않는다.

## 상호작용

가상 질문: “내일 제품 검토 회의 전에 확인할 자료와 미결 업무를 정리해 주세요.”
범위 선택→전송→03 답변 작업면. 빠른 질문 시작 전후의 모드/입력 변화를 주석 표시한다.
전문 Agent 전환 시 새 대화 시작 또는 문맥 재확인. 다른 Agent의 과거 대화를 조용히 이어붙이지 않는다.
질문 원문은 URL에 넣지 않는다. 외부 앱에서 전달된 질문이 만료되면 빈 정상 요청을 자동 제출하지 않는다.

## 위험 상태

전송 중/사용자 중단/네트워크 실패/권한 없음/선택 소스 이용 불가/마이크 거부/길이 초과.
모바일은 composer와 소스 선택을 우선하고 우측 rail은 접거나 뒤로 보낸다. 키보드가 전송을 덮지 않는다.

## 반환물

1440px 정상과 390px 모바일, 위 위험 상태 최소 2개를 제공하라. 1280/320px·200% 확대, dark/고대비/reduced motion, 키보드·focus·긴 한/영 문자열 대응을 주석으로 제시한다. 주요 터치 44px, 고정 입력/도우미의 겹침 방지. 클릭→다음 상태→실패 복구를 번호로 연결하고 기존 UI/신규 UI/신규 API/운영 조건부를 구분하라. 정상 그림 한 장으로 끝내지 않는다.
