# A08 · 감사와 데이터 보존

DWP DWAI·ON의 권한 있는 관리자 화면을 설계하라. 공통 00-common-design-contract.md와 확정한 사용자 홈 디자인 체계를 유지하되 관리 작업에 맞는 정보 밀도를 사용한다. 사용자 메뉴와 별도 관리 표면이며, 관리 권한이 개인 대화 원문 열람 권한을 뜻하지 않는다.
앱 코드는 아직 만들지 않는다. 데이터·명령이 있는 현행 기능과 신규 계약을 주석으로 구분한다. 장식 글로우/오로라, 카드 안 카드, 허구의 Live·정확도·가용률은 금지한다. 예시 값은 가상 데이터다.

## 목적과 현재

사용자: 감사 열람자/내보내기 담당자/보존 정책 관리자. 질문: “누가 어떤 정책을 바꿨고 무엇을 얼마나 보존하나?” 주 행동: 사건 조사 또는 보존 변경 검토. Archetype: audit explorer + policy form.
경로 /dwaion/admin/audit. 기존 보존 별칭은 이 화면으로 연결된다. 새 중복 메뉴를 만들지 않는다.

## 감사 화면

1. 실제 지원하는 정책 감사 범주 5종, 시간·행위자·대상·사유·상관 ID, 검색/서버 페이지.
2. 선택 사건의 메타데이터와 관련 정책으로 이동. 모든 Agent/모든 Gate 감사가 이미 한 목록에 통합됐다고 가정하지 않는다.
3. EXPORT 권한 별도, 다운로드 중/실패/완료. 서버 1만 건 제한과 잘림 정보가 있는 응답을 활용해 “전체”가 아닌 범위를 표시하는 UI를 보완.
4. 원본 질문·대화·메일 내용은 감사 관리자에게 자동 노출하지 않는다.

## 보존 화면

현재 30~3650일, Legal Hold, policyVersion을 다룬다. 감사 VIEW와 보존 VIEW/UPDATE/MANAGE를 분리한다.
변경 전후, 사유, 적용 범위, 저장 확인, 충돌을 설계한다. Legal Hold 변경은 MANAGE 권한. 변경 즉시 모든 오래된 자료가 삭제됐다고 주장하지 않는다.
영향 데이터 수 미리보기·Legal Hold 해제 이중 승인·삭제 완료 증적은 신규 계약으로 별도 프레임.

## 위험 상태

감사 결과 없음, 조회 실패, 내보내기 일부/잘림, 권한 없음, 보존 범위 오류, stale revision, hold 변경 권한 없음, 실제 삭제 작업 상태 미확인.
가상 사건은 “소스 정책 변경”, 원문 없이 대상과 사유만. 편의상 실제 이메일 주소·민감 사유를 예시로 넣지 않는다.

## 반환물

1440px 정상, 390px 주요 관리 흐름, 위험 상태 최소 2개. 1920/1280/320px·200% 확대·dark/고대비/reduced motion, 키보드/visible focus/표 대체 읽기, 긴 한/영 텍스트 대응을 주석 표시한다. 표는 비교 가능한 실제 필드와 필터/선택/상세/오류를 갖춘다. 고위험 저장은 영향→사유→확인→서버 결과→감사 연결 흐름을 번호로 설명하라. 신규 승인/검사 API는 구현된 것으로 표시하지 않는다.
