# U01 · DWAI·ON 홈

DWP 내부 DWAI·ON 화면의 디자인과 상호작용 명세를 작성하라. 기존 글로벌 헤더·사이드바·캐릭터·토큰을 유지한다. 공통 계약 00-common-design-contract.md를 함께 적용한다. 제품 코드는 아직 만들지 않는다.
현재 기능과 확장은 프레임 주석에서 구분한다. 가짜 Live/정확도/분석 진행률, 장식 오로라·글로우, 카드 안 카드, 큰 환영 히어로를 만들지 않는다. 한국어 기본이며 아래 예시는 모두 디자인용 가상 데이터다.

## 목적과 현재

사용자: 현재 테넌트의 구성원. 질문: “지금 AI와 무엇을 처리하면 좋을까?” 주 행동: 질문 시작 또는 중요한 제안 검토. Archetype: command center.
경로 /dwaion/home. 이미 홈 시안이 반영됐으므로 기존 장점을 유지하는 정합·보완 작업이다. 동봉한 01-home-current-and-expansion-brief.md를 읽는다.

## 설계

1. 짧은 인사와 현재 범위, 질문 composer. 빠른 목적은 오늘 업무 브리핑/막힌 업무 찾기/회의 준비.
2. 질문 다음에 검토할 제안 1~2건을 노출하는 확장안을 만든다. 사유, 원본 종류, 유효 상태, 검토 행동. 현재 홈은 제안 집계 중심이므로 목록 노출은 신규 UI다.
3. 우선 업무 최대 4건과 최근 대화 최대 3건을 주/보조 영역으로 배열한다. 우선 업무는 공통 큐 정렬이며 AI 재분석 완료 배지 금지.
4. 임박 업무/대화/제안/Agent/행동의 5종 신호는 작고 읽기 쉽게. 모든 숫자에 범위가 있고 클릭하면 해당 목록이다. 제안 수락 수나 앱 수를 생산성 지표로 바꾸지 않는다.
5. 전문 Agent는 대화 시작을 돕는 보조 선택. 이름·용도·사용 가능 범위를 읽을 수 있게 한다.
6. 최신성은 실제 수신 시각. 실패 영역별 재시도. 영구 움직이는 실시간 피드로 꾸미지 않는다.

## 예시와 연결

김민아 09:20. 고객 안내 초안 검토가 14:00 기한. 제안 “내일 회의 준비 항목 확인”은 검토 전이다.
빠른 질문→02/03, 제안→06, 업무→원본 앱, 대화→03, Agent→07을 주석 연결한다.
루틴/결과물은 별도 미래 프레임에만 넣는다. 초기 정상 화면에 미구현 예약/작성 중 문서를 채워 넣지 않는다.

## 위험 상태

처음 방문, 제안만 존재, 일부 조회 실패, 403 권한 변경, 503 전달 실패, 모델 미연결, 사용 가능 행동 없음.
질문 실패 시 입력 보존. 비공개 제목은 재표시하지 않는다. 첫 뷰포트에 질문과 실제 업무 일부가 함께 보여야 한다.

## 반환물

1440px 정상과 390px 모바일, 위 위험 상태 최소 2개를 제공하라. 1280/320px·200% 확대, dark/고대비/reduced motion, 키보드·focus·긴 한/영 문자열 대응을 주석으로 제시한다. 주요 터치 44px, 고정 입력/도우미의 겹침 방지. 클릭→다음 상태→실패 복구를 번호로 연결하고 기존 UI/신규 UI/신규 API/운영 조건부를 구분하라. 정상 그림 한 장으로 끝내지 않는다.
