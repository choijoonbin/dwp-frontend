# U07 · 전문 에이전트 탐색과 상세

DWP 내부 DWAI·ON 화면의 디자인과 상호작용 명세를 작성하라. 기존 글로벌 헤더·사이드바·캐릭터·토큰을 유지한다. 공통 계약 00-common-design-contract.md를 함께 적용한다. 제품 코드는 아직 만들지 않는다.
현재 기능과 확장은 프레임 주석에서 구분한다. 가짜 Live/정확도/분석 진행률, 장식 오로라·글로우, 카드 안 카드, 큰 환영 히어로를 만들지 않는다. 한국어 기본이며 아래 예시는 모두 디자인용 가상 데이터다.

## 목적과 현재

사용자: 적절한 AI 도움을 선택하는 구성원. 질문: “이 Agent가 무엇을 읽고 어디까지 해줄까?” 주 행동: 해당 Agent로 대화 시작. Archetype: capability catalog.
경로 /dwaion/agents. 현재 사용자 UI는 일반 업무와 결재 전문가를 중심으로 허용된 레지스트리 항목을 연결한다.

## 설계

1. 상단은 검색/업무 목적 필터가 필요한 정도만. Agent가 2개뿐인 상태에 거대한 marketplace나 인기 순위를 만들지 않는다.
2. 각 항목: 이름, 용도, 지원 업무, 확인 가능한 위험/버전, 대화 시작. “모든 업무 자동 수행” 같은 설명 금지.
3. 상세 inspector: 할 수 있는 일/할 수 없는 일, 읽을 소스, 작성 또는 인계 가능한 행동, 필요한 사용자 검토.
4. 선택한 Agent의 시작 질문 2~3개. 클릭은 질문 스튜디오로 연결하며 소스 문맥이 바뀌는 것을 보여준다.
5. 게시된 Agent와 운영 연결이 정상인 Agent는 다르다. 레지스트리 상태를 실시간 건강 상태로 표현하지 않는다.
6. 권한 없는 Agent의 비공개 설정·출처를 노출하지 않는다. 공개 카탈로그 요청 기능이 없다면 가짜 설치/구독 버튼을 넣지 않는다.

## 확장

목적별 큐레이션, 즐겨찾기, 담당자/지원 범위 상세는 메타데이터를 확인한 뒤 추가한다. 누구나 Agent를 만들고 게시하는 화면은 사용자 카탈로그에 끼우지 않고 관리자 14의 별도 Studio 확장으로 설계한다.

## 위험 상태

허용된 Agent 없음, 레지스트리 실패, 퇴역/버전 변경, 결재 권한 없음, 시작 후 운영 구성 필요.
예시: 일반 업무 길잡이 / 결재 검토 도우미. 평점·사용 횟수·절약 시간을 가짜로 채우지 않는다.

## 반환물

1440px 정상과 390px 모바일, 위 위험 상태 최소 2개를 제공하라. 1280/320px·200% 확대, dark/고대비/reduced motion, 키보드·focus·긴 한/영 문자열 대응을 주석으로 제시한다. 주요 터치 44px, 고정 입력/도우미의 겹침 방지. 클릭→다음 상태→실패 복구를 번호로 연결하고 기존 UI/신규 UI/신규 API/운영 조건부를 구분하라. 정상 그림 한 장으로 끝내지 않는다.
