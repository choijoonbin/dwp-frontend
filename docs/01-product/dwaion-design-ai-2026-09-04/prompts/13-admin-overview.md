# A01 · AI 운영 현황

DWP DWAI·ON의 권한 있는 관리자 화면을 설계하라. 공통 00-common-design-contract.md와 확정한 사용자 홈 디자인 체계를 유지하되 관리 작업에 맞는 정보 밀도를 사용한다. 사용자 메뉴와 별도 관리 표면이며, 관리 권한이 개인 대화 원문 열람 권한을 뜻하지 않는다.
앱 코드는 아직 만들지 않는다. 데이터·명령이 있는 현행 기능과 신규 계약을 주석으로 구분한다. 장식 글로우/오로라, 카드 안 카드, 허구의 Live·정확도·가용률은 금지한다. 예시 값은 가상 데이터다.

## 목적과 현재

사용자: 운영 담당자. 질문: “어떤 사용자 영향과 준비 문제가 있는가?” 주 행동: 문제 범위 확인 후 담당 관리 화면 열기. Archetype: operational command center.
경로 /dwaion/admin/overview. 현재 30일 실행/완료/실패, 정책/응답 상태, 평균 지연, 토큰, 활성 사용자, 대화, 피드백 집계. API는 기간 1~90일과 generatedAt을 제공한다.

## 설계

1. 테넌트·기간·생성 시각·갱신 상태. 기간 선택은 기존 API를 소비하는 신규 UI로 설계.
2. 실패와 차단의 차이를 보여주는 운영 요약. 차단이 보안 정책 정상 동작일 수도 있으므로 모두 장애로 칠하지 않는다.
3. 실행 수/응답 상태/평균 지연 등 관련 지표만 묶는다. 성공률은 분모·기간·미측정 정의가 필요하다.
4. 대화 수는 보존 유효 대화 수이며 기간 내 새 대화와 다르다. 수치 정의를 tooltip 또는 상세에 제공한다.
5. 사용자 영향→Agent/소스/정책/평가/운영 Gate로 drilldown. 필터 연결이 아직 없으면 신규로 표시.
6. 부분 실패는 해당 영역을 확인 불가로 두고 정상 영역은 유지. 데이터 미수신을 0으로 표시하지 않는다.
7. 현재 고정 100% 막대처럼 측정 의미가 없는 장식을 제거하는 안. 시계열·비용 차트는 신규 데이터 계약을 받은 뒤만 제공.

## 위험 상태

실행 0건, 수집 지연, 한 집계만 실패, 운영 권한 철회, 모델만 미구성, 평가 결과 미존재.
연결 설정·운영 승인·실제 가용성은 별도다. 운영 준비율을 SLA로 바꾸지 않는다.

## 반환물

1440px 정상, 390px 주요 관리 흐름, 위험 상태 최소 2개. 1920/1280/320px·200% 확대·dark/고대비/reduced motion, 키보드/visible focus/표 대체 읽기, 긴 한/영 텍스트 대응을 주석 표시한다. 표는 비교 가능한 실제 필드와 필터/선택/상세/오류를 갖춘다. 고위험 저장은 영향→사유→확인→서버 결과→감사 연결 흐름을 번호로 설명하라. 신규 승인/검사 API는 구현된 것으로 표시하지 않는다.
