# A07 · 운영 전환 검증과 승인

DWP DWAI·ON의 권한 있는 관리자 화면을 설계하라. 공통 00-common-design-contract.md와 확정한 사용자 홈 디자인 체계를 유지하되 관리 작업에 맞는 정보 밀도를 사용한다. 사용자 메뉴와 별도 관리 표면이며, 관리 권한이 개인 대화 원문 열람 권한을 뜻하지 않는다.
앱 코드는 아직 만들지 않는다. 데이터·명령이 있는 현행 기능과 신규 계약을 주석으로 구분한다. 장식 글로우/오로라, 카드 안 카드, 허구의 Live·정확도·가용률은 금지한다. 예시 값은 가상 데이터다.

## 목적과 현재

사용자: 구성 담당자/검증자/독립 승인자. 질문: “이 환경에서 기능을 켤 근거가 충분한가?” 주 행동: 누락 증적 확인 또는 적격 승인. Archetype: evidence-based approval workflow.
경로 /dwaion/admin/gates. 개발/스테이징/운영의 13개 Gate, 설정→증적→검증 기록→승인/반려, 유효기간·버전·감사 이력.

## 설계

1. 환경 selector와 차단/미검증/승인/만료 현황. 환경을 바꾸면 관련 목록/상세/행동도 함께 바뀐다.
2. 목록에서 누락 증적, 담당자, 만료, 상태를 먼저 본다. 준비 비율은 필수 Gate 승인 비율이지 SLA/가용률/보안 인증이 아니다.
3. 상세는 요구 증적 체크리스트, 등록 참조, 검증 기록, 승인 자격, 변경 이력.
4. 현재 검증은 담당자가 PASS/FAIL을 기록하는 기능이다. 실제 자동 진단을 실행한 녹색 애니메이션으로 표현하지 않는다.
5. 자기 승인/반려 차단과 CREATE/UPDATE/APPROVE 분리. 승인할 수 없는 사유를 이해 가능하게 표시한다.
6. 사유, 버전, 필요한 증적, 승인 만료일을 검토한 뒤 명시 확인. 승인 버튼 하나로 모든 Gate를 우회하지 않는다.
7. 구성 변경/증적 만료 시 재검증 필요의 상태를 설계한다. 자동 검사와 서명된 결과 수집은 신규 계약.

## 위험 상태

필수 증적 없음, 부적격 승인자, 자기 승인 시도, stale revision, 승인 만료, 검증 FAIL, 등록/승인 서버 실패.
가상 예시: 운영 모델 연결 증적 미등록. 관리자가 시안에서 PASS를 고를 수 있다는 이유로 운영 준비 완료라고 표현하지 않는다.

## 반환물
