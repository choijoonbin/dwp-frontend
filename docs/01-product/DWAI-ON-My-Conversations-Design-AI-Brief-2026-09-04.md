# DWAI·ON 내 대화 디자인 AI 전달 브리프

작성 기준: 2026-09-04 현재 프론트엔드 목록·상세·기록 메뉴, 한국어 리소스 및 Agent 대화 목록·삭제 계약.

목적: 개인 대화 기록을 쉽게 찾고 안전하게 이어 가는 ‘내 대화’ 메뉴의 디자인 고도화. 현재 구현과 개선 제안을 구분하며, 이번 문서 작성에서 UI·API는 변경하지 않는다.

## 1. 제품과 화면의 정체성

- DWP는 회사별 테넌트, 조직, 사용자, 권한을 기반으로 업무·메일·일정·전자결재 등 여러 앱을 제공하는 디지털 워크플레이스다.
- `DWAI·ON`은 사용자의 업무 맥락과 근거를 연결하는 DWP의 AI 앱이며 한국어 발음은 `디웨이온`이다.
- 대상 메뉴는 **내 대화**, 경로는 `/dwaion/conversations`이다.
- 항목 선택 후 대화 상세는 `/dwaion/conversations/:conversationId`에서 공통 대화 워크스페이스로 열린다.
- DWAI·ON 홈은 질문과 업무 신호의 시작점, 새 대화는 질문 작업 공간, 내 대화는 저장된 개인 기록을 다시 찾는 화면이다.
- AI 실행 이력은 처리·실패·실행 상태를 보는 별도 메뉴다. 내 대화를 실행 감사 로그나 관리자의 전사 대화 조회 화면으로 만들지 않는다.

주 사용자는 회사 구성원이고 주요 질문은 다음과 같다.

> “전에 AI와 어떤 내용을 확인했는가? 필요한 대화를 빨리 찾아 다시 이어갈 수 있는가? 불필요한 기록은 안전하게 정리할 수 있는가?”

주요 행동은 대화 찾기와 재개이며 삭제는 보조 행동이다. 화면 유형은 **개인 기록 탐색 목록에서 대화 상세로 이어지는 목록-상세 경험**이다. 숫자 대시보드, 카드 갤러리, 팀 메신저, 공개 지식 게시판이 아니다.

## 2. 공통 셸과 다른 진입점

상단의 DWP 브랜드·현재 앱·워크스페이스·검색·알림·프로필, 좌측 DWAI·ON 앱 내비게이션은 공통 셸이다. 내 대화의 디자인을 위해 이 공통 구조를 임의로 교체하지 않는다.

대화 기록을 만나는 곳은 세 군데다.

| 진입점                       | 현재 기능                                          | 디자인에서의 역할                   |
| ---------------------------- | -------------------------------------------------- | ----------------------------------- |
| DWAI·ON 홈의 최근 대화       | 제목·마지막 시각, 최대 4개, 전체 보기              | 간단한 이어 하기                    |
| 내 대화 메뉴                 | 제목 검색, 메시지 수·시각, 대화 열기, 확인 후 삭제 | 기록 탐색의 주 화면                 |
| 대화 화면 헤더의 기록 아이콘 | 최근 목록 팝업, 대화 전환, 새 질문, 삭제           | 현재 작업을 벗어나지 않는 빠른 전환 |

이 세 곳이 서로 다른 종류의 기록 저장소처럼 보이면 안 된다. 같은 개인 대화를 서로 다른 크기의 표면에서 탐색하는 구조다. 다만 현재 삭제 확인 등 세부 동작에는 차이가 있어 고도화 대상이다.

## 3. 현재 목록 화면 구성

```text
DWP 공통 헤더 / 좌측 내비게이션

내 대화                                      + 새 대화
내 권한 범위에서 생성된 DWAI·ON 대화를 이어서 확인합니다.

대화 검색
[검색 아이콘  대화 제목으로 검색                       ]

대화 제목                                      삭제
메시지 N개 · 마지막 대화 날짜와 시간
---------------------------------------------------
대화 제목                                      삭제
메시지 N개 · 마지막 대화 날짜와 시간
---------------------------------------------------
...
```

- 상단은 제목·설명과 주요 액션 ‘새 대화’로 구성된다.
- 작은 화면에서는 제목과 버튼이 세로로 배치된다.
- 검색 입력 최대 너비는 현재 560px이다.
- 목록은 넓은 본문에 가로 행으로 펼쳐지고 위·아래 경계선과 행 사이 구분선을 사용한다.
- 각 행의 왼쪽은 대화 열기 버튼, 오른쪽은 별도의 삭제 버튼이다.
- 대화 제목은 굵은 한 줄로 표시되며 길면 생략된다.
- 행의 현재 메타정보는 `메시지 {{count}}개 · {{date}}`이다.
- 현재 목록에는 답변 요약, 마지막 질문 발췌, 에이전트명, 연결된 앱, 태그, 즐겨찾기 표시가 없다.

이 구성은 현재 상태를 설명하는 것이며, 넓은 화면에서 행을 끝없이 늘리는 배치를 반드시 보존해야 하는 것은 아니다.

## 4. 데이터와 검색의 정확한 범위

### 어떤 기록을 보여주는가

- 프론트엔드는 `/api/agent/v1/conversations`에서 개인 대화 요약 목록을 조회한다.
- 서버의 tenant/user 범위와 접근 정책을 따르는 기록이다. 회사 전체 사용자 대화나 다른 사람의 비공개 기록이 아니다.
- PostgreSQL 목록은 마지막 메시지 시각의 내림차순이다.
- 현재 프론트 호출은 페이지·커서·limit을 전달하지 않는다. 서버 기본 limit은 **30개**이다.
- 따라서 현재 UI는 ‘전체 보관 기간의 모든 대화를 제한 없이 탐색하는 완성된 검색 화면’이 아니라 **최근 최대 30개를 받아 표시하는 목록**이다.
- 현재 더 보기, 페이지 번호, 무한 스크롤, 기간별 서버 검색은 없다.
- 완료된 가시 메시지가 없는 대화와 보존 조건에 의해 목록에서 제외되는 대화가 있을 수 있다. 실행 실패 기록 전체가 이 목록에 포함되는 것은 아니다.
- 목록 캐시 신선도는 20초 설정이지만 해당 간격의 자동 폴링을 의미하지 않는다. 전용 수동 새로고침과 마지막 갱신 시각 표시는 현재 없다.

### 제목 검색

- 레이블: `대화 검색`.
- 입력 안내: `대화 제목으로 검색`.
- 검색어 앞뒤 공백을 제거하고 대소문자를 정규화해 현재 받은 목록의 제목에 포함되는지 검사한다.
- 타이핑에 따라 목록이 즉시 필터링된다. 별도의 검색 실행 버튼은 없다.
- 본문 전문 검색, 의미 기반 AI 검색, 출처 검색, 오래된 서버 기록까지의 검색은 아니다.
- 검색어·필터 상태는 현재 화면의 로컬 상태다. URL이나 저장된 보기로 보존하지 않는다.
- 별도의 결과 개수, 검색어 강조, 검색어 지우기 액션은 현재 화면에 없다.

‘전체 대화에서 검색’이라는 문구를 사용하거나 무한한 검색 결과를 표현하려면 실제 서버 검색·페이지 계약을 추가해야 한다. 디자인으로만 검색 범위를 확대해서는 안 된다.

## 5. 목록에서 가능한 행동

### 새 대화

헤더의 `새 대화` 버튼은 `/dwaion/new`로 이동한다. 정상 빈 목록에도 같은 시작 액션이 있다. 새 대화는 기존 기록의 복제가 아니라 새로운 질문 시작이다.

### 대화 열기

행의 제목·메타 영역을 선택하면 해당 ID의 대화 상세 경로로 이동한다. 현재 화면에서 오른쪽 미리보기를 펼치는 split view는 아니다. 목록의 검색어·스크롤 위치를 전용 저장 상태로 복원하는 계약도 아직 없다.

### 삭제

내 대화 목록의 삭제 흐름은 다음과 같다.

```text
행의 삭제 클릭 → 확인 대화상자
→ 취소 또는 삭제 확인
→ 삭제 API 요청
→ 성공 시 대화상자 닫기와 목록 재조회
```

현재 문구:

- 제목: `대화를 삭제할까요?`
- 설명: `이 대화와 메시지는 복구할 수 없습니다.`
- 버튼: `취소`, `삭제`.
- 처리 중: `삭제 중`.

확인 대화상자는 파괴적 동작의 경고 스타일이고 취소가 기본 포커스다. 삭제 중에는 닫기·취소와 중복 요청을 제한한다.

현재 휴지통·복원·실행 취소·대량 선택·일괄 삭제는 없다. 원본 메일·일정·결재를 삭제하는 행동도 아니다. 삭제를 원본 시스템과 감사 기록까지 모두 지우는 ‘완전한 흔적 제거’로 설명하지 않는다.

### 보존 정책과 삭제 제한

서버는 보존 잠금(legal hold)이 있으면 삭제를 409로 거절할 수 있고, 대상이 없거나 해당 범위에서 찾을 수 없으면 404를 반환할 수 있다. 현재 목록 UI에는 이런 원인별 삭제 실패를 별도로 설명하는 처리가 충분하지 않다.

따라서 ‘모든 대화는 언제든 삭제 가능’이라고 디자인하지 않는다. 삭제 실패 시 기록을 성공한 것처럼 숨기지 말고, 정책 제한·대상 없음·일시 실패를 구분하는 UX가 필요하다. 이는 고도화 요청이다.

## 6. 현재 로딩·빈 상태·오류

| 상태                | 현재 표시와 동작                                                      |
| ------------------- | --------------------------------------------------------------------- |
| 최초 로딩           | 높이 76px의 스켈레톤 행 3개                                           |
| 대화 없음           | `아직 대화가 없습니다`, 설명과 `새 대화` 액션                         |
| 제목 검색 결과 없음 | `검색 결과가 없습니다`, `다른 검색어를 입력해 보세요.`                |
| 목록 조회 실패      | `대화 기록을 불러오지 못했습니다. 잠시 후 다시 시도하세요.` 오류 안내 |
| 삭제 대기           | 확인 대화상자                                                         |
| 삭제 처리 중        | 삭제 중 표시, 닫기·취소 제한                                          |
| 삭제 성공           | 목록 캐시를 무효화하고 다시 조회                                      |

현재 오류 안내와 빈 상태 렌더링이 완전히 배타적으로 분리되어 있지 않아, 실패 상황에서 ‘아직 대화가 없습니다’가 함께 보일 여지가 있다. 오류를 정상적인 0건과 혼동하지 않도록 개선해야 한다.

목록 조회 실패에 대한 명시적 재시도 버튼, 삭제 실패의 원인별 안내, 검색 결과 0건의 지우기 버튼은 현재 완성된 기능이 아니다.

## 7. 대화 상세를 다시 열었을 때

내 대화의 가치는 목록 디자인만으로 완성되지 않는다. 사용자가 기록을 선택한 다음의 재개 경험을 함께 설계해야 한다.

### 현재 재개 화면

- 공통 대화 워크스페이스의 DWAI·ON 헤더가 표시된다.
- 저장된 메시지가 `나`와 `DWAI·ON`으로 구분되어 순서대로 표시된다.
- 메시지 본문은 줄바꿈을 유지하는 텍스트이고, 역할 아이콘과 서로 다른 표면 톤을 사용한다.
- 출처가 있으면 제목 칩을 표시한다.
- 근거 기반 대체 응답은 별도 배지와 당시 AI 비교·종합 없이 원본 근거를 정리한 응답이라는 안내를 유지한다.
- 정책상 보류된 메시지는 내부 상태 코드만 본문으로 보여주지 않고 보류 안내로 표현할 수 있다.
- 아래 축약 입력창에서 후속 질문을 입력할 수 있다. 새 질문마다 권한과 근거를 다시 검증한다.
- 대화 조회 결과로 확인된 ID를 사용해 요청을 이어 간다. 임의 경로 ID만으로 권한이 확장되는 구조가 아니다.

### 최신 답변과 과거 메시지의 기능 차이

| 기능                              | 방금 받은 답변                  | 저장 기록을 다시 연 과거 메시지                |
| --------------------------------- | ------------------------------- | ---------------------------------------------- |
| 본문 보기                         | 있음                            | 있음                                           |
| 대체 응답 식별                    | 배지와 설명                     | 배지와 설명                                    |
| 복사·답변 듣기·평가·재실행 컨트롤 | 최신 답변 컴포넌트에서 제공     | 메시지별 동일 툴바는 현재 없음                 |
| 출처 미리보기·원본 열기           | 검증 패널에서 제공              | 현재 출처 제목 칩은 클릭 기능 없음             |
| 신뢰도·정책·모델 사용량·감사 정보 | 현재 실행 응답의 검증 패널      | 과거 실행별 검증 패널 복원이 현재 없음         |
| 담당 앱 액션 연결                 | 현재 실행 응답 조건에 따라 제공 | 기록 조회만으로 과거 액션 영역이 복원되지 않음 |

현재 오른쪽 패널은 재진입한 과거 메시지의 상세 증적이 아니라 기본 검색 범위와 업무 신호를 보여줄 수 있다. 최신 응답을 받으면 그 실행의 검증 패널로 전환된다.

대화 상세의 제목 위치도 현재는 공통 `DWAI·ON` 헤더이며, 저장된 대화 제목을 전용 문서 제목처럼 크게 표시·편집하는 UI가 아니다. 메시지 데이터에는 시각 정보가 있지만 현재 transcript에서는 메시지별 시각을 표시하지 않는다.

### 상세 조회의 예외

404이면 새 대화로 이동한다. 404는 다른 사용자의 기록 여부를 알려 주는 수단으로 사용하지 않는다. 현재 상세 조회의 로딩·403·503 등은 전용 상태 화면이 충분히 구성되어 있지 않으므로, 고도화 시 목록에서 상세로 전환하는 구간까지 포함해야 한다.

## 8. 헤더의 최근 대화 팝업

이 팝업은 내 대화 메뉴와 같은 목록 API를 사용한다.

- 기록 아이콘을 눌러 연다.
- 현재 폭은 340px, 작은 화면에서는 화면 너비에서 24px를 뺀 범위로 제한된다.
- 목록 내부 높이는 최대 360px이고 세로 스크롤된다.
- 제목은 `최근 대화`, 설명은 암호화 보관과 보존 정책 안내다.
- 제목·마지막 시각을 표시하고 현재 대화를 선택 상태로 보여준다.
- 새 질문 아이콘과 개별 삭제 아이콘이 있다.
- 현재 대화를 삭제하면 새 질문 상태로 이동한다.

**현재 이 팝업의 삭제는 내 대화 목록과 달리 확인 대화상자 없이 API를 호출한다.** 이를 표준으로 복제하지 말고 두 진입점의 파괴적 행동을 같은 확인·진행·실패 계약으로 정합화하는 방향을 제안한다. 팝업의 로딩·빈 상태·조회 실패 역시 구분이 필요하다.

기록 팝업을 완전한 내 대화 탐색 화면으로 비대하게 만들 필요는 없다. 빠른 전환과 전체 목록 탐색의 역할을 분리한다.

## 9. 현재 지원하지 않거나 화면에 연결되지 않은 기능

| 기능                     | 현재 상태                                                          | 확장 시 필요한 것                          |
| ------------------------ | ------------------------------------------------------------------ | ------------------------------------------ |
| 제목 변경                | 프론트 API 함수와 서버 PATCH는 존재, 현재 목록·상세에 편집 UI 없음 | 제목 편집·검증·취소·성공·실패·목록 갱신 UX |
| 전체 기간 검색           | 없음, 최근 기본 30개 제목 필터                                     | 서버 검색·페이지·접근 범위 계약            |
| 날짜 그룹·기간 필터      | 없음                                                               | 그룹·기간 기준, 시간대, 서버 범위 정합     |
| 즐겨찾기·고정·폴더·태그  | 없음                                                               | 영속 메타데이터·정렬·권한·동기화           |
| 대화 공유·내보내기       | 없음                                                               | 정보 반출 정책·권한·만료·감사·마스킹       |
| 답변 요약·미리보기       | 목록에는 없음                                                      | 실제 요약 데이터·노출 정책·실패 상태       |
| 대량 삭제·휴지통·복원    | 없음                                                               | 삭제·보존 정책과 일괄 처리 계약            |
| 본문 내 찾기·메시지 점프 | 없음                                                               | 메시지 탐색 UI와 대규모 기록 처리          |
| 대화 분기·응답 버전 비교 | 없음                                                               | 분기·버전 데이터 계약과 작업 UX            |

이 기능들이 일반 AI 제품에서 익숙하다는 이유만으로 ‘현재 구현 완료’로 그려서는 안 된다. 디자인 시 추가 개발 항목으로 명시하고, 핵심인 찾기·재개·안전한 정리를 우선한다.

## 10. 고도화 디자인 방향

이 절은 현재 문제를 해결하기 위한 제안이다.

### 정보 구조

1. 읽기 쉬운 제목과 마지막 대화 맥락을 중심으로 재구성한다. 단순 ID·메시지 수가 시각적 주인공이 되어서는 안 된다.
2. 제목 검색의 범위를 정직하게 표시한다. 기존 데이터만 사용하는 안은 최근 목록 검색, 전체 검색안은 별도 개발 요구로 구분한다.
3. 새 대화는 명확한 주요 명령으로 유지하고, 삭제는 보조 메뉴나 아이콘으로 조용하게 정리할 수 있다. 접근 가능한 이름과 확인 절차는 유지한다.
4. 대화 제목이 길면 2줄 허용이나 상세 제목 표시로 맥락을 보완한다. 한 줄 생략만으로 모든 항목이 비슷하게 보이지 않게 한다.
5. 날짜별 묶음은 현재 받은 기록만으로 가능한 개선이지만 ‘전체 기록’처럼 보이지 않게 한다. 날짜 기준과 사용자 시간대를 명확히 정한다.
6. 광폭 화면의 목록을 제한된 읽기 폭으로 정돈하거나 목록-상세형 탐색을 제안할 수 있다. 현재는 상세 경로 이동이므로 새 split view 동작은 신규 구현으로 표시한다.
7. 상세에 들어갔다가 돌아올 때 검색어·선택·스크롤을 복원하는 경험을 제안한다. 민감한 검색어를 URL에 저장하는 것은 별도의 개인정보 판단 없이 기본값으로 삼지 않는다.

### 재개 경험

- 선택한 대화의 제목과 과거 기록이라는 시간 맥락을 명확히 보여준다.
- 과거 답변은 당시 근거이며 현재 업무 상태와 다를 수 있음을 이해할 수 있게 한다. 현재 질문은 새 검증이라는 차이를 유지한다.
- 과거 출처 확인과 최신 답변의 출처 확인을 일관되게 만들되, 원본 재조회는 현재 권한을 통과해야 한다.
- 과거 메시지의 복사·듣기·근거 열기 등은 현재 미연결 기능임을 표시한다. 데이터에 실행 ID가 있다는 이유만으로 모든 버튼을 무조건 활성화하지 않는다.
- 삭제나 보존 만료 이후 돌아온 경우 조용한 빈 화면 대신 이해 가능한 안내와 새 대화·목록 복귀 경로를 제공한다.

### 안전한 정리

- 삭제 확인에 대상 대화의 제목을 표시해 어떤 기록을 지우는지 알게 한다. 현재 확인창에는 선택 제목이 포함되지 않는다.
- 목록과 기록 팝업의 삭제 확인을 통일한다.
- 보존 잠금·일시 실패·이미 삭제됨을 구분한다.
- 복원 기능이 없는 동안 ‘되돌리기’ 토스트를 가짜로 제공하지 않는다.

## 11. 시각·모션·반응형 원칙

- DWAI·ON의 고급스러움은 읽기 편한 기록, 명확한 탐색, 부드러운 상태 전환으로 표현한다. SAP·Salesforce형 관리 테이블이나 일반 카드 대시보드를 모방하지 않는다.
- 기존 DWP 디자인 시스템, Lucide 아이콘, 파랑 `#1557D5`과 청록 `#008F7A`의 의미 있는 강조를 유지한다. 라이트 캔버스는 `#F5F7FB`이며 다크·고대비는 테마에 맞춘다.
- 대화 목록에 로봇 일러스트·우주 배경·반짝이는 장식을 반복하지 않는다. 빈 상태에서만 기존 캐릭터를 절제해 활용할 수 있다.
- 거대한 대화 카드나 카드 속 카드 대신 스캔 가능한 목록을 우선한다. 카드가 필요하면 기존 반경을 따르고 특별한 이유 없이 8px 초과 라운드를 남용하지 않는다.
- 선택·호버·포커스·삭제 진행은 서로 구분한다. 삭제 완료 후 목록 축소는 자연스럽게 하되 성공 여부를 모션으로만 알리지 않는다.
- 1440px·1280px·390px·320px, 200% 확대, 긴 한국어·영어 제목을 제공한다.
- 모바일에서 삭제 버튼 때문에 제목이 거의 사라지지 않게 한다. 보조 동작 메뉴로 재배치하는 것은 가능하지만 숨겨진 기능의 발견성·접근성을 보완한다.
- 키보드로 검색→목록→대화 열기→삭제 확인→취소 후 원래 항목 복귀가 가능해야 한다.
- 일반 본문 대비 4.5:1, 주요 타깃 44px 수준, 아이콘 이름·툴팁, 색상 외 상태 표시를 설계한다.
- 화면 너비에 비례한 무조건 폰트 축소, 음수 자간, 가로 스크롤, 삭제창과 가상 키보드의 충돌은 피한다.
- Reduced Motion에서도 선택·삭제·탐색 관계가 전달되어야 한다.

## 12. 반드시 디자인할 상태와 흐름

| 상태·흐름                | 필수 설계 내용                             |
| ------------------------ | ------------------------------------------ |
| 첫 방문 0건              | 신규 질문으로 자연스럽게 시작, 오류와 구분 |
| 정상 목록                | 짧은·긴 제목, 여러 날짜, 다양한 메시지 수  |
| 제목 검색 성공·0건       | 검색 범위, 결과 구분, 검색 지우기 대안     |
| 목록 초기 로딩·재조회    | 구조 유지와 갱신 구분                      |
| 403·503 등 목록 실패     | 권한과 일시 장애 구분, 가능한 재시도·복귀  |
| 대화 상세 진입           | 로딩·기록 표시·후속 질문의 연결            |
| 삭제 확인·취소·진행·성공 | 대상 식별과 포커스 복귀                    |
| 보존 잠금·삭제 실패      | 기록 유지, 정책 안내, 재시도 가능 여부     |
| 삭제·보존 만료된 대화    | 과도한 정보 노출 없이 목록·새 대화로 회복  |
| 대체 응답 기록           | 당시 응답 방식과 한계를 유지               |
| 모바일·다국어            | 제목·메타·보조 액션의 읽기 균형            |

전용 상태가 현재 모두 구현되어 있다는 뜻이 아니라 디자인 고도화에서 놓치지 말아야 할 수용 범위다.

## 13. 디자인 AI에 요청하는 결과물

1. 현재 API와 콘텐츠만 사용하는 정돈된 목록 시안과, 신규 계약이 필요한 확장안을 별도로 제시한다.
2. 내 대화 목록, 검색 상태, 삭제 확인, 목록→상세→후속 질문, 헤더 기록 팝업의 시각적 일관성을 보여준다.
3. 데스크톱·모바일, 라이트·다크, 빈·오류·권한·삭제 제한 상태를 포함한다.
4. 간격·타입·행 높이·정렬·긴 제목·보조 명령·포커스·모션 규격을 명시한다.
5. 허구의 사용 성과, 전체 검색으로 오인할 표현, 실제 없는 공유·복원·즐겨찾기를 미구현 표시 없이 넣지 않는다.
6. 디자인 예시에는 가상의 이름·업무 제목만 사용하고 예시임을 표시한다. 실제 직원 기록을 임의로 수집하거나 노출하지 않는다.

### 바로 전달할 요약 지시문

> DWP 솔루션의 DWAI·ON ‘내 대화’ 메뉴를 고도화해 주세요. 목적은 사용자가 개인 AI 대화 기록을 빠르게 찾고 다시 이어 가며 불필요한 기록을 안전하게 정리하는 것입니다. 현재는 최근 기본 30개 대화를 가져와 제목으로 필터링하고, 제목·메시지 수·마지막 시각을 표시하며, 상세 열기·새 대화·확인 후 삭제를 제공합니다. 상세에서는 저장된 메시지와 대체 응답 표시, 출처 제목, 후속 질문을 보여줍니다. 검색 범위를 과장하지 말고 기록 목록·헤더의 빠른 전환·상세 재개를 일관되게 설계해 주세요. 기존 기능만으로 가능한 안과 제목 변경·전체 검색·고정·공유 등 개발이 필요한 확장안을 구분하고, 고급스러운 정보 위계와 반응형·접근성·실패 회복에 집중해 주세요. 권한·보존 정책·삭제의 실제 결과를 디자인이 왜곡해서는 안 됩니다.
