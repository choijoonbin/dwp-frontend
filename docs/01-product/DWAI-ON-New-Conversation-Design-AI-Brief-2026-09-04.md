# DWAI·ON 새 대화 디자인 AI 전달 브리프

작성 기준: 2026-09-04 현재 구현 소스, 한국어 리소스, 실제 컴포넌트 연결 및 API 소비 방식.

목적: DWAI·ON의 ‘새 대화’ 메뉴를 시작 화면뿐 아니라 질문 처리, 답변, 출처 검토, 후속 업무 연결까지 일관된 AI 작업 경험으로 고도화하기 위한 디자인 의뢰서.

이 문서는 현재 구현 설명과 개선 제안을 구분한다. 운영 환경의 모델·음성 공급자·모든 커넥터가 활성화되어 있다는 의미는 아니다. 실제 화면·서버 동작을 변경하는 개발 작업은 이번 문서 작성에 포함하지 않는다.

## 1. 제품 정체성과 이번 화면의 목적

- DWP는 회사별 테넌트, 조직, 사용자, 권한을 기반으로 업무·메일·일정·전자결재 등 여러 앱을 제공하는 디지털 워크플레이스다.
- `DWAI·ON`은 DWP 안에서 사용자의 업무 맥락과 근거를 연결하는 AI 앱이다. 시스템명은 `DWAION`, 한국어 발음은 `디웨이온`이다.
- 브랜드 문장: **당신의 업무를 연결하는 DWP AI**.
- 이번 대상은 **새 대화 메뉴 `/dwaion/new`와 그곳에서 시작한 질문의 작업 흐름**이다.
- 회사 배경 위에 앱 위젯을 배치하는 DWP 전체 홈, 업무 신호를 요약하는 DWAI·ON 홈 `/dwaion/home`, 기록 목록인 내 대화 `/dwaion/conversations`와 구분한다.

주 사용자는 회사 구성원이며, 해결할 질문은 다음과 같다.

> “업무에서 궁금한 것을 어떻게 물어보고, 답변을 어떤 근거로 믿으며, 다음 업무로 어떻게 이어갈 수 있는가?”

주요 행동은 질문 작성·전송이다. 답변 이후에는 근거 확인과 후속 질문이 중요하고, 원본 업무 변경은 담당 앱의 검토 절차로 연결한다. 화면 유형은 **집중형 입력에서 대화·근거 검토로 전환되는 AI 작업 공간**이다. 단순 검색창, 메신저, 마케팅 랜딩 페이지, 관리 통계 대시보드가 아니다.

## 2. 다른 메뉴와의 관계 및 공통 셸

공통 헤더는 DWP 브랜드, 현재 앱, 워크스페이스 맥락, 공통 검색, 알림, 사용자 프로필 등을 담당한다. 좌측에는 DWAI·ON 홈, 새 대화, 내 대화, AI 실행 이력, AI 제안함, 전문 에이전트, 업무 실행 및 연결이 권한에 따라 노출된다. 운영·관리는 별도 권한의 표면이다.

이 공통 셸을 유지하면서 본문을 고도화한다. 앱 내부에 또 다른 전역 검색·프로필·관리 메뉴를 중복 추가하지 않는다. 공통 검색은 앱 전체 탐색, 본문 질문 입력은 AI 요청이라는 목적 차이가 있다.

| 진입 경로            | 현재 동작                                                                           |
| -------------------- | ----------------------------------------------------------------------------------- |
| 좌측 ‘새 대화’       | 기본 DWAI·ON의 빈 질문 화면                                                         |
| 홈의 질문·빠른 시작  | 일회성 질문 전달을 소비한 뒤 같은 작업 공간에서 질문 실행                           |
| 전문 에이전트의 시작 | 선택된 에이전트 맥락의 질문 화면                                                    |
| 내 대화의 항목       | 저장된 대화 상세 `/dwaion/conversations/:conversationId`를 같은 워크스페이스로 표시 |
| 기존 `/ask` 경로     | 호환 진입 경로. 신규 디자인의 대표 주소로 사용하지 않음                             |

질문 본문을 URL에 넣지 않는다. 외부 화면에서 전달된 질문은 검증된 일회성 식별자로 전달하며, 만료·실패하면 다시 입력하도록 안내한다.

## 3. 현재 시작 화면의 구성

```text
DWP 공통 헤더 / 좌측 앱 내비게이션

DWAI·ON 전용 작은 헤더
캐릭터 + 권한 기반 업무 AI / DWAI·ON     기록 메뉴 / 내 권한 범위 / 읽기 전용

주 작업 영역                                  오른쪽 컨텍스트 패널
캐릭터와 개인화 인사                           현재 검색 범위
질문 입력 / 소스 선택 / 마이크 / 전송            업무·메일·일정 설명
                                               현재 업무 신호
바로 시작하기 4개                               원본 권한 안내

최근 업무 컨텍스트 최대 4개
```

- 본문은 큰 화면에서 가변 폭 작업 영역과 304px 컨텍스트 패널로 나뉜다.
- 오른쪽 패널은 `lg` 이상에서 상단 82px 위치를 기준으로 sticky 동작을 한다. 오버레이가 아니라 레이아웃의 실제 열이다.
- 작은 화면에서는 패널이 본문 아래로 이어진다. 현재 모바일용 별도 근거 드로어는 아니다.
- 시작 영역의 인사·입력 내부 콘텐츠는 최대 820px로 제한된다.
- 시작 질문은 `sm` 이상에서 2열, 작은 화면에서 1열로 표시된다.
- 이 구조와 수치는 현재 구현 설명이며 새 디자인이 반드시 그대로 유지해야 하는 값은 아니다.

### 전용 헤더 문구

- 작은 식별 문구: `권한 기반 업무 AI`
- 제목: `DWAI·ON`
- 상태 표시: `내 권한 범위`, `읽기 전용`
- 기록 아이콘: `대화 기록 열기`

‘읽기 전용’은 질문·분석 과정이 원본 업무를 직접 변경하지 않는다는 의미다. 대화 저장이나 피드백까지 전혀 기록하지 않는다는 뜻은 아니다. 이 의미가 오해되지 않도록 신뢰 안내를 정리할 필요가 있다.

### 개인화 인사

- 작은 문구: `업무와 연결된 AI`
- 인사: `{{name}}님, 무엇을 함께 해결할까요?`
- 이름이 없는 경우: `무엇을 함께 해결할까요?`
- 설명: `업무, 메일, 일정을 현재 권한 안에서 연결해 근거와 함께 답합니다.`

기존 디웨이온 캐릭터 이미지 `/assets/assistants/dwaion-link-v1.png`를 사용한다. 현재 캐릭터에는 부유 모션, 시작 영역에는 이동하는 미세한 시각 효과가 있고 Reduced Motion에서는 꺼진다. 이는 현재 표현이지 그대로 복제해야 할 요구는 아니다. 개선 시 업무에 집중할 수 있도록 움직임의 빈도와 역할을 재검토한다.

## 4. 질문 입력과 검색 범위

### 텍스트 입력

- 입력 안내: `찾고, 비교하고, 정리할 업무를 입력하세요`
- 기본 2줄, 최대 5줄, 최대 4,000자.
- Enter로 전송, Shift+Enter로 줄바꿈. 한글 IME 조합 중 Enter는 전송하지 않는다.
- 빈 질문은 전송할 수 없다.
- 시작 입력창은 자동 포커스를 요청한다. 모바일 가상 키보드와 첫 화면 노출의 관계는 디자인 검토 대상이다.
- 전송하면 작성 중 텍스트는 입력창에서 비워지고, 제출한 질문이 결과 영역 상단에 표시된다.

### 기본 에이전트의 소스 선택

현재 새 대화에서는 `업무 항목`, `메일`, `일정`을 선택·해제할 수 있다. 기본값은 세 종류 모두 선택이다. 최소 한 종류는 유지되며 마지막 선택 하나를 해제할 수는 없다.

**홈의 동일한 표시는 안내용이지만, 새 대화 시작 화면의 표시는 실제 소스 선택 컨트롤이라는 차이가 있다.**

현재 선택 컨트롤은 넓은 화면의 비축약 입력창에서만 보인다. 모바일과 답변 후의 축약 입력창에서는 소스 칩이 숨겨진다. 선택 상태는 요청에 전달되지만, 소스를 선택했다고 원본 자료의 접근 권한이 생기는 것은 아니다.

현재 소스 선택은 컴포넌트 상태이며 영구 저장 설정이 아니다. 모델 선택, 파일 첨부, 이미지 업로드, 음성 파일 첨부, 문서 드래그 업로드는 이 입력창의 현재 기능이 아니다.

### 음성 입력 STT

```text
마이크 클릭 → 마이크 권한 확인 → 녹음
→ 사용자가 종료하거나 최대 45초 후 자동 종료
→ 서버 받아쓰기 → 텍스트를 입력창에 추가
→ 사용자가 확인·수정 → 전송
```

항상 듣는 음성 비서나 양방향 실시간 음성 통화가 아니다. 음성 변환만으로 질문을 자동 제출하거나 업무를 실행하지 않는다. 지원되지 않는 브라우저, 권한 거부, 녹음·변환 실패 상태가 있고 텍스트 입력은 대안으로 유지된다.

상태 문구는 `마이크 권한 확인 중`, `듣는 중 · 눌러서 종료`, `받아쓰는 중`, `받아쓰기 완료 · 전송 전 확인`, `음성 입력 다시 시도`이다.

## 5. 바로 시작하기 4개

현재 일반 새 대화는 홈의 3개와 달리 **4개 작업 유형**을 제공한다. 각각 아이콘, 제목, 설명, 오른쪽 화살표를 가진 버튼이다.

| 제목             | 현재 설명                                           | 클릭 시 실제 전달 질문                                               |
| ---------------- | --------------------------------------------------- | -------------------------------------------------------------------- |
| 오늘 업무 브리핑 | 마감과 우선순위를 기준으로 지금 할 일을 정리합니다. | 오늘 처리할 업무를 우선순위와 마감 위험 기준으로 요약해 주세요.      |
| 막힌 업무 찾기   | 지연 신호와 다음 조치가 필요한 항목을 찾습니다.     | 현재 진행을 막는 업무와 필요한 다음 조치를 찾아주세요.               |
| 회의 준비        | 일정과 관련 업무를 연결해 준비 사항을 확인합니다.   | 오늘 예정된 회의와 관련 업무를 바탕으로 준비할 내용을 정리해 주세요. |
| 정책·접근 확인   | 정책 근거와 올바른 요청 경로를 함께 확인합니다.     | 이 요청에 필요한 정책과 접근 경로를 근거와 함께 알려주세요.          |

클릭은 템플릿 설명을 여는 것이 아니라 질문을 즉시 제출한다. 서로 독립된 업무 자동화 엔진 4개가 실행되는 것도 아니다. 동일 질문 경로에 서로 다른 질문과 선택 소스가 전달된다.

## 6. 최근 업무 컨텍스트와 오른쪽 패널

### 최근 업무 컨텍스트

- 제목: `최근 업무 컨텍스트`
- 설명: `지금 처리할 수 있는 실제 업무에서 질문을 시작합니다.`
- 업무 큐 API에서 최대 4개를 보여준다.
- 정렬은 우선순위 high→medium→low, 같은 우선순위에서는 최근 갱신 순이다.
- 업무 제목, 요약 또는 권장 다음 행동 또는 원본 시스템, 원본 시스템명, 업무 열기 액션으로 구성된다.
- 클릭하면 원본 업무 경로나 해당 업무가 지정된 업무함으로 이동한다. 현재 질문에 업무를 첨부하거나 자동으로 분석하는 동작이 아니다.
- 로딩에는 스켈레톤, 빈 결과와 조회 실패에는 각각 안내가 표시된다.

### 답변 전 오른쪽 패널

- 제목: `현재 검색 범위`
- 설명: `권한에 따라 자동 선택`
- 기본 소스: 업무 항목, 메일, 일정의 설명과 사용 가능 표시.
- 현재 업무 신호: 전체·임박·대기 숫자.
- 하단 안내: `원본 시스템에서 현재 사용자에게 허용된 정보만 검색합니다.`

현재 패널은 입력창에서 선택한 `sourceScopes`가 아니라 에이전트의 `availableSourceScopes`를 받는다. 따라서 표시된 소스 목록을 ‘이번 요청에 선택된 소스’ 또는 실시간 커넥터 정상 확인으로 설명하면 안 된다. 업무 신호의 미조회 값도 0으로 대체될 수 있어 고도화 시 별도 로딩·실패 표현이 필요하다.

## 7. 질문 제출 후의 동작과 화면

### 상태 전환

```text
빈 시작 화면 → 질문 제출 → 권한 확인·자료 조회·응답 처리
→ 답변 또는 보류·설정 필요·오류
→ 출처 확인 / 후속 질문 / 재실행 / 새 질문 / 담당 앱 연결
```

질문을 제출하면 인사와 시작 질문 대신 제출 질문·결과 영역이 중심이 된다. 아래에는 후속 질문용 축약 입력창이 표시된다. 현재 이 입력창은 본문 흐름 안에 있으며 항상 화면 하단에 고정된 도크가 아니다.

서버 응답에 대화 ID가 있으면 대화 상세 경로로 전환하고 관련 기록을 갱신한다. 처음 빈 화면에 진입했다는 이유만으로 저장된 대화가 항상 즉시 만들어지는 것으로 표현하지 않는다.

### 진행 상태

서버 진행 이벤트에 따라 다음 문구를 표시한다.

| 단계        | 현재 문구                                 |
| ----------- | ----------------------------------------- |
| AUTHORIZING | 권한과 정책 경계를 확인하고 있습니다      |
| RETRIEVING  | 접근 가능한 업무 근거를 수집하고 있습니다 |
| REASONING   | 근거를 연결해 응답을 구성하고 있습니다    |
| VERIFYING   | 인용과 응답을 교차 검증하고 있습니다      |
| PERSISTING  | 암호화된 대화 기록을 저장하고 있습니다    |
| COMPLETED   | 검증이 완료되었습니다                     |

현재 프론트는 진행 이벤트와 최종 결과를 받는다. **답변 텍스트를 토큰마다 실시간 출력하는 UI는 아니다.** 모든 단계가 사용자에게 충분한 시간 동안 하나씩 보인다는 보장도 없다.

보조 시각 요소로 ‘권한 경계 확인 / 근거 수집 / 응답 검증’ 세 항목이 있지만, 현재 각 항목이 실제 완료 여부에 맞춰 개별 체크되는 스텝퍼는 아니다. 새 디자인에서 진행률이나 완료 체크를 만들려면 실제 이벤트에 맞춰야 한다. 임의 퍼센트, 허구의 도구 실행 로그, 내부 사고 과정처럼 보이는 텍스트는 추가하지 않는다.

### 중단·재시도·새 질문

- 처리 중 `응답 생성 중단`을 누를 수 있다. 클라이언트의 요청 구독을 중단하고 제출 질문을 초안으로 되돌린다.
- 이것을 이미 완료된 서버 저장이나 원본 업무를 되돌리는 ‘롤백’으로 표현하지 않는다.
- 실패 시 재시도, 결과 확인 후 다시 실행, 별도 새 질문 시작이 가능하다.
- 재실행은 새로운 요청 ID로 다시 검증하는 동작이다. 이전 결과 버전을 비교하는 전용 UI는 아니다.
- 새 질문·대화 전환·브라우저 탐색에서는 진행 중 요청을 정리하고 화면 상태를 전환한다. 작성 초안의 영구 보관이나 대화별 자동 초안 복원은 현재 제공하지 않는다.

## 8. 답변 영역과 신뢰 설계

### 현재 답변 구성

- 제출한 질문과 `새 질문` 액션.
- 답변 제목·보조 설명, 상태 배지.
- 답변 본문: 줄바꿈을 유지한 일반 텍스트. 현재 별도의 풍부한 Markdown 표·코드·차트 렌더러가 아니다.
- 답변 듣기 TTS, 답변 복사, 도움됨·도움 안 됨 평가, 다시 실행 컨트롤.
- 하단 안내: `대화 맥락은 이어지지만 매 질문마다 권한과 근거를 새로 검증합니다.`

TTS는 사용자가 답변 듣기를 선택했을 때 시작하고 준비·재생·중지·실패 상태가 있다. 자동 재생은 하지 않는다. 피드백은 실행 ID와 연결해 제출되며 현재 화면에서는 성공 후 중복 평가를 막는다. 피드백 수정·댓글 입력 UI는 없다.

### 반드시 구분할 결과

| 현재 상태           | 의미와 디자인 주의                                                    |
| ------------------- | --------------------------------------------------------------------- |
| 검증된 답변         | 서버 계약을 통과한 답변. 모든 내용이 절대 정확하다는 보증 표시는 아님 |
| 근거 기반 대체 응답 | AI 비교·종합 대신 검증된 원본 근거를 직접 정리한 제한된 응답          |
| 답변 보류           | 근거 부족, 정책 거부, 소스 일시 장애, 승인 절차 필요 등               |
| 설정 필요           | 관리자 런타임·에이전트·모델 등의 설정이 필요한 상태                   |
| 통신·처리 오류      | 응답을 정상적으로 받지 못한 상태. 재시도와 입력 맥락 유지 필요        |

대체 응답에는 `현재는 원본 근거를 직접 정리한 응답입니다`라는 별도 안내가 있다. 모델 추론을 수행한 것처럼 성공 연출을 하면 안 된다. 거부·보류를 빈 답변이나 알 수 없는 오류로 모두 합치지 않는다.

## 9. 검증 패널과 출처 미리보기

응답이 도착하면 오른쪽 패널은 ‘현재 검색 범위’에서 **검증 패널**로 전환된다.

- 처리 상태.
- 높은·중간·낮은 신뢰도 또는 신뢰도 미산정. 서버 응답의 등급이며 통계적 정확도 퍼센트가 아니다.
- 검토한 소스 수.
- 인용 출처 목록: 순번, 제목, 자료 종류, 원본 시스템.
- 처리 정책: 허용·절차 연결·거부 등의 서버 결과.
- 모델 사용량: 토큰 수 또는 호출 없음.
- 감사 ID 일부.
- 대체 응답일 경우 별도 응답 방식.

출처 경로가 있는 항목의 아이콘을 누르면 미리보기 대화상자를 연다. 미리보기에는 제목, 자료 종류, 원본 시스템, 시각 정보가 있으면 해당 날짜·시간, 공개 가능한 발췌문, 권한 안내, 원본 열기가 있다. 내부 경로는 앱 내 탐색, 외부 원본은 별도 창으로 연결된다.

출처의 전체 원문이나 현재 사용자가 보지 못하는 데이터를 임의로 펼치지 않는다. 감사 ID·토큰 수 같은 기술 정보는 가치를 보존하되 답변 내용보다 시각적 우선순위가 낮아도 된다. 상세 접기로 정리하는 것은 개선 제안이다.

## 10. 다음 업무로 이어가기

응답이 있고 정책이 DENY가 아니며 사용 가능한 액션 목록이 있으면 `다음 업무로 이어가기` 영역이 표시될 수 있다. 현재는 허용된 액션 카탈로그를 보여주는 구조이지 질문 의도에 따라 항상 완벽하게 선별된 추천 목록은 아니다.

알려진 액션은 다음과 같다. 모든 사용자에게 네 종류가 항상 보인다는 뜻은 아니다.

- 일정 초안 만들기.
- 메일 초안 만들기.
- 서비스 요청 준비하기.
- 결재 요청 준비하기.

```text
액션 선택 → 서버에서 권한·위험·대상 경로 검증
→ 전달할 초안 요약과 확인 대화상자
→ 사용자가 ‘검토 화면으로 이동’ 선택
→ 담당 앱에서 다시 검토·저장·제출
```

현재 미리보기는 제목, 일정, 대상 인원수, 본문 글자 수, 요청 요약 등 제한된 요약을 보여준다. 모든 본문이 편집 가능한 미리보기 양식은 아니다. 위험 등급 L0~L3를 표현할 수 있다.

**채팅에서 메일이 이미 발송되었거나, 결재가 승인되었거나, 일정이 저장되었다고 표시하면 안 된다.** 실제 실행은 담당 앱의 명시적 검토·승인과 서버 결과에 따른다.

## 11. 전자결재 전문 에이전트 변형

기본 새 대화와 같은 구조를 사용하는 별도 에이전트 모드가 있다. 대표 주소는 `/dwaion/new?agent=DWP_APPROVAL_EXPERT`이며 권한이 있는 경로로 진입해야 한다.

- 제목: `DWAI·ON 전자결재 전문가`.
- 인사: `{{name}}님, 결재 흐름을 근거와 함께 검토하세요`.
- 설명: 현재 결재 권한 안에서 업무함·요청·양식·SLA 위험과 통제 증적을 설명하며 승인·반려는 사람이 수행한다.
- 소스: 결재 업무, 요청, 양식, 운영.
- 시작 질문: 결정 브리핑, 흐름 병목 찾기, 결재선 설명, 통제 검토.
- 기본 업무 큐 조회와 최근 업무 컨텍스트, 업무 신호 숫자는 이 모드에서 제외된다.
- 현재 기본 에이전트와 동일한 대화 기록 메뉴·기존 대화 ID 재개 흐름을 제공한다고 가정하면 안 된다. 전문 모드에서는 해당 메뉴가 숨겨지고 질문 요청에도 기본 대화 ID를 넘기지 않는다.

별도 앱처럼 완전히 다른 디자인을 만들기보다 제목·업무 언어·소스·예문이 바뀌는 공통 작업 공간의 변형으로 설계한다.

## 12. 현재 한계와 디자인 고도화 요청

이 절은 개선 제안이며 현재 완성된 기능의 설명이 아니다.

1. 첫 질문 전 인사 영역이 상대적으로 크고, 일반 홈과 유사한 인사가 반복된다. ‘입력에 집중하는 새 대화’의 목적을 강화한다.
2. 캐릭터·패널·입력 도구가 여러 겹으로 프레임 처리되어 있다. 중첩 카드와 장식적 움직임을 줄이고 계층을 단순하게 만든다.
3. 오른쪽의 사용 가능 소스와 이번 요청의 선택 소스를 명확히 구분한다. 소스 가용성을 실제 정상 연결 상태처럼 표현하지 않는다.
4. 모바일과 후속 질문에서도 선택 소스를 확인·변경할 대안을 마련한다. 현재 숨겨지는 컨트롤을 새로운 드로어·메뉴로 보완할 경우 개발 필요를 표시한다.
5. 답변이 길어질 때 입력창이 멀어지지 않도록 하단 도킹을 검토한다. 현재 고정 도크는 아니므로 신규 동작으로 명시한다.
6. 답변 본문, 근거, 다음 행동, 기술 증적의 시각적 우선순위를 나눈다. 감사 정보가 읽기 흐름을 압도하지 않게 한다.
7. 실제 진행 이벤트에 맞는 상태 전환을 사용한다. 현재 동시에 움직이는 세 항목을 완료된 단계로 오해하게 하지 않는다.
8. 과거 대화 메시지는 현재 최신 답변의 복사·TTS·평가·근거 미리보기와 기능이 동일하지 않다. 기록 재개 경험과 새 결과 경험의 일관성을 개선한다.
9. 본문 편집·첨부·모델 선택·응답 버전 비교·자동화 실행은 현 기능이 아니다. 추가 시 필수 신규 계약과 분리해 제안한다.
10. 삭제, 대화 전환 시 초안 손실, 읽기 전용과 업무 연결의 의미를 명확히 설명한다. 확인 없이 원본 변경이 일어나는 인상을 주지 않는다.

## 13. 시각·반응형·접근성 원칙

- 고급스러움은 정확한 위계, 좋은 읽기 폭, 상태의 정밀함, 자연스러운 전환으로 만든다. SAP·Salesforce나 일반 관리 대시보드의 시각 구성을 모방하지 않는다.
- 기존 DWP 디자인 시스템과 Lucide 아이콘을 사용한다. 기본 제품 강조색은 파랑 `#1557D5`, 보조는 청록 `#008F7A`, 라이트 캔버스는 `#F5F7FB`이다. 다크·고대비 모드에서는 테마를 따른다.
- AI라는 이유로 우주 배경, 보라색 발광 구체, 과도한 네온을 추가하지 않는다. 기존 캐릭터 정체성을 유지하고 실제 콘텐츠를 첫 화면에 노출한다.
- 입력, 답변, 자료 출처를 읽는 데 필요한 공간을 확보하되 광폭 화면에 우연한 빈 공간을 만들지 않는다.
- 카드 반경은 기존 시스템을 따르고 특별한 이유 없이 8px를 넘는 카드 라운드를 남용하지 않는다. 페이지 전체를 카드 안에 넣지 않는다.
- 1440px·1280px·390px·320px, 200% 확대, 긴 한국어·영어, 다크·고대비, Reduced Motion을 설계한다.
- 모바일에서 근거 패널은 읽기 흐름을 막지 않게 재구성할 수 있다. 출처 버튼에서 열리는 보조 표면은 닫기와 포커스 복귀가 명확해야 한다.
- 아이콘 버튼에는 이름·툴팁, 주요 터치 컨트롤에는 44px 수준의 타깃, 키보드에는 뚜렷한 포커스가 필요하다.
- 일반 본문 대비 4.5:1을 목표로 하고 상태는 색상만으로 구분하지 않는다. 폰트를 화면 너비에 비례해 무조건 줄이거나 음수 자간으로 맞추지 않는다.
- 모션은 입력→처리→답변, 소스→미리보기 등의 관계를 설명한다. 상시 움직임보다 실제 상태 반응을 우선한다.

## 14. 디자인 AI에 요청하는 결과물

1. 기존 기능만으로 가능한 고도화안과 추가 개발이 필요한 확장안을 구분한다.
2. 빈 시작 화면, 텍스트 작성, 음성 처리·검토, 질문 처리 중, 정상 답변, 대체 응답, 근거 부족·거부·설정 필요·통신 오류 화면을 제시한다.
3. 출처 미리보기, 후속 질문, 액션 초안 검토→담당 앱 이동, 기록 재개 흐름을 함께 보여준다.
4. 데스크톱·모바일과 라이트·다크를 제공하고, 간격·타입·그리드·컨트롤·포커스·모션 규격을 설명한다.
5. 허구의 AI 정확도·절감 시간·임의 진행률·자율 실행 성공·항상 듣는 음성 모드를 넣지 않는다.

### 바로 전달할 요약 지시문

> DWP의 DWAI·ON ‘새 대화’를 고도화해 주세요. 이 화면은 사용자가 텍스트 또는 음성으로 업무 질문을 시작하고, 권한 범위의 자료를 근거로 받은 답변을 검토하며, 후속 질문이나 담당 앱의 검토 화면으로 이어가는 AI 작업 공간입니다. 현재 기능은 입력·소스 선택, 네 가지 시작 질문, 최근 업무 컨텍스트, 처리 진행·중단·재시도, 답변·복사·음성 듣기·평가, 검증 패널·출처 미리보기, 검토형 업무 연결입니다. 기본 에이전트와 전자결재 전문 모드를 같은 디자인 체계로 수용해 주세요. 정교하고 친근하며 집중도 높은 실제 작업 화면을 만들고, 기존 기능과 신규 제안을 구분해 주세요. 권한·근거·명시적 검토 원칙을 약화하거나 미구현 자율 실행을 완성된 것처럼 표현하면 안 됩니다.
