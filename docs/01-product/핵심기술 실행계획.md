## 1. 목적

이 문서는 DWP 로드맵의 기술 작업을 실제 구현 순서와 종료 증거로 변환한다. 메뉴나
Demo 화면의 개수를 진척으로 보지 않고, Tenant 격리·권한·감사·운영·자동검증을 갖춘
재사용 가능한 Platform Capability만 완료로 본다.

## 2. 공통 완료 정의

각 Capability는 다음 조건을 모두 충족해야 `implemented baseline`이다.

1. Product Scope, Non-goal, 데이터 Owner와 Runtime 소비자가 정의된다.
2. Tenant·Identity·권한 경계와 Fail-closed 조건이 코드에 적용된다.
3. Schema, API, Lifecycle, Version, Error, Audit와 보존 계약이 문서화된다.
4. Frontend·Backend·Agent 중 영향받는 저장소의 Contract가 일치한다.
5. Unit·Integration·E2E·Axe 중 위험에 맞는 자동 Test가 통과한다.
6. 실제 Database와 Gateway 경로를 검증하고 임시 데이터는 제거한다.
7. 운영 Secret, SLO, RLS, 외부 고객 승인처럼 닫지 못한 Gate를 완료로 숨기지 않는다.

## 4. 구현 순서

### Stage 0. 공통 신뢰 기반

`T0 -> P1 -> P2 -> A0 -> A1`

현재 Baseline이 완료됐다. 이후 모든 기능은 이 경로의 Tenant Context, Registry, Audit와
Service Identity를 재사용한다.

### Stage 1. Enterprise Administration

1. **I1 Organization & Access:** Tenant User·Role, Organization Unit, 기본 조직 이동과
   직접 User Group Baseline은 완료했다. 다음은 SCIM 2.0 Mapping, Group Role,
   Effective Permission, 위임 범위와 Separation of Duties다.
2. **F1 Typed Configuration:** Feature Definition, Tenant Override, Evaluation Context,
   단계 Rollout, Kill Switch와 변경 Audit
3. **Catalog Entitlement:** Provider Catalog와 Tenant Assignment, App·Service·Widget
   가시성, 사용자 역할 기반 접근
4. **Security Operations:** Audit Filter·Export, 보존정책, Session·Credential 경고와
   Admin Overview

Identity와 Entitlement가 없으면 Connector나 Agent를 누구에게 노출할지 안전하게 결정할
수 없으므로 Stage 2보다 먼저 구현한다.

### Stage 2. 실제 업무 연결

1. **C1 Connector Detail:** OAuth Credential Reference, Scope, Cursor, Sync Job, Health,
   Rate Limit, Retry와 삭제 전파
2. **S1 Search ACL:** 원본 ACL Snapshot, Keyword Baseline, Citation, Freshness와 삭제
3. **W1 Workflow:** Approval, Timer, Retry, Idempotency, Compensation과 Human Task
4. **E1 Event Backbone:** Outbox, CloudEvents Envelope, Trace·Metric·Log 상관관계

외부 Tenant나 Dataset이 준비되지 않은 동안에는 Port·Reference Adapter·Contract Test까지만
구현하고 실제 Provider Gate를 통과했다고 표시하지 않는다.

### Stage 3. Governed Agent Execution

1. Agent Definition, Prompt·Context Version과 Model Route
2. Tool Definition, Input·Output Schema, Credential Scope와 Policy Grant
3. Risk Tier별 Plan Preview, Approval Token, 실행·취소·보상 Timeline
4. Evaluation Dataset, Shadow·Canary, Budget·Rate Limit과 Kill Switch
5. AgentOps 품질·지연·비용·정책 위반 Dashboard

### Stage 4. Productization

Provider Admin, Tenant Provisioning, Entitlement, Release Ring, Private·Hybrid Data Plane,
SLO·DR·Capacity, Connector Certification과 Industry Pack을 순서대로 확장한다.

## 5. Admin Capability 전체 범위

| 관리 영역   | Provider Admin           | Tenant Admin                   | Delegated Admin         |
| ----------- | ------------------------ | ------------------------------ | ----------------------- |
| Tenant      | 개통, Tier, Region, 상태 | Branding, Locale, 정책         | 해당 없음               |
| Identity    | Federation 기준          | 사용자, 조직, 그룹, Role, SCIM | 위임 조직 Membership    |
| Standards   | Global Template          | 기준정보·분류·Label            | 허용 Set의 Draft 제안   |
| Catalog     | 제품 Definition·Release  | Entitlement·노출               | Domain Service·Template |
| Integration | Connector 인증·지원      | Instance·Credential Ref·Sync   | 지정 Source 운영        |
| AI          | Model·Agent 인증 기준    | Agent·Tool·Policy·Budget       | 지정 Agent 운영         |
| Security    | Global 통제·Incident     | 보존·Consent·Audit Export      | 범위 내 Review          |
| Operations  | Release·SLO·비용·지원    | Adoption·Health·Quota          | Domain KPI              |

사용자 개인의 Theme, Density, 언어, 알림과 Home 선호는 Admin Plane이 아니라
Self-service Preference다. Font, 임의 Color Preset과 Navigation 구조를 일반 사용자에게
열지 않지만, Brand·Accessibility·운영 정책을 위한 기능 자체는 Design System과
Tenant Admin 영역에 유지한다.

## 6. 즉시 다음 Backlog

1. SCIM 2.0 Inbound Mapping과 Idempotent Provisioning Contract Spike
2. Group Role·Effective Permission과 Session·Cache Invalidation 계약
3. 위임 범위·SoD·Access Review 정책과 승인 계약
4. Typed Feature Definition·Tenant Override와 OpenFeature Evaluation Adapter
5. Provider Catalog·Tenant Entitlement 설계 후 App Launcher를 실제 Registry로 전환
6. Audit 보존·검색·Export와 Admin Security Overview

## 7. 외부 Gate

- 디자인 파트너와 실제 사용자 Baseline·Pilot Charter
- Microsoft 365 또는 Google Workspace Test Tenant와 최소 Delegated Scope
- Knowledge 원본, ACL·삭제 Event와 Data Owner 승인
- Workflow 비교에 사용할 실제 승인·Timer Journey
- Model Provider, 데이터 Residency, Budget과 Evaluation Dataset
- Production Secret Store, Workload Identity·mTLS, SIEM과 보존정책
- Figma 라이선스 준비 후 Foundation Library와 Feature Frame 연결

이 Gate가 준비될 때까지 로컬 구현과 자동 Test는 계속 진행할 수 있지만, Pilot Ready나
Production Ready로 상태를 올리지는 않는다.
