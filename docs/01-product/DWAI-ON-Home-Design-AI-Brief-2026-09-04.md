# DWAI·ON 홈 화면 디자인 AI 전달 브리프

작성 기준: 2026-09-04 현재 프론트엔드 구현 소스, 한국어 다국어 리소스, 제품 내비게이션 및 공통 디자인 토큰.

목적: 현재 구현된 기능을 정확히 보존하면서 DWAI·ON 홈의 정보 구조, 시각적 위계, 상호작용을 고도화하기 위한 디자인 의뢰서.

이 문서의 1~~9장은 현재 구현 설명이고, 10~~13장은 디자인 개선 요청이다. 이번 문서는 소스 기반 설명이며, 작성 시점의 실서버 데이터 수치나 모든 테넌트의 기능 활성화를 보증하는 운영 점검 결과는 아니다.

## 1. 제품과 화면의 정체성

### DWP와 DWAI·ON의 관계

- DWP는 회사별 테넌트, 사용자, 조직, 권한을 기반으로 업무·메일·일정·전자결재 등 여러 앱을 제공하는 디지털 워크플레이스 솔루션이다.
- DWAI·ON은 그 안에서 사용자의 업무 맥락을 연결하고 질문에 답하며, 다음 행동을 검토하도록 돕는 AI 앱이다.
- 공식 브랜드 표기는 `DWAI·ON`, 시스템 표기는 `DWAION`, 한국어 발음은 `디웨이온`이다.
- 브랜드 문장은 **“당신의 업무를 연결하는 DWP AI”**이다.
- 장기 지향점은 Agentic AI 기반의 지능형 업무 수행 환경이다. 그러나 현재 구현을 무제한 자율 실행 시스템이나 모든 앱을 음성만으로 제어하는 완성형 에이전트로 표현하면 안 된다.

### 이번 디자인의 정확한 대상

- 대상 화면: **DWAI·ON 앱 홈**, `/dwaion/home`.
- 앱 기본 경로: `/dwaion`. 사용자 업무 화면과 운영·관리 화면이 구분된다.
- 이 화면은 일반 구성원이 AI와 업무를 시작하는 개인 업무 진입점이다. 관리자도 사용자 업무 화면에서는 본인 맥락으로 이용한다.
- 회사 배경 이미지 위에 앱 아이콘과 위젯을 배치하는 **DWP 전체 홈**과는 다른 화면이다.
- 전역의 디웨이온 캐릭터 플로팅 패널, 새 대화 화면, 대화 상세 화면도 각각 별도의 표면이다.
- DWP 전체 홈의 배경 사진, 위젯 드래그 편집, 앱 아이콘 흔들림을 DWAI·ON 홈의 기존 기능으로 오해하지 말아야 한다.

### 이 화면이 해결하는 질문

> “지금 어떤 업무를 먼저 확인해야 하고, AI에게 무엇을 요청할 수 있으며, 이전 작업은 어디에서 이어갈 수 있는가?”

주 사용자는 회사 구성원이다. 주요 행동은 질문을 작성하거나 추천 질문을 선택하여 대화를 시작하는 것이다. 보조 행동은 우선 업무 열기, 이전 대화 재개, 전문 에이전트 선택이다. 화면 유형은 마케팅 랜딩 페이지나 관리자 통계 대시보드가 아닌 **개인 AI 업무 시작 화면**이다.

## 2. 전체 화면 구조와 공통 셸

### 상단 공통 헤더

헤더는 DWAI·ON 홈 전용 컴포넌트가 아니라 DWP의 공통 셸이다. 제품 브랜드, 현재 앱 식별, 워크스페이스 맥락, 공통 검색, 알림, 사용자 프로필 등의 기능을 담당한다. 화면·권한에 따라 앱 관리 진입이나 표면 전환 컨트롤이 달라질 수 있다.

디자인 시 현재 앱이 DWAI·ON이라는 점과 현재 조직·워크스페이스 맥락을 유지한다. 관리 권한이 없는 사용자에게 관리자 진입점을 상시 노출하는 시안은 피한다. 공통 검색과 아래의 AI 질문 입력은 목적이 다르므로 구분되어야 한다.

### 좌측 사용자 내비게이션

| 그룹 | 현재 메뉴명       | 경로                    | 사용 목적                       |
| ---- | ----------------- | ----------------------- | ------------------------------- |
| 시작 | DWAI·ON 홈        | `/dwaion/home`          | 질문과 업무 맥락의 시작점       |
| 대화 | 새 대화           | `/dwaion/new`           | 새로운 AI 질문 시작             |
| 대화 | 내 대화           | `/dwaion/conversations` | 저장된 개인 대화 탐색 및 재개   |
| 실행 | AI 실행 이력      | `/dwaion/activity`      | AI 요청의 처리 상태와 이력 확인 |
| 제안 | AI 제안함         | `/dwaion/proposals`     | 검토할 업무 제안 확인 및 처리   |
| 탐색 | 전문 에이전트     | `/dwaion/agents`        | 허용된 전문 에이전트 선택       |
| 탐색 | 업무 실행 및 연결 | `/dwaion/actions`       | 검토형 액션과 대상 앱으로 연결  |

메뉴는 제품 이용 권한과 세부 작업 권한을 반영한다. 특히 ‘업무 실행 및 연결’은 관련 액션 권한 조건이 적용된다. 모바일에서는 공통 셸의 축소·드로어 내비게이션을 활용하며, 데스크톱 메뉴를 그대로 좁게 압축하지 않는다.

운영·관리 표면에는 운영 현황, 에이전트 및 게시 관리, 데이터 소스와 커넥터, 액션과 실행 권한, 정책 및 안전 제어, 응답 품질과 평가, 운영 전환 검증, 데이터 보존과 감사가 있다. 이 운영 정보를 일반 구성원의 홈 본문에 모두 섞지 않는다.

### 현재 본문 배치

```text
공통 헤더
좌측 내비게이션 | 개인화 인사                          권한·정책 안내
                |
                | 업무에서 바로 질문하기
                | 질문 입력창 + 검색 범위 안내 + 마이크 + 전송
                | 오늘 업무 브리핑 / 막힌 업무 찾기 / 회의 준비
                |
                | 임박 업무 | 대화 기록 | AI 제안 | 에이전트 | 검토형 작업
                | 부분 조회 실패 시 경고
                |
                | 먼저 살펴볼 업무        | 최근 대화
                | 최대 4개 업무           | 최대 4개 대화
                |                        | 전문 에이전트
```

현재 질문 영역은 최대 너비 980px이고 본문 왼쪽에 정렬된다. 요약 지표는 큰 화면에서 5열, 작은 화면에서 2열이다. 하단은 `xl` 이상에서 약 1.25:0.75의 두 열, 그보다 작은 화면에서 한 열로 표시된다. 이 비율과 분기점은 현재 상태의 설명이며 새로운 디자인을 고정하는 제약은 아니다.

## 3. 개인화 인사와 신뢰 안내

현재 상단 문구는 다음과 같다.

- 작은 식별 문구: `나의 업무 인텔리전스`
- 주 제목: `{{name}}님, 무엇을 함께 해결할까요?`
- 보조 문구: `지금 처리할 업무와 허용된 정보에 근거해 답하고, 실행 전에는 반드시 검토를 요청합니다.`
- 우측 방패 아이콘과 안내: `현재 권한과 원본 시스템 정책 적용`

이름은 로그인 사용자 정보에서 가져온다. 이름이 없으면 `구성원`을 사용한다. 이름이나 회사명을 시안에 고정값으로 구현하지 않는다.

이 영역의 목적은 과장된 AI 소개가 아니라 개인화된 시작과 신뢰 경계의 전달이다. 별도의 대형 프로모션 배너, 장문의 기능 소개, 광고성 카피는 현재 목적에 맞지 않는다. 권한 안내는 중요하지만 사용자의 핵심 행동보다 강하게 강조할 필요는 없다.

## 4. 핵심 질문 입력 영역

### 현재 표시 내용

- 제목: `업무에서 바로 질문하기`
- 설명: `업무, 메일, 일정과 결재 맥락을 연결해 근거가 있는 답을 확인하세요.`
- 입력 안내: `찾고, 비교하고, 정리할 업무를 입력하세요`
- 입력창 하단 안내: `권한 범위에서 자동 검색`
- 현재 홈의 범위 표시: `업무 항목`, `메일`, `일정`
- 우측 컨트롤: 마이크 아이콘, 위쪽 화살표 전송 아이콘.

입력은 여러 줄을 지원한다. 기본 2줄에서 최대 5줄까지 늘어나며 4,000자 제한이 있다. Enter는 전송, Shift+Enter는 줄바꿈이고, 한글 입력기의 조합 중 Enter는 전송하지 않는다. 빈 질문은 전송할 수 없다.

### 현재 동작에서 중요한 구분

1. 홈의 세 가지 소스 표시는 **안내용**이다. 현재 홈에서는 클릭해서 켜고 끄는 필터가 아니다.
2. 소스 표시는 해당 커넥터가 모두 실시간 정상 연결되었거나 사용자가 모든 원본 자료를 읽을 수 있다는 뜻이 아니다. 최종 조회는 서버의 권한·정책·데이터 가용성에 따른다.
3. 홈은 답변을 그 자리에서 길게 펼치는 대화 화면이 아니다. 질문 전달을 준비한 뒤 새 대화 워크스페이스로 이동한다.
4. 질문은 안전한 일회성 전달 식별자를 통해 넘긴다. 질문 본문을 URL의 `q=` 등에 넣는 디자인·개발은 하지 않는다.
5. 전송 준비 중에는 중복 제출을 막고 전송 아이콘에 진행 상태를 표시한다. 현재 홈에는 응답 생성 취소 버튼이 따로 없으며, 대화 화면의 취소 기능과 구분한다.
6. 준비 실패 시 입력을 지우지 않고 `안전한 질문 전달을 준비하지 못했습니다. 입력한 질문은 유지되니 다시 시도하세요.`라고 안내한다.
7. 홈의 입력 영역에는 현재 파일 첨부, 드래그 앤 드롭 업로드, 모델 선택 드롭다운이 없다. 이를 시안에 추가한다면 신규 기능 제안으로 명시한다.

### 음성 입력 STT

현재 실제 구현은 **녹음 후 받아쓰기 방식**이다. 실시간 양방향 음성 통화나 항상 듣는 음성 비서가 아니다.

```text
마이크 클릭
→ 브라우저 마이크 권한 요청
→ 녹음 중
→ 사용자가 중지 또는 최대 45초 후 자동 종료
→ 서버 받아쓰기 요청
→ 변환된 텍스트를 질문 입력창에 추가
→ 사용자가 확인·수정
→ 전송
```

현재 상태 문구는 `마이크 권한 확인 중`, `듣는 중 · 눌러서 종료`, `받아쓰는 중`, `받아쓰기 완료 · 전송 전 확인`, `음성 입력 다시 시도`이다. 브라우저가 지원하지 않으면 이를 알리고 마이크 컨트롤을 사용할 수 없게 한다. 화면 이탈이나 비활성화 시 녹음·요청을 정리한다.

음성이 텍스트가 되었다는 이유로 질문을 자동 전송하거나 메일 발송·결재·일정 변경을 자동 실행해서는 안 된다. TTS ‘답변 듣기’ 기능은 연결된 답변 화면에 있고, 현재 홈에는 재생할 답변 본문이 없다.

## 5. 빠른 시작 질문 3개

현재 입력창 아래에는 작은 텍스트형 액션 3개가 있다. 단순 카테고리 전환이나 설명 팝업이 아니라, 정해진 질문으로 **대화를 바로 시작하는 버튼**이다. 입력창에 예문만 넣는 동작이 아니다.

| 버튼명           | 전달하는 실제 질문                                                   | 사용자 기대                     |
| ---------------- | -------------------------------------------------------------------- | ------------------------------- |
| 오늘 업무 브리핑 | 오늘 처리할 업무를 우선순위와 마감 위험 기준으로 요약해 주세요.      | 오늘 무엇을 먼저 처리할지 정리  |
| 막힌 업무 찾기   | 현재 진행을 막는 업무와 필요한 다음 조치를 찾아주세요.               | 지연·차단 원인과 후속 조치 확인 |
| 회의 준비        | 오늘 예정된 회의와 관련 업무를 바탕으로 준비할 내용을 정리해 주세요. | 일정과 연관 업무를 연결한 준비  |

첫 진입 시 이미 만들어진 브리핑 결과가 자동 표시되는 것은 아니다. 클릭 후 권한 범위의 자료를 조회하는 대화 흐름이 시작된다. 자료 부족, 접근 제한, 모델 가용성 제한이 있으면 그 사실을 표현해야 하며 항상 풍부한 답변이 나오는 것처럼 그리면 안 된다.

`정책·접근 확인`이라는 추가 질문은 공용 번역 리소스에 있으나, 현재 홈의 버튼은 위 3개뿐이다.

## 6. 업무 신호 요약 지표 5개

현재 한 줄의 요약 지표는 아이콘, 이름, 숫자, 보조 설명으로 구성된다. 현재 이 지표 자체에는 클릭·드릴다운 동작이 없다.

| 현재 지표          | 숫자의 실제 의미                    | 현재 보조 문구          | 오해하면 안 되는 의미                                   |
| ------------------ | ----------------------------------- | ----------------------- | ------------------------------------------------------- |
| 임박 업무          | 업무 큐 API의 `summary.dueSoon`     | 현재 업무 큐 기준       | 전체 미완료 업무 수나 AI가 새로 계산한 위험 점수가 아님 |
| 대화 기록          | 현재 받아온 대화 목록의 길이        | 안전하게 저장된 내 대화 | 반드시 전체 기간의 누적 대화 총계인 것은 아님           |
| 검토할 AI 제안     | 제안함 API의 활성 제안 수           | 우선 확인 N개           | 이미 자동 실행된 업무 수가 아님                         |
| 사용 가능 에이전트 | 현재 홈에서 노출 가능한 에이전트 수 | 게시 상태와 권한 적용   | 모델의 실시간 정상 상태나 전체 등록 에이전트 수가 아님  |
| 검토형 작업        | 액션 API가 반환한 작업 목록의 길이  | 사용자 확인 후 실행     | 나를 기다리는 승인 건수나 완료된 자동화 수가 아님       |

홈은 업무 큐, 대화, 제안, 에이전트 레지스트리, 액션 API를 각각 호출한다. 화면에 적힌 숫자를 하드코딩하지 않는다. 개발 환경의 원본 데이터는 씨드일 수 있지만, 이 홈 컴포넌트는 API 응답을 사용한다.

현재 캐시 신선도 설정은 대화·제안 20초, 업무 30초, 에이전트·액션 60초이다. 이는 해당 간격마다 반드시 자동 갱신한다는 뜻이 아니며, 홈에 전용 주기 폴링은 설정되어 있지 않다. 따라서 현재 홈을 ‘실시간으로 계속 갱신되는 대시보드’라고 설명하지 않는다.

## 7. 하단의 실제 콘텐츠

### 7.1 먼저 살펴볼 업무

- 제목: `먼저 살펴볼 업무`
- 설명: `마감과 진행 신호를 기준으로 우선순위를 정리했습니다.`
- 섹션 액션: `업무함 열기`
- 표시 개수: 최대 4개.
- 표시 항목: 업무 제목, 확인해야 하는 이유 또는 권장 다음 행동 또는 원본 시스템, 마감일이 있으면 월·일과 시계 아이콘.
- 현재 프론트 정렬: 우선순위 `high → medium → low`, 동일 우선순위이면 최근 갱신 순서. 프론트에서 마감일을 직접 정렬하는 구조는 아니다.
- 클릭: 원본 앱의 상세 경로가 있으면 그곳으로 이동, 없으면 해당 업무가 지정된 업무함 경로로 이동.
- 로딩: 목록 영역 스켈레톤.
- 빈 상태: `지금 처리할 우선 업무가 없습니다`와 `새 업무가 배정되면 영향도와 마감 순으로 표시됩니다.`

현재 제목은 한 줄 생략 표시되고 업무 설명은 보조 텍스트로 나온다. 승인·완료·메일 발송을 이 목록 안에서 바로 처리하는 컨트롤은 없다. ‘할 일 체크리스트’처럼 체크만 하면 원본 업무가 완료되는 것으로 디자인하면 안 된다.

### 7.2 최근 대화

- 제목: `최근 대화`
- 설명: `이전에 확인한 맥락에서 바로 이어갑니다.`
- 섹션 액션: `전체 보기`
- 표시 개수: API가 제공한 목록의 앞 4개.
- 표시 항목: 대화 제목, 마지막 메시지의 날짜·시간.
- 클릭: 해당 대화 상세를 열어 이전 맥락으로 이어간다.
- 로딩: 대화 목록 영역 스켈레톤.
- 빈 상태: `아직 대화가 없습니다`, 설명과 `대화 시작` 버튼.

현재 홈의 대화 목록에는 답변 요약, 고정하기, 삭제, 공유, 검색 입력이 붙어 있지 않다. 이런 기능을 제안할 경우 현재 구현과 구분한다.

### 7.3 전문 에이전트

- 제목: `전문 에이전트`
- 설명: `현재 역할에 허용된 전문 에이전트입니다.`
- 섹션 액션: `에이전트 보기`
- 표시 항목: 레지스트리의 에이전트명, 설명, `시작` 액션.
- 클릭: 해당 에이전트가 선택된 빈 대화 화면으로 이동한다.
- 현재 홈이 인식하는 에이전트 키는 `DWP_ASSISTANT`와 `DWP_APPROVAL_EXPERT` 두 종류다.
- 전자결재 전문 에이전트는 전자결재 앱 이용 권한도 확인한다. 실제 표기 이름과 설명은 서버 레지스트리 값이므로 시안에서 영구 고정하지 않는다.

모든 사용자가 항상 2개를 보는 것은 아니다. 등록·게시·응답·권한에 따라 달라진다. 현재 이 섹션에는 별도의 에이전트 전용 로딩·빈 상태가 충분히 구성되어 있지 않다.

## 8. 홈 밖으로 연결되는 기능의 경계

홈 디자인은 아래 기능으로의 연결성을 이해하되 모든 기능을 첫 화면에 펼치지 않는다.

| 연결 화면         | 현재 역할                                                                    | 홈에서의 관계                                           |
| ----------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------- |
| 대화 워크스페이스 | 질문, 처리 진행, 답변, 근거·출처 확인, 후속 대화, 답변 듣기                  | 질문 제출 후 도착하는 핵심 작업 공간                    |
| 내 대화           | 보관된 개인 대화 탐색·재개                                                   | 최근 대화의 전체 목록                                   |
| AI 실행 이력      | 요청의 진행·완료·실패 등 실행 상태 확인                                      | 별도 내비게이션으로 진입                                |
| AI 제안함         | 활성 제안, 미룸·처리 상태, 근거 확인, 분석 사용 설정·분석 요청·제안함 비우기 | 현재 홈에는 요약 숫자만 표시, 제안 본문 미리보기는 없음 |
| 전문 에이전트     | 역할에 맞는 에이전트 탐색과 시작                                             | 홈의 작은 선택 목록을 확장                              |
| 업무 실행 및 연결 | 사용 가능한 검토형 액션과 앱 연결                                            | 홈에는 개수만 표시                                      |
| 운영·관리         | 게시, 소스, 실행 권한, 안전, 평가, 감사 등                                   | 권한 있는 운영자만 별도 표면에서 접근                   |

제안함에서 제안을 검토하거나 승인한다는 사실과 원본 업무 앱에서 실제 변경이 실행되었다는 사실을 동일하게 표현하지 않는다. 실행 결과는 해당 액션의 서버 응답·원본 앱 정책을 기준으로 표시해야 한다.

대화 화면에는 모델 답변과 `근거 기반 대체 응답`을 구분하는 표현이 있다. 모델을 사용할 수 없어 제한된 대체 응답을 받은 상태를 완전한 생성형 분석 완료로 포장하지 않는다. 홈 고도화에서 답변 미리보기를 추가한다면 이 구분도 유지해야 한다.

## 9. 현재 디자인 기반과 확인된 한계

### 기존 스타일 기반

- React, MUI와 DWP 공통 디자인 시스템을 사용한다.
- 페이지 캔버스, 버튼, 아이콘 버튼, 입력 필드, 빈 상태 등은 공통 컴포넌트로 구성한다.
- DWAI·ON 제품 콘셉트 토큰: `intelligence-flow`, 정보 밀도 `comfortable`.
- 기본 라이트 토큰: 주요 강조 `#1557D5`, 보조 강조 `#008F7A`, 부드러운 표면 `#EAF1FF`, 본문 배경 `#F5F7FB`, 사이드바 `#FBFCFF`, 선택 상태 `#E6EEFC`.
- 실제 다크·대비 모드에서는 테마 변환을 사용하므로 위 색상을 모든 모드에 고정하지 않는다.
- 아이콘은 Lucide 계열이다. 기본 화면은 밝은 중립 배경, 절제된 파랑·청록, 얇은 경계선, 목록 위주로 구성된다.
- 캐릭터는 연결 리본이 AI 코어를 감싸는 기존 DWAI·ON 자산을 사용한다. 새로운 로봇이나 다른 캐릭터로 임의 교체하지 않는다.

### 고도화가 필요한 현 상태

1. 질문 입력 영역만 최대 980px이고 다른 영역은 넓게 퍼져, 넓은 화면에서 오른쪽 빈 공간과 읽기 흐름이 어색할 수 있다.
2. 질문, 업무, 대화, 에이전트가 존재하지만 시각적으로 ‘사용자의 다음 행동’을 충분히 안내하지 못한다.
3. 다섯 지표의 중요도가 같아 보이지만 실제로는 ‘임박 업무·검토할 제안’과 ‘보유 대화·에이전트·액션 수’의 성격이 다르다.
4. 지표에는 현재 클릭 동작이 없다. 클릭 가능한 카드처럼 보이게만 꾸미면 사용성을 해친다.
5. 조회 중이거나 실패한 지표가 기본값 0으로 보일 수 있다. 실제 0건, 아직 모름, 조회 실패를 분리해야 한다.
6. 부분 실패 경고가 전체 한 개의 안내로 표시되어 어느 자료가 실패했는지 분명하지 않을 수 있다.
7. 업무·최근 대화의 오류 시 빈 상태가 함께 나타날 여지가 있다. 실패와 정상적인 빈 결과를 시각적으로 구분해야 한다.
8. 에이전트가 없을 때 섹션이 비어 보일 수 있다. 표시할 수 없는 이유와 대체 시작 경로가 필요하다.
9. 현재 홈에는 마지막 성공 갱신 시각과 데이터별 신선도를 명시적으로 보여주는 UI가 없다.
10. ‘검토할 AI 제안’은 숫자만 있어 사용자가 왜 확인해야 하는지 알기 어렵다. 미리보기는 유용하지만 현재 기능이 아닌 확장 제안이다.
11. 긴 한국어 업무명·에이전트 설명이 생략되어 맥락을 충분히 전달하지 못할 수 있다.

이 한계들은 디자인 개선의 대상이지 현재 기능을 제거해야 한다는 뜻은 아니다.

## 10. 디자인 AI에 요청하는 고도화 방향

### 핵심 방향

> 질문을 입력하는 빈 채팅 시작 화면을 넘어, ‘지금 중요한 업무를 이해하고 다음 행동으로 자연스럽게 이어 주는 개인 AI 업무 홈’으로 발전시킨다. 다만 권한, 근거, 실행 전 검토라는 신뢰 경계는 유지한다.

### 우선순위

1. **핵심 입력 경험 강화:** 첫 화면에서 무엇을 요청할 수 있는지 알 수 있고, 텍스트·음성 입력과 빠른 시작의 관계가 명확해야 한다.
2. **업무 맥락의 의미 강화:** 단순 숫자 나열보다 지금 확인할 업무와 검토할 제안을 앞세운다. 대화·에이전트·액션 개수는 보조 정보로 재구성할 수 있다.
3. **이어 하기 강화:** 최근 대화를 찾기 쉬운 위치에 두고, 질문을 새로 시작하는 행동과 명확히 구분한다.
4. **정직한 상태 표현:** 대기·실패·권한 없음·데이터 없음·모델 제한·최신성 부족을 서로 다른 상태로 디자인한다.
5. **일관된 앱 연결:** 업무를 열 때 원본 앱으로 이동한다는 점, 질문할 때 AI 대화로 이동한다는 점을 예측 가능하게 한다.

### 시각적 방향

- 목표 인상: 지적이고 친근하며 정돈된 현대적 업무 도구. 고급스러움은 장식의 양이 아니라 정보 위계, 타이포그래피, 균형 있는 여백, 정확한 상태 표현으로 만든다.
- SAP·Salesforce의 딱딱한 관리 화면이나 일반적인 관리자 대시보드를 시각적 템플릿으로 사용하지 않는다.
- AI라는 이유로 우주 배경, 보라색 그라데이션, 발광 구체, 과도한 네온, 무의미한 파형을 추가하지 않는다.
- 동시에 얇은 선과 회색 글씨만으로 모든 영역을 나누는 밋밋한 화면도 피한다. 의미 있는 표면 차이, 선택 상태, 작업별 시각적 단서를 사용한다.
- 주요 브랜드 신호는 DWAI·ON 명칭과 기존 캐릭터·아이콘 체계로 제공한다. 캐릭터는 입력이나 업무 내용을 가리지 않는 보조 역할이어야 한다.
- 페이지 전체를 카드 안에 넣거나 카드 속에 다시 카드를 반복하지 않는다. 입력 도구와 개별 반복 항목처럼 실제 경계가 필요한 곳만 프레임을 사용한다.
- 화면 섹션은 자연스럽게 이어지는 레이아웃으로 구성한다. 모서리 곡률은 기존 시스템을 따르고, 특별한 이유 없이 8px를 넘는 카드 라운드를 남용하지 않는다.
- 기술 설명, 디자인 자랑, 기능 사용법을 본문에 장문으로 추가하지 않는다. 필요한 상태·권한·업무 맥락만 간결하게 쓴다.

### 제안 가능한 재배치 예시

이는 미구현 기능을 포함할 수 있는 제안이며 현재 화면의 설명과 구분한다.

```text
개인화 인사 + 간결한 신뢰/갱신 상태
주 질문 입력 + 음성 + 바로 시작 3개
지금 주의할 업무 / 검토할 제안 중심의 우선 행동 영역
우선 업무 목록                  최근 대화·이어 하기
                               전문 에이전트
보조 운영 수치는 필요 시 작고 조용하게 배치
```

AI 제안 미리보기, 지표 드릴다운, 홈 내 브리핑 미리보기, 갱신 버튼, 소스 선택 기능을 추가할 수 있으나 반드시 ‘신규 개발 필요’로 표시한다. 첫 시안은 기존 데이터·행동만으로 구현할 수 있는 안을 우선하고, 확장안은 별도로 제시한다.

## 11. 상호작용·접근성·반응형 요구

### 상호작용

- Hover는 항목이 열릴 수 있다는 것을, Focus는 키보드 현재 위치를 명확히 보여준다. 중요한 정보는 Hover에만 의존하지 않는다.
- 질문 전송 시 기존 입력 영역에서 진행 상태로 자연스럽게 전환하고 대화 화면으로 연결한다. 과도한 화면 전체 애니메이션은 피한다.
- 음성은 ‘듣는 중’에만 반응형 움직임을 표시할 수 있다. 실제 입력 볼륨 데이터가 없으면 정밀한 음량 파형처럼 속이지 않는다.
- 녹음 중지, 받아쓰기 진행, 검토 가능한 텍스트 상태를 분리한다. 마이크 권한 거부 이후에도 텍스트 입력은 유지한다.
- 목록 갱신 시 높이와 정렬이 급격히 바뀌지 않게 한다. 진행 애니메이션을 업무 성공으로 오해하게 만들지 않는다.
- 움직임은 상태 변화와 공간적 연결을 설명하는 데 사용하고, Reduced Motion에서는 필수 정보가 그대로 전달되게 한다.

### 접근성

- 마이크·전송·이동 등 아이콘 버튼에 접근 가능한 이름과 필요한 툴팁을 제공한다.
- 주요 터치 컨트롤은 44px 수준의 충분한 타깃을 유지한다.
- 상태는 색상만으로 구분하지 않고 텍스트·아이콘을 병행한다.
- 일반 본문 대비 4.5:1을 설계 목표로 하고, 다크·고대비 모드도 함께 검토한다.
- 키보드 순서가 시각적 읽기 순서와 일치해야 한다. 인사 다음 질문 입력, 빠른 시작, 우선 업무·대화 등으로 자연스럽게 이어지게 한다.
- 한글 이름, 긴 업무명, 영문 제목을 수용한다. 핵심 제목은 필요 시 2줄을 허용하고, 한 줄 생략만으로 중요한 업무 맥락을 숨기지 않는다.
- 화면 너비에 비례해 폰트를 무조건 줄이지 않는다. 레이아웃 재배치와 줄바꿈을 우선하고 음수 자간을 사용하지 않는다.

### 반응형

- 데스크톱 1440px와 1280px, 모바일 390px와 320px, 200% 확대 상태를 제공한다.
- 넓은 화면에서도 질문 입력과 하단 콘텐츠의 축이 어긋나거나 우측에 우연한 공백이 남지 않게 한다.
- 모바일의 우선순위는 질문 시작, 빠른 질문, 중요한 업무, 이어 할 대화 순서로 검토한다. 보조 지표와 에이전트는 필요에 따라 뒤로 이동할 수 있다.
- 5개 지표를 단순히 2열로 나열해 마지막 하나가 어색하게 남는 구조를 개선한다.
- 헤더, 사이드바, 플로팅 런처, 가상 키보드, 화면 하단 안전 영역이 본문과 주요 액션을 가리지 않아야 한다.
- 긴 입력, 로딩, 오류 문구로 컨트롤이 겹치거나 페이지 전체에 가로 스크롤이 생기면 안 된다.

## 13. 디자인 AI에 요청하는 최종 산출물

1. 현재 기능·데이터·이동 경로를 보존한 고도화 시안 1개를 우선 제공한다.
2. 신규 기능이 포함된 확장 시안은 별도로 제공하고, 각 추가 요소에 필요한 데이터와 서버 동작을 설명한다.
3. 데스크톱 1440/1280과 모바일 390/320의 실제 앱 화면을 제시한다. 소개용 랜딩 페이지는 만들지 않는다.
4. 라이트·다크, 첫 방문, 실제 콘텐츠, 부분 실패, 권한 제한, 음성 입력 상태를 제시한다.
5. 그리드, 여백, 타입 크기, 색상 역할, 컴포넌트 높이, 포커스·호버·로딩·비활성 상태를 명시한다.
6. ‘오늘 업무 브리핑 클릭 → 전달 준비 → 대화 진입’, ‘음성 입력 → 텍스트 검토 → 전송’, ‘업무 클릭 → 원본 앱 진입’의 흐름을 보여준다.
7. 어떤 현재 문제를 어떤 설계로 해결했는지 설명한다. 단순히 ‘고급스럽다’, ‘트렌디하다’는 평가만 제시하지 않는다.
8. 아래 사항은 금지한다: 허구의 성과·절감 시간·AI 정확도 표시, 동의 없는 자동 실행, 모든 원본 데이터 접근 가능 표현, 질문 본문 URL 노출, 녹음하지 않을 때 상시 청취 표현, 실제 없는 첨부·모델 선택·자동화 기능의 무표시 추가.

### 시안용 데이터 원칙

SKAX는 현재 개발 맥락의 예시 테넌트일 뿐이다. 솔루션은 다른 회사에서도 사용할 수 있어야 한다. 시안에는 `김하늘`, `프로젝트 일정 검토`, `회의 안건 정리`, `오늘의 우선 업무 확인` 등 가상의 이름과 업무명을 사용할 수 있지만 모두 예시 데이터임을 표시한다. 직원 실명·이메일·업무 본문을 추가로 수집하거나 실제 연결 상태인 것처럼 꾸미지 않는다.

### 전달용 요약 지시문

> 위 설명을 기준으로 DWP 솔루션의 DWAI·ON 앱 홈을 고도화해 주세요. 이 화면은 기업 사용자가 현재 권한 안에서 업무를 이해하고 AI 질문을 시작하며, 중요한 업무와 이전 대화를 이어 가는 개인 AI 업무 시작 화면입니다. 현재 기능은 개인화 인사, 텍스트·음성 질문 입력, 오늘 업무 브리핑·막힌 업무 찾기·회의 준비, 5종 업무 신호, 우선 업무, 최근 대화, 전문 에이전트입니다. 기존 기능과 보안·권한·명시적 검토 원칙은 유지하되, 정보 위계와 균형, 동적인 상태 전환, 사용자의 다음 행동을 중심으로 재설계해 주세요. 과장된 AI 장식이나 일반적인 관리자 카드 대시보드 대신, 정교하고 친근하며 업무 집중도가 높은 실제 사용 화면을 만들어 주세요. 기존 기능만으로 가능한 안과 신규 개발이 필요한 확장안을 명확히 구분해 주세요.
